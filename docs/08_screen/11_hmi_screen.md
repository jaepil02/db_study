이 문서는 발표의 마지막 화면 — "회사 카드 생산 라인에 붙이면 무엇이 보이나" — 를 명세한다. **HMI-PLANT는 상태와 데이터 종류만 보는 최소 HMI다.** 설비 30대가 지금 가동 · 대기 · 정지 · 통신 끊김 중 무엇인지, 설비마다 어떤 종류(온도 · 압력 · 속도 · 전류 · 진동 · 수량 · 상태 · 기타)의 데이터를 어떤 형식 · 주기로 보내는지를 보인다. 알람(임계 판정 · 확인)과 원격 조작(설비에 쓰기)은 없다 — 범위 경계는 [../01_overview/02_goals_scope.md](../01_overview/02_goals_scope.md)가 정본이고, 회사 라인에 붙일 때의 구성은 [../04_architecture/10_plant_adoption.md](../04_architecture/10_plant_adoption.md)가 정본이다.

**세 저장소가 한 화면에서 각자의 몫을 낸다.** 지금 값은 Redis(rt:latest — 30대를 한 번에), 최근 10분 추이는 ClickHouse(tag_raw), 설비 · 태그 정보(이름 · 형식 · 주기 · 종류)는 PostgreSQL(마스터 — api가 메모리 사본으로 붙인다)이 낸다 — 화면은 이 출처를 상세 머리에 표지로 단다. ①에서 원리로 본 역할 분담(대기줄 · 지금 값 / 업무 기록 / 센서 원본)이 실제 화면에서 어떻게 쓰이는지가 이 화면이다.

**화면의 데이터는 가상 PLC가 낸다.** 카드 라인 30대는 컨테이너 안의 가상 PLC(PlcSim — Modbus TCP 서버)이고, 수집기가 실제 PLC와 같은 Modbus TCP로 읽어 Redis 대기줄에 싣는다. 설비 가동이 꺼져 있으면 아무것도 보내지 않는다 — 화면 머리의 설비 가동 스위치로 켠다. 로컬 기동 기본값은 꺼짐이고(Compose SENSOR_AUTOGEN off), api를 다시 띄우면 켜 두었던 상태를 지우고 이 기본값으로 돌아간다(apps/api/src/modules/plant/plant-runtime.service.ts).

**진입**: 좌측 내비 현장 적용 섹션 "HMI 설비 현황판". 진입 파라미터 없음 — 처음에는 라인 1의 첫 공정(인쇄) 설비가 상세에 열린다.

```plain
┌ 카드 생산 라인 3개, 설비 30대 지금 상태  칸 하나가 설비 한 대예요 — 누르면 아래에 자세히 보여요   [설비 가동 ● 켜짐] [데이터 지우기] ┐
├ 요약 ─ ▶가동 N  ‖대기 N  ■정지 N  ⛓통신 끊김 N │ 초당 N개 데이터(주기 기준) │ 보내는 데이터 종류  온도 N% ▬ 압력 N% ▬ 속도 … 기타 ┤
├ 라인 판 ─ (설비 가동이 꺼져 있어요 — 오른쪽 위 스위치로 켜 보세요) ────────────────────────────────────────────┤
│        인쇄 › 합지 › 라미네이팅 › 펀칭 › 핫스탬핑 › 칩 홈 가공 › 칩 삽입 › 개인화 › 검사 › 포장                          │
│ 라인 1 [▬▬▬▬]  [▬▬▬▬] [▬▬▬▬]  …  ← 칸 = 상태 색 띠 · 상태 기호 · 초당 N개 · 핵심 값(큰 숫자 + 단위) · 종류 기호 줄 │
│ 라인 2 [ … 10칸 … ]                                                     (칸 뒤로 지나가는 가는 선 = 한 라인의 흐름)    │
│ 라인 3 [ … 10칸 … ]                                                                                          │
├ 고른 설비 자세히 ─ ▶ 라인 1 · 인쇄  L1-PRT  가동  태그 N개 · 초당 N개   ● 지금 값 Redis ● 최근 10분 ClickHouse ● 설비 · 태그 정보 PostgreSQL ┤
│ 종류   ●이름           ●지금 값   ●형식     ●주기   ●최근 10분                    ← 이 목록만 안에서 세로 스크롤     │
│ 속도    인쇄 속도        N 장/분   FLOAT32   1초    [작은 선]                                                   │
│ 온도    잉크 온도        N ℃      FLOAT32   1초    [작은 선]                                                   │
│ 수량    시트 수          N        UINT32    1초    [작은 선]                                                   │
│ 상태    운전 상태        가동      UINT16    1초    [계단 선]                                                   │
│ (회색 각주) 1초마다 새로 읽어요 · 통신 끊김 = 값이 5초 넘게 안 바뀐 설비 ⓘ                                       │
└──────────────────────────────────────────────────────────────────────────────────────────────┘
```

- **라인 판이 주인공이다.** 맞춤 보기에서 본문은 요약(내용 높이) · 라인 판(본문의 45% 이상 · 남는 높이) · 상세(목록 자리 높이만) 세 줄이다 — 큰 화면에서 상세 아래가 비지 않고 남는 높이를 라인 판이 가진다. 낮은 화면에서는 라인 판이 45% 아래로 줄지 않고 상세 목록이 안에서 스크롤한다.
- **공정 이름은 열 머리에 한 번만 쓴다(리드 승인 2026-10-11).** 세 라인이 같은 공정 순서라 칸마다 되풀이하지 않는다 — 대신 칸의 접근성 이름에는 "라인 1 인쇄 — 가동 · 인쇄 속도 N 장/분 · 초당 N개" 전체를 싣는다. 열 머리 사이 꺾쇠(›)가 공정 순서를 말한다.
- **와이어프레임의 N · 단위는 자리 예시다** — 이름 · 단위 · 형식 · 주기의 정본은 카드 라인 정본(packages/shared/src/card-line.ts)과 마스터(tag_master)이고 값은 §데이터 원천에서 읽는다.

- **시연 전용 설비는 보이지 않는다.** ⑥ 직접 보내 보기가 센서 점(flow 전용 태그 50개)과 업무 명령을 함께 싣는 시연 설비(DEMO-FLOW-DEV)와 시험용 슬라이스 설비는 api가 개요에서 뺀다 — 라인 판은 카드 라인 활성 설비만 그린다. 직접 보내 보기는 카드 라인 30대의 태그에 쓰지 않으므로 실행 중에도 30칸의 상태 · 지금 값 · 작은 선이 시연 값으로 바뀌지 않는다(apps/api/src/modules/runs/flow-runner.ts).
- **⑤ 직접 비교의 과거 구간 넣기는 지금 값을 바꾸지 않는다.** 적재는 지금보다 1시간 넘게 오래된 점을 원본에는 싣되 지금 값(rt:latest)에는 쓰지 않는다(신선도 가드 — 현행 값 1시간 · 코드 상수 LATEST_MAX_AGE_MS · apps/api/src/modules/ingest/latest-value-write.port.ts) — 지금 값 쓰기는 더 새 시각만 받는 조건부 쓰기라, 가드가 없으면 지금 값이 빈 때(지운 뒤 · 가동 전) 넣은 과거 값과 무결성 시험 행이 지금 값 자리에 남아 태그 목록에 지금 값처럼 보인다. 작은 선은 최근 10분만 읽으므로 과거 구간이 들어오지 않는다.

### 상태 판정 표시

설비 상태 4의 판정은 api가 하고(정본 [../07_api/06_realtime.md](../07_api/06_realtime.md)) 화면은 색 · 모양 · 글자 셋으로 그린다 — 색만으로 가르지 않는다.

| 상태 | 판정(api) | 색(띠 · 기호 · 글자) | 모양 | 칸 표시 |
|------|------|------|------|------|
| 가동 | 상태 태그 값 2 | 초록 #16a34a · 글자 #15803d | 재생(면) | 핵심 값 진하게 |
| 대기 | 상태 태그 값 1 | 노랑 #eab308 · 기호 #b8860b · 글자 #a16207 | 일시 정지(면 둘) | 핵심 값 진하게 |
| 정지 | 상태 태그 값 0 · 또는 설비 가동 꺼짐이면 30대 전부 | 연회색 띠 #cbd5e1 · 기호 #64748b · 글자 #475569 | 정지(면 사각) | 핵심 값 흐리게 |
| 통신 끊김 | 설비 태그 지금 값 중 가장 최근 갱신이 5초(PLANT_OFFLINE_AFTER_MS)보다 오래됨(단 설비 가동을 켠 뒤 5초 안이면 깨어나는 중이라 정지) · 또는 상태 태그 품질이 통신 불량(BAD_COMM) · 상태 값 없음 | 진회색 #475569 · 글자 #334155 | 끊긴 고리(선) | 핵심 값 흐리게 |

- 검산: 상태 = **4**(공용 계약 PLANT_DEVICE_STATES) · 판정 순서 — 설비 가동 꺼짐 → 전부 정지 / 마지막 갱신 5초 초과 → 통신 끊김(켠 직후 5초는 정지) / 상태 태그 통신 불량 · 값 없음 → 통신 끊김 / 그 밖 상태 태그 값 2 · 1 · 0
- **상태 색은 저장소 색과 겹치지 않는다.** 저장소 색(Redis 빨강 · PostgreSQL 파랑 · ClickHouse 주황)은 출처 표지에만 쓰고, 상태는 초록 · 노랑 · 회색 둘이다 — 보라는 색각 이상에서 PostgreSQL 파랑과 구분되지 않아 버렸다(대비 · 구분 실측은 lib/hmi.ts 주석 — 흰 바탕 기호 3 : 1 · 글자 4.5 : 1 이상).
- **데이터 종류 8은 색이 아니라 모양 기호다.** 온도 · 압력 · 속도 · 전류 · 진동 · 수량 · 상태 · 기타(공용 계약 TAG_KINDS · TAG_KIND_LABEL) — 기호는 장식이고 뜻은 옆 글자 · 칸 이름이 말한다.
- **B형 — 설비 가동을 끈 뒤 칸이 "정지"인데 상세 상태 태그가 "가동"일 수 있다.** 결론 — 끄면 api가 30대를 모두 정지로 판정하지만 Redis 지금 값은 멈추기 전 마지막 값으로 남는다. 반대 시나리오 — 지금 값을 그대로 판정에 쓰면 꺼진 공장이 가동으로 보이고, 지금 값을 지우면 켜는 순간까지 상세가 비어 형식 · 주기만 보인다. 파생 지침 — 상세 머리에 "보이는 값은 멈추기 전 마지막 값이에요"를 달고 값을 흐리게 그린다.

### 데이터 원천

| 화면 값 | 원천 | 이름 · 필드 |
|------|------|------|
| 상태 4 개수 · 초당 개수 · 기준 | GET /api/v1/plant/overview | totals(running · idle · stopped · offline · pointsPerSec) · pointsPerSecBasis(measured — 수집기가 실제로 센 수 · nominal — 통신 중 설비의 태그 주기 합) |
| 종류 비율 | 상동 | pointsPerSecByKind(TAG_KINDS 8) · 꺼짐이면 lines[].devices[].tags[].scanRateMs로 1000 ÷ 주기 합(화면 계산 — 머리에 "주기 기준" 표지) |
| 설비 가동 여부 | 상동 | power |
| 라인 판 · 칸 | 상동 | at · lines[](code · name · devices[] — deviceId · code · name · lineCode · processCode · processName · order · state · lastUpdateAt · pointsPerSec · keyTagId) |
| 태그 목록 · 핵심 값 | 상동 | devices[].tags[](tagId · code · name · kind · unit · dataType · scanRateMs · value — 공학 단위 · ts · quality) |
| 최근 10분 | POST /api/v1/timeseries/query | 요청 tagIds(고른 설비 태그 전부) · from · to(오프셋 포함 KST · 지금 전 10분부터 다음 분 경계까지) · interval raw · maxPoints 660 / 응답 series[](tagId · points) · meta.columns(값 열 위치) |

- 검산: 원천 행 = **6** — 필드 정본은 공용 계약 PlantOverview · TimeseriesQuery와 [../07_api/06_realtime.md](../07_api/06_realtime.md) · [../07_api/05_timeseries.md](../07_api/05_timeseries.md)
- **화면은 새 숫자를 만들지 않는다 — 예외 하나.** 설비 가동이 꺼져 초당 개수가 전부 0일 때 종류 비율만 태그 주기로 "켜면 보낼 몫"을 계산하고(api nominal과 같은 식) 머리 표지와 연한 막대로 계산값임을 밝힌다.
- **끝 시각은 다음 분 경계로 올려 보낸다.** 서버는 원시 조회도 범위 양 끝을 1분 경계로 내린다(SW-04 시각 스냅) — 끝을 지금으로 보내면 진행 중인 1분이 빠져 설비 가동을 켠 직후 최대 1분 동안 선이 비고 끝 점이 지금 값보다 최대 1분 늦다(2026-10-11 e2e에서 발견). 미래 끝은 계약이 받고 최근 5분 창이라 서버가 캐시하지 않는다 · 앞 끝 내림으로 더 온 점(10분보다 앞선 점)은 화면이 자른다.
- **maxPoints 660은 원시 11분의 1초 태그 점 수다.** 요청 범위가 10분 + 다음 분 경계까지(1분 미만)이고 서버는 원시 예상 점 수를 1초 주기로 세므로, 이보다 작게 보내면 1분 해상도로 올라가 10분이 10점이 된다 — 0.1초 태그(최대 6,600점)는 서버 다운샘플(LTTB)이 660점으로 줄인다(TSQ-06 · 차트 표준 "서버 다운샘플이 1차 방어선").

### 호출 표면 · 갱신

| 표면 | 호출 시점 | 경로 | 쓰는 응답 |
|------|------|------|------|
| GET /api/v1/plant/overview | 진입 · 1초 폴링(탭이 가려지면 멈춤 · 창 초점 재조회 없음) | 브라우저 → BFF(/bff/plant/overview) → api · no-store | §데이터 원천 개요 5행 |
| POST /api/v1/timeseries/query | 상세 설비가 정해지면 · 5초 폴링 · 설비를 바꾸면 그 설비 키로 | 브라우저 → api 직결(CORS 허용 오리진 http://localhost:13001) | series · meta.columns |
| GET · POST /api/v1/plant/power | 진입 · 5초 폴링 · 스위치 누름 | BFF 경유 · no-store | on · changedAt |
| GET /api/v1/data/sensor/stats · POST /api/v1/data/sensor/purge | 지우기 확인 창을 열 때 · [지우기] | 상동 | §공용 컨트롤 |

- 검산: 부르는 자리 = 개요 1 + 시계열 1 + 설비 가동 2(GET · POST) + 지우기 2(현황 · 지우기) = **6**
- 캐시 층 — 개요 plant · overview(staleTime 0 · 1초) · 최근 10분 plant · trend · {deviceId}(staleTime 0 · 5초 · gcTime 시계열과 같다 — 설비를 다시 고르면 바로 보이고 5초 안에 새로 읽는다) · 서버 층 — 개요는 Redis 지금 값을 매번 파이프라인 한 번으로 읽고 설비 · 태그 메타는 api 프로세스 메모리 사본(정본 [../07_api/06_realtime.md](../07_api/06_realtime.md)) · 최근 10분은 원시 최근 구간이라 조회 결과 캐시를 쓰지 않는다([01_standards.md](./01_standards.md) §갱신 주기와 캐시 층 정렬 시계열 최근 구간 행).
- **개요가 BFF를 거치는 것은 고빈도 실시간 직결 원칙의 기록된 예외다.** 1초 개요는 api가 BFF 경유 표면(CORS 없음)으로 냈다 — 브라우저 출처를 api에 더 열지 않는 대신 BFF 한 번의 중계를 더한다. 최근 10분은 기존 직결 표면을 그대로 쓴다([../07_api/01_conventions.md](../07_api/01_conventions.md) §BFF 경유와 직결).

### 스위치 영향

| 스위치 | 이 화면에서 보이는 것 |
|------|------|

| SW-11 collector | 그림이 바뀌지 않는다 — 지금 값(rt:latest)을 적재(Ingest) 대신 수집기가 쓸 뿐 개요가 읽는 키는 같다 |

### 비고

- **칸 핵심 값의 글자는 칸 폭을 따라 큰다**(컨테이너 단위 16cqi · 본문 단계와 큰 숫자 단계 사이) — 1280에서 내비를 펼친 좁은 칸에서도 다섯 자리 값 + 단위가 잘리지 않는다.
