**화면은 데이터를 소유하지 않는다.** 모든 수치는 07_api 표면을 거쳐 오고, 화면 명세는 어느 표면을 어떤 빈도로 부르는지와 그 응답을 어느 캐시 층이 얼마 동안 들고 있는지를 고정한다. 표면은 **메서드 + 경로**로 인용한다. 원본에 없는 표면은 07_api 해당 파일의 확정을 기다리며 "07_api/{파일} 확정 대기"로 적는다.

**이 문서가 닫는 인계 1건** — 무효화 체인 ⑥단의 신호 키 → 브라우저 쿼리 키 대응([../06_pipeline/07_business_crud.md](../06_pipeline/07_business_crud.md) 미확인 등재)을 §무효화 신호 수신에서 고정한다. staleTime의 라이브러리 설정값은 [../09_tech_stack/01_frontend.md](../09_tech_stack/01_frontend.md)가 갖고, 이 문서는 값이 따라야 할 관계식을 갖는다.

## 화면 명세 템플릿

화면 하나 = H2 하나다. H2 제목은 "{화면 코드} — {화면명}"이고 아래 필드를 이 순서로 둔다.

| 필드 | 내용 | 비워 두면 |
|------|------|------|
| 메타 표 | 화면 코드 · 웹 경로 · 페르소나 · 역할(전원 무인증 — D-16) · 도입 단계 · 요청 경로(BFF 경유 · 직결) | 화면이 어느 단계에 생기고 누가 쓰는지 몰라 없는 권한 검사를 기대한다 |
| 목적 | 페르소나가 이 화면에서 답을 얻는 질문 한 문장 | 요소가 목적 없이 늘어난다 |
| 진입 | 진입 경로와 진입 파라미터(설비 · 태그 · 범위) | 딥링크가 어떤 상태로 열리는지 정해지지 않는다 |
| 레이아웃 | plain 펜스 와이어프레임 1개 | 요소 표의 위치 열이 가리킬 자리가 없다 |
| 요소 표 | 요소 · 위치 · 동작 · 기능 ID · 표면 | 기능 → 화면 추적([02_traceability.md](./02_traceability.md))의 근거가 끊긴다 |
| 상태 4행 | 로딩 · 빈 값 · 오류 · 정상 — §상태 4행 | 실패가 빈 화면으로 보여 결함과 설계 동작을 가를 수 없다 |
| 호출 표면 | 메서드 + 경로 · 호출 시점 · 경로 · 응답에서 쓰는 필드 | 화면이 표면에 없는 필드를 기대한다 |
| 갱신 주기 | 폴링 · WebSocket 프레임 · 수동 · 신호 무효화 중 무엇으로 새 값을 얻는가 | 화면이 스스로 낡는다 |
| 캐시 층 | 브라우저 쿼리 캐시 · BFF 서버 fetch 캐시 · Redis · Dictionary 중 응답이 지나는 층과 staleTime | 옛 값이 보일 때 어느 층의 창인지 가를 수 없다 |
| 스위치 영향 | 이 화면의 표시가 달라지는 SW-NN과 그때 보이는 것 | 실험 중 화면 변화가 버그로 신고된다 |
| 비고 | 표준과 다른 처리 · 확정 대기 자리 | 해당 없음 |

- 검산: 필드 = **11**
- **요소 표의 기능 ID 열이 추적성의 정본 자리다.** [02_traceability.md](./02_traceability.md)는 이 열을 모아 세며, 요소 표에 없는 기능을 화면에 매핑하지 않는다.
- 레이아웃 펜스는 plain 와이어프레임이다. 한 장에 들어가는지의 기준(맞춤 보기 페이지 스크롤 0 · 검사 4크기)은 §반응형 규칙이 갖고, 색 값 · 간격 토큰은 [../09_tech_stack/01_frontend.md](../09_tech_stack/01_frontend.md)의 구성 선택을 따른다.

화면 블록의 골격이다.

```plain
## {화면 코드} — {화면명}
├── 메타 표          코드 · 경로 · 페르소나 · 역할 · 단계 · 요청 경로
├── 목적 · 진입      한 문장 · 진입 파라미터
├── 레이아웃         plain 와이어프레임
├── 요소 표          요소 · 위치 · 동작 · 기능 ID · 표면
├── 상태 4행         로딩 · 빈 값 · 오류 · 정상
├── 호출 표면        메서드 + 경로 · 시점 · 경로 · 쓰는 필드
├── 갱신 · 캐시      주기 · 층 · staleTime 관계
└── 스위치 영향      SW-NN별 표시 변화          ← 없으면 "해당 없음" 행 하나
```

- **요소 표와 호출 표면 표는 같은 표면을 두 방향에서 본다.** 요소 표는 사람이 누르는 것에서, 호출 표면 표는 네트워크에서 출발한다 — 한쪽에만 있는 표면은 화면이 부르지 않는 표면이거나 버튼 없는 호출이다.
- **화면 안의 하위 영역은 H3로 나누지 않고 요소 표의 위치 열로 가른다** — H3는 명세 필드 묶음(요소 · 상태 4행 · 호출 표면 등)에만 쓴다. 화면 코드로 시작하는 H2 하나에 화면 하나가 대응해야 [02_traceability.md](./02_traceability.md)의 화면 수 검산이 문서 구조로 확인된다.

## 상태 4행

모든 화면 블록은 아래 4행을 갖는다. 행을 빼거나 합치지 않는다 — 해당 없는 행은 "해당 없음"과 그 이유를 적는다.

| 상태 | 반드시 적을 것 | 금지 |
|------|------|------|
| 로딩 | 첫 페인트에 무엇이 먼저 보이는가 · 스켈레톤 영역 · 이전 값 유지 여부 | 표 전체를 스피너 하나로 가리기 — 부분 응답(최신값은 왔고 트렌드는 안 온 상태)을 볼 수 없게 된다 |
| 빈 값 | **빈 사실의 종류를 가른다** — 조건 결과 0 · 측정값 아직 없음(200 빈 목록) · 기능 미도입 단계 | "데이터 없음" 한 문구로 셋을 묶기 — 신규 설비의 빈 목록이 장애로 읽힌다 |
| 오류 | 받는 에러 코드 목록 · 코드별 표시는 §에러 코드별 사용자 표시를 인용 · 오류 중 기존 값의 처리 | 코드 없는 일반 오류 문구 · 오류 중 기존 값을 지워 빈 화면 만들기 |
| 정상 | 값이 무엇을 기준으로 신선한가(ts · 캐시 여부 · 해상도) · 사용자가 판단할 표지 | 신선도 표지 없이 값만 표시 — STALE · 다운샘플 · 캐시 히트가 정상 응답 안에 섞여 있다 |

- 검산: 상태 = **4**
- **200 응답 안의 경고를 오류 행이 아니라 정상 행에 적는다.** STALE 품질 · meta.downsampled · meta.cached · 비운 메타는 에러가 아니라 보정이다([../11_glossary/02_error_codes.md](../11_glossary/02_error_codes.md) §에러 코드가 아닌 것). 오류 행에 두면 화면이 보정을 실패로 그려 운영자가 정상 값을 의심한다.
- 권한 거부(403) · 인증 부재(401)는 없다 — 로그인 · 권한을 D-16으로 지워 모든 표면이 무인증이다(§단계별 화면 가용성). 오류 행은 §에러 코드별 사용자 표시의 코드만 인용한다.

## 한 화면 원칙

7화면이 지키는 표현 원칙이다(D-15 — 사용자 지시 2026-10-03 · 학습자 눈높이 · 한 화면 · D-16 — 한 장에 한 주제 · 글자 최소). 사용자는 1년차 학습자이고 선배 개발자 앞에서 발표한다 — "스크롤이나 접기 · 펼치기 없이 구현 의도와 내용이 한 눈에" 들어와야 한다. D-14 설계의 정보 4층(결론 띠 · 주 차트 · 원리 · 접힘 서랍)은 정보를 지우지 않고 서랍으로 내렸지만, 학습자에게는 서랍을 여는 일 · 코드표 · 지수 표기가 이해를 막았다 — 그래서 **세부는 화면에서 빼고, 정확성 계약만 각주와 툴팁으로 남긴다.** 요소별 배정은 각 화면 블록의 요소 표가 갖는다([09_learn_screens.md](./09_learn_screens.md) · [10_lab_screen.md](./10_lab_screen.md) · [08_evidence_screens.md](./08_evidence_screens.md) · [11_hmi_screen.md](./11_hmi_screen.md)).

| 6 | 색 3개 고정 | ClickHouse 주황 · PostgreSQL 파랑 · Redis 빨강 — 이긴 쪽 표시도 이 색 · 값 정본 §차트 표준 저장소 색 · 저장소가 아닌 뜻(⑦ 설비 상태)에 이 색을 쓰지 않는다 | 화면마다 색이 다르면 같은 저장소가 다른 것으로 읽힌다 |

- 검산: 원칙 = **6**
- **각주 · 툴팁으로 옮긴 계약은 계약 수에서 빠지지 않는다.** 지어낸 값 금지 · 승패는 3회 모두 같을 때만 · 시간은 참고값이라는 표기 · 계산값 표지 · 라이브 표지는 화면 블록의 표시 계약 · 공통 규칙에 그대로 있고 표시 자리만 각주 한 줄과 툴팁이다. 화면에서 뺀 요소는 그 표시 계약도 함께 지웠다 — 기록 · 판독기 · api 표면은 남는다.
- **원칙 1의 범위 밖은 작은 화면이다.** 1280 × 720보다 작은 창(지원 범위 밖)은 한 줄로 쌓고 셸 본문만 세로로 스크롤한다 — 작은 화면에서도 지키는 것은 셋이다 — 가로 스크롤 0 · 겹침 0 · 화면 안 글자 12px 이상(§반응형 규칙 · §글자와 화면 표면).
- **큰 화면은 늘어난다(D-16).** 본문 폭 상한을 두지 않고 2560 × 1440까지 글자 · 간격 · 그림이 화면 크기 비율로 는다(§반응형 규칙 늘고 주는 크기) — 옛 공통 최대 폭(본문 88rem)과 1680 × 1000 이상 한 단계 키움은 D-16으로 없어졌다.

화면 문구의 정본 용어표다. 왼쪽 열은 화면 1층(툴팁 밖)에 쓰지 않는다 — 문서 · 코드 · 툴팁은 왼쪽 열을 그대로 쓴다.

| 쓰지 않는다 | 쓴다 |
|------|------|
| 10^9 · 10^7.5 | 10억 행 · 약 3천만 행 |
| p50 · 중앙값 | 보통(중간값) — "중간값"은 각주에서만 |
| Q1~Q5 · I1 · I2 · EXP-NN · SW-NN · 기록 053 | 질문 이름("센서 1개 · 7일") · "PG(목차 있음)" — 코드는 툴팁에만(설정을 고쳐야 하는 안내 문구의 스위치 이름은 예외 — ⑤ "동시 적재 스위치(SW-09)가 꺼져 있어요") |
| 웜 · 콜드 | 쓰지 않는다(웜 기준 — 각주) |
| 구조 판정 · 참고값 · discarded · valid | "3번 모두 같은 결과" · "시간은 참고용" |
| 랙 · lag · 백프레셔 | 밀린 데이터 · 처리가 밀리는 중 |
| 배치 · flusher · XADD · XACK | 모아서 한 번에 저장(배치) · 묶음 |

| 원자성 · 트랜잭션 | 전부 되거나 전부 안 되거나(트랜잭션) · 실패하면 전부 되돌리기 |
| 그래뉼 · B-tree · BRIN · MVCC · WAL · 파트 머지 | 화면 1층에 쓰지 않는다 — "왜?" 문장은 쉬운 비유로(목차 · 묶음 · 조각) · 용어는 괄호로만(목차(B-tree) · 병합) |

- 검산: 용어 행 = **10**
- **용어표는 문구의 정본이지 사실의 정본이 아니다.** 쉬운 말로 옮겨도 사실은 정본 문서(05_data_stores/10 · 06_pipeline)의 것을 바꾸지 않는다 — 비유가 사실과 어긋나면 비유를 고친다.

## 반응형 규칙

7화면이 함께 지키는 크기 규칙이다(D-16 — 사용자 결정 2026-10-11 "1280 × 720 ~ 2560 × 1440에서 페이지 스크롤 0 · 스크롤은 목록형 컴포넌트 안에서만"). 옛 1440 × 900 픽셀 예산(화면마다 고정 높이 배분)과 화면별 미디어 분기는 이 규칙으로 대체해 지웠다 — 고정 픽셀 대신 비율 격자 · clamp 토큰 · 그림 viewBox가 높이를 나눈다. 값의 자리는 웹 전역 스타일(apps/web/app/globals.css — 변형 fit: · 토큰 --fs · 글자 토큰 · 셸 치수)과 공통 틀(components/shell/screen.tsx)이고 검사는 e2e 공통 도우미(apps/web/e2e/support.ts)다.

| # | 규칙 | 내용 | 어기면 |
|:--:|------|------|------|
| 1 | 맞춤 보기 범위 | **가로 80rem(1280) 이상 그리고 세로 45rem(720) 이상**이면 맞춤 보기(웹 변형 fit:) — 화면 틀이 셸 본문 높이에 꼭 맞고, 안쪽 덩어리는 줄고 늘 수 있게(min-h-0 · flex-1) 남는 높이를 나눠 가진다 · 문서 · 셸 본문 스크롤 0 · 가로 넘침 0 | 1280 × 720 노트북에서 결론이 접힌 아래에 숨고, 큰 모니터에서 그림이 위에 몰려 아래가 빈다 |
| 2 | 목록형만 스크롤 | 세로 스크롤은 목록형 조각(ScrollList — data-scroll-list) 안에서만 — 상자 높이는 바깥이 정하고 넘치는 줄만 안에서 움직인다(⑦ 태그 목록) · 그 밖의 상자는 넘치지 않게 **줄이거나 줄 수를 줄인다**(⑥ 세로 820px 미만이면 아래 줄을 뺀다) | 상자마다 스크롤이 생겨 어느 것을 굴려야 결론이 보이는지 모른다 |
| 3 | 작은 화면 | 1280 × 720 미만(지원 범위 밖)은 한 줄로 쌓고 셸 본문만 세로로 스크롤 · **가로 스크롤은 어디서도 없다** · 겹침 0 | 좁은 창에서 칸이 겹치거나 옆으로 밀려 글자가 잘린다 |
| 4 | 늘고 주는 크기 | 화면 크기 S = min(가로, 세로 × 16/9) · --fs = S가 1280일 때 0px · 2560일 때 1px인 길이 — 크기 = 바닥 + N × --fs를 clamp로 양끝 고정 · 셸 머리 높이 44 → 64 · 바깥 여백 12 → 20 · 칸 사이 8 → 20 · 칸 안 여백 10 → 24 · 내비 행 34 → 44 · 내비 폭 248 → 320 · 글자 토큰(§글자와 화면 표면 규격 2) | 큰 화면에서 글자만 작게 남아 멀리서 읽히지 않고, 작은 화면에서 글자가 12px 아래로 내려간다 |
| 5 | 격자와 그림 | 격자는 fr · minmax(고정 픽셀 열 없음) · 그림은 SVG viewBox(meet) · ECharts는 크기 관찰로 다시 그린다 · 칸 안 큰 숫자는 컨테이너 단위(cqi)로 칸 폭을 따라 큰다(⑦ 핵심 값) | 창 크기를 바꾸면 그림이 칸을 넘거나 빈 띠가 생긴다 |
| 6 | 셸 | 1440 미만 창은 저장값이 없으면 사이드바 레일(56)로 시작(§요청 경로와 공통 셸) · 머리 · 여백은 규칙 4의 clamp | 1280에서 펼친 내비가 본문 폭을 먹어 그림 배율이 1 아래로 내려간다 |
| 7 | 검사 | e2e 공통 도우미 — 맞춤 보기 4크기(1280 × 720 · 1440 × 900 · 1920 × 1080 · 2560 × 1440)에서 문서 · 셸 본문 scrollHeight ≤ clientHeight · 가로 넘침 0 · 목록형 밖 잘린 상자 0(expectFits) · 작은 화면 1024 × 768은 가로 넘침 0만(expectNoSideScroll) · 화면 뿌리는 data-screen으로 찾는다 | 한 화면만 고쳐도 다른 크기에서 스크롤이 생긴 것을 모른 채 넘어간다 |

- 검산: 규칙 = **7** · 맞춤 보기 검사 크기 = **4** + 작은 화면 1
- **화면이 줄 수를 줄이는 것은 정보를 버리는 것이 아니다(B형).** 결론 — 세로가 짧은 맞춤 보기에서 ⑥은 아래 줄(왜 나눌까 · 모아서 vs 하나씩)을 빼고 흐름도가 배율 1을 지킨다. 반대 시나리오 — 아래 줄을 지키려고 흐름도를 줄이면 노드 글자가 12px 아래로 내려가 화면의 주인공이 가장 안 읽히고, 페이지 스크롤을 허용하면 규칙 1이 깨진다. 파생 지침 — 뺄 수 있는 줄은 화면 블록의 비고에 적고(무엇을 · 몇 px 아래에서), 결론 · 그림은 빼지 않는다.

## 공통 틀

7화면이 같은 조각으로 짓는 화면 틀이다(components/shell/screen.tsx). 화면은 이 틀 위에 자기 그림을 놓고, 틀이 반응형 규칙 1 · 2를 맡는다.

| 조각 | 자리 | 규칙 |
|------|------|------|
| Screen | 화면 뿌리(data-screen = 경로 이름 — e2e가 찾는 이름) | 머리 줄 — 질문형 제목(h2 · title 토큰) + 설명 한 줄(body 회색) + 오른쪽 aside(화면 단위 동작 — ⑤ ⑥ ⑦의 공용 컨트롤) → 본문(남는 높이 · 기본 세로 쌓기) → 회색 각주 · 맞춤 보기에서 셸 본문 높이에 꼭 맞는다 · 화면 이름은 셸 머리 h1 하나(제목 줄은 화면 이름을 되풀이하지 않는다) |
| Panel | 흰 칸 | 제목(head) + 용어 괄호(note 회색) · 오른쪽 덧붙임 · 1px 중립 테두리 한 겹 · 줄고 늘 수 있다(min-h-0) · 칸 안에 칸을 다시 두르지 않는다 |
| Footnote | 맨 아래 한 줄 | foot 토큰 회색 + ⓘ 단추 — 세부는 툴팁(title)이고 단추라 키보드 초점으로 닿으며 접근성 이름이 같은 세부를 읽는다 |
| ScrollList | 목록형 조각 | data-scroll-list · 높이는 바깥이 정하고 안에서만 세로 스크롤(가로 숨김) · 접근성 이름 필수 |

- 검산: 조각 = **4**
- **제목 줄 aside는 셸 머리 동작 자리와 다르다.** 셸 머리 동작 자리는 셸이 그리는 자리에 화면이 조작을 넘기는 포털이고(⑥ 직접 보내 보기 · 지난번 글자), aside는 화면 틀 안 제목 줄 오른쪽이다(⑤ ⑥ ⑦ 공용 컨트롤 — [10_lab_screen.md](./10_lab_screen.md) §공용 컨트롤).

## 글자와 화면 표면

7화면이 함께 지키는 시각 규격이다(다듬기 — 사용자 지시 2026-10-03 · 리드 판정 .omc/plans/web-ux-polish.md §2.1 · §7.0 · §7.1). 구성 · 기능 · 문장 뜻은 바꾸지 않고 위계 · 가독성 · 시각 문법만 정한다 — 답이 되는 숫자가 본문과 같은 크기로 묻히고 상자가 겹겹이던 화면을 "한 눈에"(§한 화면 원칙)의 첫 눈이 숫자를 잡게 고친 결과다. 값의 자리는 셋으로 가른다 — 규격은 이 절 · 글꼴 파일과 토큰은 웹 전역 스타일(apps/web/app/layout.tsx · globals.css 테마) · 글꼴 버전은 [../09_tech_stack/03_data_infra.md](../09_tech_stack/03_data_infra.md) §버전 고정표, 화면마다 놓인 자리와 크기는 각 화면 문서의 요소 표가 갖는다.

| 5 | 줄바꿈 | 한국어는 **어절 단위로 끊는다**(word-break keep-all) · 어절 하나가 칸보다 길 때만 아무 데서나 끊는다(overflow-wrap anywhere) · 좁은 칸은 두 줄까지이고 그 안에 드는 짧은 문장만 쓴다 · 한 줄 자리(진행 띠 · 각주)는 잘라 쓰고(…) 전문은 툴팁 | 낱말 가운데서 줄이 바뀌어 "처리 / 중"처럼 읽히고, 잘린 문장("센서가 잰 값이 DB에 들어가기까…")은 고장처럼 보인다 |
| 6 | 선택 · 포커스 · 누름 | 글자 선택(::selection)은 강조 연한 색 바탕 · 글자색 그대로 · 키보드 포커스(:focus-visible)는 **2px 강조 색 링 · 바깥 2px** — 한 줄 높이를 지키려고 넘침을 자르는 자리(진행 띠 중단 버튼)만 링을 안쪽(−2px)으로 · 누를 수 있는 줄(그림 1)은 줄 전체가 버튼이고 마우스 올림 바탕 · 손가락 커서 · 누름 상태(aria-pressed) · 툴팁에만 있는 실행 결말(셸 머리 "지난번 …" 글자)은 키보드 · 낭독기로도 닿게 한다(탭으로 닿고 숨은 상세 문장을 설명으로 읽는다) | 브라우저 기본 링은 화면 색과 어긋나고, 잘린 링은 키보드 사용자가 지금 위치를 잃으며, 누를 수 있다는 표시가 회색 안내 한 줄뿐이면 상호작용을 발견하지 못한다 |
| 7 | 움직임 줄이기 | 운영체제의 움직임 줄이기(prefers-reduced-motion: reduce)를 따른다 — 깜빡임(로딩 틀 · 상태 칩 점 · 진행 점)은 멈춘 채 보이고 · 흐름도 점은 움직이지 않고 그 묶음이 가장 오래 머문 단계 노드에 나타났다 사라진다 · **정보는 줄지 않는다** | 움직임에 민감한 사용자가 화면을 볼 수 없고, 움직임을 끄면서 점까지 지우면 "시간이 어디서 갔나"가 사라진다 |
| 8 | 묶음 | **카드 안 카드 금지** — 묶음은 연한 바탕 머리 띠 + 1px 중립 테두리 한 겹이고, 그 안의 하위 묶음은 가는 줄(1px 중립)로 가른다 · 상자를 다시 두르지 않는다 | 상자가 겹겹이라 무엇이 묶음인지 흐려지고 시선이 테두리에 걸린다(옛 성능 비교 두 열 안 상황 카드 4 · 왜? 카드 2) |
| 9 | 테두리 | **화면 상자(HTML)에 1px 넘는 테두리 금지**(전체 · 한쪽 — 저장소 색 테두리 포함 · 그림(SVG · 캔버스) 안의 선 굵기는 이 규격 밖) · 저장소 색은 테두리가 아니라 머리 띠 바탕(연한 짝) · 이름 앞 색 점 · 글자(진한 짝) · 막대 · 선이 갖는다 | 굵은 색 테두리가 결론보다 먼저 시선을 잡는다(옛 2px 구역 테두리 · 4px 왼쪽 색 테두리) |
| 10 | 그린 기호 | 아이콘 · 결과 표지는 **그린 SVG**(같은 격자 · 같은 선 굵기 · 선 끝 둥글게)로 그린다 · 유니코드 기호 글자(▶ ■ ✓ ✕ ⚠ ⌛ ↺)를 글자로 그리지 않는다 · 기호는 장식이고 뜻은 옆 글자 · 접근성 이름이 말한다 | 글꼴마다 기호의 모양 · 폭 · 기준선이 달라 표지가 흔들리고, 낭독기가 기호 이름을 읽는다 |

- 검산: 규격 = **10** · 고정 단계 = 12 · 13 · 14 · 16 · 20 · 28 = **6** · 늘고 주는 토큰 = foot · note · body · head · title · big · hero = **7**(바닥 전부 12px 이상)
- **검사 자리는 셋이다.** 소스 단위 시험(apps/web/test/type-floor — 단계 밖 크기 · 임의 px · 12 미만 글자 크기 · 늘고 주는 토큰의 clamp 바닥 12px · 1px 넘는 테두리) · 흐름도 배치 시험(test/flow-layout — 글자 크기 × 배율) · e2e(§반응형 규칙 규격 7) — 규격을 바꾸면 세 자리를 같은 변경 단위에서 고친다. 소스 단위 시험의 대상 폴더는 flow · echart · shell · runs · ui · learn · lab · hmi · controls · app이다(D-16 새 화면 셋을 2026-10-11에 더함).
- **구역 상자에 저장소 색 테두리가 없는 것은 원칙 6(색 3개)을 버린 것이 아니다(B형).** 결론 — 저장소 색은 머리 띠 바탕 · 진한 글자 · 색 점 · 막대 · 선이 갖는다. 반대 시나리오 — 색 테두리로 구역을 가르면 안쪽 묶음과 겹쳐 묶음이 흐리고, 원색 주황(#d97706)을 작은 글자에 쓰면 흰 바탕 대비 3.2 : 1로 작은 글자 기준(4.5 : 1)에 못 미친다. 파생 지침 — 저장소 색 글자는 같은 계열의 진한 짝을 쓴다(§차트 표준 저장소 색).

## 단계별 화면 가용성

화면은 학습 단계(정본 [../01_overview/05_priorities_roadmap.md](../01_overview/05_priorities_roadmap.md))에 따라 열린다. **로그인 · 권한이 없어 모든 화면은 무인증이다(D-16).**

| 단계 | 열리는 화면 | 인증 · 역할 | 화면이 전제하는 것 |
|------|------|------|------|
| S2~S4 | 현행 화면 없음 — 이 단계에 열리던 화면(DSH-REALTIME · EXP-CONSOLE · ANL-TREND · ADM-MASTER · EXP-COMPARE)은 D-14로 폐지 | 없음 | 해당 없음 — 표면은 api에 남는다(D-14 결정 1) |
| S5 · S6 | EXP-FLOW | 없음 | flow 프레임 발행이 화면의 전제 · 옛 EXP-PERF는 D-16 폐지 |
| S7 | 화면 추가 없음 — 이 단계에 열리던 화면(AUTH-LOGIN · ALM-CONSOLE · ALM-RULES · ADM-WORKORDER · ADM-AUDIT)은 D-14로 폐지 | 없음(D-16) | 해당 없음 |
| D-16 재구성(2026-10-11) | LRN-CONCEPTS · LRN-STRENGTHS · LRN-TIMESERIES · LRN-ARCHITECTURE · EXP-LAB · HMI-PLANT | 없음(D-16) | ②③④ 측정 기록(docs/measurements)과 BFF 판독기 · ⑤ SW-09 gated 동시 적재 · 직접 비교 실행 · run_result · ⑦ 카드 라인 시드 30대 · 설비 가동 스위치 · HMI 개요 표면 |

- 검산: 현행 화면 = S5 1 + D-16 6 = **7** — [README.md](./README.md) 화면 인벤토리와 같다
- **화면에 권한 거부 행이 없는 것은 결함이 아니다.** 로그인 · 권한을 D-16으로 지웠고 표면은 127.0.0.1 바인드 안에 있다 — 출처 방어(CORS · Host · WebSocket Origin · BFF가 상태를 바꾸는 POST의 Origin을 허용 출처 http://localhost:13001 · http://127.0.0.1:13001 밖이면 403으로 막는 검사 — apps/web/lib/bff.ts)만 남는다. BFF 403은 다른 출처의 요청이라 화면 자신은 받지 않는다 — 그래서 위 표에 행이 없다.

## 요청 경로와 공통 셸

같은 웹 화면이라도 요청 성격에 따라 경로가 둘로 갈린다. 기준의 정본은 [../07_api/01_conventions.md](../07_api/01_conventions.md)이고 이 표는 화면별 적용이다.

| 요청 | 경로 | 이 문서군의 화면 | BFF 서버 fetch 캐시 |
|------|------|------|------|
| 사이트 · 라인 · 설비 · 태그 목록과 마스터 쓰기 | 브라우저 → BFF → api | 현행 화면 없음(폐지 전 ADM-MASTER · 설비 선택기) | 있음 — 쓰기 성공 시 체인 ⑤ |
| 명령 조회 · 라이브 실행(시작 · 현재 · 단건 · 중단 · 부분별 최근) | 브라우저 → BFF → api | EXP-FLOW(실행 조작부) · EXP-LAB(패널 ▶ · 부분별 최근 결과) — 명령 조회는 현행 화면 없음 | **no-store** |
| 최신값 | 브라우저 → api 직결 | 현행 화면 없음(폐지 전 DSH-REALTIME) | 해당 없음 |
| 시계열 조회 · 내보내기 | 브라우저 → api 직결 | HMI-PLANT(최근 10분 작은 선 — 시계열 조회만 · 내보내기는 현행 화면 없음) | 해당 없음 |
| WebSocket | 브라우저 → api 직결 | EXP-FLOW(subscribe_flow · 연결 상태는 흐름 구독 표지) · 공통 셸(연결 하나 · 출처 거절 처리 — 셸 표지 없음) | 해당 없음 |
| health · metrics(화면) | 브라우저 → BFF → api · 메트릭 텍스트 해석은 BFF가 한다 | EXP-FLOW(health — 각주 툴팁 · metrics 5초) | 없음 |
| 측정 기록 읽기 | 브라우저 → BFF · BFF가 docs/measurements를 읽기 전용으로 읽는다 — api 표면 없음 | LRN-STRENGTHS · LRN-TIMESERIES · LRN-ARCHITECTURE(성능 보기 view=perf · 업무 보기 view=evidence — 진입 1회) | 없음 — no-store(기록은 커밋으로만 바뀐다) |
| 설비 가동 · 센서 데이터 현황 · 지우기(공용 컨트롤) | 브라우저 → BFF → api | EXP-LAB · EXP-FLOW · HMI-PLANT(머리 공용 컨트롤 — 설비 가동 5초 폴링) · EXP-LAB(쌓인 비교 데이터) | **no-store** |
| HMI 개요 | 브라우저 → BFF → api — **api 표면이 BFF 경유 표면(CORS 없음)이라 1초 고빈도인데도 BFF를 거친다**(고빈도 직결 원칙의 기록된 예외) | HMI-PLANT(1초 폴링) | **no-store** |

- 검산: 요청 유형 = **9** · BFF 경유 6(마스터 · 실행 · health · metrics · 측정 기록 · 공용 컨트롤 · HMI 개요) + 직결 3(최신값 · 시계열 · WebSocket) = **9** · 현행 화면 · 셸이 쓰는 유형 = 실행 · 시계열 조회 · WebSocket · health · metrics · 측정 기록 · 공용 컨트롤 · HMI 개요 = **7** · 나머지 2(마스터 목록 · 쓰기 · 최신값)는 표면이 api에 남고(D-14 결정 1) 웹 화면이 부르지 않는다 · 옛 로그인 행은 D-16 폐지
- **health · metrics는 기계 호출에는 공개 직결이지만 화면은 BFF로 읽는다.** 브라우저가 Prometheus 텍스트 전체를 받아 파싱하지 않게 BFF가 해석한 결과만 내린다 — 같은 표면을 두 경로로 부르는 것은 호출 주체가 다르기 때문이다.

공통 셸은 화면 코드가 아니다 — 모든 화면을 감싸는 레이아웃(좌측 내비 · 콘텐츠 머리)이며 기능 매핑에서 "공통"으로 센다([02_traceability.md](./02_traceability.md)). D-16 뒤 셸이 감싸는 화면은 일곱이고, / 는 /concepts(① — 발표 첫 화면)로 · 옛 /performance는 /strengths(②)로 보낸다.

- **스크롤이 생긴다면 콘텐츠 본문 하나만 갖는다.** 페이지 전체(body)는 화면 높이에 고정하고 좌측 내비와 콘텐츠 머리는 움직이지 않는다(사용자 요구 2026-09-27 · 레이아웃 결정은 D-14 · D-15 뒤에도 유지). D-16 뒤 맞춤 보기에서는 본문도 스크롤하지 않는다(§반응형 규칙 규격 1) — 이 규칙은 작은 화면에서 본문만 스크롤해 현재 위치 · 실행 상태 칩 · 연결 표지가 늘 보이게 하는 자리로 남는다.

- **셸 머리에 WS 표지를 두지 않는다(리드 판정 2026-10-03).** 연결 상태는 EXP-FLOW 머리의 흐름 구독 표지 하나가 3상태(구독 중 · 재연결 중(다음 시도까지 초) · 끊김 — 4403 출처 거절 사유 포함)로 겸한다([08_evidence_screens.md](./08_evidence_screens.md) EXP-FLOW §요소). 셸 표지를 함께 두면 /monitoring 머리가 "구독 중"과 "연결"로 같은 사실을 두 번 말한다.
- **사이드바는 저장값이 없으면 창 폭 1440 미만에서 레일로 시작한다(리드 판정 — 다듬기 §7.0 · §7.1 R4 · 웹 상수 RAIL_BELOW_PX).** 첫 렌더는 펼침이고, 마운트 뒤 이 브라우저의 저장값을 읽고 없으면 창 폭으로 정한다. 1280 창에서 펼친 내비(248)는 본문 폭을 줄여 EXP-FLOW 흐름도의 배율이 1 아래로 내려가고 노드 글자가 12px 아래가 된다 — 레일(56)이면 본문이 흐름도 원래 폭(viewBox 1126)보다 넓어 배율 1을 지킨다(§글자와 화면 표면 최소 크기). **사용자가 직접 펼치거나 접으면 그 선택이 저장되고 창 폭보다 이긴다** — 그때 흐름도 배율이 1 아래인 것은 허용 예외다(사용자가 고른 배치다 · 글자 바닥 검사는 새로 연 창 기준).
- **본문 폭에 상한이 없다(D-16 — 옛 공통 최대 폭 90.5rem 삭제).** 2560 × 1440까지 화면이 넓어지는 만큼 그림이 는다 — 바깥 여백만 12 → 20으로 늘고 남는 폭은 칸 비율(fr)이 나눠 가진다. D-16 반응형 규칙이 "내용은 화면에 맞춰 줄고 는다"를 정했다 — 상한을 두면 2560에서 본문이 가운데 일부만 써 남는 폭을 그림이 받지 못한다(옛 최대 폭은 1920에서 1440 비율을 지키려던 장치였다).
- **화면 이름은 콘텐츠 머리의 h1 하나다.** 본문 첫 줄의 의도(질문형 제목 + 설명 한 줄 — §한 화면 원칙 원칙 2)는 화면 이름을 되풀이하지 않는 h2 · 문단이다 — 한 문서에 h1이 둘이면 보조 기술이 화면 이름을 두 번 읽고, 의도 줄이 화면 이름을 되풀이하면 같은 말이 두 줄을 먹는다.
- **한계 — 뒤로 가기의 스크롤 복원이 없다.** 브라우저의 스크롤 복원은 문서(window) 기준이라 콘텐츠 본문이 스크롤을 가지면 긴 목록에서 상세로 갔다가 돌아올 때 위치가 처음으로 간다. 필요해지면 경로별 본문 scrollTop을 세션에 저장해 되돌린다(미구현).

- **기본값과 다른 스위치는 각주 툴팁이 health 한 번으로 강조한다.** 이 시스템에서 "느리다"의 대부분은 스위치 하나로 설명된다([../01_overview/03_personas_roles.md](../01_overview/03_personas_roles.md)) — 그래서 셸 배지를 지우면서 그 일을 EXP-FLOW 각주 툴팁으로 옮겼다(D-14 서랍 → D-15 각주). 구현 선택 스위치(SW-11 · SW-12)는 기본값(ingest · stream)과 다른 구현이 주입되면 강조한다 — SW-12 direct면 툴팁에 "업무 쓰기 옛 경로 — 202 · 명령 멱등 없음"을 붙인다. 툴팁은 health switches 전수를 싣으므로 스위치가 늘어도 모양은 그대로다.
- **WebSocket 연결은 셸이 하나만 연다.** 화면마다 연결을 열면 탭 하나가 연결 여럿을 가져 연결 수 메트릭이 사용자 수가 아니라 화면 전환 수를 센다. 구독 목록만 화면이 subscribe · unsubscribe 메시지로 바꾼다 — URL 쿼리 구독은 4400으로 닫힌다([../07_api/11_websocket.md](../07_api/11_websocket.md) §구독 방식 판정).

공통 셸의 요소 표다. 횡단 기능은 특정 화면이 아니라 셸이 받으므로 [02_traceability.md](./02_traceability.md)는 이 표를 "공통 셸" 행으로 센다.

## 차트 표준

**서버 다운샘플이 1차 방어선이고 차트는 2차 방어선이다**(원본 tech_stack.md §4.2). 서버는 롤업 테이블로 1차 축소하고 여전히 많으면 LTTB로 2차 축소한다 — 브라우저는 받은 점을 그리기만 한다.

- 검산: 자리 = **7**
- **A형 — "화면 시각이 9시간 어긋났다"는 대개 저장 문제가 아니다.** 통념은 저장값이 틀렸다는 것이다. 부정 — 저장은 epoch이고 시간대 인자는 표시 · 파싱 · 달력 함수만 바꾼다. 진짜 축은 변환이 몇 번 일어났는가다. 대체 경로 — 같은 행을 epoch 밀리초로 보이는 툴팁과 수동 조회의 toUnixTimestamp64Milli 결과를 대조한다. 수동 조회는 UTC로 출력된다(ADR-27) — toTimeZone(ts, 'Asia/Seoul') 또는 epoch로 대조한다.
- **DB 처리 시간대 UTC(ADR-27) 뒤에도 화면 규칙은 불변이다** — API가 이미 UTC(epoch ms · Z)로 내리고 화면이 KST로 한 번 바꾼다.

## 업무 쓰기 응답 — 명령 경로

업무 쓰기는 api가 검증한 뒤 명령 스트림(stream:biz:cmd)에 싣고 워커가 PostgreSQL 트랜잭션으로 적용하며, api는 **커밋 결과를 받은 뒤에만** 응답한다(사용자 결정 2026-09-27 · 기전 정본 [../06_pipeline/07_business_crud.md](../06_pipeline/07_business_crud.md) §업무 명령 경로). 결과가 대기 상한(현행 참고 5초) 안에 오면 화면이 받는 응답은 옛 경로와 같다. 달라지는 것은 아래 셋이고, 대상 화면은 업무 쓰기를 하는 화면 전부다. **D-14 뒤 현행 화면 적용 없음** — 업무 쓰기 화면(ADM-MASTER · ALM-RULES · ALM-CONSOLE(확인) · ADM-WORKORDER(S7 ②))이 모두 폐지됐고, EXP-FLOW의 flow 실행이 싣는 업무 명령은 api 안(BizWritePort)에서 들어가 화면이 이 응답을 받지 않는다. 표면은 api에 남으므로(D-14 결정 1) 계약은 그대로 둔다 — 웹이 업무 쓰기 화면을 다시 두면 이 절을 따른다.

| 응답 | 화면 표시 | 다음 동작 | 금지 |
|------|------|------|------|
| 대기 상한 안 결과(201 · 200 · 400 · 404 · 409 등) | 옛 경로와 같다 — 성공은 로컬 무효화 · 재조회 · 오류는 §에러 코드별 사용자 표시 | 해당 없음 | 해당 없음 |
| **202 + {cmdId, status: 'pending'}**(응답 헤더 Idempotency-Key가 같은 명령 ID) | 저장 버튼 자리에 "적용 대기 — 명령 접수됨" · 폼 입력 유지 · **폼 잠금**(같은 폼 재제출 막음) | 명령 조회 GET /api/v1/commands/{cmdId}([../07_api/01_conventions.md](../07_api/01_conventions.md) 명령 조회 표면 #1 · BFF 경유 no-store)를 1 · 2 · 4초 … 최대 30초 백오프로 부른다 — status applied → 결과의 httpStatus · result로 기존 성공 처리 · rejected → error.code로 기존 오류 처리 · failed → common.postgres_unavailable/503 처리(같은 키로 다시 보내기) · expired → "적용되지 않았다 — 유효 창 초과"(다시 보낼지는 사용자가 정하고 보내면 새 키) · pending이 명령 유효 창(현행 참고 300초)을 넘으면 "오래 대기 — 같은 명령으로 다시 보내기"(같은 키) · 조회 404는 "이 명령을 볼 수 없다"(행위자가 다름) · 결말이 나면 폼 잠금 해제 | 202를 성공으로 그려 성공 안내 · 로컬 무효화 · 새 키로 재제출(워커가 두 번 적용한다) |
| **업무 쓰기 요청의 common.postgres_unavailable/503**(Redis 불가로 명령을 싣지 못함 · PostgreSQL 불가 — 07_api/01은 두 원인에 한 코드를 쓴다) | 폼 영역 띠 "업무 쓰기 저장소 응답 불가 — 조회는 된다 · 같은 키로 다시 보내면 안전"(Redis 불가 · PostgreSQL 불가 두 원인에 맞는 문구) · 목록 · 상세 유지 · 폼 입력 유지 · 조회까지 실패하면 조회 영역은 자기 503 띠("업무 저장소 응답 불가")를 따로 보인다 | 백오프 뒤 재시도 버튼 — 같은 키로 보낸다(적용되지 않았으므로 이중 쓰기가 아니다) | 목록 · 상세 숨기기(Redis 불가만이면 읽기는 PostgreSQL 직행이라 살아 있다) · 코드 이름으로 원인을 짐작해 다른 대응을 두기 — 대응이 같다 |
| 같은 키 재시도 | 화면이 폼 제출마다 UUID를 만들어 요청 헤더 **Idempotency-Key**에 싣고, 결말(applied · rejected · expired)이 날 때까지 그 키를 쓴다 · 네트워크 실패로 응답을 못 받은 제출 · 503 뒤 재시도 · 오래 대기 재전송이 모두 같은 키다 · 입력을 고쳐 다시 저장하면 새 키 | 첫 판정(applied · rejected)의 응답을 그대로 받는다 | 재시도마다 키를 새로 만든다 · 키 없이 보내 api 발급 키에 기대기(응답을 못 받으면 키를 모른다) |
- 검산: 응답 = **4**
- **B형 — 202는 실패가 아니다.** 결론 — 명령은 스트림에 있고 워커가 적용하면 결과가 원장에 남는다. 반대 시나리오 — 202를 오류로 그리면 사용자가 다시 저장해 새 명령이 생기고, 워커가 멈췄다 돌아오면 두 명령이 차례로 적용돼 태그가 둘 생기거나 409가 뒤늦게 난다. 파생 지침 — 폼을 잠그고 명령 조회로만 결말을 본다.
- **명령 조회로 적용을 확인한 뒤의 재조회는 BFF 사본을 건너뛴다.** 202에는 BFF 체인 ⑤가 걸리지 않으므로(07_business_crud) 화면은 로컬 무효화에 더해 신선 창 표지(x-bff-fresh)를 달아 목록을 다시 읽는다 — 표지 없이 읽으면 revalidate 창(현행 참고 30초)만큼 옛 목록을 보고 "적용됐다면서 안 바뀌었다"로 신고된다.
- **SW-12 direct에서는 202 · 명령 조회 · Redis 불가로 인한 쓰기 503이 없다** — 옛 경로(api 직접 커밋)라 Redis 불가 중에도 쓰기가 된다. Idempotency-Key는 형식 검사만 하고 되싣지 않으며 같은 키 재요청을 막지 못한다. 화면은 같은 코드로 두 경로를 받는다 — 202가 오지 않을 뿐이다.
- 낙관적 갱신 금지(§에러 코드별 사용자 표시)는 그대로다 — 명령 경로에서는 응답 전 반영이 202 대기 동안 더 오래 거짓으로 남는다.

- 쿼리 키 표기의 가운뎃점은 키 배열의 원소 구분이다 — 구현에서는 배열 원소가 된다.

## 무효화 신호 수신 — 체인 ⑥단

마스터 쓰기 뒤 ch:cacheinv로 발행된 **무효화된 키 이름**을 RLT-09가 WebSocket으로 중계하고, 공통 셸이 받아 아래 쿼리 키를 무효화한다. **D-14 뒤 현행 화면 적용 없음** — 아래 표의 영향 화면이 모두 폐지돼 셸이 신호를 받지 않는다(§요청 경로와 공통 셸 — RLT-09는 화면 없음(API 전용)). 중계 표면은 api에 남으므로 계약은 그대로 둔다. 단 번호의 정본은 [../06_pipeline/07_business_crud.md](../06_pipeline/07_business_crud.md) 무효화 체인 6단이다. 신호는 cacheinv 메시지(keys — 무효화된 키 이름 배열 · 접두 포함)로 오고 스로틀 병합 대상이 아니다([../07_api/11_websocket.md](../07_api/11_websocket.md)).

| 신호 키(ch:cacheinv) | 무효화할 쿼리 키 | 영향 화면 | 무효화하지 않는 것과 이유 |
|------|------|------|------|
| cache:tagmeta:{tag_id} | master · tags(목록 전부) · master · tag · {tag_id} · 그 태그를 가진 realtime · device · {device_id} | ADM-MASTER · DSH-REALTIME | timeseries 쿼리 — cache:q 결과는 체인 대상이 아니라 재조회해도 서버가 옛 이름을 TTL만큼 낸다 · 재조회는 무거운 쿼리를 한꺼번에 다시 부를 뿐이다 |
| cache:devlist:{site_id} | master · devices · {site_id} · 같은 사이트 설비의 modbus 설정 조회 | ADM-MASTER · DSH · ANL 설비 선택기 | realtime 쿼리 — 설비 목록 변경은 최신값 Hash 내용을 바꾸지 않는다 |

- 검산: 신호 키 = **2** · 옛 cache:alarmrules · cache:perm 행은 D-16 폐지
- **사이트 · 라인 쓰기는 신호가 없다.** 두 목록은 Redis 사본을 두지 않아 ③에 실을 키 이름이 없다([../06_pipeline/07_business_crud.md](../06_pipeline/07_business_crud.md) W5 판정) — 다른 사용자 화면은 staleTime(BFF revalidate 창 이하)만큼 옛 목록을 보이고, 쓴 탭은 자기 쓰기 성공으로 로컬 무효화한다.
- **ch:cacheinv에 오지 않는 키는 이 표에 없다** — cache:q는 체인 대상이 아니다. 그 무효화는 쓴 사람 화면의 자기 쓰기 성공과 staleTime이 맡는다.
- **⑥은 쓴 사람의 탭을 위한 단이 아니다.** 쓴 탭은 쓰기 응답을 받는 순간 같은 쿼리 키를 로컬 무효화한다 — ⑥은 다른 사용자와 **같은 브라우저의 다른 탭**을 위한 단이다. 탭마다 WebSocket과 쿼리 캐시가 따로라 다른 탭은 신호로만 안다(AC-06 브라우저 층).
- **신호는 스로틀 대상이 아니고 병합하지 않는다.** 받은 키를 받은 대로 처리한다 — 병합하면 키가 빠질 수 있다([../06_pipeline/05_realtime_read.md](../06_pipeline/05_realtime_read.md) F-07 사이클 ④).
- **신호 뒤 2초는 신선 창이다(S4 판정 · 검수 M5).** ⑥ 신호는 ③ 시점에 발화해 BFF의 ⑤보다 먼저 닿을 수 있다 — 그대로 재조회하면 BFF 서버 사본의 옛 목록을 받아 staleTime 동안 새 값으로 믿는다. 셸은 master 계열 신호를 받으면 신선 창을 열고, 창 안의 master 조회는 표지(x-bff-fresh)를 달아 BFF가 서버 사본 없이 api를 읽게 한다(기전 [../06_pipeline/07_business_crud.md](../06_pipeline/07_business_crud.md)). 재연결 무효화는 신선 창 없이 BFF 사본을 거친다. AC-06 다른 탭 층은 이 창 아래에서 3/3 성립했다(기록 021).
- **신호를 놓치면 staleTime이 상한이다.** Pub/Sub은 전달을 보장하지 않는다 — 재연결 직후 공통 셸은 master 계열 쿼리를 한 번 무효화해 끊긴 동안 놓친 신호를 메운다. 최신값의 재연결 1회 동기화(REQ-RLT-13)와 같은 모양이다.
