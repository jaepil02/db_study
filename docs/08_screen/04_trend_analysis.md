> **작성일**: 2026-09-24
> **원천**: 원본 data_flow.md §6 · §6.1 · §6.2 · §6.3 · §14.1(커밋 ff66a37) · 원본 architecture.md §11 · §11.1 · §10.2(커밋 ff66a37) · 원본 tech_stack.md §4.2(커밋 ff66a37) · REQ-TSQ-01~17 · REQ-MST-08 · AC-04 · AC-23 · AC-24 · AC-39 · 기능 TSQ-01 · 02 · 06 · 07 · 08 · 09 · MST-01 · 02 · 04 · [../06_pipeline/06_timeseries_read.md](../06_pipeline/06_timeseries_read.md) · [../02_features/07_timeseries.md](../02_features/07_timeseries.md) · [01_standards.md](./01_standards.md)

이 문서는 엔지니어가 과거 시계열을 범위로 보는 화면 하나를 명세한다. **엔지니어는 해상도를 고르지 않는다** — 범위 길이에 따라 서버가 raw · 1m · 1h · 1d 중 하나를 고르고, 예상 점 수가 상한을 넘으면 한 단계 올린다(REQ-TSQ-03 · 04). 이 화면의 일은 그 결정을 숨기지 않고 보이는 것이다 — 요청한 해상도와 받은 해상도가 다르면 사용자가 버그로 신고하기 전에 화면이 먼저 말한다.

**원시가 꼭 필요한 긴 범위는 차트가 아니라 내보내기로 간다.** 조회 표면은 거절하지 않고 보정하며, 원시 스트리밍은 별도 표면이 맡는다(원본 architecture.md §11.1).

## ANL-TREND — 트렌드 분석

| 항목 | 내용 |
|------|------|
| 화면 코드 | ANL-TREND |
| 웹 경로 | /trend(조회 조건은 쿼리 문자열 — 태그 · 범위 · 해상도 · 집계) |
| 페르소나 | 엔지니어(주) · 실험 수행자(캐시 스위치 관찰) |
| 역할 | S7 이후 조회는 인증 사용자 전원 · **내보내기는 ENGINEER만**(REQ-TSQ-17) · S2~S6 무인증 |
| 도입 단계 | S4(해상도 자동 선택 · 캐시 · 다운샘플) — S2의 raw 고정 조회는 DSH-REALTIME 트렌드가 맡는다 |
| 요청 경로 | 시계열 조회 · 내보내기는 api 직결 · 태그 선택 목록은 BFF 경유 |

**목적**: 지난주 이 태그는 어떻게 움직였나 — 받은 해상도 · 다운샘플 여부 · 캐시 여부를 함께 보며 추이를 읽는다.

**진입**: 공통 셸 메뉴 · 쿼리 문자열 딥링크(조건 공유) · ALM-RULES 판정 분석의 "원 시계열 보기" 링크. 쿼리 문자열의 범위는 오프셋 포함 ISO 8601이다 — 링크를 받은 사람이 다른 시간대 브라우저여도 같은 구간을 연다.

```plain
┌─ 조회 조건 ────────────────────────────────────────────────────────────────┐
│ 태그 [온도-1 ✕][압력-2 ✕][+추가]  3/50   범위 [최근 7일 ▾] 2026-09-17 00:00 ~ 09-24 00:00 KST │
│ 해상도 [자동 ▾]   집계 [avg ✓][min ✓][max ✓][last][p95]   [조회]  [내보내기 ▾]   │
├─ 결과 표지 줄 ─────────────────────────────────────────────────────────────┤
│ 해상도 1h(요청 자동) · 점 168 · 다운샘플 아님 · 캐시 히트 · p95는 근사       │
├─ 차트(uPlot) ──────────────────────────────────────────────────────────────┤
│  태그별 선 · min~max 음영 · 품질 BAD 구간 끊김 · 진행 버킷 점선             │
├─ 범례 · 태그 메타 ─────────────────────────────────────────────────────────┤
│ 온도-1(℃) · 압력-2(MPa · 비활성 태그)                                       │
└────────────────────────────────────────────────────────────────────────────┘
```

- **결과 표지 줄은 차트와 한 몸이다.** 표지 없이 차트만 보이면 "7일을 원시로 봤다"고 믿는다 — 실제로는 1h 버킷 평균이다.
- **min~max 음영은 집계에 min · max가 모두 선택된 경우에만 그린다.** 평균선만 보이면 버킷 안의 스파이크가 사라진다(원본 data_flow.md §6.3).

- **태그 선택기가 상한을 먼저 막아도 서버 거절 표시는 남긴다.** 딥링크로 상한을 넘는 조건이 들어올 수 있다 — 그때는 timeseries.too_many_tags/400을 받아 "나눈다"를 안내한다. 상한 값은 2계층이며 소유 [../07_api/05_timeseries.md](../07_api/05_timeseries.md)(원본 참고 50).
- **비활성 태그를 선택기에서 숨기지 않는다.** 비활성 태그도 과거 행을 가진다 — 숨기면 스케일 변경으로 비활성화된 이전 tag_id의 과거 추이를 볼 길이 없어진다(REQ-MST-08).

### 상태 4행

| 상태 | 처리 |
|------|------|
| 로딩 | 조건 줄과 축을 먼저 그리고 차트 영역만 스켈레톤으로 둔다. 재조회 중에는 **이전 결과를 흐리게 유지**하고 표지 줄에 "조회 중"을 둔다 — 지우면 두 결과를 눈으로 비교할 수 없다. 내보내기는 진행 표시(받은 바이트)를 조건 줄에 띄우고 조회를 막지 않는다 |
| 빈 값 | ① 조건 미완성(태그 0) — 차트 자리에 "태그를 고른다" ② **범위에 행 없음** — 200과 빈 points · "이 구간에 측정값이 없다"와 태그의 첫 측정 이후인지 안내 · 없는 tag_id도 거절이 아니라 빈 points다(존재 확인에 PostgreSQL을 읽지 않는다) ③ 보존 기간 밖 raw 요청 — 서버가 해상도를 올려 답하므로 빈 값이 아니다 · 롤업 보존까지 넘은 범위만 ②로 온다 |
| 오류 | common.validation_failed/400(오프셋 없는 시각 · from ≥ to · 허용 밖 집계) · timeseries.too_many_tags/400 · timeseries.clickhouse_unavailable/503 · common.rate_limited/429 · auth.forbidden/403(내보내기 · S7) — 표시는 [01_standards.md](./01_standards.md) §에러 코드별 사용자 표시. 503 중에는 이전 결과를 유지하고 띠만 띄운다 |
| 정상 | 결과 표지 줄 + 차트 + 범례. 해상도가 요청과 다르면 표지 줄에 "요청 raw → 받음 1m(점 상한 초과로 상향)", 다운샘플이면 "LTTB로 N점에 맞춤", 캐시 히트면 "캐시" 표지. 롤업 해상도의 p95는 "근사"(TDigest · REQ-TSQ-07) |

### 결과 표지 줄

응답 meta(REQ-TSQ-05 · 필드 정본 [../07_api/05_timeseries.md](../07_api/05_timeseries.md))를 사람이 읽는 문장으로 바꾸는 규칙이다.

| meta 필드 | 표시 | 이 표시가 막는 오해 | 기능 |
|------|------|------|------|
| interval | 받은 해상도 · 요청과 다르면 "요청 → 받음"과 이유(범위 길이 또는 점 상한) | "raw로 요청했는데 1m이 왔다"를 버그로 신고한다(REQ-TSQ-04) | TSQ-02 |
| pointCount | 받은 점 수 · 태그별 합 | 점이 듬성한 차트를 결측으로 읽는다 | TSQ-01 |
| downsampled | 참이면 "LTTB로 줄임 — 스파이크는 보존" · 원시가 필요하면 내보내기 링크 | 줄어든 선을 원시로 믿고 이상치 분석을 끝낸다 | TSQ-06 |
| cached | 참이면 "캐시" 표지와 캐시 층 설명 툴팁(완전 과거 · 현재 버킷 TTL) | 방금 고친 태그명이 옛 이름인 이유를 모른다 — §태그명과 캐시 | TSQ-01 |
| from · to | 요청 범위와 다르면 "실제 범위 — 버킷 경계로 내림"과 KST 시각 | 차트 양 끝이 입력한 시각과 몇 분 어긋난 것을 결측으로 읽는다 | TSQ-01 |

- 검산: 표지로 바꾸는 meta 필드 = interval · pointCount · downsampled · cached · from · to = **6** — meta.columns는 points 열 해석에만 쓰고 표지로 보이지 않는다
- **표지 줄은 캐시 히트율 측정의 화면 쪽 창이다.** SW-03 · SW-04 실험(AC-23 · AC-24 · AC-39)에서 같은 조건을 반복 조회하면 cached 표지의 켜짐 비율이 히트율의 모양을 보인다 — 기록값은 서버 메트릭이며 화면 수치는 4요소가 없어 기록에 올리지 않는다.

해상도가 어떻게 정해지는지를 사용자가 예측할 수 있게, 범위 프리셋과 서버 선택 규칙의 대응을 조건 줄 툴팁에 둔다. 경계 정본은 [../11_glossary/03_enums_state_machines.md](../11_glossary/03_enums_state_machines.md)이고 선택 기전은 [../06_pipeline/06_timeseries_read.md](../06_pipeline/06_timeseries_read.md)다.

| 범위 길이 | 서버 선택 | 툴팁 문구 | 원본 예상 응답(M 티어 — 미확인) |
|------|------|------|------|
| 1시간 이하 | raw(tag_raw) | "원시 — 점 상한을 넘으면 1m로 오른다" | 30~80 ms |
| 1시간 초과 ~ 7일 | 1m(tag_1m) | "1분 버킷" | 40~150 ms |
| 7일 초과 ~ 90일 | 1h(tag_1h) | "1시간 버킷" | 30~100 ms |
| 90일 초과 | 1d(tag_1d) | "1일 버킷 — KST 자정 기준" | 20~60 ms |

- 검산: 해상도 = **4**
- **B형 — 1년 범위를 raw로 지정해도 원시가 오지 않는 것은 보호 장치다.** 결론 — 서버가 해상도를 올린다. 반대 시나리오 — 원시 1년 요청을 그대로 받으면 M 티어에서 수천억 행 스캔이 ClickHouse를 메모리 한계로 죽이고 적재 삽입까지 멈춘다(원본 data_flow.md §6.1). 파생 지침 — 화면은 해상도 선택지에서 raw를 숨기지 않되, 긴 범위에서 raw를 고르면 "서버가 올린다 · 원시는 내보내기"를 선택 즉시 보인다.

### 태그명과 캐시

**A형 — "태그명을 고쳤는데 트렌드에 옛 이름이 보인다"는 결함이 아닐 수 있다.** 통념은 무효화 체인이 모든 층을 즉시 지운다는 것이다. 부정 — 시계열 결과(cache:q)는 dictGet이 조회 시점에 붙인 이름을 결과 안에 담고 있고 체인 대상이 아니다(REQ-TSQ-10). 진짜 축은 **이름이 결과에 굳었는가**다. 대체 경로 — 표지 줄의 "캐시" 표지가 켜져 있으면 캐시 TTL(완전 과거 현행 참고 300초) 안의 결과다. 새 이름을 바로 보려면 캐시를 거치지 않는 범위(끝이 현재)로 조회하거나 TTL 경과 뒤 재조회한다 — AC-06은 cache:q 히트를 제외한 조회로 판정한다.

- 화면은 cache:tagmeta 신호를 받아도 timeseries 쿼리를 무효화하지 않는다([01_standards.md](./01_standards.md) §무효화 신호 수신) — 재조회해도 서버가 같은 옛 이름을 내고, 여러 무거운 조회를 한꺼번에 다시 부를 뿐이다.

| GET /api/v1/sites · GET /api/v1/devices · GET /api/v1/tags | 선택기 열기 · 신호 무효화 뒤 | BFF | siteId · deviceId(태그 목록의 필수 필터) · includeInactive · 응답 식별자 · 이름 · 단위 · isActive |
| POST /api/v1/timeseries/query | 조회 · 따라가기 주기(진행 버킷만) | 직결 | 요청 tagIds · from · to(+09:00) · interval(자동이면 생략) · aggregations · maxPoints(플롯 폭 기준) · downsample(기본 lttb) · 응답 meta(interval · from · to · columns · pointCount · downsampled · cached) · series 태그별 points(배열의 배열 · 첫 열 epoch ms) · 태그 메타 |
| GET /api/v1/timeseries/export | 내보내기 | 직결 · fetch 스트림 | 요청 tagIds(쉼표 구분) · from · to · format(csv · parquet) · 응답은 ClickHouse FORMAT 스트림 그대로 · **완결 = 종결 청크 수신**(본문 표지 없음) |

- 검산: 표면 = **5**(sites · devices · tags · 조회 · 내보내기)
- **maxPoints는 사용자가 고르지 않는다.** 화면이 플롯 영역 픽셀 폭으로 정해 보낸다([01_standards.md](./01_standards.md) §차트 표준) — 폭보다 많이 받으면 보이지 않는 점이 응답 크기와 서버 캐시 메모리만 키운다.
- **내보내기를 링크 다운로드로 만들지 않는다.** S7 이후 내보내기는 Bearer 액세스 토큰이 필요한데 링크 다운로드는 Authorization 헤더를 실을 수 없고, 토큰을 쿼리 문자열에 실으면 URL · 로그에 남는다 — fetch 스트림으로 받아 파일로 쓴다.

### 갱신과 캐시

| 조회 | 캐시 층 | staleTime 관계([01_standards.md](./01_standards.md) §갱신 주기와 캐시 층 정렬) | 새 값을 얻는 수단 |
|------|------|------|------|
| 완전 과거 범위 | 브라우저 → Redis cache:q | cache:q 완전 과거 TTL × 0.8 이하 | 수동 재조회 |
| 끝이 현재 — 확정 과거 조각 | 상동 · 버킷 경계와 최근 창에 따라 TTL 분류가 갈린다 | 받은 조각의 TTL 분류 하한 | 따라가기에서도 다시 부르지 않는다 |
| 끝이 현재 — 진행 버킷 조각 | 최근 구간이면 캐시 없음 | 0 | 따라가기 주기 = 현재 버킷 TTL × 0.8 |
| 태그 선택 목록 | 브라우저 → BFF 서버 fetch 캐시 → Redis | BFF revalidate 창 이하 | 체인 ⑥ 신호 |

- 검산: 조회 = **4**
- **서버는 두 조각을 합치지 않는다 — 화면이 합친다**(REQ-TSQ-13). 두 조각은 원천 · 캐시 수명 · 지연이 달라, 한 응답으로 합치면 진행 버킷의 실패가 확정 과거까지 지운다. 화면도 진행 버킷 조회가 실패하면 확정 과거 선은 남기고 점선 구간만 비운다.
- 따라가기는 진행 버킷만 다시 부른다. 전체 범위를 주기적으로 다시 부르면 대시보드 자동 새로고침과 같은 모양이 되어 여러 사용자의 캐시 만료가 한 순간에 몰린다 — 지터(±20%)가 흩으려던 만료를 화면이 다시 모은다(원본 data_flow.md §6.2).

### 스위치 영향

| 스위치 | 상태 | 이 화면에서 달라지는 것 |
|------|------|------|
| SW-03 REDIS_QUERY_CACHE | off | 표지 줄의 "캐시"가 켜지지 않는다 · 반복 조회도 ClickHouse 집계 지연을 그대로 본다(원본 예상치 히트 시 250 ms 대 15 ms — 미확인) |
| SW-04 CACHE_KEY_TIME_SNAP | off | 같은 프리셋 반복 조회에서도 "캐시"가 거의 켜지지 않는다 — 초 단위 now()가 키에 들어가 매 요청이 다른 키다 |
| SW-05 CACHE_STAMPEDE_LOCK | off | 한 사용자 화면에서는 달라지는 것이 없다 · 동시 요청 부하에서 캐시 미스 지연만 는다 |
| 그 밖의 8 | 해당 없음 | 조회 결과의 원천은 ClickHouse뿐이다 — SW-09 on이어도 대조군 PostgreSQL을 읽지 않는다(REQ-TSQ-16) |

- 검산: 표시 스위치 3 + 해당 없음 8 = **11**
- **SW-03 off에서 SW-04 · SW-05의 차이를 이 화면으로 보지 않는다**(조합 제약 #1) — 캐시가 없으면 키도 락도 쓰이지 않아 차이가 0이다.

### 장애 시 보이는 것

| 장애 | 캐시 히트 조회 | 캐시 미스 · 최근 구간 | 내보내기 | 근거 |
|------|------|------|------|------|
| ClickHouse 중단 | 200 · "캐시" 표지 | 503 띠 · 이전 결과 유지 | 시작 전 503 · 도중이면 스트림 중단 | REQ-TSQ-16 |
| Redis 중단 | 해당 없음 — 모든 조회가 미스로 degrade | 200 · 지연만 는다 · 표시 없음 | 영향 없음 | REQ-TSQ-11 · AC-31 |
| PostgreSQL 중단 | 영향 없음 | 영향 없음 — 메타는 Dictionary가 마지막 적재 값을 쓴다 | 영향 없음 | REQ-MST-14 · REQ-TSQ-08 |
| 적체 소진 · 스풀 재발행 중 | 과거 버킷이 원천과 다를 수 있다 — 완전 과거 TTL이 상한 | 원천 그대로 | 원천 그대로 | [../06_pipeline/06_timeseries_read.md](../06_pipeline/06_timeseries_read.md) §늦게 도착한 데이터 |

- 검산: 장애 = **4**
- **B형 — Redis가 멈춰도 이 화면이 멀쩡한 것은 캐시 계열 degrade의 결과다.** 결론 — 캐시 실패는 에러 응답이 아니라 지연 상승으로만 드러난다. 반대 시나리오 — 캐시 실패를 503으로 올리면 Redis 중단 동안 과거 추이 분석 전체가 멈춘다. 파생 지침 — 같은 순간 DSH-REALTIME은 503을 낸다. 두 화면의 반대 반응은 캐시 계열과 봉인 계열의 실패 전략 이원화(ADR-05)가 화면에 드러난 모습이다.

### 비고

- **내보내기 완결은 종결 청크 수신으로만 판정한다**(07_api/05_timeseries 판정 — 본문에 종료 표지를 넣지 않는다). fetch 스트림 읽기가 오류로 끝나면 화면은 저장 파일 이름에 "불완전" 표기를 붙이고 경고를 띄운다 — 상태 줄 200이 이미 나간 뒤라 서버는 코드를 보낼 수 없고, 표시하지 않으면 잘린 CSV를 완전한 원시로 믿고 분석한다. Parquet은 꼬리가 없으면 파일이 열리지 않아 이중으로 드러난다.
