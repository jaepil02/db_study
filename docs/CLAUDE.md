> **작성일**: 2026-09-23
> **원천**: [README.md](./README.md)의 고정 기준 · ID 규약 · 전역 불변식 · docs_ref/docs_ref/CLAUDE.md의 형식 규율 이식(열거의 정합 규칙 승계) · 저장소 루트 docs_plan.md의 형식 사양

이 문서는 상태가 아니라 **변경 규칙**이다. 각 규칙은 드리프트가 실제로 생기는 형태를 막기 위해 있다. 문서군의 현재 수치는 [README.md](./README.md)의 고정 기준이 갖고, 이 문서는 그 수치를 바꾸거나 인용할 때 지킬 절차만 갖는다.

## 이 문서군의 성격

본 문서군은 **to-be 설계 정본**이다. 아직 구현이 없으므로 모든 서술은 "구현이 이렇게 되어야 한다"는 계약이며, 근거는 실측이 아니라 **원본 설계서 4본과 확정 결정(D-NN · ADR-NN)**이다. 구현과 측정이 진행되면 해당 문서를 as-built로 승격하고 근거를 실측(EXP-NN 결과 · 코드 경로 · DB 카탈로그)으로 바꾼다.

**미확인과 미설계를 구분한다.** 실측 전 성능 수치는 "미확인 — 확정 전 임의 값 고정 금지"로 등재하고 생략하지 않는다. 설계 범위 밖의 것(확장 로드맵 후반 단계 · 채택하지 않은 기술)은 부정형으로만 언급한다.

## 편집 전 필수 절차

1. [README.md](./README.md)의 **고정 기준**을 확인한다. 수치를 바꾸는 편집이면 정본과 파생 집계를 같은 변경 단위에서 함께 고친다.
2. 서술의 근거를 명기한다 — 원본 절(원본 architecture.md §8.4 형식) 또는 결정 ID(D-NN · ADR-NN). 근거 없는 신규 사실을 만들지 않는다.
3. **같은 폴더 기존 문서의 골격(메타 블록 · H2 순서 · 표 컬럼)을 우선 따른다** — "동일한 형식, 다른 내용"이 원칙이다.
4. **"문서에 없다"고 결론짓기 전에 세 자리를 다 본다** — 같은 사실이 요약 표 · 계약 표 · 서술 문단 세 자리에 나뉘어 있을 수 있다. **없다는 결론은 있다는 결론보다 근거가 더 필요하다** — 있다는 결론은 찾은 자리가 근거이고 없다는 결론은 훑은 범위 전체가 근거다.
5. 편집을 마치면 기계 검사(python3 .omc/docs_lint.py 대상경로)를 돌리고 오류 0건을 확인한다. 웨이브 마감과 W7 전수 검사는 --final 옵션으로 돌린다.

## 구조

- 폴더 구성은 [README.md](./README.md) 문서 지도의 12폴더다. 폴더 인덱스는 README.md, 세부 파일은 NN_snake_case.md 번호 접두(2자리)다. 파일명의 정본은 각 폴더 README의 파일 목차이며 목차 밖 파일을 만들지 않는다.
- **번호 대역을 지킨다.** 02_features는 14 이상, 03_requirements는 17 이상의 파일 번호를 쓰지 않는다. 05_data_stores의 07~10은 횡단 문서 예약 대역이다 — 타 폴더의 인바운드 링크가 이 번호에 고정되므로 재배치하지 않는다.
- docs/measurements/는 실측 기록 폴더다. 공통 골격과 기계 검사의 대상이 아니며, 기록 형식은 [10_observability/04_experiment_protocol.md](./10_observability/04_experiment_protocol.md)를 따른다. 설계 수치의 정본이 되지 않는다 — 기록이 확정한 값은 해당 정본 문서가 인용해 올린다.
- 전 문서 공통 골격(예외 0건):

```plain
# H1 (문서 제목)

> **대상**: …
> **작성일**: YYYY-MM-DD
> **개정일**: YYYY-MM-DD — {요약} — {상세}   (0..N줄 · 최신이 위 · 누적 · 삭제하지 않는다)
> **원천**: 원본 절 · 결정 ID · 정본 링크      (항상 메타 블록의 마지막 줄)

도입 단락 1~4개 (이 문서가 고정하는 사실과 경계)

## H2 섹션들
…
## 관련 문서        ← 반드시 마지막 H2
```

- 메타 블록 내부에는 빈 줄을 두지 않는다. 개정일 줄은 이력이므로 사후에 고치지 않는다. 수치 변화는 A → **B**(옛값 평문 · 새값 굵게)로 적는다.
- 원본 4본은 W7에서 삭제된다. 원천 줄은 **원본 architecture.md §N(커밋 ff66a37)** 형식으로 적어 삭제 후에도 git으로 추적되게 한다. 원본 파일로 가는 링크는 만들지 않는다.

## 서술 밀도

- 밀도의 단위는 절이 아니라 **표 한 행 또는 불릿 하나**다. 한 행이 결정 · 근거 · 인접 반례 · 경계 · 잔여를 함께 담는다.
- **모든 근거는 구체적 실패로 끝난다.** "성능 때문에"가 아니라 "이 컬럼이 없으면 E2E 지연을 SQL 한 줄로 잴 수 없다"까지 쓴다.
- 반직관적 사실은 두 틀 중 하나로 쓴다.
  - **A형**(독자가 버그로 신고할 동작) — 통념 명명 → 부정 → 진짜 축 → 대체 경로.
  - **B형**(독자가 실패로 오해할 안전장치) — 결론 선언 → 반대 시나리오의 구체적 결과 → 파생 지침.
- 분량 목표는 본문 문서당 표 8~15개 · 200~400줄이다. 분량보다 행 밀도를 우선한다.

## 이 프로젝트 고유 규칙

- **스위치를 더하거나 바꾸면** [02_features/13_switch_matrix.md](./02_features/13_switch_matrix.md)(정본) · [10_observability/06_experiment_catalog.md](./10_observability/06_experiment_catalog.md)(측정 실험) · [08_screen/07_experiment_console.md](./08_screen/07_experiment_console.md)(상태 표시)를 같은 변경 단위에서 고친다. 스위치 없는 실험 · 실험 없는 스위치를 두지 않는다.
- **새 데이터 종류를 들이면** [04_architecture/04_storage_split.md](./04_architecture/04_storage_split.md)의 3계층 분기 표에 행을 먼저 두고 [06_pipeline/04_routing.md](./06_pipeline/04_routing.md)에 기전을 적는다. 목적지를 정하지 않은 데이터는 스키마에 올리지 않는다.
- **새 Redis 키 계열을 들이면** [05_data_stores/05_redis_keyspace.md](./05_data_stores/05_redis_keyspace.md)의 봉인 표 칸과 검산식을 함께 고친다. 봉인 계열인지 캐시 계열인지 정하지 않은 키는 만들지 않는다.
- **측정 수치를 인용하면** 커밋 해시 · 메모리 프로파일 · 용량 티어 · 스위치 상태 4요소가 없는 수치를 본문에 올리지 않는다. 4요소가 없는 원본 수치는 "원본 예상치"로만 인용한다.
- **흐름 ID는 F-NN 형식만 쓴다.** 원본 표기 F1~F10을 본문에 쓰지 않는다.
- 문서 안의 구현 제약(포트 · 래퍼 · 모듈 경계)은 계약으로 쓴다. 코드는 쓰지 않는다 — 인터페이스 이름과 책임만 적는다.

## 열거의 정합

- 개수를 쓰면 그 자리에서 항목을 세어 맞추고 검산식을 남긴다. 표기 위치는 문단 끝 불릿 · 표 셀 안 · 독립 ### 검산 절 셋 중 하나이며 결과는 = **N**으로 굵게 닫는다.
- 다른 문서의 집계를 빌려 쓰지 않는다 — 정본을 다시 세거나 정본을 링크한다.
- 세는 기준이 둘이면 기준을 밝힌다.
- 전수 · 유일 · ~만 · ~뿐으로 단언하기 전에 정본 집합을 확인한다.
- 항목을 추가·삭제하면 그 항목을 세는 모든 자리를 훑는다.
- 같은 사실의 정본을 둘로 만들지 않는다.
- **한 문서가 같은 수치를 여러 자리에서 세지 않는다.** 세는 자리를 하나로 두고 나머지는 그것을 가리킨다 — 표 · 검산식 · 각주가 각각 세면 **갱신이 한 자리만 닿고 나머지가 조용히 어긋난다.**
- **"불변"을 말하는 문장에 수치를 박지 않는다.** 무엇이 왜 안 바뀌는지를 적고 **값은 정본이 갖는다** — "스위치 10은 불변"이 아니라 "환경변수 기본값만 바꿨으므로 스위치 수는 불변"이다. 개정일 줄은 이력이라 고치지 않지만, 같은 문장이 본문에 있으면 다음 신설 때 조용히 과거 사실이 된다.
- **표는 열 수를 지킨다.** 두 열에 공통인 내용은 칸을 비우지 않고 **상동**으로 적거나 표 밖으로 뺀다 — **빈 칸은 "왼쪽에만 해당한다"로 읽혀 쓰려던 뜻의 반대가 된다.**
- **어긋난 사례 하나가 분류를 강제한다.** 새 사례가 기존 분류의 어느 칸에도 들어가지 않으면 칸을 늘리지 말고 분류 축 자체를 다시 짠다.
- **닫는 축을 목록으로 쓰지 않는다.** "현재 X와 Y가 둔다"처럼 전수를 세는 형태는 새 항목이 생기는 순간 틀리는데 드러날 자리가 없다. 판정 기준은 하나다 — **그 문장이 항목 하나가 늘었을 때 틀리는가.**

## 하지 말 것

- docs_ref의 **내용**을 가져오지 않는다. 가져오는 것은 조직 원리와 서술 규율뿐이다.
- 미확인 수치를 확정 값처럼 쓰지 않는다 — "미확인 — 확정 전 임의 값 고정 금지"를 유지한다.
- 정본 밖에서 ID를 채번하지 않는다. 미러(07_api/02_errors.md)에서 코드를 신설·개명·폐기하지 않는다.
- 인라인 백틱을 쓰지 않는다. sequenceDiagram을 쓰지 않는다.
- 확정된 결정(D-NN · ADR-NN)을 재론하는 서술을 다른 문서에 흩뿌리지 않는다 — 결정 문서를 링크한다.
- 원본 설계서의 서술을 복사하지 않는다. **흡수는 복사가 아니다** — 사실은 보존하고 형식과 밀도를 이 규약에 맞춰 다시 쓴다.
- 구현 코드를 쓰지 않는다. 이 문서군의 산출물은 설계이며 코드 착수는 별건이다.
- 배포 · 원격 접속 · TLS · 클러스터를 현행 범위로 서술하지 않는다 — 로컬 전용이다. 언급이 필요하면 확장 로드맵의 진입 조건 또는 부정형으로만 적는다.
