원본은 사용자를 세 종류로 그렸다 — 실시간 모니터링의 **현장 운영자**, 업무 데이터 관리의 **관리자**, 이력 분석의 **엔지니어**(원본 architecture.md §2). 이 문서는 여기에 **실험 수행자**와 **시연 청중**을 더한다. 원본 세 종류는 이 시스템이 모사하는 현장의 사용자이고, 실험 수행자는 이 시스템을 측정 장치로 쓰는 사용자이며, 시연 청중은 사내 발표에서 7화면을 메뉴 순서대로 보는 사람이다(D-16 — 청중 10년차 이상 개발자). 학습 목표 2축(D-01)의 산출물은 실험 수행자가 만들고, 시연 청중은 그 산출물과 지금 시스템을 화면으로 읽는다.

**페르소나는 사람 수가 아니라 관점이다.** 로컬 머신 1대(D-02)에서 학습자 한 명이 다섯 관점을 오간다 — 발표에서는 학습자가 시연하고 청중이 본다. 그래서 페르소나 구분은 동시 사용자 부하의 근거가 아니라 **화면 · 요청 경로를 가르는 기준**으로만 쓴다. **권한 역할은 없다** — 로그인 · 권한이 D-16(사용자 결정 2026-10-11)으로 삭제돼 모든 표면이 무인증이다([../12_security/04_threat_model.md](../12_security/04_threat_model.md) §무인증 표면).

- 검산: 원본 3(현장 운영자 · 관리자 · 엔지니어) + 신설 2(실험 수행자 · 시연 청중) = **5**
- **빈도는 정성 서술이다.** 동시 사용자 수 · 요청률은 페르소나가 아니라 생성기 주입 · 라이브 실행 매개변수가 정한다 — 옛 k6 부하 시나리오는 D-16 삭제 · 용량 산정은 [../04_architecture/07_capacity_planning.md](../04_architecture/07_capacity_planning.md)다.
- **시연 청중을 신설한 이유** — 7화면(D-16 결정 1)의 앞 넷은 측정 기록을 판독할 뿐 api를 부르지 않아 원본 세 페르소나와 실험 수행자 어느 쪽의 작업에도 걸리지 않는다. 화면 문구의 기준(쉬운 말 먼저 · 용어는 괄호 · 숫자는 적게 — 08_screen/01 §한 화면 원칙)이 누구를 향하는지를 이 페르소나가 고정한다.
- **실험 수행자를 신설한 이유** — 원본 세 페르소나로는 스위치 상태 표시 · 실험 기록 · 규모별 성능 비교 화면의 사용자가 없다. 사용자가 없는 화면은 요구사항의 근거를 잃고, 실증 화면이 "관리자 부가 기능"으로 밀려 학습 목표의 산출 자리가 사라진다.

- **운영자의 작업은 거의 전부 Redis만 본다.** 운영자가 체감하는 "시스템이 느리다"는 대개 Redis 역할 스위치 하나의 상태로 설명된다 — SW-02 off면 최신값이 ClickHouse 점조회로 떨어지고, SW-07이 0이면 프레임이 폭증한다.
- 옛 알람 받기 · 확인 2행은 알람과 함께 D-16으로 지웠다 — HMI-PLANT에도 알람이 없다(D-16 결정 3). 통신 끊김(지금 값이 5초 넘게 안 바뀜)은 알람이 아니라 상태 판정이다.

### 관리자

| 작업 | 화면 | 요청 경로 | 닿는 저장소 | 분기 계층 |
|------|------|------|------|------|
| 사이트 · 라인 · 설비 · 태그 마스터 관리 | 화면 없음(API 전용) — 폐지 화면 ADM-MASTER(D-14) | BFF 경유 | PostgreSQL · 커밋 이후 캐시 무효화 · Dictionary 재적재 | ③(ClickHouse는 Dictionary로만 닿는다) |

- 옛 로그인 · 작업지시 · 변경 이력 확인 3행은 대상과 함께 D-16으로 지웠다 — 태그 계보(tag_master_history)는 쓰기만 남고 조회 표면이 없다([../07_api/04_master.md](../07_api/04_master.md)).
- **관리자의 쓰기는 명령 스트림(stream:biz:cmd)을 거쳐 워커가 PostgreSQL에 커밋한 뒤에야 응답을 받는다.** 이것이 분기 ③계층 — Redis를 거쳐도 목적지와 동기 계약을 바꾸지 않는 분기 — 의 시연 자리다(D-04 개정 · D-11). 관리자가 태그 스케일을 바꾸면 새 tag_id가 발급되고 이전 태그는 비활성화된다(전역 불변식 "불변 사실 기록").
- **마스터 변경은 네 저장소 층을 건드린다** — PostgreSQL 커밋 → Redis 캐시 삭제 → Pub/Sub 전파 → ClickHouse Dictionary 재적재(원본 data_flow.md §7.1). 관리자 한 번의 저장이 운영자 · 엔지니어가 읽는 태그명까지 바꾸는 경로이며, 확장된 무효화 체인의 정본은 [../06_pipeline/07_business_crud.md](../06_pipeline/07_business_crud.md)다.

| 원시 데이터 내보내기 | 화면 없음(API 전용) — 폐지 화면 ANL-TREND(D-14) | 직결 · 스트리밍 | ClickHouse | ① |

- **엔지니어는 해상도를 고르지 않는다.** 조회 범위에 따라 서버가 raw · 1m · 1h · 1d 중 하나를 고른다 — 원시 1년치 요청이 ClickHouse를 마비시키는 사고를 서버가 구조로 막기 위해서다. 원시가 꼭 필요하면 내보내기로 간다.
- 옛 알람 판정 이력 분석 · 규칙 조정 2행은 알람과 함께 D-16으로 지웠다.

### 실험 수행자

| 작업 | 도구 · 화면 | 요청 경로 | 닿는 저장소 | 학습 목표 |
|------|------|------|------|------|
| 저장소 수동 실습(PEL 관찰 등) | redis-cli · psql · clickhouse-client | 호스트 CLI → 127.0.0.1 저장소 포트 | 전부 | ②(at-least-once의 실체) |
| 스위치 조건 설정 · 재기동 | 환경변수 · Compose 재기동 · EXP-FLOW 각주 툴팁(주입 구현 확인) | 호스트 셸 | 해당 없음 | ① · ② |
| 데이터 주입 | 생성기 주입 모드 A · B(k6 · 부하 주입 표면은 D-16 삭제) | 호스트 셸(실행 인자 · 재기동) · EXP-FLOW 실행 패널 | Redis Stream · ClickHouse | ① · ② |
| 계측 관찰 | observability 프로파일 대시보드 · /metrics 직접 덤프 | 호스트 → api /metrics | 해당 없음 | ① · ② |
| 볼륨 초기화 · 덤프 | 볼륨 초기화 · migrate · seed · pg_dump(스냅샷 · 복원은 D-16 삭제) | 호스트 셸 | 볼륨 전체 | 전제(같은 시드 · 같은 구성) |
| 대조 쿼리 실행 | psql · clickhouse-client(옛 EXP-PERF 역전 구간 표시는 D-16 폐지) | 호스트 CLI · 직결 | PostgreSQL 비교 사본 · ClickHouse tag_raw | ① |
| 직접 비교(넣기 · 조회 대결 · 무결성) | EXP-LAB 패널 ▶ 3 | 브라우저 → BFF → api · no-store | Redis Stream → ClickHouse · PostgreSQL 비교 사본(TimescaleDB hypertable · SW-09 gated) · run_result | ①(PostgreSQL + TimescaleDB · 라이브 시연값) |
| 설비 가동 켜고 끄기 · 센서 데이터 지우기 | EXP-LAB · EXP-FLOW · HMI-PLANT 공용 컨트롤 | 브라우저 → BFF → api · no-store | Redis ctl:plant:power · 지우기는 세 저장소의 센서 데이터 | 전제(같은 빈 상태에서 다시 시작) |

- **실험 수행자의 화면 밖 작업이 화면 안 작업보다 많다.** 스위치는 환경변수 + DI 초기화 선택이라 화면에서 바꿀 수 없고(D-06), 실증 화면은 스위치를 각주 툴팁에 표시만 하고 실행 패널로 시연 실행만 시작 · 중단한다. 화면에 토글을 기대하면 설계를 버그로 오해한다.
- **정밀 측정 세션에서는 관측 대시보드를 끈다.** 관측 스택이 측정 대상과 같은 CPU를 쓰므로 그 동안의 수치는 상대 비교용이다([../10_observability/04_experiment_protocol.md](../10_observability/04_experiment_protocol.md)).

## 요청 경로 — BFF 경유와 직결

같은 웹 화면이라도 요청 성격에 따라 경로가 둘로 갈린다(원본 architecture.md §2 · 원본 data_flow.md §7.2). 경로 기준의 정본은 [../07_api/01_conventions.md](../07_api/01_conventions.md)다.

| 요청 유형 | 경로 | 주로 부르는 페르소나 | 이유 |
|------|------|------|------|
| 마스터 CRUD | BFF 경유 | 관리자 | 저빈도 · 요청 오리진이 하나로 모여 CORS가 단순해진다 · BFF가 무효화 체인의 마지막 단이다 |
| 라이브 실행 시작 · 중단 · 진행 | BFF 경유 · no-store | 실험 수행자 | 실행 상태는 api 메모리의 순간값이다 — 캐시하면 종결된 실행이 running으로 보여 시작 버튼이 잠긴다([../07_api/01_conventions.md](../07_api/01_conventions.md)) |
| 최신값 폴링 · 시계열 조회 | 브라우저 → api 직결 | 운영자(HMI 최근 10분) · 엔지니어 | 고빈도 요청에 중계 1홉을 더할 이유가 없다 |
| HMI 개요 | BFF 경유 · no-store(1초) | 운영자 · 시연 청중 | api 표면이 CORS 없는 BFF 경유 표면이다 — 고빈도 직결 원칙의 기록된 예외([../08_screen/11_hmi_screen.md](../08_screen/11_hmi_screen.md)) |
| 설비 가동 · 센서 데이터 현황 · 지우기 | BFF 경유 · no-store | 실험 수행자 · 시연 청중 | 실행 중 상태 · 순간값이라 사본을 두면 다른 화면에서 바꾼 값이 늦게 보인다 |
| 측정 기록 읽기 | 브라우저 → BFF(docs/measurements 읽기 전용) — api 표면 없음 | 시연 청중 | 기록은 커밋으로만 바뀐다 · ②③④가 진입 때 한 번 읽는다 |
| WebSocket 실시간 | 직결 | 운영자 | BFF가 중계할 필요가 없다. 출처는 핸드셰이크 Origin 검증이 가른다(옛 첫 메시지 인증은 D-16 삭제) |
| 저장소 직접 접속 | 호스트 CLI → 127.0.0.1 저장소 포트 | 실험 수행자 | 상태를 손으로 확인하는 것이 학습 수단이다 |
| 웹 → DB 직접 | **금지** | 없음 | 커넥션을 api 한 곳으로 일원화하고 입력 검증 · 파라미터 바인딩을 우회하는 경로를 만들지 않는다 |

- 검산: 요청 유형 = **9** · BFF 경유 5(마스터 CRUD · 라이브 실행 · HMI 개요 · 공용 컨트롤 · 측정 기록) + 직결 2 + 호스트 CLI 1 + 금지 1 · 옛 로그인 · 알람 묶음은 D-16 삭제

## 페르소나 × 분기 계층

어느 페르소나가 분기의 어느 계층을 보는지를 한 표로 둔다. 빈 칸 대신 닫힌 어휘(보지 않음)를 쓴다.

| 페르소나 | ① 원시값 | ③ 업무 CRUD | 대조군 |
|------|------|------|------|
| 현장 운영자 | Redis 사본(최신값 · 푸시) | 보지 않음 | 보지 않음 |
| 관리자 | 보지 않음 | 쓰기 주체 | 보지 않음 |
| 엔지니어 | ClickHouse 롤업 · 원시 | 보지 않음 | 보지 않음 |
| 실험 수행자 | 전 경로 계측 | 명령 경로 확인(수집 스트림 무관 · 멱등 · 응답 직후 재조회) | 쓰기 · 조회 주체 |
| 시연 청중 | ⑥ 흐름도 · ⑦ HMI로 본다 | ⑥ 흐름도 업무 길로 본다 | ⑤ 직접 비교 결과로 본다 |

- **두 갈래를 함께 다루는 페르소나는 실험 수행자뿐이다**(시연 청중은 화면으로 보기만 한다). 운영자 · 엔지니어는 ①만, 관리자는 ③만 본다 — 같은 Redis를 지나는 두 스트림의 대비(학습 목표 ②)가 현장 페르소나에게는 한쪽씩만 보인다는 사실이 실험 수행자를 따로 세운 두 번째 이유다. 옛 ②계층(알람 · 실적) 열은 D-16 폐지로 지웠다 · direct 대 stream 비교(EXP-46)는 측정 전에 D-16 폐지다.

## 권한 역할

**없다(D-16).** 로그인 · 권한 · 감사 기록이 사용자 결정(2026-10-11)으로 삭제돼 역할(옛 OPERATOR · ENGINEER · ADMIN) · 역할 × 기능 매트릭스 · 권한 캐시가 함께 사라졌다. 페르소나는 화면 · 요청 경로만 가르고, 표면 앞의 검사는 출처 방어(CORS · Host · Origin)뿐이다([../12_security/03_api_surface_defense.md](../12_security/03_api_surface_defense.md)). 옛 역할 확정 표(W2)와 권한 매트릭스 원문은 커밋 28c0cc9에 있다.

- **실험 수행자의 주 권한은 머신 접근이다.** 스위치 · 저장소 포트는 환경변수와 호스트 셸로 다루며, 이 경계를 지키는 것은 127.0.0.1 바인드와 .env 비커밋이다([../12_security/05_local_exposure.md](../12_security/05_local_exposure.md)).
- **D-16 뒤에는 앱 표면도 같은 경계 하나에 기댄다.** 같은 머신의 누구든 마스터 쓰기 · 실행 시작을 부를 수 있다 — 그 노출은 결함이 아니라 기록된 잔여다([../12_security/04_threat_model.md](../12_security/04_threat_model.md) §무인증 표면).

## 단계별 페르소나 가용성

옛 학습 순서는 인증을 S7에 두었고(원본 implementation_plan.md §5 S2 "인증 없음" · S7 인증), D-16이 그 S7 인증을 지웠다 — **어느 단계에서도 역할로 페르소나를 가르지 않는다.** 순서의 정본은 [05_priorities_roadmap.md](./05_priorities_roadmap.md)다.

| 단계 | 쓸 수 있는 페르소나 관점 |
|------|------|
| S0 · S1 | 실험 수행자(CLI · 생성기 단독 실행) |
| S2 | 실험 수행자 · 운영자 관점의 최소 대시보드 1페이지 |
| S3 · S4 | 상동 + 엔지니어 관점(해상도 자동 선택 · 캐시) · 관리자 관점의 마스터 CRUD |
| S5 · S6 | 상동 — 장애 실험의 관찰자 |
| S7 | **폐지(D-16)** — 옛 알람 콘솔 · 작업지시 · 로그인 단계의 대상이 모두 삭제됐다 |
| D-16 재구성 | 전 페르소나 — 시연 청중(7화면) · 운영자(HMI-PLANT) · 실험 수행자(EXP-LAB · EXP-FLOW) |

- **무인증은 순서의 결과에서 범위가 되었다.** 옛 S2~S6 무인증은 인증을 늦게 넣는 순서의 결과였고(D-07), D-16이 S7 인증을 지워 전 단계가 무인증이다 — 모든 표면은 127.0.0.1 바인드 안에 있다.
- 옛 인증 · 역할 구분 열과 "S7 전후 측정 조건이 다르다" 경고는 인증과 함께 지웠다 — 측정 조건이 인증으로 갈리지 않는다.
