이 문서는 **role_code 값과 역할 × 기능 대응의 정본**이다. 원본이 정한 것은 역할 기반 인가의 구조뿐이다 — role(role_code 유일) · user_role(사용자 ↔ 역할 다대다) 테이블(원본 architecture.md §6)과 엔드포인트별 Guard(원본 architecture.md §18). 역할의 값과 역할별 권한은 원본에 없어 W1이 이 문서로 넘겼다. 기능 ID와 기능명의 정본은 도메인 파일 11본이며, 이 문서는 행을 인용만 한다.

**매트릭스는 S7부터 적용된다.** 인증은 학습 순서상 S7에 오고(D-07) S2~S6의 모든 표면은 무인증이며 127.0.0.1 바인드 안에 있다. 인가를 붙이는 순간 인증 비용이 요청 경로에 더해지므로 S7 전후의 조회 수치는 다른 조건이다([01_auth.md](./01_auth.md)). 인가의 기전(Guard · 권한 캐시 · 코드)은 [01_auth.md](./01_auth.md) AUT-04 · 05가 갖는다.

## 역할 정의

**판정: 역할은 3종 — OPERATOR · ENGINEER · ADMIN이다.** 원본의 사용자 3종(원본 architecture.md §2 — 현장 운영자 · 관리자 · 엔지니어)을 그대로 역할로 올린다. 네 번째 페르소나인 실험 수행자는 역할이 아니다 — 주 권한이 앱 역할이 아니라 머신 접근이다([../01_overview/03_personas_roles.md](../01_overview/03_personas_roles.md)).

| role_code | 페르소나 | 쓰기 권한 | 쓰기 권한의 근거 |
|------|------|------|------|
| **OPERATOR** | 현장 운영자 | 알람 확인(ALM-08) | 확인 전이의 주체가 운영자다(원본 data_flow.md §8.1 "운영자 확인") |
| **ENGINEER** | 엔지니어 | 알람 규칙 변경(ALM-01 쓰기) | 임계값 튜닝 · 오탐 분석의 근거인 판정 전수(alarm_eval)를 보는 역할이 규칙을 바꾼다(원본 architecture.md §7.3) |
| **ADMIN** | 관리자 | 마스터(MST-01~06 쓰기) · 작업지시 · 실적(WRK-01~03 쓰기) | 업무 데이터 관리가 관리자의 목표다(원본 architecture.md §2) |

- 검산: role_code = OPERATOR · ENGINEER · ADMIN = **3**
- **역할은 누적되지 않는다.** 각 역할은 독립 권한 집합이고, 사용자는 user_role 다대다로 여러 역할을 가지며 권한은 **합집합**으로 판정한다. 로컬 학습자 한 명이 세 관점을 오가는 구성(D-02)에서는 학습자 계정 하나에 세 역할을 모두 부여한다(시드 — [../05_data_stores/09_migrations_seed.md](../05_data_stores/09_migrations_seed.md)).
- **역할이 하나도 없는 인증 사용자는 AUT-02 · 03만 쓸 수 있다.** 아래 "인증 사용자 전원"은 역할이 1개 이상인 사용자를 뜻한다.

| 버린 대안 | 실패 시나리오 |
|------|------|
| ① 4역할(실험 수행자 역할 신설) | 스위치 전환 · 부하 주입 게이트 · 저장소 포트는 전부 앱 인가 밖이라 이 역할이 여는 표면이 하나도 없다 — 권한 없는 역할이 role 테이블에 남아 "실험은 앱 권한으로 막는다"는 오해를 만든다 |
| ② 누적 계층(ADMIN ⊃ ENGINEER ⊃ OPERATOR) | 관리자가 판정 전수를 보지 않고 임계값을 바꿀 수 있게 되어 튜닝 루프가 근거 없이 끊기고, 확인 기록의 acked_by가 "현장에서 본 사람"이라는 뜻을 잃는다 |
| ③ 역할 없이 인증만 | role · user_role 구조와 역할 기반 Guard(원본 architecture.md §18)가 장식이 된다. 로컬이어도 인가를 생략할 이유가 되지 않는다(전역 불변식 "로컬 전용") |

## 판정 어휘와 원칙

셀은 아래 닫힌 어휘로만 채운다. 빈 칸은 두지 않는다.

| 어휘 | 뜻 | 거부될 때 |
|------|------|------|
| 허용 | 그 역할의 사용자가 부를 수 있다 | 해당 없음 |
| 거부 | 인증은 됐으나 역할이 표면 권한 밖이다 | auth.forbidden/403 |
| 공개 | 인증 없이 부른다(무인증 표면) | 해당 없음 |
| 게이트 | 환경변수가 켜져 있을 때만 존재하고, 켜지면 인증 사용자 전원이 부른다 | 꺼져 있으면 datagen.bulk_disabled/404 |
| 내부 | 외부 표면이 없어 인가 대상이 아니다(내부 모듈 · 내부 단계 · 실행 인자) | 해당 없음 |
| 횡단 | 다른 표면에 끼어드는 검사 기능 자체다 — 역할로 부르지 않는다 | 해당 없음 |

- 검산: 판정 어휘 = 허용 · 거부 · 공개 · 게이트 · 내부 · 횡단 = **6**
- **읽기는 인증 사용자 전원 허용이 원칙이다.** 예외 셋 — 감사 로그 조회(before · after 원문 · ADMIN) · 원시 내보내기와 판정 이력 분석(대량 스캔 · ENGINEER)이다. 대량 스캔 읽기를 가르는 축은 레이트 리밋을 엄격히 거는 축(원본 architecture.md §18)과 같다.
- **쓰기는 역할 하나가 주체다.** 같은 쓰기를 두 역할에 열지 않는다 — 쓰기 주체가 둘이면 감사 로그의 행위자로 변경의 책임 축을 읽을 수 없다.
- 무인증 요청(공개 밖) · 토큰 만료는 역할 판정 전에 auth.unauthenticated/401 · auth.token_expired/401로 끝난다([01_auth.md](./01_auth.md)).

- 기능 수(도메인 파일 기능 목록 표의 행): AUT 7 + MST 9 + COL 9 + SIM 5 + GEN 10 + ING 13 + TSQ 9 + RLT 9 + ALM 9 + WRK 5 + OBS 6 = **91**

- 내부 48 = MST 3(07 · 08 · 09) + COL 9 + SIM 5 + GEN 9(07 제외) + ING 13 + TSQ 3(03 · 04 · 05) + ALM 5(02~06) + WRK 1(04) = **48**
- 역할 판정 31 = AUT 2(02 · 03) + MST 6(01~06) + TSQ 6(01 · 02 · 06 · 07 · 08 · 09) + RLT 9 + ALM 4(01 · 07 · 08 · 09) + WRK 4(01 · 02 · 03 · 05) = **31**

## GEN · OBS 표면 인가

W1이 넘긴 세 표면의 판정이다. 표면 명세의 정본은 [../07_api/09_datagen.md](../07_api/09_datagen.md) · [../07_api/10_metrics.md](../07_api/10_metrics.md)(W5)다.

| 표면 | 판정 | 근거 | 버린 대안의 실패 | 잔여 |
|------|------|------|------|------|
| /api/v1/health | **공개** | Compose가 api의 healthcheck로 자격 증명 없이 부른다(원본 architecture.md §3). 인증을 걸면 api가 healthy가 되려면 로그인이 되어야 하고 로그인은 api가 떠야 되는 **순환**이 생긴다 | 인증 필수 — 기동 순서가 영영 끝나지 않거나 healthcheck가 자격 증명을 들고 있어야 한다 | 응답에 업무 데이터 · 비밀을 싣지 않는다 — 저장소별 상태 · 스위치 상태 · 측정 조건 3요소(커밋 해시 · 메모리 프로파일 · 용량 티어 — 비밀 아님)만 |
| /metrics | **공개** | Prometheus 스크레이프와 정밀 측정 세션의 직접 덤프가 액세스 토큰 수명(현행 15분)과 무관하게 돌아야 한다. 스위치 상태 레이블은 모든 측정 기록의 4요소다 | 액세스 토큰 인증 — 토큰이 만료될 때마다 **측정 공백**이 생기고 공백 구간의 수치가 기록에서 빠진다. 스크레이프 전용 정적 토큰 — .env 비밀이 하나 늘지만 막는 대상은 같은 머신의 프로세스뿐이다 | 같은 머신의 다른 프로세스가 스위치 상태 · 스트림 길이 · 느린 쿼리 Top-N을 읽을 수 있다. 쿼리 값은 파라미터 바인딩(원본 architecture.md §18)이라 텍스트에 드러나지 않는다 → [../12_security/04_threat_model.md](../12_security/04_threat_model.md) 등재 대상 |
| /api/v1/ingest/bulk | **게이트 + 인증 · 역할 무관** | 기본 비활성이고 환경변수로만 켠다(원본 architecture.md §11 · §18) — 켜는 권한은 머신 접근이다. 켠 뒤에는 인증을 요구한다 — 모드 C는 **인증 비용을 측정 대상에 포함**한다(원본 data_flow.md §11.1) | ADMIN 한정 — 부하 도구(k6 스크립트 · datagen 컨테이너 환경)가 관리자 자격을 들고 다니게 되어 관리자 토큰이 실험 산출물에 퍼진다. 무인증 — 모드 C가 재려는 인증 비용이 사라진다 | S5의 모드 C 측정에는 인증이 없다(S7 전) — 두 수치를 같은 조건으로 비교하지 않는다([05_datagen.md](./05_datagen.md)) |

- 검산: 판정한 표면 = health · metrics · ingest/bulk = **3**
- **"로컬이라 인가를 생략한다"가 아니다.** health · metrics를 공개로 둔 근거는 도달 가능성이 아니라 **호출 주체가 기계이고 응답에 업무 데이터가 없다**는 것이다. 응답에 업무 데이터가 실리는 순간 이 판정은 무효다.

## 실험 수행자와 실험 콘솔

실험 수행자는 역할이 아니다. 실험의 손잡이는 전부 앱 인가 밖에 있고, 그 경계를 지키는 것은 127.0.0.1 바인드와 .env 비커밋이다([../12_security/05_local_exposure.md](../12_security/05_local_exposure.md)).

| 실험 작업 | 수단 | 앱 인가 | 경계 |
|------|------|------|------|
| 스위치 전환 | 환경변수 + 재기동(D-06) | 해당 없음 — 화면 · API에 전환 경로가 없다 | 호스트 셸 |
| 부하 주입 표면 켜기 | 환경변수 + 재기동 | 해당 없음 | 호스트 셸 |
| 생성기 실행(모드 A · B · D · 대조군 백필) | 실행 인자 · APP_ROLE=datagen | 내부 | 호스트 셸 |
| 저장소 수동 실습 · 대조 쿼리 | psql · clickhouse-client · redis-cli | 해당 없음 — 앱을 거치지 않는다 | 127.0.0.1 저장소 포트 |
| 스냅샷 · 복원 | Taskfile | 해당 없음 | 호스트 셸 |
| 실험 콘솔 열람 | 웹 화면 | **인증 사용자 전원 허용** | 인증 |

- **판정: 실험 콘솔 화면은 인증 사용자 전원에게 열린 표시 전용 화면이다.** 콘솔은 스위치를 바꾸지 않고 상태 표시 · 실행 기록 · 비교만 하며(docs_plan 보정 #14), 데이터 원천(/api/v1/health · /metrics)이 이미 공개 표면이다. 특정 역할로 막으면 막는 대상이 공개 표면의 사본뿐이라 방어가 아니라 불편이 된다. 화면 명세의 정본은 [../08_screen/07_experiment_console.md](../08_screen/07_experiment_console.md)(W5)다.
