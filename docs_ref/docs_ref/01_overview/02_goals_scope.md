# 목표·범위

> **대상**: 전원 · 평가자
> **작성일**: 2026-08-03
> **개정일**: 2026-09-16 — **v1 범위 확장 4기능 채택**(D-23) — v1.1 이월에서 AUT-05 프로필 관리 · ATT-10 실시간 근태 현황 · DSH-06 리포트 내보내기를, 영구 제외에서 DSH-03 인건비 추이를 In 범위로 옮긴다. v1 94 → **98** · 이월 44 → **41** · 영구 제외 7 → **6** · 145 불변
> **개정일**: 2026-08-08 — 셋 이상 열거의 슬래시 구분자를 가운뎃점으로 정정(작성 규약 정합)
> **개정일**: 2026-08-03 — 두루누리 완화책에 확인 문안 병기(지원 요건·80%·36개월 — 확인 완료 2026-08-03)
> **원천**: docs_ref2/features_p0.md(선정 기준 · v1 필수 94 · 제외 44와 추가 트리거 · 제외가 만드는 위험) · docs_ref2/features.md(§9 v1 제외 7) · [../CLAUDE.md](../CLAUDE.md) 범위 규약 · [06_design_decisions.md](./06_design_decisions.md) D-07~D-10

insadesk v1이 무엇을 하고 무엇을 하지 않는지를 확정한다. 범위는 원천 문서가 선정한 **v1 필수 94기능**에 2026-09-16 채택한 **운영 요약·편의 4기능**(D-23)을 더한 **98기능**이며, 그 밖의 기능은 만들지 않는다.

본 문서의 **Out 범위 절은 v1 제외 항목의 유일한 등재처**다. 다른 문서는 제외 항목을 현행 기능처럼 서술하지 않고 부정형으로만 언급한다(예: "ADVISOR 역할은 v1에 두지 않는다"). 제외 항목이 데이터 모델에 남긴 확장 지점은 비고로만 표기하고 미사용 구조를 미리 만들지 않는다.

## 목표

| 축 | 목표 |
|----|------|
| 마감 완결 | 근태 → 급여 → 명세서 → 신고 자료가 한 주기 안에서 끊기지 않고 끝난다. 어느 한 단계도 사용자가 서비스 밖에서 메우지 않아도 된다 |
| 계산 정확 | 동일 입력이면 동일 결과가 나온다. 요율·세액표·한도는 귀속 기준일로 조회하고, 누락되면 임의 값으로 메우지 않고 차단한다 |
| 법정 준수 | 명세서 교부 · 서면 명시 · 휴게 · 금품청산 · 퇴직금 · 보존기간 같은 의무를 안내문이 아니라 흐름의 차단·경보로 내장한다 |
| 규모 분기 | 5인·10인 경계를 사업장의 고정 속성이 아니라 기준일의 함수로 계산하고, 적용 조항은 조문 단위 정책값으로 버전 관리한다 |
| 온보딩 | 이미 운영 중인 사업장이 옮겨올 수 있다. 직원·근로조건·연차 잔액 기초값을 일괄 적재하는 경로를 처음부터 둔다 |
| 재현성 | 확정 결과는 덮어쓰지 않는다. 기준값·스냅샷·정책 버전을 결과에 동결해 이듬해에도 같은 금액이 재출력된다 |
| 격리·보호 | 사업장 간 데이터는 서비스 검증과 행 단위 정책의 2단 방어로 격리하고, 민감정보는 암호화·마스킹·재인증·감사로 보호한다 |

## In 범위 (v1 98기능)

채택 기준은 네 가지이며 **하나라도 해당하면 필수**다 — 제품성립(없으면 마감 경로가 끊긴다) · 법정의무(없으면 사용자가 법을 위반한다) · 계산정확성(없으면 금액이 틀린다) · 플랫폼요건(없으면 서비스 운영 자체가 불가능하거나 위법이다). **D-23의 4기능은 이 넷이 아니라 사용 경험 축으로 채택했다** — 소상공인 사장이 혼자 한 달치를 마감할 때 매일 확인하고(오늘 출근 · 인건비), 세무사에게 넘기고(내보내기), 스스로 고치는(프로필) 일이 서비스 밖으로 새지 않게 하기 위해서다. 우선순위는 넷 다 P2이며 마감 경로를 막지 않는다.

## Out 범위

다음은 v1에서 만들지 않으며 현행 기능처럼 서술하지 않는다. 구분은 둘이다 — **영구 제외**(제품 방향상 두지 않기로 확정한 것)와 **v1.1 이월**(필요하지만 첫 마감 주기에는 없어도 되는 것). 이월 항목의 기능ID는 결번으로 남기며 **재사용하지 않는다**.

| SYS-09 공지 관리 | v1.1 이월 | 상동 |
| NTF-02 푸시 알림 | v1.1 이월 | 인앱 알림으로 시작하고 앱 사용률 확인 후 추가한다 |
| NTF-05 알림 삭제 | v1.1 이월 | 상동 |
| NTF-06 알림 설정 | v1.1 이월 | 상동 |
| WRK-10 양도(OWNER 이전) | v1.1 이월(부분) | **기능ID 카운트에 포함하지 않는다** — WRK-10의 폐쇄분은 v1 채택이다. 양도는 사업장을 넘길 실제 수요가 생길 때 |

검산: TAX 8 + PAY 5 + LEV 3 + HRM 4 + CMP 3 + ATT 3 + PRV 3 + WRK 3 + DSH 3 + SYS 3 + NTF 3 = **41**. AUT는 2026-09-16 AUT-05 채택으로 이월 항목이 없다.

- WRK-10은 **부분 이월**이라 위 41에서 세지 않는다 — 폐쇄만 v1이고 양도는 v1.1이다. 폐쇄를 v1에 넣은 이유는 그것이 없으면 OWNER가 영원히 탈퇴할 수 없어 개인정보 파기 요구권과 충돌하는 데드락이 생기기 때문이다.
- 전 기능 범위 검산: v1 **98** + v1.1 이월 **41** + 영구 제외 **6** = **145**(원천이 검토한 전체 집합). 원천 선정 당시는 94 + 44 + 7이었고 채택 목록 **138**(94 + 44)은 원천 값이라 그대로 둔다 — D-23이 이월 3과 영구 제외 1을 v1로 옮겼다.

### 제외가 만드는 위험

이월은 무해하지 않다. 아래 다섯 가지는 v1 운영 중 실제로 사용자에게 닿는 위험이므로 **인지한 상태로 출시**하고 완화책을 함께 운영한다.

| 위험 | 내용 | 완화 |
|------|------|------|
| **두루누리 미지원(TAX-10)** | 지원금은 사업주 부담분뿐 아니라 **근로자 부담분도 지원**한다. 타깃 1~30인의 대다수가 10인 미만이고 보수 기준이 최저임금 월 환산 부근이라 주 사용자 상당수가 대상이다. 미지원 시 해당 직원의 **공제액과 명세서 금액이 실제와 달라진다** | 대상일 수 있다는 안내를 띄우고 계산 결과에 그 사실을 표기한다 — 안내 문안의 근거는 확인 완료됐다(10인 미만 · 월평균 보수 270만원 미만 · 신규가입자(직전 1년 무이력) · 국민연금·고용보험 양측 부담분 각각 80% · 최대 36개월). v1.1 최우선으로 착수한다 |
| **원천세·지급명세서 미지원(TAX-04 · TAX-05)** | 급여는 마감되지만 신고는 사용자가 홈택스에서 직접 해야 한다 | TAX-11 신고 기한 캘린더가 무엇을 언제까지 내야 하는지 알린다 |
| **일용직 미지원(PAY-15)** | 일용직을 쓰는 사업장은 v1을 쓸 수 없다 | 온보딩에서 고용형태를 물어 대상 여부를 사전 안내한다 |
| **연차 사용촉진 미지원(LEV-07)** | 촉진 절차가 없으면 미사용 연차 보상 의무가 면제되지 않는다 — 제품이 사실상 연차수당 지급을 강제하는 셈이 된다 | 첫 연차 소멸 6개월 전까지 반드시 추가한다 |
| **정보주체 권리행사 미지원(PRV-03)** | 열람·정정·삭제 요구는 법정 의무이며 처리 기한이 있다 | 담당자 지정 + 수동 처리 절차를 운영 문서로 마련한다 |
