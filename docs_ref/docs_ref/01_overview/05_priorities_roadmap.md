v1 **98기능**의 우선순위 분포와 구현 순서, 그리고 v1.1 이월 항목의 착수 트리거를 담는다. 기능별 우선순위 값의 정본은 [../02_features](../02_features/README.md)의 각 도메인 파일이며, 본 문서는 그 값을 도메인별로 다시 센 결과다.

## 우선순위 정의

**P0 · P1 · P2는 98기능 안에서의 구현 순위이며, v1 채택 여부와는 다른 축이다.** P2라도 98에 들어 있으면 v1에 만들고, P0라도 98 밖이면 v1에 만들지 않는다 — 채택 여부의 정본은 [02_goals_scope.md](./02_goals_scope.md)다.

| 등급 | 정의 |
|------|------|
| **P0** | 기반·진입. 없으면 다른 기능이 착수조차 되지 않거나 서비스 운영 자체가 불가능하다 |
| **P1** | 마감 경로 본체. 근태 → 급여 → 명세서 → 신고의 실제 처리량을 만드는 기능이다 |
| **P2** | 보완·후속. 마감 경로에 붙는 주변 기능이거나 특정 규모·상황에서만 발동하거나, 마감을 막지 않는 운영 요약·편의 기능이다 |

> 위 표는 [../02_features](../02_features/README.md)의 기능ID별 우선순위 값을 도메인별로 다시 센 **파생 집계**다. 기능 채번이나 우선순위 값이 바뀌면 같은 변경 단위에서 이 표를 다시 세고 아래 서술의 기능ID도 함께 갱신한다.

- P0가 진입·테넌트 축(AUT · WRK · SUB · SYS · CMP · NTF · PRV)에만 몰리고 업무 도메인에는 하나도 없다. 우선순위가 **"먼저 만들어야 하는 것"의 순서**이지 중요도 순위가 아니기 때문이다 — 급여 13기능이 전부 P1인 것은 덜 중요해서가 아니라 앞 단계 없이 착수할 수 없어서다.
- P2 **15건**은 AUT-05 · WRK-10(폐쇄) · HRM-06 · HRM-07 · HRM-09 · ATT-09 · ATT-10 · LEV-01 · LEV-02 · LEV-03 · LEV-04 · LEV-06 · SLP-07 · DSH-03 · DSH-06이다. 검산: 1 + 1 + 3 + 2 + 5 + 1 + 2 = **15**.
- **P2인데 v1 필수인 항목의 채택 근거는 우선순위가 아니라 별도 축이다.** ATT-09 근무 스케줄은 지각·결근 판정의 기준이라 없으면 ATT-04가 성립하지 않고, LEV 5기능은 5인 이상 법정 의무이며, WRK-10 폐쇄는 OWNER 탈퇴의 선행조건이라 빠지면 데드락이고, HRM-07 전자서명은 근로계약서 **교부**까지가 의무여서 서버 보관만으로는 미이행이며, SLP-07 정정본은 잘못 발행한 명세서의 유일한 복구 경로다. **AUT-05 · ATT-10 · DSH-03 · DSH-06은 필수 판정 축이 아니라 운영 경험 축으로 채택했다**(D-23) — 마감을 막지 않으므로 P2다.

- 기능ID별 우선순위와 명세의 정본은 [../02_features](../02_features/README.md)다. 위 배치는 **구현 순서 축의 파생 집계**이며 채번이 바뀌면 같은 변경 단위에서 다시 센다.
- 도메인이 여러 단계로 쪼개지는 곳은 넷이다 — WRK(1·2·5·6단계) · HRM(2·5) · PAY·SLP·TAX·CMP(각 본체 단계와 5·6단계). 퇴사 경로와 연차·보존이 각 도메인에서 뒤로 밀린 결과이며, 도메인 문서 소유권과는 무관하다.

- **0단계의 기준값이 비어 있으면 뒤 전부가 허공이다.** v1은 기준값 누락 점검 정기작업(checkStatutoryRateCoverage)을 두지 않으므로 **수동 확인 절차로 대체**한다 — 요율이 비어 있으면 급여가 통째로 틀린다. 확인자 필드가 빈 기준값 행을 배포 전 점검 목록에 넣는다.
- **백엔드 스택 전환은 2026-09-06에 확정됐고(D-21 · ADR-25~29) 설계 문서 개정을 같은 날 완료했다.** NestJS · Node.js · Prisma 축이 **Java · Spring Boot · JPA + MyBatis**로 바뀌고 스키마 정본이 저장소 루트 db_migration/으로 옮겨 Flyway가 적용한다. 전환은 구현 수단의 결정이므로 위 단계 배치·기능 수·검산은 바뀌지 않는다. 남는 착수 단서는 둘이다 — ① **행 단위 보안 세션 변수를 주입하는 데이터소스 프록시가 두 데이터 접근 축 모두에 실제로 걸리는지**를 첫 통합 테스트에서 실측 확인한다(ADR-28). ② **스키마 적용 이력 테이블이 업무 스키마 밖에 놓였는지**를 첫 적용 직후 검수 수치로 확인한다(ADR-27 · 검수 기준 정본 [../05_database/10_migrations_seed.md](../05_database/10_migrations_seed.md)).
- **웹 프론트엔드 스택 전환은 2026-08-08에 확정됐고(D-20 · ADR-24) 설계 문서 개정을 같은 날 완료했다.** 전환은 표면 구현 수단의 결정이므로 위 단계 배치·기능 수·검산은 바뀌지 않는다. 남는 착수 단서는 하나다 — 프리렌더 정적 HTML과 단일 페이지 앱 딥링크 리라이트의 우선순위를 **첫 프리뷰 배포에서 실측 확인**한다. 배포 위상의 정본은 [../04_architecture/08_deployment_topology.md](../04_architecture/08_deployment_topology.md)다.

## 미확인 — 확인 전 시드 금지

**이 절이 기준값 확인 목록의 유일한 정본이다.** 다른 문서는 목록을 다시 세지 않고 여기를 링크하며, 각 도메인 문서의 확인 절은 그 도메인에 걸리는 항목의 **상세 서술**이다. 값·조회 키의 계약 정본은 [../03_requirements/01_global_rules.md](../03_requirements/01_global_rules.md) 기준값 카탈로그다.

**2026-08-03 확인 작업으로 목록 16건이 전건 확인 완료됐다 — 미확인 잔여는 0건이다.** 각 행의 확인 결과가 확인값과 법적 근거를 담고, 공식 출처 URL은 [../03_requirements/18_official_references.md](../03_requirements/18_official_references.md)에 등재한다. 시드는 기준값 행(REQ-SYS-12 — source_url · confirmed_at · confirmed_by)에 이 근거를 옮겨 적는 것으로 완성되며, **확인자 필드가 빈 행은 미확인으로 간주해 계산이 차단**된다(REQ-SYS-14). 이후 새로 생기는 미확인 항목에는 "확인 전 시드 금지" 원칙이 그대로 적용된다.

| 16 | 소액부징수의 일용근로소득 적용 여부 | **확인 — 적용된다.** 소득세법 §86(원천징수세액 1,000원 미만 부징수)이 일용근로소득에도 적용되며, 판단 단위는 **지급 건(여러 일당 합산 지급 시 합산 세액) · 사업장별**이다. v1.1 일용 산식의 하한 처리 계약이 확정됐다 | [02_goals_scope.md](./02_goals_scope.md) |

검산: 0단계 11 + 단계 선행 3 + v1.1 착수 전 2 = **16건 — 전건 확인 완료(2026-08-03) · 미확인 잔여 0건**.

합집합 유도 — 계산·스키마 축 목록(9행. 그중 간이세액표와 건강보험 상한이 한 행에 묶여 있어 항목으로는 10) + 기준값 운영 축 목록(8항목) − 중복 3항목(간이세액표 실데이터 · 건강보험 보수월액 상한 · 건강보험 보수 재포함 범위) = **15항목**. 그중 1건이 아래대로 해소되어 14건이 남고, 도메인 문서가 보유한 2건(최저임금 산입범위 · 판결 사건번호)을 더해 **16건**이다.

**앞서 해소된 항목 1건** — 관공서 공휴일 유급 처리의 담당 기능ID 부재는 미확인이 아니다. [../02_features/06_payroll.md](../02_features/06_payroll.md) PAY-03이 "관공서 공휴일 유급(5인 이상)도 여기서 처리한다"고 확정했고, 휴일 판정은 REQ-ATT-12 · 유급 처리는 REQ-LEV-13이 계약한다. 이 항목을 미확인 목록에 다시 올리지 않는다.

- **1~11의 확인 완료로 0단계 진입 요건이 채워졌다** — 확인값을 기준값 행으로 시드하면 급여 계산(PAY-01 · PAY-04 · PAY-05 · PAY-06 · PAY-13 · CMP-01)이 차단 없이 동작한다.
- 12~14는 해당 단계의 선행 조건이었고 전건 확인됐다 — 판정·차단이 확정값으로 동작한다.
- 15~16은 v1.1 이월 기능에만 걸린다. 15는 확인된 문안으로 [02_goals_scope.md](./02_goals_scope.md) "제외가 만드는 위험" 표의 완화책(안내 표기)을 운영한다.
