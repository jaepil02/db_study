insadesk를 13개 문서 도메인으로 나누고 각 도메인의 접두사·기능 수·명세 파일과 도메인 간 의존 관계를 고정한다. **도메인 경계가 곧 문서 소유권 경계**이며, 기능ID 채번은 각 도메인 파일에서만 수행한다.

## 도메인 간 의존 관계

마감 경로는 단선이다. 앞 도메인의 확정 없이는 뒤 도메인이 계산을 시작할 수 없고, 그 위를 세 개의 횡단 도메인이 가로지른다.

```
[기반 — 계산의 전제]
  SYS 기준값(요율·세액표·최저임금·비과세 한도·단수 규칙·공휴일)
  CMP-02 규모별 적용 정책(조문 단위 · effective date)
        │  이 둘이 비어 있으면 아래 전부가 허공이다
        ▼
[테넌트 — 누가·어디서]
  AUT 인증·계정 ──▶ WRK 사업장·멤버 ──▶ HRM 인사·근로조건
        │                  │  국세청 검증 · 초대 · 임포트
        │                  └──▶ CMP-08 사업 단위 판정 ──▶ CMP-01 상시근로자 산정
        │                                                        │ 5인·10인 경계의 유일한 근거
        ▼                                                        ▼
[원장 — 무엇을 얼마나]
  ATT 근태(스케줄 → 체크인 → 판정·집계 → 승인 → 마감)
        │  마감 차단 조건: 미퇴근 · 미승인 요청 · 누락 스케줄 · 상시근로자 미산정 · 휴게 미달 · 휴게가 재실보다 긴 데이터 모순
        ├──◀ LEV 휴가·연차(승인 휴가일은 결근 미판정 · 연차수당·결근 공제)
        ▼
[계산 — 얼마를]
  PAY 급여(기준 → 근태 연동 → 법정수당 → 4대보험 → 소득세 → 최저임금 검증 → 확정)
        │  확정 시 기준값 행·상시근로자 스냅샷·정책 버전을 결과에 동결
        ▼
[교부 — 어떻게 전달하고]
  SLP 명세서(자동 생성 → 일괄 발행 → 교부 알림 → 본인 열람 → 정정본)
        ▼
[신고 — 무엇을 언제까지]
  TAX 신고 자료(4대보험 취득·상실 · 이직확인서 · 기한 캘린더)
  CMP-04 법정 서류 보존 · CMP-07 퇴사자 본인 열람

[횡단 — 전 경로를 가로지른다]
  NTF 알림   ◀── 승인 요청 · 급여 확정 · 명세서 발행 · 기한 임박 (발화만 받는 종단)
  SUB 구독   ──▶ 사업장 등록 수 · 사업장당 인원 한도 (WRK·AUT의 게이트)
  PRV 개인정보·위치정보 ──▶ 동의 이력(가입·위치) · 위치 이용 사실 확인자료(ATT 체크인마다)
```

핵심 의존 흐름:

- **SYS·CMP-02 → 전 계산**: 요율·세액표·최저임금·단수 규칙은 코드가 아니라 기준값 테이블에서 귀속 기준일로 조회한다. 규모별 적용 조항도 하드코딩하지 않고 조문 단위 정책값으로 버전 관리한다 — 하드코딩하면 법 개정마다 재배포해야 하고 과거 급여의 재현성이 깨진다.
- **CMP-08 → CMP-01 → ATT·LEV·PAY**: 상시근로자 산정은 5인·10인 분기의 **유일한 근거**다. 산정 범위는 사업 단위 판정을 따르므로 통합 운영으로 선언된 복수 사업장은 합산한다. 산정 결과가 없으면 근태 마감이 차단되고, 마감이 없으면 급여 계산이 차단된다 — 이 사슬이 끊기면 마감 경로 전체가 데드락에 빠진다.
- **ATT ↔ LEV**: 승인된 휴가일과 주휴일·관공서 공휴일(5인 이상)은 결근으로 판정하지 않는다. 공휴일을 결근 처리하면 급여가 잘못 깎인다. 반대로 연차수당·결근 공제는 급여에 반영되어야 금액이 맞는다.
- **ATT → PAY**: 급여 계산의 입력은 마감된 근태뿐이다. 미마감 기간의 계산은 차단하며, 급여 확정이 진행 중인 동안에는 해당 기간의 근태·인사 수정을 잠근다.
- **PAY → SLP**: 급여 확정이 명세서 생성의 유일한 트리거다. 확정 결과는 덮어쓰지 않으므로 명세서 정정도 원본 보존 + 정정본 신규 발행 체인으로만 한다.
- **HRM → PAY·TAX**: 부양가족 수와 8~20세 자녀 수는 간이세액표 조회 키라 없으면 소득세 계산이 시작조차 되지 않는다. 퇴사 처리는 금품청산·퇴직금·이직확인서·4대보험 상실 신고자료를 한 번에 연쇄시키는 트리거다.
- **PRV → ATT·AUT**: 개인위치정보는 별도 동의가 선행하며 체크인마다 이용·제공 사실 확인자료를 자동 기록한다. 동의는 받았다는 사실이 아니라 **어느 버전에 언제 동의했는지**가 증거라 버전별로 보관한다.
- **SUB → WRK·AUT**: 요금제가 사업장 등록 수와 사업장당 인원 한도를 정한다. 한도는 초대 발송 시점과 **수락 시점에 재검증**한다. 구독이 만료되어도 법정 보존 데이터의 조회는 막지 않는다.
- **NTF는 종단이다** — 다른 도메인의 이벤트를 받아 알림 행을 만들 뿐 되돌려 쓰지 않는다.

## 마감 경로 — 구현 순서

마감 경로를 따라 아래에서 위로 쌓는 것이 가장 빠르다. **각 단계는 앞 단계 없이 검증할 수 없다.**

| 단계 | 범위 | 완료 판정 |
|:----:|------|----------|
| 0 | 기준값(SYS-08) · 규모별 적용 정책(CMP-02) · 상시근로자 산정(CMP-01) | 요율·최저임금이 실측값으로 들어가고 5인 판정이 나온다. **이게 없으면 뒤 전부가 허공이다** |
| 1 | 인증 · 사업장 등록·검증 · 초대 · 멤버십 · 구독 게이팅(AUT · WRK · SUB) | 사장이 가입해 사업장을 만들고 직원을 초대한다 |
| 2 | 인사 등록 · 근로조건 · 근로계약(HRM) · 데이터 임포트(WRK-16) | 직원 정보와 근로조건이 들어간다. 기존 사업장이 옮겨올 수 있다 |
| 3 | 근무 스케줄 · 체크인 · 판정·집계 · 승인 · 마감(ATT) | 한 달치 근태가 마감된다 |
| 4 | 급여 계산·확정(PAY) · 명세서 생성·발행(SLP) | **한 달치 급여가 확정되고 명세서가 교부된다 — 여기가 MVP 증명점** |
| 5 | 퇴사 경로(HRM-04 · PAY-11 · PAY-19 · TAX-01 · TAX-02) | 퇴사자 1명을 끝까지 처리한다 |
| 6 | 연차(LEV) · 법정 서류 보존(CMP-04) · 신고 기한 캘린더(TAX-11) | 5인 이상 사업장을 받을 수 있다 |

- **4단계까지가 검증 MVP의 최소 경로**다. 근태 → 급여 → 명세서가 한 번 끝까지 돌아야 제품이 성립한다.
- **5단계를 빼면 퇴사자가 한 명만 생겨도 제품이 막힌다.** 금품청산 14일·이직확인서 10일·상실신고 기한(적용 보험 중 가장 이른 값 — 건강보험 14일 · 그 밖 다음달 15일)이 동시에 걸리므로 선택 사항이 아니다.
- 알림(NTF) · 개인정보·위치정보(PRV) · 시스템 관리(SYS)의 나머지는 횡단이라 각 단계에 붙여 함께 만든다 — 0단계에 기준값 관리와 감사 로그, 1단계에 동의 이력, 3단계에 위치 이용 사실 확인자료가 함께 들어간다.
- 단계별 기능ID 배치와 완료 판정의 확장은 [05_priorities_roadmap.md](./05_priorities_roadmap.md) 구현 로드맵 절이 이어받는다.
