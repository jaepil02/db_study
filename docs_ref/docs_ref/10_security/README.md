본 폴더는 insadesk의 보안 정본이다. **사업장 테넌트 격리 + 본인 소유권 인가 + 2단 방어** 접근 모델 위에서 인증·인가, RLS 격리와 봉인, 시크릿·키 관리, 개인정보와 위치정보 보호, 플랫폼 RBAC, 위협모델(보호 자산 · 위협과 통제 · 잔여 위험 · 검증 게이트)을 한곳에 모은다.

모든 통제는 **데이터베이스 계층 격리**(**61테이블** RLS 활성 + 강제 · 정책 **173개** · 헬퍼 **43종** · 제약과 트리거 가드)를 최종 방어로 전제한다. 예외는 시스템 컨텍스트를 켜는 서버 전용 경로와 정기작업이며, 그곳에서는 **진입 시점의 서비스 가드가 마지막 계층**이다.

**본 폴더는 리뷰·관점 문서다.** 정책 표현식·세션 구조·컬럼 정의를 여기서 다시 정의하지 않는다 — 각 사실의 정본을 지목하고 **어긋나면 정본이 우선한다**고 선언한 뒤 보안 함의만 서술한다. 스키마 정의는 [../05_database/README.md](../05_database/README.md), 구조 계약은 [../04_architecture/README.md](../04_architecture/README.md)에 있고 본 폴더는 그 자산을 보안 관점의 강제 규약으로 묶는다.

**이 문서군은 구현 착수 전 to-be 설계 정본이다.** 통제는 구현이 따라야 할 계약이고 검증 게이트는 구현 후 실측할 절차이며, **미실측 상태를 검증 통과로 간주하지 않는다.**

## 보안 핵심 원칙

**1. 최종 방어는 데이터베이스다.** 서비스 레이어가 통과시킨 요청도 RLS를 통과해야 한다. 애플리케이션 검증을 유일한 통제로 삼지 않으며, 새 엔드포인트 하나의 스코프 누락이 곧 테넌트 경계 붕괴가 되지 않게 한다.

**2. 정책이 없는 것이 통제다.** RLS는 정책 없는 명령을 기본 거부하므로 만들지 않은 정책은 누락이 아니라 방어의 형태다. 유출은 좁히는 것이 아니라 **표현할 수 없게** 만든다 — 정책 부재 · 함수 반환 타입 · grant 부재 · 세션 변수 축 제한이 강제 지점이다.

**3. 판정 실패는 통과가 아니라 거부다.** 세션 컨텍스트 미주입 · 시크릿 미설정 · 역할 조회 실패는 전부 불통과다. 미주입이 **데이터 유출이 아니라 조회 실패로** 나타나는 것이 이 설계의 안전 실패 방식이다.

**4. 클라이언트 판정을 신뢰하지 않는다.** 지오펜스 판정 · 출퇴근 시각 · 활성 사업장 · 화면 노출 제어는 전부 서버가 다시 판정한다. **클라이언트 라우터 가드와 화면 가드는 사용성 장치이며 신뢰 경계가 아니다** — 웹은 정적 산출물이라 요청을 가로채는 서버 계층 자체가 없고, 최종 강제는 서버 검증과 RLS다(D-20).

**5. 노출 여부는 이름이 선언한다.** 접두 규약이 붙은 변수만 클라이언트 번들에 들어가고, 앱 번들에는 어떤 시크릿도 넣지 않는다. 모바일 번들은 리버스 엔지니어링이 가능하다는 전제로 설계한다.

**6. 조용히 틀린 값이 오류보다 나쁘다.** 기준값이 없으면 임의 기본값으로 계산하지 않고 차단한다. 차단은 사용자가 인지하고 조치할 수 있는 상태이고, 잘못된 금액은 명세서 교부 뒤에 드러난다.

**7. 원장은 세션이 쓰지 못하고 아무도 고치지 못한다.** 감사·보안 이벤트·확인자료·연차 원장은 삽입 전용이며 수정·삭제 정책이 없다. 정정은 새 기록 추가이고, 고칠 수 있는 이력은 이력이 아니다.

**8. 사전 통제가 약한 곳은 사후 통제를 명시한다.** 관리자의 소속 직원 개인정보 열람과 플랫폼 관리자의 지원 접근은 업무상 필요해 사전에 좁힐 수 없다. 그 자리는 **사유 필수 감사**가 맡고, 데이터베이스 트리거가 사유 없는 기록을 거부한다.

**9. 인가 축은 멤버십 하나가 아니다.** 명세서·급여이력·근로계약은 본인 소유권으로 인가한다. 퇴사·사업장 폐쇄·구독 만료 뒤에도 보존기간 내 본인 열람이 끊기지 않아야 하며, 그 단절 자체가 법정 교부 의무 위반 소지다.

**10. 잔여 위험을 숨기지 않는다.** 통제로 제거되지 않은 것과 의식적으로 선택하지 않은 것을 판단 근거와 함께 등재한다. 등재되지 않은 위험은 관리되지 않는 위험이다.

| 금지 | 대응 |
|------|------|
| **평문 주민번호·계좌 저장** | 평문 컬럼 자체를 두지 않는다 — 암호문 + blind index + 마스킹 3축 분리 저장. 서비스는 마스킹 컬럼만 투영한다 |
| 사유·감사 없는 개인정보 복호화 | **4요건**(재인증 · 사유 · 감사 · 1회성 응답) 전부 충족. 사유 없는 감사 행을 트리거가 거부해 **기록 없는 복호화가 성립하지 않는다** |
| 클라이언트·앱 번들의 시크릿 노출 | 접두 규약 + 정적 분석 규칙 + 배포 전 산출물 검색. 앱에는 노출돼도 무해한 값만 둔다 |
| **RLS 우회 롤 사용** | 앱 롤이 테이블 소유자가 아니고 NOSUPERUSER · NOBYPASSRLS이며 전 테이블에 강제 옵션까지 건다. DELETE·DDL grant 자체가 없다 |
| RLS 비활성 상태 개발 | 개발 착수 시점부터 활성 + 강제 상태로 진행한다. **새 테이블은 정책보다 활성이 먼저**이며 정책 없이 배포하지 않는다 |
| **감사 로그 수정·삭제** | 수정·삭제 정책이 없고 트리거가 다시 막는다. 정정은 새 정정 로그 추가다 |
| **미확인 기준값 시드** | 확인자가 비어 있는 행을 미확인으로 간주해 계산을 차단한다. 임의 기본값·직전 연도 값 대체를 금지한다 |
| 확정 결과 덮어쓰기 | 확정 결과에 사용자 갱신 정책이 없다. 정정은 원본 무효화 → 정정본 신규 생성 체인으로만 한다 |
| 클라이언트에 저장소 서명 URL 전달 | 비공개 버킷 + **1회용 다운로드 토큰 + 서버 스트리밍**. 서버의 저장소 접근 서명은 서버 안에 머문다 |
| **위치정보 별도 동의 없는 GPS 수집** | 동의가 없으면 측위 자체를 시작하지 않고 요청은 차단한다. 확인자료 기록이 좌표 기록보다 **선행**하며 기록 실패 시 처리를 중단한다 |
| 확인자료의 관리자 조회 | 정보주체 본인 전용이며 사업장 관리자에게도 플랫폼 관리자에게도 정책을 두지 않는다 |
| **개인정보·금액의 로그·알림·외부 전송 유출** | 로그·에러 추적에 원문·금액·자격 증명·토큰을 남기지 않는다. 알림 타입에 민감정보 포함 금지 플래그를 두고 본문은 사건과 링크만 담는다 |
| 개인정보의 국외 이전 | 파일·백업을 서울 리전에 두고 국외 복제를 켜지 않는다. PDF 변환에 외부 서비스를 쓰지 않는다 |
| 플랫폼 권한의 와일드카드 부여 | 역할별 권한 집합을 정적 상수로 열거하고 **미정의 키는 기본 거부**한다. 사업장 업무 대행 키를 만들지 않는다 |
| 보존기간 내 파기 · 기산일 없는 파기 | 유형별 기산일로 만료를 판정하고 일괄 연 단위 파기를 돌리지 않는다. 두 의무가 충돌하면 **보존이 우선**한다 |

여기에 이 제품 고유의 금지가 하나 더 있다 — **급여 계산과 법정 판정에 AI·LLM 추론을 쓰지 않는다.** 계산은 서버 전용 룰 기반이며 동일 입력에 동일 결과를 낸다. 재현되지 않는 계산은 분쟁 시 근거가 될 수 없다.
