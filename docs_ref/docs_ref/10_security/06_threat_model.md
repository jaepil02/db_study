insadesk의 고위험 자산은 **사업장 간 데이터 격리 · 주민번호와 계좌 원문 · 급여 계산의 정확성과 재현성 · 임금명세서의 진정성 · 근태 기록의 무결성 · 감사 원장의 불변성 · 서버 전용 키**다. 위협모델은 이 자산이 노출·오용·변조되는 경로를 정의하고 검증 게이트로 고정한다.

**최종 방어는 언제나 데이터베이스다.** 예외는 시스템 컨텍스트를 켜는 서버 전용 경로와 정기작업이며, 그곳에서는 **진입 시점의 서비스 가드가 마지막 계층**이다.

이 제품의 최악 시나리오는 데이터 유출만이 아니다 — **조용히 틀린 급여가 확정되고 명세서로 교부되는 것**이 그에 못지않다. 유출은 사고로 인지되지만 틀린 계산은 이듬해 재출력 시점에야 드러나며, 그때는 이미 교부와 신고가 끝나 있다.

**본 문서군은 구현 착수 전 to-be 설계 정본이다.** 아래 통제는 구현이 따라야 할 계약이고 검증 게이트는 구현 후 실측할 절차다 — **미실측 상태를 검증 통과로 간주하지 않는다.**

## 핵심 원칙

**1. 통제는 규약이 아니라 구조여야 한다.** "그렇게 하지 않는다"는 통제가 아니다. 통제는 "그렇게 할 수 없다"여야 하며, 각 위협의 통제 칸에는 그 불가능을 만드는 **구조 지점**을 적는다.

**2. 조용히 틀린 값이 오류보다 나쁘다.** 기준값이 없을 때 임의 기본값으로 계산하는 것보다 계산이 차단되는 편이 낫다. 차단은 사용자가 인지하고 조치할 수 있는 상태이고, 잘못된 값은 교부 뒤에 드러난다.

**3. 사전 통제가 약한 곳은 사후 통제를 명시한다.** 관리자의 소속 직원 PII 열람과 플랫폼 관리자의 지원 접근은 업무상 필요해 사전에 좁힐 수 없다. 그 자리는 **사유 필수 감사**가 맡는다.

**4. 계산의 재현성은 보안 속성이다.** 급여는 분쟁 시 근거로 제출되는 값이다. 재현되지 않는 계산은 근거가 될 수 없으므로 **결과 값 동결과 확정 불변**을 무결성 통제로 다룬다.

**5. 잔여 위험은 숨기지 않고 등재한다.** 통제로 제거되지 않은 것과 의식적으로 선택하지 않은 것을 그대로 적고 판단 근거를 남긴다. 등재되지 않은 위험은 관리되지 않는 위험이다.

## 보호 자산

| 자산 | 위치 | 노출 시 영향 |
|------|------|-------------|
| 사업장 간 격리 | 테넌트 스코프 44테이블(NOT NULL 39 · 선택 5) | 타사 인건비·직원 명부·급여가 노출된다. 소상공인 대상 서비스에서 신뢰가 즉시 소멸한다 |
| 주민등록번호·급여계좌 | employee_personal_infos | 고유식별정보 유출이다. 통지·신고 의무가 발생하고 2차 피해가 금전으로 이어진다 |
| 급여액·공제 내역 | payroll_employee_results · payroll_employee_result_items | 개인의 임금이 동료·외부에 드러난다. 사업장 내 인간관계와 노무 분쟁으로 직결된다 |
| 임금명세서 | payslips · S3 비공개 버킷 | 법정 교부 문서이며 개인 임금·인적사항이 담긴다. 위조는 분쟁 시 증거 조작이다 |
| 근로계약서·전자서명 | contracts · contract_signatures · S3 | 서명 증적이 조작되면 계약 성립 자체가 다투어진다 |
| 근태 기록의 무결성 | attendance_records · attendance_daily_summaries · attendance_period_closings | 근태가 급여의 입력이다. 조작은 곧 임금 조작이며 연장·야간 가산에서 증폭된다 |
| 급여 계산의 재현성 | 동결된 기준값 참조와 값 · 상시근로자 스냅샷 · 정책 버전 | 재현되지 않으면 과거 명세서 재출력이 원본과 달라지고 그 불일치가 분쟁이 된다 |
| 기준값 원장 | statutory_rates · income_tax_table_entries | 요율·세액표가 틀리면 **전 사업장의 급여가 동시에 틀린다** |
| 감사 원장 | audit_logs | 고위험 조치의 근거가 사라진다. 위조 가능하면 사후 통제가 통째로 무의미해진다 |
| 보안·계정 이벤트 | security_events · account_status_events | 침해 흔적과 제재 이력이 사라진다 |
| 위치정보 확인자료 | location_usage_records | 법정 기록이며 정보주체의 확인 수단이다. 사업주가 조회하면 그 자체가 감시 수단이 된다 |
| 서버 전용 키 | 세션·JWT 서명 키 · PII 암호화 키 · blind index 키 · 외부 연동 자격 | 세션 위조 · PII 원문 복원 · 외부 서비스 오남용 |
| 논리 백업 | S3 서울 리전 | **마스킹되지 않은 원본**이 통째로 담긴다 |
| 플랫폼 관리 권한 | system_admins | 전 사업장에 대한 지원·제재 권한을 얻는다 |

검산: 격리 1 + 개인정보 2 + 문서 2 + 계산 3 + 원장 3 + 키·백업 2 + 권한 1 = **14자산**.

## 주요 위협과 통제

| # | 위협 | 통제(구조 지점) |
|:-:|------|-----------------|
| 1 | 타 사업장 데이터 조회·변경 | 서비스 1차 검증 + **RLS 2차 심층방어**. 전 **61테이블** ENABLE + FORCE · 기본 거부 · 앱 롤 NOSUPERUSER · NOBYPASSRLS · 비소유자. 비멤버에게는 행 존재조차 노출되지 않는다 |
| 2 | 요청 파라미터로 사업장을 바꿔 스코프 탈취 | **활성 사업장을 세션 변수로 두지 않는다.** 정책은 행의 사업장 열과 멤버십 헬퍼로 평가하고 서버가 매 요청 멤버십·역할을 재검증한다 |
| 3 | 사업장 내 권한 상승(STAFF → MANAGER) | 역할 변경은 **OWNER 전용**이다. 멤버십 UPDATE 정책이 관리자 축을 요구하고, 그 위에서 **guard_role_change() 트리거가 역할 컬럼 변경을 소유자 축으로 좁혀** MANAGER의 승격·강등 시도를 거부한다(workplace.role_change_forbidden/403). 같은 트리거가 OWNER를 역할 직접 변경으로 만드는 경로도 막는다. 역할 이벤트는 append-only로 남는다 |
| 4 | OWNER 단일성 무력화(마지막 OWNER 강등·자기 제거) | 서비스 레이어 + DB 제약 **양쪽**에서 차단한다. 한쪽만 두면 다른 경로로 같은 결과가 만들어진다(D-13) |
| 5 | 지오펜스를 우회한 원격 출퇴근 | **서버가 판정한다.** 앱은 좌표와 정확도를 보낼 뿐이고 반경 내외 판정·허용·차단은 서버가 내린다. 클라이언트 판정은 우회 가능하다 |
| 6 | 단말 시각 조작으로 출퇴근 시각 위조 | **체크인 시각은 서버가 기록한다.** 클라이언트가 보낸 시각을 신뢰하지 않으며 저장은 UTC · 일 경계 판정은 KST 고정이다(ADR-17) |
| 7 | 마감·확정 후 소급 변조 | 근태 마감은 기간 잠금이고 **재오픈은 OWNER 전용 + 급여 미확정 조건 + 사유 + 감사**다. 전이 조건은 정책이 아니라 트리거가 강제한다 |
| 8 | 확정된 급여 결과 덮어쓰기 | **확정 결과에 사용자 UPDATE 정책이 없다.** 확정 불변을 규칙이 아니라 표현 불가능성으로 강제하고, 트리거가 서버 경로의 확정 후 변경까지 막는다. 정정은 원본 무효화 → 정정본 신규 생성 체인이다 |
| 9 | 본인이 대상자로 포함된 급여의 단독 확정(자기거래) | **자기포함 런의 확정은 OWNER 전용** — MANAGER 시도는 auth.workplace_forbidden/403으로 차단하고 자기포함 플래그·감사 기록을 함께 남긴다. 본인 요청 본인 승인은 근태·휴가에서 원천 차단한다(REQ-GLB-16) |
| 10 | 기준값 조작·누락으로 계산 결과 왜곡 | 변경은 settings:update 권한 + **사유 필수 감사**이며 전후값과 발효일을 남긴다. 누락 시 **임의 기본값·직전 연도 값 대체 없이 계산을 차단**하고, 확정 결과에 기준값 행 식별자와 실제 값을 동결한다(REQ-GLB-09 · REQ-GLB-10) |

| 12 | 명세서 정정 체인 파괴(원본 삭제·이력 세탁) | 정정본 발행은 **OWNER 전용**이고 원본을 보존한 채 연결한다. 명세서·교부 이력에 사용자 UPDATE·DELETE 경로가 없다 |
| 13 | 세션 탈취(스크립트 접근·중간자) | **HttpOnly · Secure · SameSite=Lax** 쿠키 + 전 구간 TLS + 전송 보안 헤더. access token을 JavaScript에 노출하지 않는다 |
| 14 | 교차 사이트 요청 위조 | 웹 상태 변경 요청에 **CSRF 토큰 필수**이며 부재·불일치는 차단한다. 교차 출처 허용을 웹 오리진 하나로 좁히고 와일드카드를 쓰지 않는다 |
| 15 | 폐기된 앱 토큰 재사용 | refresh 회전 재발급 + **access 블랙리스트**(TTL = 토큰 잔여 수명). 정지·탈퇴 시 전 토큰을 폐기하고 RLS 헬퍼가 프로필 상태를 다시 본다 |
| 16 | 계정·사업장 열거 | 로그인 실패 **단일 응답** · 재설정 요청 **동일 응답** · 아이디 중복 확인은 불리언만 · 비멤버에게 사업장 행 미노출 · 타인 초대 행 미노출 |
| 17 | PII 복호화 남용 | **4요건 전부 충족**(재인증 5분 작업 단위 · 사유 · 감사 · 1회성 응답). 사유 없는 감사 행을 트리거가 거부하므로 기록 없는 복호화가 성립하지 않는다 |
| 18 | PII·금액이 로그·알림·외부 전송으로 새어 나감 | 로그·에러 추적에 개인정보 원문·금액·자격 증명·토큰을 남기지 않는다. **알림 타입에 민감정보 포함 금지 플래그**를 두고 본문은 사건과 링크만 담는다. PDF는 외부 변환 서비스를 쓰지 않는다 |
| 19 | 내부자(플랫폼 관리자) 남용 | 권한은 **명시 화이트리스트 · 미정의 키 기본 거부**이며 사업장 RBAC와 완전 분리다. 제재·강제 폐쇄·기준값 변경·감사 내보내기는 **사유 필수 감사**이고 마지막 SUPER_ADMIN은 보호된다. **PII 원문·민감 문서·명세서 PDF는 플랫폼 축 권한 키도 정책도 없어 v1에서는 접근 자체가 표현되지 않는다**([07_platform_rbac.md](./07_platform_rbac.md)) |
| 20 | 국세청 API 키 유출·오남용 | **서버 전용 호출**이며 클라이언트·앱 번들에 들어가지 않는다. 호출에는 사업자등록번호만 실리고 개인정보를 싣지 않는다. 검증 시도는 이력 테이블에 남는다 |
| 21 | 백업 유출 | 서울 리전 · 서버 측 암호화 · **백업 전용 자격 분리**. PII 암호화 키가 백업에 담기지 않으므로 백업 단독으로는 주민번호·계좌 원문이 복원되지 않는다 |
| 22 | 공급망 침해(의존성) | 락 파일 커밋 + CI가 **락 파일 그대로 재현 설치**. 품질 게이트를 통과하지 못한 커밋은 이미지를 만들지 않는다. 헤드리스 브라우저와 한글 폰트를 이미지에 포함해 **렌더 시점 외부 다운로드를 없앤다** |
| 23 | rate limit 우회 | 로그인은 (IP, username) 조합 키라 한쪽만 바꿔서는 창을 벗어나지 못한다. 인증 후 API는 사용자 단위다. **잠금 중에는 올바른 자격 증명이어도 429**를 반환한다 |
| 24 | 임포트 파일의 악성 콘텐츠·대량 오염 | 업로드는 인가 → 크기 → 선언 형식 → **매직넘버** → 해시 → 저장 순서다. 임포트는 미리보기 후 **확정이 OWNER 전용 + 감사**이며 부분 실패 리포트를 남긴다 |
| 25 | 파일 무단 다운로드 | **비공개 버킷 + 클라이언트 서명 URL 미발급 + 1회용 토큰 + 서버 스트리밍**. 서버를 통과하므로 열람·다운로드 기록이 남아 교부 증빙이 된다(ADR-16) |
| 26 | 감사 원장 위조·삭제 | audit_logs·security_events·account_status_events에 **UPDATE·DELETE 정책이 없고** 트리거가 다시 막는다. 앱 롤에 DELETE grant 자체가 없다 |
| 27 | 오픈 리다이렉트를 통한 자격 증명 탈취 | 로그인 후 복귀 대상을 **내부 경로만 허용**한다 |

검산: 격리·권한 4(1~4) + 근태 3(5~7) + 급여·기준값 3(8~10) + 문서 2(11~12) + 세션·토큰 3(13~15) + 열거 1(16) + 개인정보 2(17~18) + 내부자·키·백업 3(19~21) + 공급망·남용 2(22~23) + 파일 2(24~25) + 원장·리다이렉트 2(26~27) = **27**.

## 도메인별 특이 위협

| 도메인 | 위협 | 통제 |
|--------|------|------|
| 근태 | 관리자가 직원 대신 출퇴근을 만들어 넣는다 | 직원 본인 INSERT는 본인 축 + ACTIVE 멤버십 + 사업장 쓰기 가능을 요구하고, **관리자 보정은 수정 요청·승인 경로로만** 흐른다. 승인 이력이 남는다 |
| 근태 | 마감 직전 대량 수정으로 집계를 흔든다 | 동일 일자 대기 요청은 1건만 허용하고 승인은 **본인 승인 차단**이다. 마감은 기간 잠금이며 급여 확정 중 해당 기간 수정을 트랜잭션 잠금으로 막는다 |
| 급여 | 확정 진행 중 근태·인사·휴가가 바뀌어 결과가 흔들린다 | 멱등키가 **같은 요청의 중복만** 막고 경합은 못 막는다 — 같은 사업장 귀속월의 동시 확정과 해당 기간 수정을 **트랜잭션 잠금**으로 직렬화한다(REQ-GLB-15) |
| 급여 | 최저임금 미달을 무시하고 확정한다 | 미달 시 확정을 차단하거나 **관리자 명시 확인 + 사유 필수 감사**를 요구한다. 최저임금 환산액은 반올림하지 않는다 |
| 명세서 | 발행 실패가 교부 미이행으로 남는다 | **PDF 생성 실패가 급여 확정을 롤백하지 않고** 명세서만 실패 상태로 남으며 재시도 정기작업이 이어받는다. 발행 알림은 필수 알림이라 수신 설정으로 생략되지 않는다 |
| 인사 | 퇴사 처리가 본인의 법정문서 열람을 끊는다 | 명세서·급여이력·근로계약을 **본인 소유권 축**으로 인가해 멤버십과 독립시킨다(CMP-07). 퇴사·폐쇄·구독 만료 어느 경우에도 보존기간 내 열람이 유지된다 |
| 인사 | 관리자가 동료 연락처·민감정보를 수집한다 | 동료 조회는 이름·역할만 반환하는 함수로만 열고 **연락처가 반환 타입에 없다**. 멤버 목록 응답에 급여·주민번호·계좌·상세 주소를 포함하지 않는다 |
| 휴가 | 본인 신청을 본인이 승인한다 | 정책의 WITH CHECK가 본인의 결과 상태를 취소로 못박아 승인·반려는 관리자 분기만 통과한다 |
| 구독 | 한도 초과 상태를 동시 요청으로 만든다 | 초대 수락 시 인원 한도 재검증과 사업장 등록 시 소유 한도 재검증을 **행 잠금으로 직렬화**한다. 초대 수락은 서버 원자 함수 경로로만 열린다 |
| 알림 | 알림 본문으로 급여액이 새어 나간다 | **민감정보 포함 금지 플래그가 타입 속성**이며 서버 고정 카탈로그가 미정의 타입 생성을 거부한다. 본문은 사건과 링크만 담는다 |
| 알림 | 타인 알림을 조회·조작한다 | 개인 수신함이라 **관리자 축이 없고** 수신자 본인만 조회·갱신한다. 갱신 가능 컬럼은 트리거가 좁힌다 |
| 위치정보 | 확인자료 없이 좌표가 처리된다 | 기록이 **선행 단계**다. 확인자료 기록이 실패하면 좌표를 기록하지 않고 처리를 중단한다 |
| 위치정보 | 사업주가 직원의 위치 이용 이력을 상시 조회한다 | 확인자료에 **관리자 SELECT 정책이 없다** — 전 업무 테이블 중 유일하게 관리자 축이 없는 배치다 |

| 시스템 | 마지막 SUPER_ADMIN이 사라져 플랫폼이 관리 불능이 된다 | 역할 회수·삭제와 **해당 계정의 정지·탈퇴를 함께 차단**한다. 한쪽만 막으면 계정 정지로 같은 결과가 만들어진다 |
| 실시간 | 사업장 전환 후 이전 사업장 이벤트가 흘러든다 | 스트림은 **수신자 고정 단일 연결 1개**이며 클라이언트가 사업장 채널을 구독·해제하는 개념이 없다 — 무엇을 보낼지는 서버가 정한다. **이벤트 페이로드를 캐시에 직접 병합하지 않고** 무효화 후 재조회하므로, 전환 후 화면에 실리는 값은 재조회 시점의 RLS 판정을 다시 지난다 |
| 배치 | 정기작업이 중복 실행돼 부수효과가 두 번 난다 | 작업 이름별 **분산락**으로 중복 실행을 막고 멱등키로 재실행의 중복 부수효과를 막는다. 대상 일자를 실행 시각에서 역산하지 않고 인자로 받는다 |

## 개인정보 유출 대응

개인정보 유출 시 **72시간 내 정보주체 통지와 전문기관 신고** 의무가 있다. 유출 정황·가능성만으로도 통지하도록 요건이 강화되는 개정이 예정돼 있어 기준을 보수적으로 잡는다.

**PRV-05 개인정보 유출 대응 기능을 v1에 두지 않는다**(v1.1 이월). 따라서 v1에는 유출 사건을 등록·추적·통지 발송하는 제품 화면이 없으며, 대응은 **담당자 지정 + 수동 절차**로 수행한다. 이 절차는 제품 데이터가 아니라 운영 문서로 관리한다.

```plain
① 인지 — 유출 또는 그 정황을 인지한 시각을 기록한다
   ⚠ 72시간 시계는 인지 시점부터 돈다. 원인 규명 완료 시점이 아니다
② 즉시 차단 — 노출 경로를 닫는다
   ├─ 자격·키 유출  → [03_secrets_keys.md](./03_secrets_keys.md) 유출 대응 절차
   ├─ 권한 오설정   → 정책·권한 즉시 정정 후 격리 검증 재실행
   └─ 파일 노출     → 객체 접근 차단 + 발급된 다운로드 토큰 무효화
③ 범위 확정 — 어떤 항목이 · 몇 명분이 · 언제부터 언제까지 노출됐는지 확정한다
   근거는 audit_logs · security_events · 서버 접근 로그 · 저장소 접근 기록이다
④ 통지 대상 판단 — 고유식별정보(주민번호) 포함 여부가 통지 방식과 긴급도를 가른다
⑤ 정보주체 통지 — 인지 후 72시간 내. 유출 항목 · 시점 · 경위 · 피해 최소화 방법 · 대응 조치 · 접수 창구를 담는다
   ⚠ 범위 확정이 끝나지 않아도 확인된 범위로 먼저 통지하고 이후 갱신한다
⑥ 전문기관 신고 — 인지 후 72시간 내. 신고 제도의 출처는 03_requirements/18_official_references.md
⑦ 사업주 고지 — 해당 사업장의 OWNER에게 별도 고지한다
   근로자의 개인정보이므로 사업장도 이해관계자다
⑧ 사후 기록 — 인지 · 조치 · 통지 · 신고 · 재발 방지 항목을 남긴다
```

| 판정 항목 | 기준 |
|-----------|------|
| 유출로 볼 것인가 | **판단이 서지 않으면 유출로 간주한다.** 늦은 통지의 대가가 불필요한 통지의 대가보다 크다 |
| 72시간 기산점 | **인지 시점**이다. 원인 규명 완료를 기다리지 않는다 |
| 부분 통지 | 확인된 범위로 먼저 통지하고 갱신한다. 완전한 범위를 기다리다 기한을 넘기지 않는다 |
| 키 유출과 데이터 유출의 구분 | 키가 새어도 암호문에 접근한 흔적이 없으면 개인정보 유출이 아니다. **그 판단 근거를 ③에서 남긴다** |
| 준비 상태 | 통지 문안 템플릿 · 접수 창구 · 담당자 지정은 **출시 전에 갖춘다**. 사건 발생 후 만들면 72시간을 쓰게 된다 |

- **v1에 유출 대응 기능이 없다는 사실이 의무 면제가 아니다.** 기능 부재를 보완하는 것은 운영 절차이며, 그 절차의 존재 여부가 출시 조건이다.
- 시스템 관리 화면의 감사 조회·내보내기가 ③의 근거 수집 경로다. **내보내기 자체도 사유 필수 감사 대상**이다.

| 3 | 배포 재기동이 순간 중단을 동반한다 | 무중단 배포를 v1에 두지 않는다 | **의식적 선택** — 배포 창을 업무 시간 밖으로 잡는다 |
| 4 | 모의 위치 앱 탐지·기기 바인딩이 없다 | ATT-15가 v1.1 이월이다 | **이월** — 서버가 좌표·정확도를 기록하므로 사후 이상 패턴 확인은 가능하다. 부정 출퇴근 신고 발생 시 도입한다 |
| 5 | 오프라인·앱 미설치 직원의 근태를 관리자가 대신 입력한다 | 대체 입력 경로가 없으면 그 직원의 근태를 만들 수 없다 | **수용** — 대리 입력은 수정 요청·승인 경로를 거치고 이력이 남는다. 본인 확인 축이 약한 것은 구조적 한계다 |
| 6 | 관리자 계정 탈취 = 소속 직원 전원의 PII·급여 접근 | 관리자는 업무상 그 범위가 필요하다 | **수용** — 사전 통제가 없으므로 **사유 필수 감사**가 사후 통제를 맡는다. 재인증 4요건이 원문 열람을 좁힌다 |
| 7 | 플랫폼 SUPER_ADMIN 탈취 = 전 사업장 영향 | 최상위 운영 권한이다 | **수용** — 관리자 수 최소화 · 만료일 있는 역할 · 마지막 SUPER_ADMIN 보호 · 전 액션 감사 |
| 8 | 조회(SELECT)는 감사에 남지 않는다 | 원시 조회는 함수 호출이 없어 데이터베이스가 가로챌 수 없다 | **구조적 한계** — 감사 대상 접근을 전부 서버 경유 함수·스트리밍 경로로 설계한다 |
| 9 | PII 암호화 키가 호스트 환경 파일에 평문으로 존재한다 | 키 관리 서비스를 v1에 두지 않는다 | **의식적 선택** — 호스트 접근 인원 최소화와 파일 권한 제한이 완화책이다([03_secrets_keys.md](./03_secrets_keys.md)) |
| 10 | 2단계 인증이 없다 | 비밀번호 단일 요소이며 민감 작업만 재인증으로 보강한다 | **의식적 선택** — 타깃 사용자 특성상 도입 비용 대비 이탈이 크다 |
| 11 | 상시 스테이징 환경이 없다 | 인스턴스·데이터베이스·시크릿·기준값 시드를 한 벌 더 운영해야 한다 | **의식적 선택** — 계산 검증은 골든 케이스가, 격리 검증은 통합 테스트가 담당한다 |
| 12 | 웹 방화벽·침입 탐지가 없다 | 관리형 계층을 v1에 두지 않는다 | **수용** — rate limit · 입력 검증 · 파라미터 바인딩 · 2단 방어가 대응 축이다. 필요해지는 시점에 도입한다 |
| 13 | 지표 대시보드·분산 추적이 없다 | 단일 프로세스라 추적할 서비스 경계가 없다(ADR-23) | **의식적 선택** — 구조화 로그와 에러 추적으로 좁힌다. 이상 징후 인지가 늦어질 수 있음을 인정한다 |
| 14 | 자동 파기 배치가 없다 | 보존기한 관리가 식별하고 파기는 담당자 확인 후 수행한다 | **의식적 선택** — 잘못된 자동 파기는 되돌릴 수 없다 |
| 15 | 정보주체 권리행사·데이터 반출·유출 대응 기능이 없다 | PRV-03 · PRV-04 · PRV-05가 v1.1 이월이다 | **이월** — 담당자 지정 + 수동 처리 절차로 대응하며 그 절차를 출시 전에 갖춘다 |
| 16 | ADVISOR 역할이 없어 세무사에게 계정을 공유할 유인이 생긴다 | WRK-13이 v1.1 이월이다 | **이월** — v1은 내보내기 결과물 전달로 대체한다. 계정 공유는 감사 추적을 무력화하므로 안내 문구로 억제한다 |
| 17 | 검증 게이트가 아직 실측되지 않았다 | 구현 착수 전 설계 정본이다 | **이월** — 구현 후 실측으로 승격하며 미실측을 통과로 간주하지 않는다 |

검산: 인프라·가용성 3(1~3) + 근태 2(4~5) + 권한 탈취 2(6~7) + 감사·키 2(8~9) + 인증·환경 3(10~12) + 관측·운영 2(13~14) + 범위 이월 2(15~16) + 검증 1(17) = **17건**. 판단값 분포는 **의식적 선택 8**(1 · 2 · 3 · 9 · 10 · 11 · 13 · 14) · **수용 4**(5 · 6 · 7 · 12) · **이월 4**(4 · 15 · 16 · 17) · **구조적 한계 1**(8)이며 8 + 4 + 4 + 1 = **17**이다.

## OWASP 기준 적용

| 항목 | 대응 |
|------|------|
| 접근 통제 실패 | 서비스 1차 검증 + **전 61테이블 RLS(FORCE)** + 헬퍼 **43종** + 트리거 가드. 애플리케이션 판정에만 의존하지 않는다 |
| 암호화 실패 | 전 구간 TLS · 주민번호·계좌 AES-GCM + 키 버전 · 비밀번호 적응형 해시 · 재설정 토큰 해시 저장 · 파일 비공개 버킷 · 백업 서버 측 암호화 |
| 인젝션 | SQL은 파라미터 바인딩과 ORM 경유이며 문자열 조립 쿼리를 두지 않는다. DB 함수는 검색 경로를 고정해 스키마 탐색 경로 공격을 차단한다. **LLM을 계산·판정에 쓰지 않으므로**(REQ-GLB-01) 프롬프트 인젝션 표면이 없다 |
| 안전하지 않은 설계 | "유출을 표현할 수 없는 구조"를 원칙으로 삼는다 — 정책 부재 · 함수 반환 타입 · grant 부재 · 세션 변수 축 제한이 강제 지점이다 |
| 보안 설정 오류 | 시크릿 미설정을 **부팅 실패**로 처리한다. 데이터베이스·캐시를 호스트 포트로 노출하지 않고 교차 출처 허용을 웹 오리진 하나로 좁힌다. 개발 착수 시점부터 RLS를 켠 상태로 진행한다(REQ-TEC-07) |
| 취약·구식 컴포넌트 | 락 파일 커밋 + CI의 재현 설치 + 상위 안정 라인 유지. 품질 게이트 실패 시 이미지를 만들지 않는다 |
| 인증 실패 | 계정 열거 차단(단일 응답·동일 응답) · rate limit 7축 · 계정 상태 선검증 · 재설정 토큰 1회용 · 재인증 4종 |
| 소프트웨어·데이터 무결성 실패 | 확정 불변 · 정정 체인 · 원장 append-only · 감사 UPDATE·DELETE 봉인 · 파일 해시 검증 · 계약 PDF 해시 일치 강제 · 결과 값 동결 |
| 로깅·모니터링 실패 | 감사 원장(사유 필수 액션 — 전수 정본 [../05_database/15_system.md](../05_database/15_system.md)) · 보안 이벤트 · 구조화 로그 · 에러 추적 · 정기작업 실행 이력. **개인정보 원문·금액·토큰을 로그에 남기지 않는다** |
| 서버측 요청 위조 | 외부 호출 대상이 **고정된 셋**(국세청 사업자등록 API · 메일 발송 · 에러 추적)이며 사용자 입력이 대상 주소를 결정하지 않는다. PDF 렌더는 이미지에 포함된 템플릿·폰트만 쓰고 렌더 시점에 외부에서 내려받지 않는다 |
