insadesk의 데이터 접근 표면은 **Spring REST 단일 축**이다. 직원 앱(app_front)과 웹(web_front)이 같은 엔드포인트를 공유하고 인증 축만 갈리며, 브라우저는 API 서브도메인을 직접 호출한다(D-03 · D-20). **GraphQL · WebSocket을 쓰지 않으며, 웹 호스팅 계층에 업무 데이터 경로를 두지 않는다.**

본 폴더는 요구사항이 정의한 사용자 행위·서버 행위를 REST 종점으로 옮긴 **설계 정본**이다. 기능 ID는 [../02_features](../02_features/README.md), 에러 코드는 [../09_glossary/02_error_codes.md](../09_glossary/02_error_codes.md), 화면 코드는 [../07_screen/README.md](../07_screen/README.md), 테이블은 [../05_database](../05_database/README.md)가 정본이며 **본 폴더는 새 ID를 채번하지 않는다**. 어긋나면 각 정본이 우선한다.

## 계층 요약

| 계층 | 방식 | 무결성 강제 | 규모 |
|:----:|------|------------|------|
| REST | HTTP 요청·응답 JSON. 컨트롤러 진입에서 요청 DTO를 선언적 검증으로 파싱한다 | 필터 체인·서비스 계층(멤버십·역할·활성 사업장) → 서비스 규칙 → DB 제약·RLS 2단 방어 | **238표면** |
| SSE | 서버 → 클라이언트 단방향 이벤트 스트림. Redis 채널 팬아웃 | 연결 수립 시 수신자 스코프 고정. 이후 이벤트는 그 스코프만 흐른다 | **1표면** |
| 다운로드 | 1회용 토큰 발급 + 서버 스트리밍 응답 | 토큰 단기 만료·1회 소비 · 세션·IP·user agent 보조 바인딩 · 열람 이력 기록 | **7표면** |
| 서버 내부 | HTTP 표면이 없는 종점 — 정기작업 · 도메인 이벤트 부수효과 · 자동 기록 | 서버 전용 실행 경로. 사용자 세션으로 도달할 수 없다 | **21등재**(실체 20 · 참조 1) |

계층을 고르는 기준은 하나다 — **클라이언트가 요청할 수 있는 일인가.** 요청할 수 있으면 REST이고, 서버가 밀어 주기만 하면 SSE이며, 응답 본문이 파일이면 다운로드이고, 사용자가 요청할 수 없어야 하면 서버 내부다.

**서버 내부 종점을 두는 이유는 셋이다.** ① 사용자 요청과 무관하게 성립해야 하는 상태(정기작업 8건) ② 다른 트랜잭션의 부수효과로만 의미가 있는 처리(명세서 생성 큐 등록 · 퇴사 연동 트리거 · 알림 발화) ③ 사용자가 조작하면 법정 의무 이행 자체가 증명되지 않는 기록(위치정보 이용·제공 사실 확인자료 · 원좌표 파기)이다.

- **반대 방향도 하나 있다 — 기능ID를 갖지 않는 표면이다.** [14_system.md](./14_system.md) #34(정기작업 재실행)는 정기작업의 운영 트리거인데 **정기작업은 기능ID를 갖지 않는 서버 실행 항목**이라 기능 집계 밖이다(정본 [../02_features/15_scheduled_jobs.md](../02_features/15_scheduled_jobs.md)). 표를 채우려고 기능ID를 채번하면 **기능 수가 움직이므로** 그 문서의 기능 열은 **정본을 가리키는 형태**로 적는다. 이 절의 대조 축은 기능 → 표면이고 이 표면은 그 축의 반대편에 대응이 없다 — 등재는 [../03_requirements/17_traceability.md](../03_requirements/17_traceability.md) SYS 절의 표면 전용 표가 맡는다.

- 표면 번호(#N)는 **문서 지역 번호**다. 문서 간에 이어지지 않으며 다른 문서의 표면을 가리킬 때는 문서 링크와 함께 표기한다.
- **신설 표면은 말미에 채번한다.** 업무 흐름상 자리가 중간이어도 기존 번호를 밀지 않으며, 상세 절은 번호 오름차순 자리에 두고 표면 요약 표의 각주가 흐름상 자리를 밝힌다. **번호 재배치는 타 문서의 상호참조를 한꺼번에 깨뜨리므로 하지 않는다** — 번호는 식별자이지 순서 표시가 아니다. **번호를 폐지해도 재사용하지 않는다** — 결번이 남으며 그 자리의 각주가 근거를 밝힌다.
- **한 표면이 둘로 갈리면 셋 다 새 번호를 쓰지 않는다 — 갈린 둘이 새 번호이고 원래 번호는 폐지된다.** 남은 쪽에 원래 번호를 물려주면 **같은 번호가 다른 메서드·다른 경로를 가리키게 되고**, 타 문서가 인용한 그 번호가 어느 쪽을 뜻하는지 문서만 보고는 알 수 없다. 실측 — [11_compliance.md](./11_compliance.md) #9(기한 과제 전이)가 #14 · #15로 갈렸고 #9는 결번이다.
- 계층 어휘는 **REST · SSE · 다운로드 · 서버 내부** 4종으로 고정한다. 다른 어휘를 쓰지 않는다.

## 페이지네이션 요약

목록 표면은 셋 중 하나를 쓰고 각 도메인 문서의 표면 요약 표에 방식을 표기한다. 상세 규약과 응답 형태의 정본은 [01_conventions.md](./01_conventions.md)다.

| 방식 | 표면 수 | 적용 근거 |
|------|:------:|----------|
| 오프셋 | **34** | 모집단이 **사업장 활성 멤버 30명 상한** 또는 한 급여월 단위라 총 건수가 세 자리를 넘지 않는다. 마감 작업 화면이 "전체 12건 중 처리 3건"을 요구하는데 커서는 총 건수를 주지 않는다 |
| 커서 | **4** | 알림([12](./12_notification.md) #2) · 명세서 교부 이력([09](./09_payslip.md) #9) · 감사 로그([14](./14_system.md) #19) · 위치정보 확인자료([15](./15_privacy.md) #2). 넷 다 시간 역순 **무한 증가**라 오프셋은 같은 행을 두 번 주거나 건너뛴다 |
| 범위 조회 | **9** | 근태 기록·일 집계·스케줄·휴게 준수·한도 경고([06](./06_attendance.md)) · 급여 이력 2종 · **인건비 추이**([08](./08_payroll.md)) · 기한 캘린더([10](./10_tax.md)). 조회 단위가 기간이라 스스로 상한을 갖고, 쪽을 나누면 달력·차트가 잘린다 |

검산: 34 + 4 + 9 = **47표면**이 쪽 나눔을 갖는다. 나머지 조회 표면은 단건이거나 고정 크기 집합(요금제 3등급 · 휴가 유형 4종 · 알림 타입 24종 · 보험 5종)이다.
