# 10 실시간·파일

> **대상**: SSE 연결 계약과 Redis 팬아웃 · S3 저장 구조 · 업로드 검증 순서 · 1회용 토큰 다운로드 · 명세서 PDF 생성 파이프라인
> **작성일**: 2026-08-03
> **개정일**: 2026-08-08 — 명세서 파이프라인 ⑥의 통지를 **관리자용 생성 완료 통지**로 명시하고 직원 발행(도착) 알림이 게시(DELIVERED) 트랜잭션의 부수효과임을 구분 등재(정본 06_api/09_payslip.md #6 · #17)
> **개정일**: 2026-08-08 — SSE 채널 계약을 수신자 고정 단일 스트림으로 정정(클라이언트 사업장 구독·재구독 삭제 · 사업장 분리는 서버 내부 채널만), 명세서 파이프라인 ⑥을 생성 완료(GENERATED)까지로 좁히고 교부(DELIVERED)를 관리자 게시 행위로 분리, 파일 수명 주기 행에 v1 자동 파기 미채택 명시
> **원천**: docs_ref2/requirements_p0.md(REQ-NTF-01~06 · REQ-SLP-01~08 · REQ-HRM-23·24 · REQ-WRK-32) · docs_ref2/features.md(NTF-01 SSE + Redis Pub/Sub · 민감정보 국내 리전 저장) · docs_ref2/schema_p0.md(documents · payslips · batch_jobs · import_jobs) · [../08_tech_stack/04_data_infra.md](../08_tech_stack/04_data_infra.md)

실시간과 파일은 성격이 다르지만 한 가지 제약을 공유한다 — **둘 다 인가 판정을 우회하기 쉬운 표면**이다. 실시간 채널은 한 번 붙으면 이후 이벤트가 검증 없이 흘러가기 쉽고, 파일은 링크 하나가 유출되는 순간 인증 없이 열린다. 그래서 두 표면 모두 **연결·발급 시점이 아니라 매 전달 시점에 스코프를 강제**하는 구조로 만든다.

v1의 실시간 표면은 **인앱 알림 배달(NTF-01) 하나**다. 클라이언트가 실시간으로 보낼 것이 없어 서버에서 클라이언트로 가는 단방향 SSE로 충분하다(ADR-14). **실시간 근태 현황판을 v1에 두지 않는다.** 클라이언트 연결은 **수신자를 고정한 단일 스트림 1개**이며, 사용자·사업장으로 갈리는 것은 **서버 내부 Redis 채널뿐**이다 — 클라이언트가 사업장 채널을 골라 구독하는 표면을 두면 그 선택이 곧 격리의 근거가 되어 서버 판정이 요청 파라미터로 내려앉는다. 파일은 서울 리전 S3에 두고 공개 URL을 만들지 않는다(ADR-16).

## SSE 계약

| 항목 | 계약 |
|------|------|
| 방향 | 서버 → 클라이언트 단방향이다. 클라이언트 발신은 전부 REST다 |
| 인증 | 웹은 Domain=.{domain} 세션 쿠키가 자동으로 실린다(D-03) · 앱은 Authorization 헤더다. **연결 시점에 인증을 판정하고, 스코프는 이벤트 전달 시점에 다시 본다** |
| 스트림 | 클라이언트 표면은 **수신자 고정 단일 스트림 1개**다(NTF-01 — 정본 [../06_api/01_conventions.md](../06_api/01_conventions.md)). 연결 수립 시 수신자를 박고 이후 그 수신자의 이벤트만 흐른다 |
| 채널 | 사용자 스코프와 사업장 스코프로 나뉘는 것은 **서버 내부 Redis 채널**이다. 사업장 공통 알림은 서버가 수신 대상자를 확정해 각자의 스트림으로 내보내며, **클라이언트가 사업장 채널을 구독·해제하는 개념을 두지 않는다**. 화면은 이벤트 payload의 사업장 식별자로 표시 대상을 가른다 |
| 이벤트 형식 | 이벤트 종류 · 식별자 · 최소 페이로드를 담는다. **급여 금액 · 주민번호 · 계좌 같은 민감 값을 페이로드에 싣지 않는다**(REQ-NTF-01) |
| 클라이언트 반영 | 이벤트를 받으면 해당 도메인 쿼리 키를 **무효화하고 재조회**한다. 페이로드를 캐시에 직접 병합하지 않는다 — 수신 시점 권한과 조회 시점 권한이 다를 수 있고 재조회가 가시성을 다시 판정한다 |
| 하트비트 | 주기적으로 주석 프레임을 보내 프록시·모바일 네트워크가 유휴 연결을 끊지 않게 한다 |
| 재연결 | 클라이언트가 지수 백오프로 재연결한다. 재연결 폭주를 막기 위해 지터를 둔다 |
| 이벤트 식별자 | 각 이벤트에 식별자를 부여하고, 재연결 시 클라이언트가 마지막으로 받은 식별자를 헤더로 보낸다. 서버는 그 이후 발생분을 재전송한다 |
| 유실 보충 | **재전송 버퍼를 유일한 보장으로 삼지 않는다.** 미연결 중 발생분은 재접속 후 목록 조회로 보충하는 것이 정본 경로이며 재전송은 체감 지연을 줄이는 보조다(REQ-NTF-02) |
| 팬아웃 | 이벤트 생산자가 Redis 채널에 발행하고, SSE 핸들러가 구독해 **자신이 보유한 연결에만** 전달한다. 생산자는 어느 인스턴스에 연결이 붙어 있는지 알 필요가 없다 |
| 저장 순서 | **저장 먼저 · 발행 나중**이다. 발행이 먼저면 저장 실패 시 목록에 없는 알림이 화면에 뜬다 |
| 실패 격리 | 알림 생성·발행 실패가 원 이벤트를 롤백하지 않는다. 급여 확정이 알림 실패로 되돌아가서는 안 된다 |
| 연결 정리 | 연결 종료·타임아웃 시 서버가 내부 구독을 정리한다. **사업장 전환은 재연결을 요구하지 않는다** — 스트림 스코프가 수신자 고정이라 전환의 영향을 받지 않는다 |
| 프록시 | nginx가 SSE 경로의 버퍼링을 끄고 읽기 타임아웃을 길게 잡는다(정본 [08_deployment_topology.md](./08_deployment_topology.md)) |
| 연결 상한 | 사용자당 동시 연결 수에 상한을 둔다. 탭을 여럿 연 사용자가 연결을 무한히 늘리지 못하게 한다 |

**WebSocket을 쓰지 않는다.** 양방향 프로토콜·핸드셰이크·하트비트·프록시 설정을 관리하면서 절반만 쓰게 된다(ADR-14).

## 파일 저장

| 항목 | 계약 |
|------|------|
| 리전 | **ap-northeast-2(서울) 고정**이다. 주민번호·계좌·근로계약·명세서가 담기므로 국내 저장을 요건으로 둔다. 국외 리전 복제를 켜지 않는다 |
| 공개 설정 | **전 버킷 비공개**다. 퍼블릭 읽기를 켜지 않으며 공개 URL·영구 링크를 만들지 않는다 |
| 암호화 | 서버 측 암호화를 켠다. 필드 수준 민감정보(주민번호·계좌)는 그와 별개로 애플리케이션이 암호화한다 |
| 수명 주기 | 법정 보존기간이 붙은 산출물에 자동 삭제 규칙을 걸지 않는다. **v1은 보존만료 자동 파기 배치를 두지 않으며**(정기작업 8건에 없다 — v1.1 이월) 보존 기한 도달 목록 제시까지가 범위다([07_batch_scheduling.md](./07_batch_scheduling.md)) |
| 메타 정본 | 파일 실체의 경로·해시·크기·보존 기한은 documents 테이블이 일원 보유하고, 명세서 등 소비 테이블은 참조만 한다 |

저장 대상과 키 구조는 **6종**이다. 검산: 명세서 1 + 근로계약 교부본 1 + 직원 문서함 1 + 임포트 원본 1 + 익스포트 산출물 1 + 아바타 1 = **6**.

| 대상 | 키 구조 | 성격 |
|------|--------|------|
| 임금명세서 PDF | 사업장 / payslips / 급여 귀속월 / 명세서 식별자 | 법정 보존(지급일 + 3년) · 민감 |
| 근로계약서 교부본 | 사업장 / contracts / 직원 식별자 / 계약 식별자 | 법정 보존(종료일 + 3년) · 민감 |
| 직원 문서함 | 사업장 / documents / 직원 식별자 / 문서 식별자 | 민감 여부가 문서 분류에 따라 갈린다 |
| 임포트 원본 | 사업장 / imports / 작업 식별자 | 검증 후 보관. 개인정보를 포함하므로 보존 기한을 둔다 |
| 익스포트 산출물 | 사업장 / exports / 작업 식별자 | 단기 보관. 만료 후 삭제한다 |
| 아바타 | users / avatars / 사용자 식별자 | 비민감. 그래도 비공개 버킷에 둔다 |

- **키의 첫 세그먼트는 사업장 식별자**다. 경로만 보고도 어느 테넌트의 자산인지 드러나 잘못된 스코프의 접근이 코드 리뷰에서 눈에 띈다.
- 파일명에 원본 이름을 그대로 쓰지 않는다. 원본 이름은 메타에 보관하고 키에는 식별자를 쓴다 — 이름 자체가 개인정보인 경우가 있다.
- **RLS는 메타 행의 가시성만 담당한다.** 객체 접근 통제는 버킷 정책 · 서비스 인가 · 다운로드 토큰 · 서버 스트리밍 넷이 함께 만든다.

## 업로드 검증 순서

```plain
① 인증·인가 — 사업장 멤버십 · 역할 · 대상 직원 스코프 확인
② 크기 검증 — 애플리케이션 상한으로 판정한다 (nginx 상한은 뒤에 둔다)
                초과는 common.payload_too_large/413
③ 확장자·선언 MIME 검증 — 허용 목록에 없으면 거부
④ 매직넘버 검증 — 파일 앞부분을 읽어 실제 형식을 확인한다
                  선언 MIME과 실제가 다르면 거부한다
⑤ 파일 해시 산출 — 중복 업로드 판별과 무결성 확인에 쓴다
⑥ S3 업로드 — 사업장 스코프 키로 저장
⑦ 메타 행 생성 — 경로 · 원본명 · MIME · 크기 · 해시 · 보존 기한
⑧ 후처리 — 임포트는 행 검증 큐로, 문서함은 분류·보존 기한 확정으로 이어진다
```

- **④를 건너뛰지 않는다.** 선언 MIME만 믿으면 확장자만 바꾼 실행 파일이 통과한다.
- **⑥보다 ①~⑤가 앞선다.** 검증 전에 올리면 거부된 파일이 스토리지에 남는다.
- 임포트는 **⑦까지가 업로드이고 커밋이 아니다**. 행 검증·미리보기 단계에서는 어떤 업무 데이터도 만들지 않으며 확정은 OWNER의 별도 조작이다(REQ-WRK-32).
- 업로드 경로를 클라이언트가 직접 S3로 가는 방식으로 두지 않는다. 직접 업로드는 ①~⑤를 우회할 수 있고, 우회한 파일이 메타 없이 버킷에 남는다.

### 크기 상한

| 대상 | 애플리케이션 상한 | 근거 |
|------|-----------------|------|
| 직원 문서함 · 근로계약서 첨부 | **10MB** | 스캔 계약서·증빙 다수를 담는 최대 축이다 |
| 임포트 CSV | **5MB** | 타깃 규모(상시 근로자 1~30인)에서 직원 명부 한 벌은 이 범위를 넘지 않는다 |
| 아바타 | **2MB** | 표시용 축소 이미지이며 원본 보관 목적이 아니다 |

**nginx 요청 본문 상한은 애플리케이션 상한보다 1MB 크게 잡는다**(문서함 기준 11MB). 두 상한을 같게 두면 경계 근처 요청을 nginx가 먼저 끊어 응답이 애플리케이션 에러 규격이 아닌 프록시 오류 페이지로 나가고, 클라이언트는 common.payload_too_large/413 대신 파싱할 수 없는 응답을 받는다. **413은 애플리케이션에서 나가야 한다** — nginx 상한은 애플리케이션에 닿기 전에 비정상적으로 큰 본문을 끊는 안전망일 뿐이다. 값이 바뀌면 [08_deployment_topology.md](./08_deployment_topology.md)의 nginx 절을 같은 변경 단위에서 함께 고친다.

- 위 수치는 **설계 재량값이며 기준값 테이블 대상이 아니다**(법정값이 아니다).
- 멀티파트 요청 전체 크기와 개별 파일 크기를 각각 검사한다. 파일 하나가 상한 이하여도 여러 개를 합치면 넘을 수 있다.

## 다운로드

법정 문서와 민감 문서의 다운로드는 **1회용 토큰 + 서버 스트리밍**이다(REQ-SLP-08 · REQ-HRM-24).

```plain
① 다운로드 요청 → 서비스 인가 판정
   명세서·근로계약·급여이력은 본인 소유권 · 그 외는 사업장 역할
   민감 문서는 재인증(5분) + 사유 입력 + 감사 기록을 함께 요구한다
② 1회용 다운로드 토큰 발급 (단기 만료 · Redis 보관)
   세션 · IP · user agent를 보조 바인딩해 복사 재사용을 막는다
③ 클라이언트가 토큰으로 다운로드 요청
④ 서버가 토큰을 소비(1회) → 만료·재사용은 410으로 거부
⑤ 서버가 S3 객체를 읽어 응답으로 스트리밍
   서명 URL은 서버 안에 머문다 — 클라이언트에 전달하지 않는다
⑥ 열람·다운로드 시각 · IP · 기기를 기록한다
```

| 항목 | 계약 |
|------|------|
| 서명 URL 노출 | **클라이언트에 서명 URL을 내려주지 않는다.** URL이 전달되는 순간 그 URL은 수명 안에서 누구에게나 열리고, 서버는 그 접근을 기록할 수도 막을 수도 없다 |
| S3 접근 | 서버의 S3 접근 자체는 언제나 수명 제한 서명 요청으로만 한다. 공개 URL·영구 링크를 만들지 않는다 |
| 토큰 성격 | 단기 만료 · **1회 사용**. 만료·재사용은 payslip.download_token_expired/410 규약을 명세서와 민감 문서가 공유한다 |
| 발급 빈도 | 명세서 열람 · 민감 문서 · 아바타가 같은 경로를 쓰므로 **(사용자, 시간) 단위 발급 한도**를 건다. 수치 정본은 [02_authn_session.md](./02_authn_session.md) rate limit 표다 |
| 부재 처리 | 타인 명세서 요청은 403이 아니라 **404로 행 존재 자체를 숨긴다**(REQ-SLP-08) |
| 기록 | 열람(VIEWED)과 다운로드(DOWNLOADED)를 구분해 기록한다. **교부(ISSUED)와 실제 열람은 별개 이벤트**다 |
| 비민감 자산 | 아바타도 같은 서버 스트리밍 경로를 쓴다. 1회용은 아니되 단기 만료 토큰을 요구하고 응답 캐시 수명을 짧게 둔다 |
| 사업장 폐쇄 후 | 본인 소유권으로 인가되는 문서는 폐쇄·퇴사 후에도 열람과 다운로드가 유지된다(CMP-07) |

## 명세서 PDF 파이프라인

```plain
① 급여 확정(CONFIRMED) → 직원별 명세서 생성 작업 등록
   자동 트리거는 원본 최초 생성만 담당한다 (정정본은 별도 단일 경로)
② 명세서 데이터 조립 — 확정 결과의 동결값 + 근로시간 + 계산방법 + 공제 내역
③ 법정 필수항목 점검 — 누락이면 실패 상태로 두고 보완 항목 목록을 반환한다
   (누락 상태로 교부하지 않는다)
④ 서버 HTML 템플릿 렌더 → 헤드리스 브라우저가 PDF로 출력
   관리자 웹 미리보기와 같은 템플릿을 공유한다
⑤ S3 업로드 → documents 메타 생성 → 명세서 행이 문서를 참조
⑥ 생성 완료(GENERATED) + 생성 결과 통지(관리자용 — 생성 성공·실패 건수)
   자동 파이프라인은 여기까지다
   교부(DELIVERED 전이 + ISSUED 기록)는 관리자의 게시 행위가 수행한다
⑦ 실패분은 실패 상태와 사유를 유지한다
   → retryPayslipAndPush(15분 주기)가 재큐잉한다
```

**⑥에서 멈추는 것이 계약이다.** 교부는 법적 사실이 성립하는 시점이라 시스템이 대신 선언하지 않는다 — 자동 파이프라인은 PDF를 만들어 GENERATED까지 올리고, DELIVERED 전이와 교부(ISSUED) 기록은 관리자의 게시 조작이 만든다(정본 [../03_requirements/08_payslip.md](../03_requirements/08_payslip.md)).

**⑥의 통지는 관리자용 생성 완료 통지다** — **직원에게 가는 발행(도착) 알림은 게시(DELIVERED) 트랜잭션의 부수효과**이며 이 파이프라인 단계에서 발화하지 않는다(정본 [../06_api/09_payslip.md](../06_api/09_payslip.md) #6 · #17).

| 항목 | 계약 |
|------|------|
| 생성기 | **헤드리스 브라우저의 HTML 템플릿 렌더**를 쓴다. 좌표로 조립하는 방식은 항목이 늘 때마다 레이아웃을 다시 맞춰야 하고 한글 폰트 임베딩·줄바꿈을 따로 해결해야 한다(ADR-15) |
| 폰트 | 컨테이너 이미지에 한글 폰트를 포함한다. 렌더 시점에 외부 폰트를 내려받지 않는다 |
| 자원 통제 | 브라우저 인스턴스를 풀로 관리하고 **동시 실행 수에 상한**을 둔다. 요청마다 새로 띄우면 메모리가 인스턴스 한도를 넘는다 |
| 실행 위치 | 대량 생성은 요청 응답 경로가 아니라 일괄 실행 경로에서 수행한다 |
| 실패 격리 | **PDF 생성 실패가 급여 확정을 롤백하지 않는다.** 확정은 확정대로 유효하고 명세서만 실패 상태로 남는다 |
| 재시도 | retryPayslipAndPush가 실패 상태를 재큐잉한다. 재시도 상한 초과 시 실패를 유지하고 담당자에게 알린다 — **조용한 성공 처리를 하지 않는다** |
| 멱등 | (급여 실행, 직원) 원본 부분 유일 제약 + 멱등키로 중복 생성을 막는다 |
| 스냅샷 | 확정 시점 데이터와 적용 기준값 버전을 스냅샷으로 담아 **이후 기준값이 바뀌어도 명세서가 불변**이게 한다 |
| 정정본 | 원본 PDF를 덮어쓰지 않는다. 정정본은 새 문서를 만들고 원본을 가리킨다 |
| 차단 | 사업장이 검증 대기 상태면 발행을 차단한다 |

근로계약서 교부본도 같은 렌더 경로를 쓴다. 서명 이미지가 포함되므로 **서명 완료 이후에만** 교부본을 생성한다.
