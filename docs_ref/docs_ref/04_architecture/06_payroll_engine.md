# 06 급여 계산 엔진

> **대상**: 결정론 계산 파이프라인 8단 · 재현성 계약 · 기준값 조회 계약 · 값 동결 · 정정 체인 · 골든 케이스 회귀
> **작성일**: 2026-08-03
> **개정일**: 2026-08-08 — DB 커버리지 감사 반영 — 값 동결 표 9 → **11행**(계산 입력 · 임금대장 법정 기재) · 세액표 구간 축 명칭을 월 급여액으로 정정 · ⑧의 산출물 교체 계약 명문화
> **개정일**: 2026-08-08 — ③ 법정수당 단계에 주휴 분기(payroll_terms.monthly_includes_weekly_holiday — 포함이면 지급 0 라인 동결 · 미포함이면 별도 지급 산식) 명문화(REQ-PAY-15)
> **개정일**: 2026-08-08 — 소득세 단계(⑥)에 간이세액표 2축 조회와 자녀 수별 세액 차감 단계를 명문화(조회 → 차감 → 하한 0 → 선택비율 → 절사 순서 고정)
> **원천**: docs_ref2/requirements_p0.md(REQ-GLB-01~10 · REQ-ATT-10 8버킷 · REQ-PAY-19~30) · docs_ref2/schema_p0.md(타입 매핑·역직렬화 · 동결 필드) · 확정 결정 D-05 · D-16 · D-17([../01_overview/06_design_decisions.md](../01_overview/06_design_decisions.md))

급여 계산은 insadesk에서 **틀리면 가장 늦게 드러나고 가장 크게 터지는** 연산이다. 오차는 계산 시점이 아니라 명세서 교부 뒤, 또는 이듬해 과거 명세서를 재출력할 때 드러나며 그때는 이미 법정 문서가 나간 뒤다. 그래서 이 엔진의 설계 목표는 빠름이 아니라 **같은 입력이 언제 어디서 몇 번을 돌아도 바이트 단위로 같은 결과를 내는 것**이다.

목표를 규칙으로만 두지 않고 **구조로 강제**한다. 계산은 값 객체만 주고받는 순수 함수 계층에 격리해 데이터베이스·현재 시각·난수에 접근할 수 없게 만들고(D-05 · ADR-18), 반올림은 항목별 최종 금액에서 딱 한 번만 일어나게 하며(D-16), 확정 시점의 기준값과 판정 결과를 결과에 동결한다(D-17).

**계산 규칙 자체의 정본은 [../03_requirements/01_global_rules.md](../03_requirements/01_global_rules.md)와 [../03_requirements/07_payroll.md](../03_requirements/07_payroll.md)다.** 본 문서는 그 규칙을 실행하는 파이프라인의 구조와 계약을 고정한다.

## 계산 파이프라인

**본 절이 계산 단계 순서의 유일 정본이다.** 다른 문서([../06_api/08_payroll.md](../06_api/08_payroll.md)의 실행 흐름 · [../02_features/06_payroll.md](../02_features/06_payroll.md)의 기능 간 순서 요약)는 같은 순서를 다른 입도로 보여줄 뿐이며, 어긋나면 본 절이 우선한다.

```plain
① 입력 동결
   마감된 근태(LOCKED) · 인사 정보(근로조건 · 4대보험 정보) · 승인 휴가
   · 급여 기준(지급일 포함) · 귀속 기준일별 기준값 행
   · 상시근로자 스냅샷 → 규모 정책(5인 · 10인 경계) 판정
   → 규모 분기는 여기서 판정되어 ③의 가산율 입력이 된다
   → 하나라도 없으면 계산을 시작하지 않고 차단 사유를 전부 모아 반환한다

② 시간 버킷 분해
   일자별 실근로 시간대를 상호배타 8버킷에 분 단위로 배정한다
   regular · night · overtime · overtime_night
   · holiday · holiday_night · holiday_overtime · holiday_overtime_night
   → 불변식: Σ버킷 = raw 실근로분. 어긋나면 계산을 중단한다

③ 지급 항목 산출
   통상임금·통상시급 산출(중간 몫 반올림 금지 · 환산 제수 보존)
   → 기본급(월급 일할 · 시급 · 일급)
   → 법정수당(주휴 · 연장 · 야간 · 휴일 — ①이 판정한 규모 분기를 가산율에 반영)
     주휴는 payroll_terms.monthly_includes_weekly_holiday로 분기한다
     true면 주휴 라인을 산출하되 추가 지급 0 (월급 포함 표기를 결과에 동결)
     false면 (주 소정근로시간 ÷ 40) × 8 × 통상시급을 별도 지급한다 (정본 REQ-PAY-15)
   → 무급공제(결근 · 지각 · 조퇴 · 무급휴가 — 지급 확정액에 반영)
   → 산출물: 이 직원의 지급 확정액과 항목 라인

④ 비과세 분리 · 보험별 보수 base 산출
   비과세 한도 적용 → 초과분 과세 전환
   → 국민연금 · 건강보험(장기요양) · 고용보험 · 산재보험의 base를 각각 산출
   → 보험별 상·하한 적용

⑤ 4대보험 공제
   보험별 base × 근로자 부담 요율 → 보험 항목별로 각각 10원 미만 절사
   → 산재보험은 사업주 전액 부담이라 근로자 급여에서 공제하지 않는다

⑥ 소득세 · 지방소득세
   간이세액표(지급일 기준 버전) 표 세액 조회 — 조회 키는 2축이다
     지급일로 고른 세액표 버전 안에서 과세표준 구간 + 공제대상 부양가족 수
   → 8~20세 자녀 수별 세액 차감 (자녀 수는 조회 축이 아니라 조회 후 차감 축)
   → 하한 0 (차감 결과가 음수면 0으로 둔다)
   → 원천징수 선택비율(80 · 100 · 120% · 미선택 시 100%) 적용
   → 10원 미만 절사
   → 지방소득세 = 소득세 × 10% → 10원 미만 절사

⑦ 최저임금 검증
   월 산입 임금(**무급공제 반영 전 — ③ 이전 값을 입력으로 쓴다**, REQ-PAY-26) ÷ 월 환산 기준시간(divisor와 같은 산식) → 반올림 없이 기준값과 비교
   기준값 적용 누락 점검 · 보험 가입 판정 근거 확인 · 자기포함 급여 여부 판정
   → 미달·누락은 확정을 차단하거나 명시 확인을 요구한다. 경고로 흘리지 않는다

⑧ 합계 · 값 동결
   지급 합계 · 공제 합계 · 실지급액을 이미 반올림된 정수 항목의 합으로 낸다
   라인 순서를 고정한다(항목 정렬 순서 · 항목 코드)
   기준값 행 식별자와 실제 값 · 상시근로자 스냅샷 · 정책 버전 · 규칙 버전
   · 보험별 적용 보수월액 · 간이세액표 입력값 전체를 결과에 동결 저장한다
   → 확정 결과는 이후 어떤 경로로도 덮어쓰지 않는다
```

**순서 자체가 계약이다.** 단계를 바꿔도 각 산식이 그대로면 결과가 같을 것 같지만 그렇지 않다.

- **무급공제(③)가 base 산출(④)보다 앞서는 이유는 무급공제가 과세소득과 보험 보수를 바꾸기 때문이다.** 결근·지각으로 깎인 뒤의 금액이 과세표준과 보수월액의 입력인데, 공제를 뒤로 미루면 깎이기 전 금액으로 소득세와 4대보험료를 매기게 되어 근로자가 받지도 않은 임금에 세금과 보험료를 낸다.
- **규모 분기(①)가 법정수당(③)보다 앞서는 이유**는 5인 미만 판정이 가산율의 입력값이기 때문이다. 수당을 다 계산한 뒤 규모로 깎는 방식은 실근로분 1.0배까지 함께 지워 임금체불을 만든다.
- **비과세 분리(④)가 4대보험(⑤)·소득세(⑥)보다 앞서는 이유**는 보험별 base가 서로 다르기 때문이다. 하나의 과세표준을 네 보험에 공용하면 건강보험료가 틀린다.
- **최저임금 검증(⑦)이 합계(⑧)보다 앞서는 이유**는 미달을 확정 전에 막기 위해서다. 합계와 동결이 끝난 뒤의 검증은 이미 확정된 값을 되돌리는 일이 된다.
- **⑥의 네 연산 순서가 계약이다.** 자녀 차감을 선택비율 뒤로 미루면 같은 입력에서 다른 세액이 나오고, 하한 0을 차감 직후에 두지 않으면 음수 세액이 선택비율에 곱해져 부호가 뒤집힌다. 자녀 공제를 조회 축으로 오해해 3축으로 조회하면 표에 없는 구간을 찾게 되어 계산이 성립하지 않는다 — 조회 키는 2축이고 자녀 수는 차감 축이다(REQ-PAY-24 · [../03_requirements/01_global_rules.md](../03_requirements/01_global_rules.md) §1.3 TAX_TABLE).

반올림은 **각 항목의 최종 금액에서 딱 한 번** 일어난다 — ③의 지급 항목과 무급공제, ⑤의 보험 항목, ⑥의 세액이 각각 그 자리에서 1회다. 중간 몫을 반올림해 저장한 뒤 재사용하지 않으며, ⑧의 합계는 이미 반올림된 정수 항목의 합이라 다시 반올림하지 않는다. 방향 키의 정본은 [../03_requirements/01_global_rules.md](../03_requirements/01_global_rules.md) §1.1이다.

- ①에서 ⑧까지가 **한 트랜잭션이 아니다.** ①~⑦은 재실행 가능한 계산이고 ⑧의 동결만 상태를 만든다. 재계산은 부수효과 없이 반복 가능해야 하며, 그래야 확정 전 미리보기와 확정 계산이 같은 코드 경로를 쓸 수 있다.
- **미리보기는 ①의 차단을 적용하지 않는다.** 불확실 입력을 차단이 아니라 경고로 표시하고, 그 결과를 명세서·임금대장·잠금에 쓰지 않는다(REQ-PAY-30).
- ②의 불변식이 깨지면 그 뒤 단계는 전부 무의미하다. 버킷 합과 원본 실근로분의 일치를 계산 중단 조건으로 둔다.

## 재현성 계약

| 항목 | 계약 | 어기면 생기는 일 |
|------|------|-----------------|
| 시각 주입 | 계산 계층은 현재 시각을 **읽지 않는다**. 귀속 기준일 · 지급일 · 산정 기준일을 전부 인자로 받는다 | 같은 급여를 다시 돌릴 때 기준값 버전이 달리 선택돼 금액이 바뀐다 |
| 난수·정렬 불안정 금지 | 난수 · 해시 순회 순서 · 객체 키 순회 순서에 의존하지 않는다 | 라인 순서가 실행마다 달라져 명세서 출력과 골든 케이스 비교가 흔들린다 |
| 순서 고정 | 항목 라인은 (항목 정렬 순서, 항목 코드) · 일자 집계는 근무일 오름차순 · 주 집계는 ISO 주 번호 오름차순 · 시간 버킷은 8버킷 순서로 누적한다 | 정수 연산이라 값은 같아도 출력 순서가 달라져 인수 기준 비교가 실패한다 |
| 로케일·시간대 비의존 | 프로세스 기본 로케일·시간대에 의존하지 않는다. 일 경계는 KST로 명시 판정하고 date 값은 문자열로 다룬다 | 실행 환경이 바뀌면 근무일 귀속이 하루 밀린다 |
| 부동소수점 전면 금지 | 금액은 정수 원 · 시간은 정수 분 · 비율과 중간 몫은 십진이다. 표시용 파생값도 예외가 아니다 | 화면 계산값과 서버 확정값이 어긋나고 사용자는 어느 쪽이 맞는지 알 수 없다 |
| 역직렬화 강제 | 큰 정수는 정수 타입으로, 십진은 십진 또는 문자열로, date는 문자열로 받는다 | 데이터베이스 타입이 맞아도 드라이버 계층에서 원칙이 조용히 깨진다 |
| 외부 호출 금지 | 계산 계층에서 네트워크·파일·데이터베이스에 접근하지 않는다 | 결과가 외부 가용성에 의존해 재현이 불가능해진다 |
| 부수효과 없는 재계산 | ①~⑦의 반복 실행이 상태를 만들지 않는다 | 재계산이 값을 두 번 반영하거나 이전 계산 결과를 오염시킨다 |

**규칙을 정적 분석 규칙으로 차단한다.** 계산 계층에서 현재 시각·난수 접근과 금액·비율 경로의 부동소수점 변환을 규칙으로 막는다(ADR-18). 리뷰로 지키기에는 위반 지점이 너무 많고 위반 비용이 너무 크다.

## 기준값 조회 계약

**요율·세액표·한도·최저임금·가산율·공휴일·반올림 규칙·규모 정책·통상임금 규칙은 코드·상수·시드에 박지 않는다.** 전부 기준값 테이블에서 **귀속 기준일**로 조회한다.

| 항목 | 계약 |
|------|------|
| 조회 단위 | 연도가 아니라 **귀속 기준일**이다. 같은 연도 안에도 경계가 있다 — 국민연금 상하한은 7월 경계, 간이세액표는 지급일 기준이다 |
| 기준일 종류 | 귀속 근로일 · 귀속월 · 지급일 셋이며 카테고리마다 다르다. 어느 기준일을 쓰는지의 정본은 [../03_requirements/01_global_rules.md](../03_requirements/01_global_rules.md) §1.3 기준값 카탈로그다 |
| 겹침 차단 | 같은 카테고리·키의 유효 기간 겹침은 데이터베이스 제약이 차단한다. 애플리케이션이 "가장 최근 행"을 골라 겹침을 봉합하지 않는다 |
| 누락 처리 | 필요한 값이 하나라도 없으면 **계산을 차단**한다. 임의 기본값 · 직전 연도 값 대체 · 0 처리를 하지 않는다 |
| 미확인 처리 | 확인자 필드가 비어 있는 행은 **미확인으로 간주해 동일하게 차단**한다. 값이 채워져 있다는 사실이 확인됐다는 뜻이 아니다 |
| 캐시 | 한 번의 계산 실행 안에서 같은 (카테고리, 키, 기준일) 조회는 실행 스코프 메모이제이션으로 1회만 수행한다. **실행을 넘겨 캐시하지 않는다** — 기준값이 정정되면 다음 실행이 옛 값을 쓴다 |
| 차단 응답 | 누락 항목 목록을 details로 전부 반환한다. 하나씩 알려주면 사용자가 여러 번 시도하게 된다 |

**차단은 실패가 아니라 정상 동작이다.** 기준값이 비어 있는데 계산이 통과하면 모든 직원의 공제액이 틀린 명세서가 교부된다. 화면 문안도 오류가 아니라 "무엇을 채우면 진행되는가"로 쓴다.

## 값 동결

확정 시점의 **입력과 판정 결과를 결과에 저장**한다. 이력 조회만으로는 재현이 깨지기 때문이다 — 기준값 행이 사후 정정되거나 정책 버전이 바뀌면 참조만 남긴 결과는 이듬해 재출력에서 전부 틀어진다(D-17).

| 동결 대상 | 저장 위계 | 없으면 생기는 문제 |
|-----------|----------|------------------|
| 적용 기준값 행 식별자 + **실제 값** | 급여 항목 라인 | 기준값 정정 시 과거 명세서 재출력이 통째로 틀어진다 |
| 보험별 적용 보수월액 | 급여 항목 라인 | 요율만 동결하면 보수월액 변동 시 재현이 불가능하다 |
| 각 수당 라인의 기준시간 · 단가 · 가산율 · 적용 법칙 | 급여 항목 라인 | 명세서 계산방법 표기 의무를 이행할 수 없다 |
| 통상시급 · 통상임금 월액 · 환산 제수 | 직원별 결과 | 제수가 없으면 통상시급을 재계산할 수 없다 |
| 평균임금 일액 + 산정 근거 기간 | 직원별 결과 | 퇴직금 재현이 불가능하다 |
| 상시근로자 스냅샷 식별자 + 5인·10인 경계 판정 결과 | 직원별 결과 | 규모 분기를 재현할 수 없다 |
| 간이세액표 입력값 전체(**월 급여액** · 부양가족 수 · 8~20세 자녀 수 · 세액표 버전 · 원천징수 선택비율) | 직원별 결과 | 자녀 수·선택비율이 바뀌면 과거 명세서와 불일치한다. **구간 축은 비과세·학자금을 제외한 월 급여액이며 소득공제 후 과세표준이 아니다** |
| 규모 정책 버전 · 통상임금 규칙 버전 · 반올림 규칙 버전 | 급여 실행 헤더 | 규칙이 바뀌면 과거분 전체가 뒤틀린다 |
| 지원사업 적용 여부 | 직원별 결과 | v1은 미지원이나 필드를 미리 둔다 — 나중에 붙이면 과거분 재현이 깨진다 |
| **계산 입력 — 적용 급여 기준·근로조건의 행 식별자와 값** | 직원별 결과 | 이력 테이블이 사후 변경되면 "같은 입력 → 같은 출력"을 검증할 **입력 자체가 사라진다** |
| **임금대장 법정 기재 — 성명 · 근로자 식별정보 · 고용 연월일 · 종사 업무** | 직원별 결과 | 개명·직무 변경이 3년 보존 대상인 과거 임금대장을 소급 변형한다 |

- 동결 필드의 수치는 **문자열로 직렬화**해 저장한다. 구조화 저장 과정에서 부동소수점으로 되돌아가는 경로를 남기지 않는다.
- **동결 대상은 산출물만이 아니다.** 계산 입력과 법정 기재사항을 참조로만 두면 이력·인사 변경이 과거 확정분을 소급 변형한다 — 동결이 막는 것은 기준값 정정만이 아니라 **입력 쪽의 사후 변경 전부**다.
- **⑧이 이전 산출물을 교체한다.** ①~⑦의 재실행이 상태를 만들지 않는다는 계약은 미확정 실행의 항목 라인과 검증 결과를 지우고 다시 적재한다는 뜻이며, 덧쌓으면 합계 불변식이 반드시 깨진다.
- 동결 항목의 전수 정본은 [../03_requirements/01_global_rules.md](../03_requirements/01_global_rules.md) §1.4다. 항목을 늘리면 그 자리를 먼저 고친다.

## 확정과 정정 체인

```plain
DRAFT → CALCULATED → CONFIRMED
          ↑    ↓
          └────┘  재계산(부수효과 없음)

CONFIRMED ─(사유 + 감사 + OWNER 권한)→ VOIDED
                                        └→ 정정본 신규 생성(supersedes로 원본 연결)
```

| 항목 | 계약 |
|------|------|
| 확정 전 점검 | 근태 마감 · 계산 완료 · 검증 무오류 · 상시근로자 스냅샷 · 직원별 실지급액을 전부 확인한다. 미해결이면 차단한다 |
| 자기거래 통제 | 본인이 대상자로 포함된 급여의 확정은 **OWNER 전용**이다 — 자기포함 표시 + MANAGER 실행 차단(auth.workplace_forbidden/403) + 감사 기록을 모두 수행한다(REQ-GLB-16 · REQ-PAY-27) |
| 동시성 | 같은 사업장·귀속월의 동시 확정과 확정 진행 중 해당 기간 근태·인사 수정을 트랜잭션 잠금으로 차단한다(REQ-GLB-15) |
| 멱등 | 확정은 멱등키를 갖는다. 재시도가 두 번 반영되지 않는다 |
| 되돌림 금지 | 확정 상태를 계산 상태로 되돌리지 않는다 |
| 정정 | **원본을 삭제하지 않는다.** 사유·감사와 함께 원본을 무효화한 뒤 원본을 가리키는 정정본을 새로 만들고 차액을 보존한다 |
| 권한 | 무효화·정정본 발행은 **OWNER 전용**이다. MANAGER는 조회만 한다 |
| 명세서 연동 | 정정본 발행은 명세서 정정본 경로와 짝을 이룬다. 원본 명세서를 덮어쓰지 않는다 |

**정정 체인은 실수를 지우는 장치가 아니라 실수를 기록하는 장치다.** 원본이 남아야 무엇이 어떻게 바뀌었는지 근로자에게 설명할 수 있다.

## 골든 케이스 회귀

계산 엔진의 회귀 검증은 **순수 함수 계층 직접 호출**로 한다. HTTP·데이터베이스를 거치면 무엇이 깨졌는지 특정할 수 없다.

| 항목 | 계약 |
|------|------|
| 입력 | 마감 근태 · 기준값 행 · 귀속 기준일 · 지급일을 고정 픽스처로 둔다. 실행 시각에 의존하는 입력을 두지 않는다 |
| 기대값 | 항목별 금액과 합계를 **정수 원으로 명시**한다. **기대값 확정 절차의 정본은 [../03_requirements/16_acceptance_criteria.md](../03_requirements/16_acceptance_criteria.md)** — 기준값 확인 완료 후 수기 계산 대조로 기대값 정수 세트를 확정·동결하며, **구현 출력을 스냅샷해 기대값으로 삼는 것을 금지한다**(구현이 틀린 채 고정되면 회귀 테스트가 그 오류를 영구히 보증한다) |
| 비교 | **근사 비교를 쓰지 않는다.** 허용 오차를 두는 순간 부동소수점 회귀가 테스트를 통과하고, 그 오차는 명세서 금액 불일치로 드러난다 |
| 재현성 | 동일 입력을 반복 계산해 결과가 바이트 단위로 동일한지 확인한다 |
| 역직렬화 | 기동 시 큰 정수 · 십진 · date 파서 설정을 타입 단언으로 검증하는 스모크 테스트를 둔다 |
| 부정 케이스 | 기준값이 없을 때 계산이 **차단되는지**를 검증한다. 기본값 대체가 일어나지 않음을 확인하는 것이 목적이다 |
| 규모 분기 | 5인 미만 기간에 가산율이 0이면서 **실근로분 1.0배는 지급되는지**를 별도 케이스로 둔다 |
| 정본 | 케이스 목록 · 기대값 · **기대값 확정 절차**의 정본은 [../03_requirements/16_acceptance_criteria.md](../03_requirements/16_acceptance_criteria.md)다. 본 문서는 절차를 재정의하지 않고 참조한다 |
