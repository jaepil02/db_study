본 파일은 관리자 웹 사이드바 "급여·명세서" 섹션 6항목의 화면 명세다. 여섯 화면은 **기준 설정 → 미리보기 → 실행·확정 → 대장 → 명세서 → 퇴직 정산** 순의 한 줄기이며, 앞 화면이 남긴 상태가 뒤 화면의 전제가 된다. 급여 기준에 지급일이 없으면 미리보기가 소득세를 산출하지 못하고, 근태가 마감되지 않으면 확정이 차단되며, 확정이 없으면 명세서도 퇴직금 개산액도 성립하지 않는다.

**이 줄기의 분기점은 미리보기와 확정 사이에 있다.** 미리보기까지는 되돌릴 수 있으므로 불완전한 입력을 경고로 보여 주고, 확정부터는 되돌릴 수 없으므로 같은 조건을 차단으로 막는다. 되돌리는 유일한 방법은 원본 무효화 + 정정본 신규 생성이며 원상 복구가 아니다(REQ-GLB-13). 그래서 확정·무효화·정정본·일괄 발행은 [01_standards.md](./01_standards.md) §3-2의 2단 확인 + 멱등 계약을, 여섯 화면 전부는 §3-6의 낙관적 갱신 금지를 그대로 따른다.

**계산 결과는 참고자료이며 신고·납부의 최종 책임은 사업주에게 있다**(REQ-GLB-20). 표시 문안은 §3-7과 §5-6의 급여·법정 안내 톤을 따라 단정적 표현을 쓰지 않고, 책임 한계 고지는 §3-7이 지정한 화면에 닫기 버튼 없이 상시 노출한다. 요율·세액·한도의 구체 수치는 어느 화면에도 박지 않고 전부 기준값 조회 결과로 렌더한다 — 확인되지 않은 기준값은 확정 값처럼 그리지 않고 차단된 상태를 그대로 보여준다. 데이터 연동의 메서드 경로는 [../06_api/01_conventions.md](../06_api/01_conventions.md)의 자원 명명·사업장 스코프·멱등 규약을 따르며, 표면 전수와 요청·응답 규격의 정본은 [../06_api/08_payroll.md](../06_api/08_payroll.md) · [../06_api/09_payslip.md](../06_api/09_payslip.md)다.

| 직원별 급여 기준 등록·수정 | 급여형태(시급·월급·일급)와 기본임금·고정수당·비과세 항목을 유효기간과 함께 등록한다. **급여형태별 단위를 검증한다** — 시급은 원/시 · 월급은 원/월 · 일급은 원/일이며 단위가 어긋난 값은 제출 전에 필드 오류로 막는다 | PAY-01 |
| 지급일 설정 | **지급일은 두 축을 한 문장으로 고른다 — 「익월 10일」처럼 달과 날짜를 함께 고르고 숫자만 받지 않는다.** 숫자만 받으면 사용자가 어느 달을 뜻했는지 화면에서 확인할 방법이 없고, 서버는 귀속월로 가정할 수밖에 없어 **익월 지급 사업장의 간이세액표 버전이 한 달 어긋난다.** 기본값은 익월이다(실무 다수). **지급일은 필수다.** 지급일이 없으면 간이세액표 버전을 고를 수 없어 소득세 계산이 성립하지 않으므로 저장 시점에 필수 검증하고, 누락 상태로 계산을 시도하면 payroll.missing_payroll_terms/422로 되돌아온다. 지급일이 영업일이 아니면 직전 영업일로, 그 달에 없는 날이면 말일로 **서버가 단일 규칙으로 보정**하며(REQ-PAY-04) 화면은 보정 결과를 **표시만** 한다 — 사업장 선택지가 아니다 | PAY-01 |
| 유효기간 겹침 차단 | 같은 직원의 급여 기준 기간이 겹치면 저장을 거부한다 — payroll.payroll_terms_overlap/409. 사전 확인을 통과했어도 최종 제출에서 충돌할 수 있으므로 **서버 판정 결과를 기간 필드로 되돌려 표시**한다(§3-3 경합 오류) | PAY-01 |
| 통상임금 산입 규칙 버전 표시 | 적용 중인 통상임금 판단 규칙 버전과 효력 시작일을 읽기 전용으로 보여준다. **2024-12-19 전원합의체 판결로 고정성 요건이 폐기되었고 판결은 장래효**이므로, 귀속 시점에 따라 다른 규칙 버전이 적용된다는 사실을 화면에서 밝힌다 | PAY-01 |
| 비과세 한도 관리 | 항목별 비과세 한도를 사업장 값으로 설정하되 **기준값의 공식 월 한도 이하만 허용**하고 초과 입력은 필드 오류로 막는다. 한도를 넘는 지급분은 **과세로 전환**되어 소득세 과세표준과 4대보험 보수에 반영된다는 사실을 항목 옆에 안내한다 | PAY-13 |
| 보험별 보수 포함 매핑 확인 | 비과세 항목이 보험별 보수에 포함되는지를 보험 4종 열로 나란히 보여준다. **하나의 과세표준을 네 보험에 공용하지 않는다**는 점과 건강보험 재포함 범위(소득세법 §12(3) 차목·파목·거목 3계열 — 확인 완료)를 함께 표기한다 | PAY-13 |

**주요 UI 요소**: 페이지 헤더(급여월 무관 · 기준일 선택기), 급여 항목 카탈로그 표(축 4열 · 인라인 편집 행), **직원 목록 표(이름·직위·재직 상태) + 선택 직원의 급여 기준 유효기간 이력 페인**(급여형태·기본임금·지급일·유효기간·상태), 기준 등록·수정 모달(단일 레이어 · 단계 전환), 비과세 한도 섹션, 보험별 보수 포함 매핑 표, 통상임금 규칙 버전 안내 배너.

**레이아웃·스크롤·모바일**: 페이지 헤더와 기준일 선택기는 스크롤 밖에 고정하고 스크롤 소유자는 본문 데이터 영역 하나로 둔다. 급여 항목 카탈로그 표와 보험별 보수 포함 매핑 표는 열이 많으므로 각각 자체 가로 스크롤 컨테이너를 갖고 첫 열(항목명)을 고정하며 **페이지 본문이 가로로 스크롤되지 않게 한다**. 768 미만에서는 사이드바가 걷히고 두 표가 항목당 카드 한 장으로 전환되어 축 4열이 카드 안 정의 목록이 되며, 기준 등록 모달은 전체 폭 시트로 바뀌되 내부 스크롤을 만들지 않고 단계 전환으로 수납한다.

**데이터 연동**

- 급여 항목 카탈로그 조회·등록·수정 → GET · POST · PATCH /v1/workplaces/{workplaceId}/pay-items/{payItemId} → **pay_items**
- 직원별 급여 기준 조회·등록·수정 → GET · POST · PATCH /v1/workplaces/{workplaceId}/employees/{employeeId}/payroll-terms/{termId} → **payroll_terms**
- 비과세 항목별 공식 월 한도·사업장 설정값·기준값 부재 여부 조회 → GET /v1/workplaces/{workplaceId}/pay-items/nontax-limits → **statutory_rates**(사업장 스코프 읽기). **플랫폼 기준값 표면(GET /v1/system/statutory-rates)을 이 화면에서 직접 호출하지 않는다** — 그 표면은 플랫폼 RBAC 축이고 사업장 관리자 화면이 넘을 경계가 아니다(SYS-RATES가 소비처다)
- 보험별 보수 포함 매핑과 통상임금 규칙 버전은 **화면이 따로 조회하지 않는다** — 미리보기·확정 응답의 라인마다 적용 기준값 행 식별자와 실제 값이 동결되어 오므로 그 값을 그대로 표시한다(D-17)
- **기본 정렬**: 직원 목록은 이름 오름차순이며 동률은 식별자 내림차순이다. 선택 직원의 유효기간 이력 페인은 유효 시작일 내림차순이다. 급여 항목 카탈로그는 **표시 순서 오름차순 · 코드 오름차순**(카탈로그성 목록 기본값)이다(§3-4)
- 상세 정본은 [../06_api/08_payroll.md](../06_api/08_payroll.md)다.

**담은 기능ID**: PAY-01 · PAY-13

**비고**: 건강보험 보수 재포함 범위(차목·파목·거목 3계열) · 보육수당 적용 단위(2026-01-01부터 자녀 1인당 월 20만원) · divisor 209(주 40시간 고시 공인)는 **확인 완료**됐다 — 화면은 확정값을 그대로 그리되, **기준값 행이 미등록인 항목은 §3-7 미확인 값 표기를 유지**한다(확인과 시드는 별개 단계다). 이 화면은 값을 확정하지 않고 계산 전제를 등록할 뿐이므로 되돌릴 수 없는 작업이 없다 — 다만 **확정된 급여가 참조한 급여 기준을 사후에 고쳐도 그 급여 결과는 변하지 않는다**(REQ-GLB-10 값 동결)는 사실을 수정 시점에 안내한다.

## ADM-PAYROLL-PREVIEW — 급여 미리보기

| 항목 | 내용 |

| 화면코드 | ADM-PAYROLL-PREVIEW |

**목적**: 확정하기 전에 직원별 예상 지급·공제·실수령과 불확실 요소를 검토해 확정 후 정정 부담을 줄인다.

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 미리보기 산출 | 급여월과 대상 직원 범위를 골라 예상 결과를 산출한다. **확정이 아니며 이 결과를 잠금·명세서·급여대장에 사용하지 않는다**는 사실을 결과 영역 상단에 상시 문안으로 둔다 | PAY-07 |
| 경고 목록 표시 | **차단 조건을 차단이 아니라 경고로 표시한다** — 미마감 근태 · 누락 보험 정보 · 기준값 누락 · 상시근로자 스냅샷 미확정을 각각 무엇이 불확실한지와 함께 목록으로 제시하고, 결과는 그대로 보여준다. 각 경고에 해당 조치 화면(ADM-ATTENDANCE-CLOSING · ADM-EMPLOYEE-DETAIL · ADM-EMPLOYEE-COUNT) 링크를 붙인다 | PAY-07 |
| 직원별 요약 표시 | **이 표면은 요약형이다**(D-2) — 미리보기 응답이 직원별로 담는 것은 계산 대상 제외 사유(excludedReason) · 지급 총액(grossPay) · 공제 총액(totalDeduction) · 실수령(netPay) · 전월 실수령(previousNetPay) · 전월 대비 차액(netPayDelta) · 그 직원 한정 경고뿐이다. **8버킷 시간 분해 · 법정수당 라인별 근거 · 4대보험 보수월액·요율 · 소득세 산출 단계는 이 표면에 없다** — 항목별 근거는 계산본(ADM-PAYROLL-RUN의 CALCULATED 상태 실행) 결과 상세가 답하며, 계산본도 확정 전이라 이 화면과 같은 뜻에서 되돌릴 수 있다. 화면은 근거를 지어내지 않고 계산본으로 가는 동선을 낸다. 직원 행은 **팝업이 아니라 목록 옆 항목 페인**으로 이 요약 필드를 편다 | PAY-02 · PAY-03 · PAY-04 · PAY-05 |
| 최저임금 경고 표시 | 최저임금 미달은 **전용 배지·필드가 아니라 경고 배열의 항목(code·detail)**으로 온다 — 화면은 detail 맵을 그대로 정의 목록으로 편다. **미리보기 단계에서는 경고이며 차단하지 않는다** — 차단은 확정 단계(ADM-PAYROLL-RUN)의 계약이다 | PAY-06 |
| 휴가 연동 반영 | 승인된 유급 휴가·무급 휴가·결근·연차미사용수당의 반영 결과는 **직원별 실수령 요약에 이미 합산돼 있을 뿐 지급 항목으로 분리해 보여주지 않는다** — 항목 라인 분리는 계산본의 계약이다. 연차 사용촉진 미지원 사실을 결과 근방에 표기한다 | LEV-06 |
| 전월 대비 변동 | 직원별 실수령의 전월 대비 증감(previousNetPay · netPayDelta)을 검토용으로 표시한다. **판정이 아니라 검토 보조**임을 문안으로 밝힌다 | PAY-07 |

**주요 UI 요소**: 급여월 선택기와 대상 범위 필터, 책임 한계 고지 배너(상시), 툴바 끝 ⓘ("확정이 아닙니다" 설명), 경고 목록 패널, 직원별 결과 표(지급·공제·실수령 요약) + 옆 항목 페인(선택 직원의 제외 사유·경고), 계산본(ADM-PAYROLL-RUN) 이동 링크.

**레이아웃·스크롤·모바일**: 목록+상세 페인(MD) 배치다. 급여월 선택기 · 필터 바 · 책임 한계 고지 배너 · 표 헤더 행은 스크롤 밖에 고정하고 직원별 결과 표와 옆 항목 페인이 각자 스크롤 소유자(ScrollRegion)다. 결과 표는 열이 많으므로 자체 가로 스크롤 컨테이너를 갖고 직원명 열을 고정한다. 1024 미만에서는 분할이 스택되어 결과 표가 직원당 카드 한 장으로 전환되고, 책임 한계 고지 배너는 화면 폭 전체를 쓰되 상단 고정 위치를 유지한다.

**레이아웃·스크롤·모바일**: 목록 화면은 필터 바와 표 헤더 행을 고정하고 표 본문만 스크롤한다. 상세 화면은 실행 헤더 · 상태 배지 · 하단 액션 바(확정 · 무효화)를 스크롤 밖에 고정하고 직원별 결과 표가 스크롤 소유자가 되며, 결과 표는 자체 가로 스크롤 컨테이너와 고정 첫 열을 갖는다. 확인 모달은 중첩하지 않고 **같은 모달의 단계 전환**으로 2단을 처리하며 내부 스크롤을 만들지 않는다 — 대상 인원이 많으면 요약 수치와 상위 몇 건만 담고 전체는 배경 표로 미룬다. 768 미만에서도 확정과 무효화를 끝낼 수 있어야 하므로 하단 액션 바를 유지하고, 결과 표는 직원당 카드로 전환하며 확인 모달은 전체 폭 시트가 된다.

"열람"은 열람 전이면 "미열람", 애초에 미교부면 "—"로 갈라 적는다. **앱 게시는 열람 가능한 상태로 입력된 때, 이메일은 발송된 때가 교부 성립 시점**임을 열 설명으로 밝히고, 직원이 열지 않아도 교부 의무는 이행된 상태임을 안내한다 | SLP-03 |

| 로딩 | 현황 표와 같은 행 구성의 스켈레톤을 깔고 일괄 발행 진행 중에는 진행률을 상태 영역으로 알린다 |
| 빈 상태 | 3분기다 — ① 전체 0건: "아직 발행된 명세서가 없습니다" + 확정된 급여 실행이 있으면 일괄 발행 CTA, 없으면 ADM-PAYROLL-RUN 안내 ② 권한: "열람할 수 있는 명세서가 없습니다" ③ 필터 0건: "조건에 맞는 명세서가 없습니다" + 필터 초기화 |
| 에러 | payslip.run_not_confirmed/409 → 대상 급여 실행이 확정 상태가 아님을 알리고 ADM-PAYROLL-RUN으로 잇는다 · payslip.missing_required_field/422 → **보완 항목 목록**을 렌더하고 각 입력 화면으로 잇는다 · payslip.generation_failed/422 → 실패 사유와 재생성 액션을 두고 급여 확정은 유지된다고 밝힌다 · payslip.bulk_in_progress/409 · payslip.bulk_conflict/409 · payslip.already_issued/409 → 각각 진행 중 · 키 충돌 · 이미 발행됨으로 구분해 안내한다 · payslip.download_token_expired/410 → 토큰 재발급 경로를 둔다 · payslip.correct_forbidden/403 → OWNER 전용임을 밝힌다 · workplace.verification_pending/409 → 검증 대기 사업장은 발행이 차단됨을 알린다 |
| 권한거부 | **404 위장(존재 비노출)**이다 — 명세서 조회 경로는 부재와 권한 부족을 구분하지 않고 payslip.not_found/404로 수렴시킨다. 403으로 답하면 그 명세서가 존재한다는 사실이 노출된다. 반면 관리 액션의 권한 부족(정정본 발행)은 payslip.correct_forbidden/403으로 사유를 밝힌다 |

**데이터 연동**

- 명세서 현황 조회 → GET /v1/workplaces/{workplaceId}/payslips(급여월 · 상태 필터) → **payslips** · **employees** · **documents**. 응답이 최초 열람 시각과 교부 채널 배열을 함께 낸다(신설 · B2) — 열람 전이거나 미교부면 그 필드가 생략된다
- 목록 내보내기: POST /v1/workplaces/{workplaceId}/list-exports(listType=payslips · 민감이라 사유 필수)로 조건에 맞는 전 행을 파일로 낸다. 화면의 근로시간 기재 한 열은 서버에서 근무일수·총 근로시간 두 열로 갈려 있어 보낼 때 풀어 보낸다
- 일괄 발행 → POST /v1/workplaces/{workplaceId}/payroll-runs/{payrollRunId}/payslips/bulk-issue(Idempotency-Key 필수 · 재발행 정책) → **payslips** · **batch_jobs**
- 진행률·실패 사유 조회 → GET /v1/workplaces/{workplaceId}/payslip-batches/{batchJobId} → **batch_jobs**
- 교부 이력 조회 → GET /v1/workplaces/{workplaceId}/payslips/{payslipId}/deliveries → **payslip_deliveries**
- 재발급 다운로드 → POST /v1/workplaces/{workplaceId}/payslips/{payslipId}/download-token 후 서버 스트리밍 → **payslip_deliveries** · **documents**
- 정정본 발행 → POST /v1/workplaces/{workplaceId}/payslips/{payslipId}/corrections(Idempotency-Key 필수 · 사유 필수) → **payslips**(supersedes 연결) · **audit_logs**
- **기본 정렬**: 발행 시각 내림차순 · 식별자 내림차순이며, 실패(FAILED) 건은 필터 없이도 목록 위로 올린다(§3-4)
- 상세 정본은 [../06_api/09_payslip.md](../06_api/09_payslip.md)다.

**담은 기능ID**: SLP-01 · SLP-02 · SLP-03 · SLP-04 · SLP-05 · SLP-07

**비고**: **생성과 교부는 다른 사건이고 주체도 다르다** — 생성(GENERATED)은 급여 확정이 거는 자동 파이프라인의 끝이고, 교부(DELIVERED · ISSUED)는 관리자가 이 화면에서 일으키는 게시 행위다. 그래서 GENERATED 상태의 명세서는 "PDF는 있으나 아직 게시 전"이며 직원 화면에서도 미교부로 보인다. 두 사건을 한 트랜잭션으로 묶지 않는 이유는 **법정 필수항목 검증 결과를 사람이 확인한 뒤에 교부가 성립해야** 누락 상태 교부를 막을 수 있기 때문이다. **교부는 법정 사건이므로 화면 표시가 사실보다 앞서면 안 된다** — 낙관적 갱신을 쓰지 않고 서버 확정 후에만 상태를 갱신한다(§3-6). 발행 알림(SLP-06)은 서버가 발화하는 부수효과라 이 화면의 기능 표에 두지 않으며, 직원이 수신을 거부해도 법정 교부 알림은 생략되지 않는다. 원본 급여 실행이 무효화되는 시점에 대기·실패 상태인 명세서는 생성을 중단하고 실패로 고정되므로, 그 사유를 실패 목록에서 구분해 표시한다.

## ADM-SEVERANCE — 퇴직 정산·금품청산

| 항목 | 내용 |
|------|------|
| 화면코드 | ADM-SEVERANCE |
| 라우트 | web_front SPA /payroll/severance |
| 접근권한 | MANAGER |
| 우선순위 | P1 |

**목적**: 퇴직자의 퇴직금 대상 여부와 개산액을 확인하고 퇴직일 + 14일 금품청산 기한 안에 미지급 항목을 정리한다.

**진입경로**: 사이드바 급여·명세서 > 퇴직 정산 · ADM-EMPLOYEE-RESIGN 퇴사 처리 완료 후 다음 단계 링크 · ADM-DEADLINE-CALENDAR의 금품청산·퇴직금 지급 기한 항목 바로가기 · 기한 임박 알림 바로가기.

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 퇴직금 대상 판정 | **계속근로 1년 이상 + 4주 평균 주 15시간 이상**을 충족하는지 판정 결과와 판정 근거(계속근로기간 · 4주 평균 소정근로시간)를 함께 보여준다. **5인 미만을 포함한 전 사업장 의무**임을 화면에 명시해 규모로 오해되지 않게 한다 | PAY-11 |
| 비대상 사유 명시 | 비대상이면 어느 요건을 못 채웠는지 사유를 명시한다. 사유 없이 "대상 아님"만 적지 않는다 | PAY-11 |
| 개산액 산출·표시 | 평균임금(일액)과 재직일수를 함께 보이고 개산액을 산출한다. **1일 통상임금이 평균임금 일액보다 크면** 그것을 하한으로 삼았다는 사실을 근거로 표시한다. **개산액임을 결과에 명시하고 사업주 확인을 요구**한다 — 상여 안분 등 정밀 산정은 v1 범위 밖임을 함께 적는다 | PAY-11 |
| 산정 원천 부재 차단 | 산정에 필요한 확정 급여가 없으면 개산액을 만들지 않고 차단한다 — payroll.severance_source_missing/409. 어떤 급여월의 확정이 빠졌는지 지목하고 ADM-PAYROLL-RUN으로 잇는다 | PAY-11 |
| 금품청산 14일 시계 | **퇴직일 + 14일** 마감시계를 남은 일수와 함께 보여준다. 기한이 임박하거나 경과하면 목록에서 우선 노출하고 경보를 표시하되 사용자를 탓하지 않는 문안으로 기준·현재 값·다음 행동을 적는다 | PAY-19 |
| 미지급 항목 체크리스트 | **임금 · 퇴직금 · 연차미사용수당** 세 항목의 지급 여부를 체크리스트로 관리한다. 각 항목의 산출 근거 화면(ADM-PAYROLL-RUN · ADM-PAYROLL-LEDGER)으로 잇는다 | PAY-19 |
| 퇴직금 지급 기한 병기 | 퇴직금 지급 기한도 퇴직일 + 14일이라는 사실을 금품청산과 같은 행에 병기해 두 시계를 따로 관리하다 놓치는 일이 없게 한다 | PAY-19 |

**주요 UI 요소**: 퇴직자 목록 표(퇴직일·대상 판정·개산액·기한 잔여일·청산 상태), 기한 임박·경과 경보 배너, 퇴직자 상세 패널(판정 근거 · 평균임금 산출 근거 · 개산액 · 사업주 확인 체크), 미지급 항목 체크리스트, 산정 원천 부재 안내 카드, 책임 한계 고지 배너(상시).

**레이아웃·스크롤·모바일**: 기한 경보 배너와 필터 바 · 표 헤더 행을 스크롤 밖에 고정하고 퇴직자 목록 표만 스크롤한다. 상세 패널은 새 오버레이 레이어를 만들지 않고 목록 옆 2단 배치의 우측 영역으로 열며, 그 영역이 자체 스크롤 소유자가 된다. 768 미만에서는 2단 배치를 1열로 접어 목록 → 상세 순서로 쌓고, 기한 잔여일은 카드 상단에 고정 배지로 남겨 스크롤 위치와 무관하게 보이게 한다.

**데이터 연동**

- 퇴직 정산 대상 목록·상세 조회 → GET /v1/workplaces/{workplaceId}/employees/{employeeId}/severance → **severance_assessments** · **employees** · **payroll_employee_results**
- 퇴직금 판정·개산액 산출 → POST /v1/workplaces/{workplaceId}/employees/{employeeId}/severance/assess(대상 직원 · 기준일) → **severance_assessments**
- 금품청산 기한 과제·체크리스트 조회 → GET /v1/workplaces/{workplaceId}/compliance-tasks(유형 필터) · 완료 → POST /v1/workplaces/{workplaceId}/compliance-tasks/{taskId}/complete · 면제 → POST /v1/workplaces/{workplaceId}/compliance-tasks/{taskId}/waive → **compliance_tasks**
- **기본 정렬**: 기한 잔여일 오름차순(임박한 건이 위) → 퇴직일 내림차순이며 동률은 식별자 내림차순이다(§3-4)

**비고**: **금품청산은 소상공인이 가장 자주 어기는 조항**이라 이 화면의 가치는 계산이 아니라 인지에 있다 — 그래서 기한 잔여일을 목록의 1차 정렬 축으로 두고 경과 건을 맨 위에 올린다. 개산액은 **확정 금액이 아니므로 확정처럼 보이는 표기를 쓰지 않는다**(§3-7 급여·법정 안내) — 사업주 확인 체크를 통과하기 전에는 지급 실행 동선을 열지 않는다. 기한 감지는 정기작업이 담당하며 이 화면은 그 결과를 읽는 표면이다.
