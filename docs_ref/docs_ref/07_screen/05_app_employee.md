직원 앱은 **STAFF의 본인 데이터 표면**이다. 열람·수정 범위가 본인뿐이며 승인·확정·인사 수정 표면을 두지 않는다 — STAFF는 요청을 제출하고 본인 결과를 조회하는 축까지다. 9본 중 8본은 드로어 5섹션(홈 · 근무 · 급여 · 알림 · 내 정보)에 배치되고 명세서 열람(APP-PAYSLIP) 1본만 급여 화면 위의 스택 하위이며, 초대 수락(APP-INVITE)만 드로어 밖 인증 스택에 있다(내비게이션 정본 [01_standards.md](./01_standards.md) §4-2 · 인증 스택 정본 [04_auth_onboarding.md](./04_auth_onboarding.md)).

**본인 소유권 인가가 이 표면의 특징**이다. 명세서·급여 이력·근로계약 세 화면은 사업장 멤버십이 아니라 직원 레코드의 사용자 식별자로 인가하므로, **퇴사·사업장 폐쇄 후에도 보존기간 내 열람이 끊기지 않는다**(CMP-07). 사업장 컨텍스트가 없는 상태에서도 이 세 화면에 도달할 수 있어야 한다.

**v1은 오프라인 기록을 지원하지 않는다**(ATT-14 이월). 네트워크 실패를 큐에 쌓아 나중에 보내지 않고 실패를 즉시 표시하며 재시도 액션만 둔다 — 큐에 쌓은 뒤 실패하면 근무는 했는데 기록이 없는 상태가 조용히 만들어진다. **푸시 알림도 v1에 없으므로**(NTF-02 이월) 알림은 앱을 열었을 때 도착하고, 명세서 교부처럼 도달이 법정 의무인 통지는 이메일 대체 경로(SLP-06)가 담당한다.

## APP-CHECKIN — 출퇴근 체크인(홈)

| 항목 | 내용 |
|------|------|
| 화면코드 | APP-CHECKIN |
| 라우트 | app_front 드로어 홈 > Checkin(드로어 초기 화면) |
| 접근권한 | STAFF — 본인 체크인만 한다. **위치정보 별도 동의가 선행**한다 |
| 우선순위 | P1 |

**목적**: 근무지에서 출근·퇴근을 찍고 휴게를 기록해 급여 계산의 원천 데이터를 만든다.

**진입경로**: 앱 실행 직후 드로어 초기 화면 · 드로어 홈 > 출퇴근 항목 · 근태 이상 알림의 바로가기.

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 출근·퇴근 체크인 | 큰 단일 버튼으로 현재 상태에 맞는 액션(출근 또는 퇴근)을 낸다. **시각은 서버가 찍고** 기기 시각은 별도로 전송해 차이를 위험 판정 입력으로 쓴다. 순서 검증이 셋을 막는다 — 같은 근무일 미퇴근 상태의 중복 출근 · 출근 없는 퇴근 · 퇴근이 출근보다 이른 기록 | ATT-01 |
| 지오펜스 재검증 | 좌표를 전송하면 **서버가 근무지 좌표와 반경으로 거리를 다시 계산**한다. 클라이언트 판정을 결과로 쓰지 않으며, 화면은 서버 판정 전까지 성공을 그리지 않는다 | ATT-02 |
| 현재 위치 상태 표시 | 근무지까지의 거리와 허용 반경을 보인다. 반경 안이면 버튼을 열고 밖이면 거리와 함께 사유를 보인다. **정확도 한계값을 넘긴 경우는 차단하지 않고 대기 저장 안내**를 보인다 | ATT-02 |
| 휴게 시작·종료 | 출근 후 휴게 시작·종료를 기록한다. 출근 전·퇴근 후 휴게와 중복 시작을 막는다. **실근로분 = 재실분 − 휴게분**이며 오늘 누적 휴게 시간을 함께 보인다 | ATT-03 |
| 휴게 부여 안내 | 실근로가 4시간·8시간 경계에 가까워지면 법정 최소 휴게(4시간 이상 8시간 미만 30분 · 8시간 이상 60분)를 안내한다. **판정과 마감 차단은 서버가 하며 이 안내는 사전 알림**이다 | ATT-12(안내) |
| 오늘 근무 요약 | 출근 시각 · 퇴근 시각 · 재실 시간 · 휴게 시간 · 현재 상태를 보인다. 근무 스케줄이 있으면 예정 시각과 나란히 놓는다 | ATT-01 · ATT-04(결과 표시) |
| 미퇴근 보정 유도 | 전일 미퇴근 레코드가 남아 있으면 상단에 배너로 알리고 근태 수정 요청 경로를 안내한다 | ATT-01 · ATT-06(진입점) |

**주요 UI 요소**: 상단 사업장·이름 표시, 오늘 날짜와 현재 시각, 위치 상태 카드(거리 · 허용 반경 · 정확도), 대형 체크인 버튼, 휴게 시작·종료 버튼, 오늘 요약 카드, 미퇴근 배너, 위치 권한 안내 카드.

**레이아웃·스크롤·모바일**: 본문이 스크롤 소유자이며 **대형 체크인 버튼은 하단 안전 영역 위에 고정**해 스크롤과 무관하게 항상 도달 가능하게 한다. 터치 타깃은 최소 44포인트이며 체크인 버튼은 그보다 크게 잡는다. 위치 상태 카드는 값이 갱신될 때 레이아웃이 흔들리지 않도록 높이를 고정한다. 백 제스처는 드로어 초기 화면이라 해당 없으며, 체크인 제출 중에는 드로어 이동을 막지 않되 버튼만 잠근다.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 오늘 요약과 위치 상태 카드 자리를 잡는 스켈레톤을 보이고 체크인 버튼은 비활성 상태로 자리만 잡는다. 위치 측정 중에는 카드 안에서만 진행 표시를 돌린다 |
| 빈 상태 | 오늘 체크인 기록이 없으면 요약 카드에 "아직 출근 기록이 없습니다"와 체크인 안내를 둔다. 이는 정상 시작 상태이므로 오류처럼 보이지 않게 한다 |
| 에러 | attendance.invalid_sequence/409는 "이미 출근 기록이 있습니다" 등 순서별 문안과 오늘 요약 갱신 · attendance.out_of_geofence/422는 **현재 거리와 허용 반경을 함께** 보이고 근태 수정 요청 경로 안내 · attendance.accuracy_too_low/422는 "위치를 확인하지 못했습니다"와 재시도 · privacy.location_consent_required/403은 동의 화면(PUB-CONSENT)으로 유도 · **네트워크 실패는 즉시 표시하고 재시도 버튼만 둔다**(큐에 쌓지 않는다) |
| 권한거부 | **권한 안내**다 — 위치정보 미동의는 차단이 아니라 동의 유도로, 기기 위치 권한 거부는 오류 배너가 아니라 안내 카드와 설정 이동 경로로 처리한다. 세부 규격은 [01_standards.md](./01_standards.md) §5-5가 정본이다 |

**데이터 연동**

- 오늘 상태 조회 → GET /v1/me/attendance/current → **attendance_records** · **attendance_breaks** · **work_schedules**. 출근 → POST /v1/workplaces/{workplaceId}/attendance/clock-in · 퇴근 → POST /v1/workplaces/{workplaceId}/attendance/clock-out → **attendance_records** · **location_usage_records**(확인자료 선행 기록). 휴게 → POST /v1/workplaces/{workplaceId}/attendance/breaks/start · POST /v1/workplaces/{workplaceId}/attendance/breaks/end → **attendance_breaks**. **낙관적 갱신 없음** — 시각과 지오펜스를 서버가 판정하므로 성공을 먼저 그리면 반경 밖 체크인이 성공한 것처럼 보인다. 상세 정본은 [../06_api/06_attendance.md](../06_api/06_attendance.md)다.

**담은 기능ID**: ATT-01 · ATT-02 · ATT-03 · ATT-12(안내) · ATT-04(결과 표시) · ATT-06(진입점)

**비고**: **위치 확인자료 기록은 처리의 필수 선행 단계**이며 기록에 실패하면 체크인 처리를 중단한다(PRV-01). 화면에는 이 단계가 드러나지 않지만 실패 시 체크인이 성공하지 않으므로, 원인 불명의 실패에는 재시도와 관리자 문의 경로를 함께 둔다. **모의위치 의심·기기와 서버의 시각 차이·비정상 이동거리는 차단하지 않고 위험 플래그로만 기록**하며 직원 화면에 경고를 띄우지 않는다 — 오탐이 정상 근로자의 기록을 막으면 안 되기 때문이고, 플래그는 관리자 화면(ADM-ATTENDANCE)에만 드러난다.

## APP-ATTENDANCE — 내 근태 내역

| 항목 | 내용 |
|------|------|
| 화면코드 | APP-ATTENDANCE |
| 라우트 | app_front 드로어 근무 > Attendance |
| 접근권한 | STAFF — 본인 근태만 조회한다 |
| 우선순위 | P1 |

**목적**: 월별 근태 판정과 집계를 확인하고 틀린 기록에 수정 요청을 낸다.

**진입경로**: 드로어 근무 > 근무 기록 항목 · APP-CHECKIN의 미퇴근 배너 · 근태 승인·반려 알림의 바로가기.

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 월별 근태 목록 | 근무일별 출근·퇴근 시각 · 재실 · 휴게 · 실근로 시간과 **판정 8종**(정상 · 지각 · 조퇴 · 결근 · 미퇴근 · 휴가 · 휴일 · 주휴일)을 보인다. 판정은 **텍스트 라벨과 함께** 표시하고 색만으로 가르지 않는다 | ATT-04 |
| 시간 집계 표시 | 월 누적 실근로 시간과 **연장 · 야간 · 휴일 시간**을 보인다. 8버킷 분해의 상세는 관리자 화면이 담당하며 앱은 사용자가 읽을 수 있는 축(소정 · 연장 · 야간 · 휴일)으로 묶어 보인다 | ATT-05 |
| 5인 미만 표기 | 사업장이 5인 미만 기간이면 **가산이 적용되지 않는다는 사실과 근거**를 함께 표기한다. 실근로 시간은 그대로 집계되며 가산만 없다는 점을 밝힌다 | ATT-05 |
| 휴게 상세 | 일자별 휴게 시작·종료와 합계를 보인다. 법정 최소 휴게 미달인 날은 사유와 함께 표시하되 **직원이 조치할 수 없는 상태이므로 관리자 문의 경로만** 안내한다 | ATT-03 · ATT-12(표시) |
| 수정 요청 제출 | 대상 일자 · 요청 출퇴근 시각 · 사유 · 증빙을 제출한다. **동일 일자의 대기 요청은 1건만** 허용하며 이미 있으면 기존 요청으로 안내한다 | ATT-06 |
| 요청 상태 추적 | 제출한 요청의 상태(대기 · 승인 · 반려 · 취소)와 처리 사유를 보인다. 대기 중 요청은 취소할 수 있다 | ATT-06 |
| 마감 표시 | 마감된 기간은 잠금 표시를 하고 수정 요청 버튼을 감춘다. 마감 후에는 원본이 급여의 확정 입력이 되므로 변경할 수 없음을 안내한다 | ATT-08(표시) |

**주요 UI 요소**: 월 이동 헤더, 월 요약 카드(실근로 · 연장 · 야간 · 휴일 · 결근·지각 건수), 일자 목록(판정 배지 · 시각 · 실근로), 일자 상세 시트, 수정 요청 폼 시트, 요청 상태 목록, 마감 잠금 배너, 5인 미만 안내 블록.

**레이아웃·스크롤·모바일**: 본문이 스크롤 소유자이며 월 이동 헤더와 월 요약 카드를 스크롤 안에서 상단에 붙인다. 일자 목록 행 전체를 터치 영역으로 넓혀 44포인트를 확보하고, 상세와 수정 요청은 **바텀 시트 한 레이어**로 열며 시트 안에 스크롤을 만들지 않는다(§3-1) — 넘치면 단계 전환으로 나눈다. 시트 안 제출 중에는 백 제스처로 닫히지 않게 잠그고 그 사실을 표시한다.

**상태 처리**

| 상태 | 처리 |

**비고**: **급여 이력을 사업장 RBAC로만 막으면 퇴사 순간 본인 급여 이력에 접근할 수 없게 된다** — 그래서 인가 조건은 직원 레코드의 사용자 식별자와 요청자의 일치 하나뿐이고 멤버십의 존재·상태를 요구하지 않는다. **쓰기·재발행은 불가**하며 이 화면에는 어떤 변경 액션도 두지 않는다. 계산 근거를 화면에 보이되 **클라이언트가 금액을 재계산하지 않는다** — 서버가 내려준 동결 값을 그대로 렌더한다.

| 바로가기 | 알림별 딥링크로 해당 화면에 들어간다. 클라이언트는 **알 수 없는 타입을 안전한 기본 UI로 표시**하고 딥링크가 없으면 목록에 머문다 | NTF-04(소비) |

**레이아웃·스크롤·모바일**: 본문이 스크롤 소유자이며 사업장 필터 칩과 모두 읽음 액션을 상단에 붙인다. 알림 행 전체를 터치 영역으로 넓혀 44포인트를 확보하고 행 안에 보조 액션 버튼을 겹치지 않게 한다. 상세는 바텀 시트 한 레이어이며 시트 안에 스크롤을 만들지 않고 본문이 길면 원 화면으로 보낸다(§3-1). 상대 시각은 수신자 시간대 기준이며 화면이 열려 있는 동안 갱신한다.

**상태 처리**

| 상태 | 처리 |
|------|------|

- **기본 정렬**: 수신 시각 내림차순이며 **동률은 식별자 내림차순**이다 — §3-4 전역 기본값을 그대로 쓴다. 커서 방식이라 동률 고정이 없으면 쪽을 넘길 때 행이 흘러 사라진다

**담은 기능ID**: NTF-01 · NTF-03 · NTF-04(소비) · SLP-06(수신 표면)

**비고**: **알림 본문에 급여·개인정보 상세를 담지 않는다** — 알림은 잠금화면·미리보기에 노출되므로 금액이 그대로 새어 나간다. 본문은 사건과 링크만 담고 상세는 인가를 통과한 화면에서 본다. **v1에는 알림 삭제와 수신 설정이 없다**(NTF-05 · NTF-06 이월) — 이 화면에 삭제 액션과 설정 진입점을 두지 않고 부정형으로만 언급한다. **관리자 웹에는 독립 알림함 화면을 두지 않으며** 헤더 알림 벨 오버레이가 같은 목록을 제공한다(규격 정본 [01_standards.md](./01_standards.md) §4-1).

| 전문 보기 | 각 문서의 활성 버전 원문(PUB-LEGAL)으로 이동한다 | SYS-11(진입점) |

**주요 UI 요소**: 동의 현황 카드 3장(종류 · 동의 버전 · 동의 시각 · 철회 시각 · 전문 보기), 위치정보 동의 토글과 확인 단계, 재동의 안내 배너, 이용내역 필터(기간), 이용내역 목록(일시 · 목적 · 주체 · 경로), 더 불러오기 버튼, 보존 정책 안내 블록.

**레이아웃·스크롤·모바일**: 본문이 스크롤 소유자이며 동의 현황 카드를 상단에 두고 이용내역 목록을 아래에 쌓는다. 이용내역은 목록만 커서로 잇고 더 불러오기 버튼을 목록 아래 둔다(§3-4) — 목록 자체에 내부 스크롤을 만들지 않아 이중 스크롤을 피한다. 위치정보 철회 확인은 같은 화면 안의 인라인 확인 줄로 처리하고 새 레이어를 만들지 않는다(§3-1).

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 동의 카드 3장과 이용내역 행 5개 높이의 스켈레톤을 보인다 |
| 빈 상태 | **3분기다** — ① 이용내역 0건: "위치정보 이용 기록이 없습니다"와 GPS 체크인을 하면 기록된다는 안내 ② 기간 필터 결과 0건: "이 기간에 기록이 없습니다"와 필터 초기화 ③ 위치정보 미동의: 이용내역 대신 "동의하지 않아 수집된 기록이 없습니다"를 보인다 |
| 에러 | 조회 실패는 "기록을 불러오지 못했습니다"와 다시 시도 · privacy.consent_version_conflict/409는 오류로 표시하지 않고 완료로 수렴시킨다 · system.terms_not_found/404는 "문서를 준비 중입니다"와 문의 경로를 낸다 |
| 권한거부 | **권한 안내**다 — 본인 이력만 조회 대상이므로 타인 기록에 도달할 경로가 없다. 미인증은 **로그인 유도**로 되돌린다(§1-2) |

**데이터 연동**

- 동의 이력 조회 → GET /v1/me/consents → **user_consents** · **terms_documents**. 재동의 대기 조회 → GET /v1/me/consents/pending. 위치정보 동의·철회 → POST /v1/me/consents · POST /v1/me/consents/{consentId}/revoke → **user_consents**(철회 시각만 추가 · 행 삭제 없음). 이용내역 조회 → GET /v1/me/location-usage-records → **location_usage_records**. **낙관적 갱신 없음.** 상세 정본은 [../06_api/15_privacy.md](../06_api/15_privacy.md)다.

**담은 기능ID**: PRV-01(본인 조회) · PRV-02 · SYS-11(진입점·연계)

**비고**: **확인자료 자동 기록 자체는 화면이 없는 서버 전용 처리**이며 이 화면은 **정보주체 본인 조회 경로**만 담당한다 — 위치정보법 §16②이 기록·보존을 의무로 두고, 정보주체가 자기 기록을 확인할 수 있어야 그 의무가 실질적으로 작동한다. **동의 이력은 append-only**이므로 철회해도 행이 지워지지 않고 철회 시각만 더해진다 — 동의했던 사실과 철회한 사실이 모두 증거이기 때문이다.
