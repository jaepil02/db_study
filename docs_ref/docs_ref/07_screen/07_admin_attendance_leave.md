# 07. 관리자 웹 — 근태·휴가 (ADM)

> **대상**: ADM-SCHEDULE · ADM-ATTENDANCE · ADM-ATTENDANCE-APPROVAL · ADM-ATTENDANCE-CLOSING · ADM-LEAVE-APPROVAL · ADM-LEAVE-BALANCE (6본)
> **작성일**: 2026-08-03
> **개정일**: 2026-09-17 — Phase 3 교차 검수 수정 반영. ADM-ATTENDANCE 보기 전환(일자별 표 ⇄ 월간 출근부)과 칸 선택 해제를 **한 번의 쿼리 쓰기**로 합친다(둘로 나눠 쓰던 동안 둘째 쓰기가 전환을 덮어 월간 출근부를 눌러도 일자별 표에 머물렀다). 합계 행을 "기간 합계 · N건"(행 수)으로, 가산 근거 없음 고지를 "근무일 N일의"(서로 다른 근무일 수)로, ADM-ATTENDANCE-CLOSING 요약 줄을 "근태 기록 N건"으로 고친다 — 직원 × 근무일 행 수를 날짜처럼 적지 않는다. 일자별 행 펼침의 출처를 기록이 없는 날에는 판정 사유로 적고(휴가 승인 · 출근 간주 보호 기간 · 기록 없음 — 서버 코드를 내지 않는다) 편성을 편성 · 편성 휴게 두 필드로 가르며 "미기록"은 출근했는데 퇴근이 없는 날에만 쓴다(기록 없는 휴가일은 출근 · 퇴근 둘 다 —). ADM-SCHEDULE 편성 칸을 시간 범위 한 값으로 줄이고(휴게는 칸 이름과 설명) 격자 열 폭을 격자가 정한다 — 고정 열 넷을 뺀 자리를 일자 열이 똑같이 나누고(최소 3rem) 격자 자리가 좁으면 짧은 글자(09–18)를 쓴다. 1280 주 보기가 일요일까지 가로 스크롤 없이 서고 2560 월 보기가 한 달 전체를 세우며 그보다 좁은 월 보기만 격자 안에서 가로로 스크롤한다. 근태 현황 플래그 열 · 근태 수정 승인 대리 제출 · 증빙 · 처리 제약 · 휴가 승인 증빙 · 잔여 · 예약 · 연차 적용은 **불러온 행 전부가 빈 열이면 먼저 접힌다**(우선순위 3 · 연차 현황 표시 열과 같은 동적 판정). 근태 수정 승인 상태 탭은 고른 탭의 건수(표 N건과 같은 값)와 0건 숫자를 내지 않고 넓은 자리의 버튼만 남은 행 펼침은 테두리 상자 없이 처리 줄만 둔다. ADM-LEAVE-APPROVAL 페인 머리의 상태 배지는 목록 상태 열이 보이면 내지 않고(스택 · 카드일 때만) 일괄 작업 바는 2건 이상일 때만 선다 — 1건만 고르면 그 신청을 페인에 연다(스택에서는 1건도 바). 처리 시각을 목록과 같은 날짜 표기로 적는다. ADM-ATTENDANCE-CLOSING 차단 항목의 해소 링크는 보이는 글자가 "열기"이고 접근 이름이 일자 · 대상 · 사유를 싣는다. ADM-LEAVE-BALANCE ⓘ를 사업주가 읽는 말로 고치고(내부 용어를 두지 않는다) 발생 표의 차감 건수 · 근속 연차(1년 미만 발생분은 "1년 미만")를 일수 열과 단위가 섞이지 않게 적는다. **화면 수 · 화면코드 · 라우트 · 권한 · 담은 기능ID는 전건 불변**
> **개정일**: 2026-09-17 — ADM-LEAVE-APPROVAL 검토 페인도 **목록 표가 지금 보이지 않게 둔 열의 값만** 낸다(표가 알리는 보이지 않는 열 · 스택에서는 목록이 덮이므로 전부). 걷힌 열은 신청 내용 탭(사유 · 증빙 문서 경로 · 기간 · 일수 · 신청일 · 대기)과 잔액·근태 탭(사용 가능 잔여 · 신청자 예약 합계 · 연차 적용)의 접힌 열 묶음에 서고, 페인 머리(신청자 · 유형 · 상태)와 페인 고유 값(반차 시간대 · 같은 기간 다른 휴가 · 처리 시각 · 처리 의견 · 이 신청의 예약 · 차감하지 않는 유형 · 연차 원장)은 늘 선다. **화면 수 · 화면코드 · 라우트 · 권한 · 담은 기능ID는 전건 불변**
> **개정일**: 2026-09-17 — 행 펼침이 **지금 보이지 않는 열**만 받는 공통 계약(frontend-architecture §7) 반영. ADM-ATTENDANCE-APPROVAL · ADM-ATTENDANCE(일자별 표) · ADM-LEAVE-BALANCE의 행 펼침은 맨 위 "접힌 열" 한 묶음(라벨 · 값)에 **자리가 모자라 걷히거나 사용자가 끈 열의 값만** 내고(카드 모드는 카드에 없는 열만) 보이는 열의 값은 되풀이하지 않는다. 그래서 좁은 폭에서는 걷힌 값이 펼침에 서고 넓은 폭에서는 펼침이 행과 겹치지 않는다. 근태 현황 일자별 행 펼침의 8버킷 분해 탭을 걷는다(버킷 · 검산은 열이거나 접힌 열 묶음 한 자리 — 월간 출근부 옆 페인은 그대로 둔다). 근태 수정 승인 펼침은 사유 전문을 되풀이하지 않고(말줄임된 사유는 설명으로 전문) 처리 이력을 처리자 · 처리 시각 · 처리 사유 칸으로 가르며 보일 내용이 없으면 처리 줄만 둔다. **화면 수 · 화면코드 · 라우트 · 권한 · 담은 기능ID는 전건 불변**
> **개정일**: 2026-09-17 — 담당 6화면 자체 검수(1280 · 1440 · 1920 · 2560) 반영. **펼친 자리 · 목록형 구획은 행에 없는 값만 두고 표처럼 읽힌다.** ADM-ATTENDANCE-CLOSING 차단 항목을 일자 · 대상 · 해소 링크 세 칸 격자로, 한도 경고를 기간 · 직원 · 기준 · 실적 · 초과 표로, 전이 이력을 시각 · 전이 · 행위자 · 사유 표로 가르고, 차단 0건의 "차단 사유가 없습니다"와 마감 · 종결된 달의 설명 한 줄 차단 구획을 걷는다(재검사하지 않는 이유는 ⓘ · 검사 중에는 자리 스켈레톤). ADM-ATTENDANCE 일자별 표의 행 펼침은 행의 열(근무일 · 판정 · 직위 · 출퇴근 · 재실 · 휴게 · 실근로)을 되풀이하지 않고 편성 · 출처 · 가산(적용되지 않을 때만 — 판정 근거 없음 · 5인 미만) · 보정 사유만 둔다(월간 출근부 옆 페인은 칸이 약어뿐이라 전부 낸다). 가산 · 스케줄 없음 설명 고지를 걷는다. ADM-ATTENDANCE-APPROVAL 행 펼침은 머리 줄(이름 · 일자 · 요청 시각 · 상태) · 현재값·요청값 대조 카드 · 대상 직원 · 본인 제출 · 처리 불가 · 중복 대기 고지를 걷고 요청 사유 전문 · 처리 이력 · 증빙 미리보기(있을 때만)와 처리 단계만 둔다 — 막힌 승인은 비활성 + 사유(설명). ADM-LEAVE-BALANCE 행 펼침의 요약 잔액 탭을 걷고(행과 같은 값) 복원 · 조정(0이 아닐 때) · 임포트 적재분(있을 때)만 위에 두며 발생 · 원장을 표로 가른다. 임박 소멸의 만료일을 응답 필드 expiresOn으로 읽는다(expiresAt으로 읽어 늘 "만료일 미정"이던 결함). ADM-LEAVE-APPROVAL 검토 페인 신청 내용에서 목록 행과 같은 기간 · 일수와 "첨부 없음"을 걷고(반차 시간대 · 증빙 링크는 있을 때만) 연차를 차감하지 않는 유형의 연차 적용 칸을 "해당 없음" 문장 대신 "—"로 둔다. 잔액·근태 탭의 "지금 잔여 · 이 신청의 예약 · 신청" 한 줄을 사용 가능 잔여 · 신청자 예약 합계 · 이 신청의 예약 칸으로 가른다. ADM-SCHEDULE 스케줄 없음 고지의 편성 버튼을 걷고(맨 위 행 이름이 같은 폼을 연다) 표식 툴팁을 대상 · 미비 서류만으로 줄이며, 직원 열을 내용 폭으로 둬 넓은 화면의 이름 잘림을 없애고 월 보기 기간을 "2026년 9월"로 적는다. **화면 수 · 화면코드 · 라우트 · 권한 · 담은 기능ID는 전건 불변**
> **개정일**: 2026-09-17 — 사용자 실측 검토 반영 다섯째. ADM-ATTENDANCE 요약 줄에서 **실근로 합계 · 연장 · 야간을 걷는다**(기간 합계 행이 정본) — 요약 줄은 합계 행에 없는 건수만 0이 아닐 때 내고 남는 것이 없으면 줄이 없다. 가산 고지는 **근거 연결을 먼저 본다** — 서버는 적용할 상시근로자 스냅샷이 없으면 가산 대상 플래그를 false로 두고 근거를 비우므로, 그 false를 5인 미만으로 읽어 기간 끝 스냅샷과 짝짓던 모순("5인 미만" 고지 + "평균 11명" 근거)을 바로잡아 근거 없는 일 집계가 있으면 "판정 근거 없음" 고지를 낸다(행 펼침 상세도 같고 재직 명부 인원을 상시근로자 수로 적지 않는다). ADM-ATTENDANCE-CLOSING은 차단 총계 한 줄 고지를 걷고(차단 구획 · 비활성 근태 마감 버튼의 사유가 전한다) 사유 카드 설명 줄을 제목 옆 ⓘ로 옮기며, 하단 실행 액션 바는 **지금 상태에서 성립하는 전이만** 낸다(미마감 · 재오픈 → 근태 마감 / 마감 → 마감 취소 · 오입력 종결 / 종결 → 없음 · 권한 부족만 비활성 + 사유). ADM-LEAVE-APPROVAL 상태 선택기 이름의 전체 건수를 걷고(표 우상단 N건 한 자리) 같은 기간 다른 휴가는 겹치는 사람이 있을 때만 둔다. ADM-LEAVE-BALANCE 표시 열은 표시할 것이 한 행도 없으면 열 자체를 두지 않는다. **화면 수 · 화면코드 · 라우트 · 권한 · 담은 기능ID는 전건 불변**
> **개정일**: 2026-09-17 — 사용자 실측 검토 반영 넷째 · 서버가 새로 싣는 값 반영. ADM-ATTENDANCE-APPROVAL에 **현재 시각 열**(그 날 현재 기록의 최초 출근 ~ 최종 퇴근 · #12 항목)을 요청 시각 앞에 둔다. ADM-LEAVE-APPROVAL 목록에 **사유 · 증빙 열**(#3 항목 — 사유는 둘째 글자 열이라 자리가 남을 때만)을 더하고 잔여 · 예약을 신청 목록 항목의 서버 값(차감 유형에만)으로 바꾸며 예약 0일은 기본 글자색이다. 검토 페인은 목록이 실은 사유 · 증빙 유무를 상세를 기다리지 않고 보인다. ADM-LEAVE-BALANCE 입사일을 잔액 목록 항목(#8)에서 읽어 인사 목록 조인을 걷고 **근속 열**(기준일까지 달력 기준 년 · 개월)을 입사일 옆에 두며, 한 칸에 발생분을 여러 줄로 쌓던 임박 소멸을 **가장 이른 소멸일 · 소멸 예정 일수** 두 열로 가른다(그 발생분의 일수 — 화면이 일수를 더하지 않는다 · 만료일 미정뿐이면 둘 다 "—"). **화면 수 · 화면코드 · 라우트 · 권한 · 담은 기능ID는 전건 불변**
> **개정일**: 2026-09-17 — 사용자 실측 검토 반영 셋째. **요약 줄은 0인 항목을 내지 않는다** — ADM-ATTENDANCE 건수 항목(위험 플래그 · 미퇴근 · 정확도 초과 대기 · 휴게 미달 · 한도 경고)은 0이면 걷고(그 조건이 켜져 있으면 남는다), ADM-LEAVE-BALANCE는 0이 아닌 항목만 두며 모두 0이면 요약 줄 자체를 두지 않는다. 예약 0일은 기본 글자색이다. ADM-ATTENDANCE-CLOSING은 **걸린 사유만** 차단 목록에 세우고(0건 사유 줄 폐기 · 차단이 없으면 차단 구획 자리에 빈 상태 한 줄) 한도 경고 건수를 요약 줄로 옮기며(0이면 없음 · 경고 구획 머리 건수 폐기) 한도 경고 · 전이 이력 구획은 **내용이 있을 때만** 세워 둘 다 없으면 차단 목록이 전 폭을 쓴다. 미승인 수정 요청 항목은 서버가 싣는 일자 · 직원으로 그 요청 한 건을 연다. ADM-SCHEDULE 일자 칸은 구분점 없이 "시작~종료" + 옅은 "휴게 N분"이고 표식 아이콘 · 직원 열을 좁혀 1440 주 보기 7일이 가로 스크롤 없이 선다. ADM-LEAVE-APPROVAL 검토 페인 항목 아래 설명 문구(같은 기간 다른 휴가의 범위 · 증빙 · 예약 차감 · 적용 판정 불가)를 걷어 툴바 끝 ⓘ로 옮긴다. **화면 수 · 화면코드 · 라우트 · 권한 · 담은 기능ID는 전건 불변**
> **개정일**: 2026-09-17 — 사용자 실측 검토 반영 둘째. **① 한 칸에 서로 다른 데이터를 섞지 않고 ② 한 값은 한 자리에만 둔다 ③ 화면 위 우측 제목 줄(meta)을 쓰지 않는다.** ADM-SCHEDULE 편성 칸을 "시작~종료 · 휴게" 한 줄로 줄이고(예외일은 점 표식) 이름 칸의 직위 · 주 소정 보조 줄을 걷어 **표식 칸(행 앞 아이콘 — 스케줄 없음 · 연소자)과 계약 주 소정 열(현행 근로조건)**로 나눈다. ADM-ATTENDANCE 직원 칸의 직위를 **직위 열**로 나누고, 제목 줄의 가산 미적용 · 근거 스냅샷 표기를 **한 줄 고지(5인 미만 · 기간 안 갈림 · 산정 결과 없음 — 해당할 때만)**로 옮긴다. 요약 한 줄은 공통 요약 줄(StatStrip)이고 건수 항목을 누르면 그 조건이 켜진 상태를 알린다. ADM-ATTENDANCE-APPROVAL "현재값 → 요청값" 한 칸을 **요청 시각 · 현재 판정 · 현재 실근로** 세 열로, 대상 일자 칸의 제출 시각과 대상 직원 칸의 직위 · 대리 제출을 걷어 **신청일 · 대기 경과 · 대리 제출** 열을 더한다. ADM-ATTENDANCE-CLOSING은 대상 월 · 마감 상태를 기간 선택기, 남은 차단 건수를 한 줄 고지, 사유별 건수와 목록을 체크리스트, 경고 건수를 경고 구획 머리, 마감 가능 여부를 마감 버튼 하나씩에만 둔다(요약 줄은 대상 인원 · 근태 일수 · 실근로 합계). 본 파일은 **급여의 유일한 실적 입력을 만드는 여섯 화면**을 담는다. 스케줄이 판정 기준을 세우고, 근태 현황이 실적을 보여주고, 두 승인 화면이 잘못된 값을 고치고, 마감이 그 결과를 잠근다. 연차 현황은 근태 결과를 입력으로 받아 유급 처리의 근거를 만든다. 순서는 편성 → 관측 → 정정 → 확정이며 화면 배열도 그 순서를 따른다.

이 도메인은 **두 방향의 원칙이 동시에 선다** — 기록은 최대한 남기고(정확도가 나빠도 저장해 승인 대상으로 넘긴다), 잘못된 값은 마감에서 막는다(차단 사유 6종). 그래서 근태 현황 화면은 차단이 아니라 표시와 승인의 표면이고, 마감 화면이 유일한 게이트다. **근로시간을 15분·30분 단위로 절사하는 처리는 임금체불이므로 어떤 화면에서도 설정으로 열지 않는다.**

**5인 미만 사업장에서 가산이 없는 것과 근로가 없는 것은 다르다.** 근태 화면은 5인 미만이어도 실근로시간을 그대로 집계해 보여주고 가산 대상 플래그만 false로 표시한다. 반대로 연차는 5인 미만에 법정 적용 자체가 없으므로 조치 없는 안내 상태로 그린다 — **적용 대상 아님(403)과 전제 미충족(422)의 구분**이 이 파일 전체의 문안 규약이다(§1-2).

**레이아웃·스크롤·모바일**: **목록 변형 배치(L)**다 — 1024 이상에서 콘텐츠 영역은 스크롤하지 않고 **편성 격자(이름 있는 스크롤 영역)만 세로 · 가로로 스크롤한다**(§5-3). 툴바 · 한 줄 고지는 스크롤 밖이고 격자의 머리 행과 표식 · 직원 이름 열을 고정한다. 칸은 한 줄이라 한 사람이 한 줄 높이만 쓰고, **기간 합계(이 격자에 편성된 소정근로)와 계약 주 소정(현행 근로조건 · 없으면 —)을 나란히 두어** 계약과 편성을 견준다. 두 합계 열은 오른쪽에 고정해 일자가 자리를 넘겨 가로로 스크롤해도 대조가 남는다. **열 폭은 격자가 정한다** — 고정 열 넷(표식 · 직원 · 기간 합계 · 계약 주 소정)을 뺀 자리를 일자 열이 똑같이 나누고 일자 열의 최소 폭은 3rem이다. 그래서 1280 이상에서 주 보기 7일이 가로 스크롤 없이 들어가고(1024도 짧은 글자로 들어간다) 2560에서 월 보기 한 달이 들어가며, 그보다 좁은 자리의 월 보기만 격자 안에서 가로로 스크롤한다. 칸 글자의 길고 짧음은 창 폭이 아니라 격자가 놓인 자리 폭으로 가른다(월 보기 머리는 날짜 숫자와 요일 두 줄). **페이지 본문은 가로로 스크롤되지 않는다.** 보기 단위 · 기준일 · 직원은 탭 쿼리(view · anchor · employee)가 가져 새로고침 · 공유 · 탭 복원에서 보던 주가 그대로 열리며 기본값(주 · 이번 주 · 전체)은 쿼리에 쓰지 않는다. 오늘 날짜 열은 머리를 강조한다. 행이 적으면 격자 아래가 빈다. 1024 미만에서는 본문이 스크롤하고 격자는 직원 이름 열을 고정한 가로 스크롤로 남는다. 390에서도 예외일 하나를 편성해 저장할 수 있어야 한다. 편집 폼은 단일 레이어 모달이며 모달 위에 모달을 띄우지 않는다(§3-1).

**화면 기능**

| 월간 출근부 | 툴바 아래 표 머리 줄의 보기 전환 **[일자별 표 ⇄ 월간 출근부]**로 연다. 행 = 직원(재직 명부 + 그 달 기록이 있는 퇴사자 · 이름 열 고정) · 열 = 1일~말일(요일 글자 · 주말 글자색 · 오늘 강조) + 실근로 · 연장 · 야간 합계(오른쪽 고정)다. 칸은 **판정 8종의 한 글자 약어 + 색**(색 단독 금지 — 범례가 늘 보이고 칸 이름이 판정 이름을 싣는다) · 스케줄이 없는 날은 판정 없음 표시 · 위험 플래그 점 · 대기(수정 요청 · 정확도 초과) 점선 테두리 · **미래 칸은 비운다**. 칸을 누르면 일자별 표의 행 펼침과 **같은 상세**가 옆 페인에 열린다. 월 · 직원 · 검색이 조건이고 쿼리는 view=month · month=YYYY-MM · 고른 칸 cell이다. 합계는 **그 달 전 행의 분 정수 합**이다 — 범위 응답이라 모집단 일부의 합이 아니다(§3-8 합계 행과 같은 근거) | ATT-04(판정 표시) · ATT-05(집계 표시) |
| 요약 한 줄 | 위험 플래그 · 미퇴근 · 정확도 초과 대기 · 휴게 미달 · 한도 경고 건수를 **표 위 한 줄(요약 줄)**로 보인다(값은 조회 기간 전 행 기준 — 월간 출근부에서는 그 달). **실근로 합계 · 연장 · 야간은 싣지 않는다** — 기간 합계 행이 정본이라 되풀이하지 않는다. **건수는 0이면 내지 않고** 남는 항목이 없으면 요약 줄 자체를 두지 않는다 — 충족 상태를 한 줄에 늘어놓지 않는다. 그 조건이 켜져 있으면 0이어도 남아 끌 수 있다. 건수 항목을 누르면 그 조건의 일자별 표로 좁히고(다시 누르면 푼다 · 켜진 항목은 눌린 상태로 알린다) 정확도 초과 대기는 대기 목록을 연다 | ATT-02 · ATT-12(위반 표시) · ATT-13(경고) |
| 판정 8종 표시 | NORMAL · LATE · EARLY_LEAVE · ABSENT · MISSING_CLOCKOUT · ON_LEAVE · HOLIDAY · WEEKLY_HOLIDAY **8종**을 표시한다. **색 단독 의존을 금지하므로 판정 8종에 텍스트 라벨을 반드시 붙인다**(§5-1). 스케줄이 없는 일자는 판정을 생략하고 실측만 표시한다 | ATT-04 |
| 8버킷 분해 표시 | 소정 · 야간 · 연장 · 연장야간 · 휴일 8시간 이내 · 휴일야간 · 휴일연장 · 휴일연장야간 **8버킷**을 분 단위로 보여주고 **버킷 합 = 원시 실근로분**을 검산 값으로 함께 표시한다. 어긋나면 그 행을 이상 값으로 표시한다 | ATT-05 |
| 5인 분기 표시 | 상시근로자 스냅샷이 5인 미만인 기간은 **가산 대상 플래그만 false로 두고 실근로시간은 그대로 집계**한다. "가산이 없다"만 적으면 실근로분도 무급으로 오해되므로 가산 미적용 사실과 근거를 함께 적는다 — **스크롤 밖 한 줄 고지**로 5인 미만(가산 미적용 · 실근로 그대로 집계) · 기간 안에서 5인 미만과 이상이 섞임 · 산정 결과 없음(상시근로자 산정 액션) 중 해당하는 하나만 내고, 근거 스냅샷(기준일 · 평균 인원 · 확정 여부)은 줄 끝 액션 이름에 싣는다. 5인 이상으로 가산이 적용되는 기간에는 줄을 두지 않는다. **근거 연결을 먼저 본다** — 서버는 그 근무일에 적용할 스냅샷이 없으면 가산 대상 플래그를 false로 두고 근거를 비우므로, 근거가 비어 있는 일 집계가 하나라도 있으면 5인 미만으로 적지 않고 "산정 근거가 연결되어 있지 않아 가산 적용 여부를 판정할 수 없다"는 고지 + 상시근로자 산정 액션을 낸다(행 펼침 상세도 같다). 5인 미만 고지의 근거 액션은 그 스냅샷이 5인 미만일 때만 붙인다 — 규모가 다른 스냅샷을 근거로 짝지으면 한 줄이 스스로 모순된다. 재직 명부 인원을 상시근로자 수로 적지 않는다 | ATT-05 |
| 휴게 기록 확인 | 일자별 휴게 구간과 실근로분 산출(실근로분 = 재실분 − 휴게분)을 확인한다. 휴게가 재실보다 길거나 음수인 모순은 이상 값으로 표시하고 마감에서 막힌다 | ATT-03 |
| 휴게 미달 표시 | 실근로 8시간 이상에 휴게 60분 미만, 4시간 이상 8시간 미만에 휴게 30분 미만이면 위반으로 표시한다. **판정 정본은 GET …/attendance/break-compliance다** — 이 표면은 그 기간의 전 일자를 판정 근거(basis)와 함께 반환하므로 **violated로 걸러야 위반만 남는다**. 거르지 않으면 위반 건수가 조회 일수와 같아져 카드가 항상 위반 상태로 보인다. 일 집계 표면에도 같은 값이 실려 있지만 건수·부족분의 정본은 이 표면이다. **전 규모 적용이라 5인 미만도 예외가 없고** 마감 차단 사유가 된다 | ATT-12(위반 표시) |
| 위험 플래그 확인 | 모의위치 의심 · 기기와 서버 시각 차이 · 비정상 이동거리를 플래그로 표시한다. **탐지하되 차단하지 않았다는 사실**을 안내에 적고 관리자가 판단하게 한다 | ATT-02 |
| 정확도 초과 대기 승인 | 위치정확도 한계를 넘겨 대기 상태로 저장된 체크인을 목록으로 모아 승인·반려한다. 반경 밖 차단(attendance.out_of_geofence/422)과 정확도 대기는 **다른 상태**이므로 문안을 분리한다 | ATT-02 |

**주요 UI 요소**: 가산 한 줄 고지(해당할 때만), 툴바(이름·직위 검색 · 기간(월간 출근부는 월) · 직원 · 판정 · 플래그 검색형 콤보박스 · 저장 뷰 · 대리 보정 · ⓘ), 요약 한 줄(0이 아닌 건수만 · 없으면 줄 없음), 표 머리 줄 왼쪽 보기 전환 · 오른쪽 내보내기 · 새로고침 · N건 · 열, 근태 표(일자·직원·직위·판정·출퇴근·재실·휴게·실근로·8버킷·검산·플래그 열 — 한 칸 한 값 + 기간 합계 행 + 행 펼침 상세(접힌 열 묶음 — 지금 보이지 않는 열 · 버킷 · 검산만 + 요약·판정(행에 없는 편성 · 편성 휴게 · 출처(직원 앱 체크인 · 관리자 대리 보정 · 데이터 임포트 — 기록이 없는 날은 휴가 승인 · 출근 간주 보호 기간 · 기록 없음) · 가산(적용되지 않을 때만) · 보정 사유 또는 검토 메모) · 휴게·플래그 · 대리 보정 탭))), 월간 출근부(범례 · 직원 × 일자 격자 · 합계 열 · 칸 상세 페인), 정확도 초과 대기 목록, 대리 보정 모달(사유 필수).

**레이아웃·스크롤·모바일**: **목록 배치(L)**다 — 1024 이상에서 콘텐츠 영역은 스크롤하지 않고 **표 데이터 영역**(일자별 표) 또는 **출근부 영역과 칸 상세 페인 본문**(월간 출근부 — 이름 있는 스크롤 영역)만 스크롤한다(§5-3). 툴바 · 요약 한 줄 · 표 머리 줄은 스크롤 밖이다. **8버킷을 포함한 표는 넓으므로 자체 가로 스크롤 컨테이너를 갖고 근무일 열을 고정**하며, 직원 이름이 남는 폭을 흡수하는 글자 열이다(§5-7). 자리가 모자라면 **직위 · 8버킷 · 검산 열부터 걷고**(우선순위 3) 걷힌 값은 행을 펼친 상세의 8버킷 분해 탭에서 본다 — 근무일 · 직원 · 판정 · 실근로는 걷지 않는다. 합계 행의 이름은 "기간 합계 · N건"으로 짧게 둔다(합계 첫 칸이 첫 열 폭을 넓히지 않게 — 기간 값은 툴바의 기간 필드가 보인다). N은 직원 × 근무일 행 수라 "일"로 적지 않는다. 가산 근거 없음 고지가 적는 "근무일 N일"은 서로 다른 근무일 수다. 출근 · 퇴근 칸의 "미기록"은 출근했는데 퇴근이 없는 날에만 쓰고 기록 자체가 없는 날(휴가 · 보호 기간 · 미출근)은 둘 다 —다. 플래그·경고 열은 불러온 행 전부가 —이면 우선순위 3으로 내려 검산 · 버킷보다 먼저 걷힌다. 보기 전환과 칸 선택 해제는 한 번의 쿼리 쓰기다. 월간 출근부는 머리 행 · 직원 열 · 합계 열을 고정하고 31일이 자리를 넘기면 그 영역 안에서 가로로 스크롤하며, 칸 상세 페인은 출근부 옆에 선다. 1024 미만에서는 일자별 표를 일자별 카드 목록으로, 월간 출근부를 **직원 카드 + 일자 격자**로 바꾸고 칸 상세를 목록 아래에 두며 본문이 스크롤한다. 대리 보정 모달은 단일 레이어이며 직원·일자 선택은 인라인 확장으로 처리한다(§3-1). 전 행을 한 번에 표시한다는 사실(기간 상한 366일)과 출근부 약어 · 대기 표시의 뜻은 툴바 끝 ⓘ에 둔다(§3-10).

**비고**: **휴게 미달 표면(break-compliance)은 위반만 내려주지 않는다** — 조회 기간의 모든 일자를 판정 근거와 함께 내리므로 화면이 violated로 걸러야 위반만 남는다. 거르지 않으면 위반 건수가 조회 일수와 같아져(전 규모 적용 사업장에서 실측 — 한 달 211건) 위반 여부와 무관하게 카드가 항상 위반 상태로 보인다. **이 화면은 관측과 승인의 표면이지 차단의 표면이 아니다** — 위험 플래그도 휴게 미달도 여기서 막지 않고 마감에서 막는다. 그래야 기록이 남는다. **관리자 수동 보정이 원본을 고치지 않는 것이 이 화면의 핵심 계약**이다. 원본을 직접 덮어쓰면 무엇이 실측이고 무엇이 보정인지 사후에 구분할 수 없어 근태의 증거력이 사라진다. 그래서 **체크인(ATT-01)의 표면은 직원 앱 단독**이고 관리자 웹의 보정은 수정 요청(ATT-06)과 승인(ATT-07)을 거친다 — 대리 보정에 체크인 표면을 열면 원본과 보정이 같은 경로에서 만들어져 구분이 무너진다. **15분·30분 절사는 임금체불이므로 표시·집계 어디에서도 적용하지 않으며 사업장 설정으로도 열지 않는다.** 휴게 경계는 §54의 "인 경우"를 **이상**으로 해석하는 것으로 확정됐으므로 위반 판정을 그대로 그린다 — **4시간 미만은 휴게 의무 없음 · 4시간 이상 8시간 미만은 30분 이상 · 8시간 이상은 1시간 이상**이다(확인값 정본 [../01_overview/05_priorities_roadmap.md](../01_overview/05_priorities_roadmap.md)). 다만 **§54 개정(2026-12-10 시행)이 이 경계를 바꾸므로** 시행일 전후로 판정 기준이 갈릴 수 있다는 감시 문구만 남긴다. **v1은 실시간 근태 현황판과 QR·키오스크 체크인을 두지 않으므로** 이 화면에 실시간 재실 표시나 기기 관리 요소를 만들지 않는다.

**레이아웃·스크롤·모바일**: **목록 배치(L)**다 — 1024 이상에서 콘텐츠 영역은 스크롤하지 않고 **표 데이터 영역만 스크롤한다**(§5-3). 툴바 · 한 줄 고지 · 표 머리 줄과 일괄 작업 바는 스크롤 밖이다. 검토 · 사유 입력은 새 레이어가 아니라 **행 펼침**으로 처리한다 — 목록과 사유를 같이 보면서 판단하고 위아래 요청과 견줄 수 있다(§3-1 · §7 동선). 펼침은 한 번에 하나이고 조건이 바뀌면 접힌다. 사유가 남는 폭을 흡수하는 글자 열이며(§5-7) 자리가 모자라면 현재 판정 · 현재 실근로 · 신청일 · 대리 제출 · 증빙부터 걷는다 — 걷힌 값은 펼친 검토 영역의 접힌 열 묶음에 선다. 대리 제출 · 증빙 · 처리 제약은 **불러온 행 전부가 빈 열이면 우선순위 3으로 내려** 신청일보다 먼저 걷히고, 사유는 최소 13rem이라 흔한 사유 한 줄이 말줄임 없이 선다. 상태별 건수는 상태 탭 한 자리에만 두고 고른 탭의 건수는 표 N건이 낸다(제목 줄에 되풀이하지 않는다). 걷힌 열도 처리 이력도 증빙도 없는 넓은 자리의 행 펼침은 테두리 상자 없이 처리 줄(반려 · 승인)만 둔다. 증빙 이미지는 자체 스크롤·확대 영역을 갖고 표를 밀지 않는다. 설명(승인이 주 경계까지 다시 합산한다 · 요청은 직원이 만든다)은 툴바 끝 ⓘ에 둔다. 1024 미만에서는 표를 카드 목록으로 바꾸고 현재값·요청값 대조를 상하 2행으로 접어 어느 쪽이 요청값인지 라벨을 붙이며 본문이 스크롤한다.

**레이아웃·스크롤·모바일**: **목록 변형 배치(L)**다 — 1024 이상에서 콘텐츠 영역은 스크롤하지 않는다. 툴바 · 요약 줄 · 하단 실행 액션 바는 스크롤 밖에 고정하고, 본문은 **차단 사유(왼쪽 넓은 칸) · 한도 경고와 전이 이력(오른쪽 좁은 칸 위아래)**으로 나누되 **한도 경고 · 전이 이력은 내용이 있을 때만 서고 둘 다 없으면 오른쪽 칸을 두지 않아 차단 사유가 전 폭을 쓴다.** 선 구획은 남는 높이를 나눠 **각자 스크롤한다**(이름 있는 스크롤 영역 · 구획 머리는 고정). 차단이 이 화면의 본체라 가장 넓은 자리를 준다. 차단 총계를 위에 한 줄로 다시 세우지 않는다 — 차단 구획의 사유별 배지와 같은 정보이고 해소 액션도 카드와 겹친다. 각 사유의 상세 목록은 사유 블록 안에서 접었다 펴며 별도 레이어를 만들지 않는다. 1024 미만에서는 세 구획을 한 열로 쌓되 차단 사유를 항상 먼저 두고 본문이 스크롤한다. **390에서도 마감과 재오픈을 끝까지 수행할 수 있어야 한다**(§5-2). 마감 조건 · 되돌리는 방법 설명은 툴바 끝 ⓘ에 둔다.

| 항목 | 내용 |

| 승인·반려 | 사유 입력과 함께 승인·반려를 처리한다. 전이는 PENDING → APPROVED · REJECTED · CANCELLED이며 제출 즉시 버튼을 잠근다 | LEV-03 |

**주요 UI 요소**: 연차 적용성 한 줄 고지(해당할 때만), 툴바(이름 검색 · 휴가 기간 · 상태 · 유형 · 직원 검색형 콤보박스 · 저장 뷰 · ⓘ), 표 우상단 내보내기 · 새로고침 · N건 · 열, 신청 표(행 체크박스 · 신청자 · 유형 · 기간 · 일수 · 사유 · 신청일 · 증빙 · 잔여 · 예약 · 연차 적용 · 상태 · 대기), 검토 페인(머리 — 신청자 · 유형 · 상태(목록 상태 열이 보이지 않을 때만 — 스택 · 카드) · 닫기 / 본문 — 신청 내용(목록이 걷은 열의 접힌 열 묶음 + 페인 고유 값 — 반차 시간대 · 같은 기간 다른 휴가 · 처리 시각 · 처리 의견) · 잔액·근태(걷힌 사용 가능 잔여 · 신청자 예약 합계 · 연차 적용 + 이 신청의 예약 · 차감하지 않는 유형) · 연차 원장 탭 + 차단 사유 한 줄 / 고정 처리 줄 — 승인 · 반려 · 승인 취소와 단계 전환 · 사유 입력), 일괄 작업 바(2건 이상 고를 때만 — 일괄 승인 · 일괄 반려 · 의견·사유 입력 · 결과 표 · 1건만 고르면 그 신청을 페인에 열어 페인 처리 줄이 처리한다 · 스택에서는 1건도 바). 처리 시각은 목록과 같은 날짜 표기 뒤에 시각을 붙인다. 검토 페인 항목 아래에 설명 문구를 두지 않는다 — 예약 차감의 뜻 · 원장 대상 유형 · 같은 기간 다른 휴가의 범위 · 증빙 내려받기 경로는 툴바 끝 ⓘ다.

**레이아웃·스크롤·모바일**: **목록 + 상세 페인 배치(MD)**다 — 1024 이상에서 콘텐츠 영역은 스크롤하지 않고 **표 데이터 영역과 페인 본문(이름 있는 스크롤 영역)만 스크롤한다**(§5-3). 검토 패널이 화면의 반쪽이라 첫 신청을 자동으로 열고(사용자가 닫으면 다시 열지 않는다) 선택은 탭 쿼리 requestId가 가져 알림 · 연차 현황에서 특정 신청을 지목해 열 수 있다. 툴바 · 표 머리 줄 · 페인 머리 · 처리 줄 · 일괄 작업 바는 스크롤 밖이다. 마스터 폭이 좁아(1440에서 약 690px) 걷지 않는 열은 신청자 · 상태 둘이고 신청자가 남는 폭을 흡수하는 글자 열이다 — 유형 · 잔여 · 예약 · 연차 적용 · 신청일부터 걷고 걷힌 값은 페인이 모두 보인다. 증빙 · 잔여 · 예약 · 연차 적용은 **불러온 행 전부가 빈 열이면** 우선순위 3이고 신청일 · 사유보다 오른쪽에 서서 먼저 걷힌다(같은 우선순위는 오른쪽부터 걷힌다). 페인 머리에는 신청자 · 유형 · 상태만 두고 기간 · 일수는 본문 한 자리에만 둔다. 승인 확인은 새 레이어가 아니라 페인 안 단계 전환으로 처리한다(§3-1). 1024 미만에서는 표를 카드로 바꾸고 잔액 대조를 카드 하단 3값(신청 전 · 예약 · 승인 후)으로 세로 배치하며, 페인은 목록을 덮는 전체 영역이고 자동으로 열지 않는다. 390에서도 승인·반려를 끝까지 수행할 수 있어야 한다.

| 5인 미만 미적용 표시 | 상시근로자 스냅샷이 5인 미만인 기간은 **leave.not_applicable/403 — 조치 없는 안내 상태**로 그린다. "적용 대상이 아닙니다"와 근거를 적고 **실행 버튼을 두지 않는다**. 오류 색·오류 아이콘을 쓰지 않는다 | LEV-01 |
| 스냅샷 부재 표시 | 스냅샷 자체가 없으면 **leave.employee_count_snapshot_required/422 — 조치 가능 상태**로 그린다. 판정 불가 사유를 적고 **상시근로자 산정 화면으로 가는 실행 링크를 함께 둔다**. 위 미적용 상태와 시각·문안을 분명히 구분한다 | LEV-01 |
| 연차 원장 3계층 조회 | **발생 · 원장 · 요약 잔액** 3계층을 본다 — 요약 잔액은 행의 열(발생 · 사용 · 예약 · 잔여 · 소멸)이 내고, 행을 펼치면 접힌 열 묶음(자리가 모자라 걷힌 열의 값만) · 행에 없는 복원 · 조정(0이 아닐 때) · 임포트 적재분(있을 때)과 발생 · 원장 탭(각자 표 — 발생일 · 만료일 · 발생 · 차감 건수(숫자만) · 근속 연차(1년 미만 발생분은 "1년 미만") · 출처 · 사유 / 유형 · 효력일 · 일수 · 출처 · 메모)이 선다. 원장은 append-only이며 GRANT · USE · RESTORE · EXPIRE · ADJUST 행을 시간순으로 제시한다. **원장이 정본**이고 요약은 원장을 다시 합산해 만들 수 있는 값이다 — 화면 안내(ⓘ)는 이 사실을 사업주가 읽는 말("잔액은 기록을 합한 값 · 재계산은 잔액만 고친다")로 적고 내부 용어(버전 · 진실 원천 · 파생값 · FIFO)를 두지 않는다 | LEV-01 |
| 적재분 구분 표시 | 임포트로 적재한 기초값을 자동 산정분과 구분해 표시한다. 적재 없이 잔액이 0부터 시작하면 계산이 처음부터 틀린다 — 적재분이 있으면 행 펼침 위에 "임포트 적재분 포함"을, 원장 · 발생 표의 출처 칸에 임포트 적재를 적는다 | LEV-01 |
| FIFO 차감 표시 | 사용이 **먼저 발생한 것부터 차감**된다는 규칙(설명은 ⓘ)을 발생 표의 발생분별 차감 건수로 보여준다. 어느 발생분이 언제 소진됐는지 추적 가능하게 한다 | LEV-01 |
| 요약·원장 불일치 경고 | 요약 잔액과 원장 재계산 값이 어긋나면 **스크롤 밖 한 줄 고지로 경고하고 관리자 재계산 액션을 제공**한다(오늘 기준에서만 — 지난 기준일에는 견줄 요약이 없다). 경고 상태에서는 요약 값을 확정 값처럼 그리지 않는다. 맞을 때는 고지를 두지 않고 명령 팔레트가 재계산의 상시 입구다 | LEV-04 |
| 연차미사용수당 안내 | **v1은 연차 사용촉진을 지원하지 않으므로 보상 의무 면제를 적용할 수 없고 미사용 연차는 항상 보상 대상**이다. 그 사실과 촉진 미지원은 계산 전제의 설명이라 툴바 끝 ⓘ에 표기한다(§3-10) — 지난 시점 보기의 뜻(원장에서 되짚은 값)도 같은 자리에 둔다 | LEV-06 |
| 목록 내보내기 | 표 우상단 내보내기로 화면의 검색 · 기준일 · 표시 열 그대로 XLSX를 받는다. 비민감 목록이라 사유 없이 내려받고 감사 기록만 남는다. 화면 열을 서버 열로 옮겨 싣는다 — 표시 칸은 원장 불일치 열이고 기준일 열을 늘 함께 싣는다. 근속 · 가장 이른 소멸일 · 소멸 예정 일수는 화면이 풀어 그린 값이고 입사일은 내보내기 선언 열이 아니라 싣지 않는다 | DSH-06(전역) |

**주요 UI 요소**: 불일치 한 줄 고지 + 요약 재계산, 툴바(이름 검색 · 기준일 선택기 · 지난 기준일 표식 · 오늘로 · 저장 뷰 · ⓘ), 요약 줄(불일치 · 미적용 · 판정 불가 인원 — 0이 아닌 항목만), 표 우상단 내보내기 · 새로고침 · N건 · 열, 직원별 잔액 표(직원 · 입사일 · 근속 · 발생 · 사용 · 예약 · 잔여 · 가장 이른 소멸일 · 소멸 예정 일수 · 소멸 · 표시 — 한 칸 한 값 + 행 펼침(복원 · 조정 · 적재분 — 있을 때만 · 발생 표 · 원장 표)), 미적용·판정 불가 안내 카드, 재계산 확인 다이얼로그(사유 입력).

**레이아웃·스크롤·모바일**: **목록 배치(L)**다 — 1024 이상에서 콘텐츠 영역은 스크롤하지 않고 **표 데이터 영역만 스크롤한다**(§5-3). 한 줄 고지 · 툴바 · 요약 줄 · 표 머리 줄은 스크롤 밖이다. 원장은 팝업 · 드로어가 아니라 **행 펼침**으로 보여 옆 직원과 견줘 보게 남긴다(§7 동선). 직원 이름이 남는 폭을 흡수하는 글자 열이고(§5-7) 자리가 모자라면 가장 이른 소멸일 · 소멸 예정 일수 · 소멸부터 걷는다. 표시 열은 표시할 것(불일치 · 미적용 · 판정 불가)이 한 행도 없으면 **열 자체를 두지 않는다**(폭이 남아도 "—"만 늘어선 열을 세우지 않는다). 1024 미만에서는 직원별 카드 목록으로 전환해 잔여 일수를 카드 제목 옆에 크게 두고 나머지 값을 아래에 배치한다. 미적용·판정 불가 안내는 표를 대체해 영역 가운데에 그리고 잔액을 흐린 표로 그리지 않는다 — 값이 없는 것과 적용되지 않는 것은 다르다. 기준일 선택기는 그 안내 상태에서도 남는다.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 표 행 스켈레톤과 요약 수치 자리를 유지한다. 재계산 실행 중에는 대상 행만 진행 표시로 잠근다 |
| 빈 상태 | **3분기다** — ① 전체 0건: "연차 정보를 만들 직원이 없습니다" + 직원 등록 링크 ② 권한: 가시 범위가 비면 "열람할 수 있는 연차 정보가 없습니다" ③ 필터 0건: "조건에 맞는 직원이 없습니다" + 필터 초기화. **5인 미만 미적용은 빈 상태가 아니라 안내 상태**이므로 위 셋과 별도로 그린다(§3-5) |
| 에러 | leave.not_applicable/403 → **오류로 그리지 않고** "이 기간은 법정 연차 적용 대상이 아닙니다"와 근거를 안내 카드로 적으며 조치 버튼을 두지 않는다. leave.employee_count_snapshot_required/422 → "상시근로자 산정 결과가 없어 적용 여부를 판정할 수 없습니다" + 산정 화면 실행 링크. 원장 조회 실패는 펼친 행 안 대체 영역에 "원장을 불러오지 못했습니다" + 다시 시도를 두고 목록은 유지한다. 재계산 실패는 코드를 병기하고 다시 시도를 안내한다 |
| 권한거부 | STAFF 진입은 §1-2 권한 안내로 ADM-WORKPLACE-SELECT로 되돌린다. STAFF 본인의 잔여 연차 조회는 직원 앱 표면이 담당하므로 이 화면에서 본인 접근을 열지 않는다 |

**데이터 연동**

- 직원별 잔액 조회(#8 · 검색어 q — 직원명 부분 일치 · 기준일 asOf · 항목이 입사일을 싣는다) → GET /v1/workplaces/{workplaceId}/leave/balances → **leave_balances** · **employees** · **workplace_employee_count_snapshots**
- 목록 내보내기(DSH-06 · listType leave_balances · 비민감 · filters asOf) → POST /v1/workplaces/{workplaceId}/list-exports → GET /v1/list-exports/download/{token} → **audit_logs**(list.export)
- 원장 조회 → GET /v1/workplaces/{workplaceId}/leave/ledger → **leave_transactions** · **leave_grants**
- 잔액 재계산 → POST /v1/workplaces/{workplaceId}/leave/recompute → **leave_transactions** · **leave_balances** · **audit_logs**
- 발생 이력 조회 → GET /v1/workplaces/{workplaceId}/leave/grants → **leave_grants**
- **기본 정렬**: 직원명 오름차순이며 동률은 식별자 내림차순이다. 원장 내역은 발생 시각 내림차순 · 식별자 내림차순이다(§3-4)
- 상세 규격의 정본은 [../06_api/07_leave.md](../06_api/07_leave.md)다

**담은 기능ID**: LEV-01 · LEV-04 · LEV-06(표시)

**비고**: **403과 422의 구분이 이 화면의 핵심 규약**이다(§1-2 · REQ-GLB-19) — 5인 미만 미적용은 조치가 없는 정상 상태라 안내만 두고, 스냅샷 부재는 산정이라는 조치가 있으므로 실행 링크를 함께 둔다. 둘을 같은 오류 문안으로 처리하면 사용자가 할 일이 있는지 없는지 알 수 없다. **요약은 원장의 파생값이므로 불일치를 조용히 덮지 않는다** — 경고 배너와 재계산 액션이 이 화면이 원장 진실 원천을 지키는 방식이다. **v1은 연차 사용촉진 · 회계연도 일괄 산정 · 시간 단위 신청을 지원하지 않으므로** 촉진 통지·회계연도 전환 같은 요소를 화면에 만들지 않고 부정형으로만 언급한다. 미사용 연차가 항상 보상 대상이라는 사실은 금액 단정이 아니라 계산 전제의 표기이며, 급여 반영의 정본은 급여 화면이다.
