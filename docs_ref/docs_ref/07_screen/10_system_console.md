시스템 웹은 **사업장 RBAC와 완전히 별개인 플랫폼 운영 표면**이다. 사업장 OWNER라도 플랫폼 권한이 없으면 진입조차 못 하고, 플랫폼 관리자라도 사업장 업무 권한을 자동으로 얻지 않는다. 그래서 이 7화면의 접근권한 칸은 전부 플랫폼({역할}) 값이며 OWNER · MANAGER · STAFF가 한 번도 나오지 않는다. 두 축을 섞어 표기하면 테넌트 격리가 화면 문서에서부터 무너진다. 셸은 관리자 웹과 같은 2단 골격을 쓰되 **사업장 전환기가 없다** — 플랫폼 운영은 특정 사업장 컨텍스트를 갖지 않는다(§4-3).

**v1은 역할 임명 화면을 두지 않는다.** 최초 SUPER_ADMIN은 시드가 아니라 **서버 기동 시 환경변수 1회성 부트스트랩**으로 생성하고(정본: [../05_database/10_migrations_seed.md](../05_database/10_migrations_seed.md)) 이후 역할 부여·회수는 화면 없이 운영 절차로 처리한다. 따라서 이 문서에는 관리자 계정을 만들거나 역할을 바꾸는 화면이 없으며, 시스템 웹에서 다룰 수 있는 것은 이미 부여된 역할로 수행하는 운영 액션뿐이다. 액션별 최소 역할은 [../02_features/14_permission_matrix.md](../02_features/14_permission_matrix.md) §6과 문자 수준으로 일치시킨다.

**v1에 만들지 않는 시스템 웹 화면이 셋 있다** — 플랫폼 역할 임명·회수 화면(SYS-02 이월) · 플랫폼 공지 관리 화면(SYS-09 이월) · 분석 통계 화면(SYS-10 영구 제외)이다. 그래서 v1의 시스템 웹에는 통계 대시보드가 없고 현황 조회와 운영 액션만 있다. 화면 코드·라우트의 채번 정본은 [README.md](./README.md) 화면 인벤토리이며, 본 문서는 그 7본의 화면 계약을 담는다.

## SYS-WORKPLACES — 사업장 관리

| 항목 | 내용 |
|------|------|
| 화면코드 | SYS-WORKPLACES |
| 라우트 | web_front SPA /system/workplaces |
| 접근권한 | 플랫폼(VIEWER) 조회 / 플랫폼(ADMIN) 정지·해제·강제 폐쇄 |
| 우선순위 | P0 |

**목적**: 플랫폼 전체 사업장을 찾아 상태와 검증 결과를 확인하고, 필요하면 사유를 남긴 제재를 집행한다.

**진입경로**: 시스템 웹 사이드바 운영 > 사업장. SYS-AUDIT에서 대상이 사업장인 감사 로그 행의 교차 진입. SYS-SUBSCRIPTIONS의 계정 구독 상세에서 소유 사업장 목록을 통한 교차 진입.

**화면 기능**

| 기능 | UI/처리 | 기능ID |

| 액션 결과 반영 | 정지·해제·강제 폐쇄는 낙관적 갱신을 쓰지 않는다(§3-6). 제출 즉시 버튼을 잠그고 서버 확정 뒤 목록과 상세를 다시 읽는다 | SYS-03 |
| 감사 고지 | 이 화면의 **모든 액션이 행위자·사유·전후 상태와 함께 감사 로그에 남는다**는 사실을 제재 모달에 상시 표시한다 | SYS-03 |

**주요 UI 요소**: 필터 바(상태 · 검증 결과 · 구독 소유자 검색형 콤보박스 · 등록일 범위 · 상호·사업자번호 검색 입력), 표 우상단 내보내기·새로고침·N건(조건 결과 전체)·열 관리, 사업장 표(상호 열이 남는 폭을 흡수한다 · §5-7), 행 액션 메뉴, 사업장 상세 인라인 패널, 제재 모달(사유 입력 → 최종 확인 2단), 감사 기록 고지 문구.

**레이아웃·스크롤·모바일**: 좌측 고정 사이드바 + 우측 콘텐츠 2단이며 사업장 전환기를 두지 않는다(§4-3). 페이지 헤더 · 필터 바 · 표 헤더 행은 스크롤 밖에 고정하고 **스크롤 소유자는 표 본문 하나**다. 1024 이상에서 표는 놓인 영역을 가로·세로로 채우며 상호 열을 고정하고 페이지 본문은 가로로 스크롤되지 않는다(§5-3 · §5-7). 상세 인라인 패널은 오버레이가 아니라 표 우측 분할 영역이라 모달 레이어를 소비하지 않는다. 768 미만에서는 사이드바를 걷고 상단 앱바 + 햄버거 드로어로 대체한다(§4-1). **표→카드 전환은 별개 경계인 1024 미만이다** — 768~1023에서는 사이드바가 그대로 있어도 표는 이미 카드다. 카드 전환 시 상세 패널은 전체 폭 전환 뷰로 바뀐다. 제재 모달은 단일 레이어이며 사유 입력과 최종 확인을 **같은 모달의 상태 전환**으로 처리한다(§3-1).

| 로딩 | 표와 같은 열 구성·행 높이의 스켈레톤 행을 그려 로딩 종료 시 레이아웃이 흔들리지 않게 한다. 필터 바는 로딩 중에도 조작 가능한 상태로 남긴다 |
| 빈 상태 | 필터 0건은 "조건에 맞는 사업장이 없습니다"와 필터 초기화 액션, 전체 0건은 "아직 등록된 사업장이 없습니다"로 갈라 적는다. 플랫폼 관리자가 사업장을 만드는 주체가 아니므로 **어느 쪽에도 등록 CTA를 두지 않는다**(§3-5) |
| 에러 | common.validation_failed/400 — 사유를 비운 제출을 필드 오류로 되돌린다 · common.not_found/404 — 대상 사업장 부재 · workplace.closed/409 — 이미 폐쇄된 사업장의 중복 폐쇄 요청 · common.service_unavailable/503 — 문의가 필요한 실패이므로 코드를 병기한다(§3-7) |
| 권한거부 | **권한 안내**를 쓴다(§1-2). 인증 컨텍스트가 없으면 로그인 유도로 PUB-LOGIN에 보내고, **플랫폼 권한 자체가 없으면 auth.platform_forbidden/403으로 시스템 웹 진입 단계에서 막는다**. 진입한 플랫폼(VIEWER)에게는 제재 컨트롤을 비활성 상태로 노출해 무엇이 자기 권한 밖인지 보이게 하고, 그래도 실행하면 서버가 **system.permission_denied/403**으로 거부한다 |

**데이터 연동**

- 사업장 검색·목록 → GET /v1/system/workplaces → **workplaces** · **subscriptions** · **users**
- 사업장 상세 조회 → GET /v1/system/workplaces/{workplaceId} → **workplaces** · **workplace_members**
- 정지 · 정지 해제 → POST /v1/system/workplaces/{workplaceId}/suspend · POST /v1/system/workplaces/{workplaceId}/unsuspend → **workplaces** · **audit_logs**
- 강제 폐쇄 → POST /v1/system/workplaces/{workplaceId}/close → **workplaces** · **audit_logs**
- 목록 내보내기(DSH-06 · listType system_workplaces · 비민감) → POST /v1/system/list-exports → GET /v1/list-exports/download/{token} → **audit_logs**(list.export)
- 상세 정본은 [../06_api/14_system.md](../06_api/14_system.md)다.

**담은 기능ID**: SYS-03

**비고**: **강제 폐쇄는 되돌릴 수 없는 작업**이므로 확인 문안에 그 사실을 명시하고, 되돌리는 방법이 없다는 것도 함께 적는다. 이 경로는 OWNER 자발 폐쇄(WRK-10)와 화면·주체·확인 절차가 모두 다르다 — 자발 폐쇄는 선행조건 확인과 비밀번호 재인증을 요구하지만 강제 폐쇄는 플랫폼 사유 입력이 그 자리를 대신한다. 재인증을 요구하지 않는 대신 **사유 필수와 감사 로그가 통제 수단**이므로 사유 입력을 우회할 수 있는 경로를 화면에 두지 않는다. 지원 목적으로 사업장 데이터를 더 봐야 하는 상황은 이 화면에서 해결하지 않고 별도 권한 경로로 넘긴다.

**레이아웃·스크롤·모바일**: 2단 골격 안에서 콘텐츠 영역을 2탭으로 나눈다 — 요금제와 계정 구독은 열 구성과 필터 축이 달라 한 표에 합치면 어느 쪽도 읽히지 않는다. 각 탭에서 페이지 헤더 · 탭바 · 필터 바 · 표 헤더 행을 고정하고 1024 이상에서는 표가 영역을 채우며 표 본문만 스크롤한다(§5-7). 요금제 표는 열이 많아 자체 가로 스크롤 컨테이너를 갖고 코드 열을 고정한다. 768 미만에서는 사이드바를 햄버거 드로어로 대체한다(§4-1). **표→카드 전환은 1024 미만**이며 두 표를 각각 카드 목록으로 전환하되 탭은 그대로 유지한다. 편집·조정 모달은 단일 레이어이며 입력 · 영향 확인 · 최종 확인을 **같은 모달의 단계 전환**으로 처리해 모달 내부 스크롤을 만들지 않는다(§3-1).

**주요 UI 요소**: 배포 전 수동 확인 한 줄 고지(NoticeLine), 툴바 "정기작업 재실행" 액션 버튼(눌렀을 때만 작업 선택 · 기준일 · 사유 · 결과 한 행 카드가 열린다), 카테고리 목록(19 · 전체 높이를 채운다), 귀속 기준일 입력, 미확인 건수 요약(0건이면 미노출), 표 우상단 내보내기(listType system_statutory_rates)·새로고침·N건·열 관리, 기준값 표(값 열이 남는 폭을 흡수한다 · §5-7 · 키 · 값 · 유효 시작일 · 유효 종료일 · 버전 · 출처 · 확인 시각 · 확인자 · **확인 여부(우선순위 1열)**), 미확인 라벨, 유효기간 타임라인 뷰, **새 버전 등록 모달(카테고리·키·값 키·값 편집기·유효기간·버전·출처)**, **확인 상태 갱신 모달(확인 여부·출처만)**, 변경 이력 패널.

**레이아웃·스크롤·모바일**: 2단 골격 안에서 콘텐츠 영역을 좌측 카테고리 목록 + 우측 기준값 표로 다시 나눈다. 한 줄 고지 · 페이지 헤더 · 귀속 기준일 입력 · 표 헤더 행은 스크롤 밖에 고정하고 **콘텐츠 영역의 스크롤 소유자는 기준값 표 본문**이다 — 카테고리 목록은 19행 고정이라 짧은 뷰포트에서 넘칠 수 있으므로 목록 컨테이너 안에서만 스크롤하고 페이지 본문을 늘리지 않는다(§5-3). 1024 이상에서 표는 영역을 채우며 자체 가로 스크롤 컨테이너로 키 열을 고정한다(§5-7). 768 미만에서는 사이드바를 햄버거 드로어로 대체하고 카테고리 목록을 셀렉트로 접어 세로 1열로 흐르게 한다(§4-1). **표→카드 전환은 1024 미만**이며 미확인 라벨은 카드 상단에 그대로 남긴다. 타임라인 뷰는 가로 스크롤 컨테이너를 자체 보유한다.

| 버전 작성 | 종류 · 버전 · 제목 · 본문 · 유효 시작일을 입력하고 미리보기로 게시 형태를 확인한다. 동일 종류·동일 버전 중복은 **system.terms_version_conflict/409**로 버전 필드에 되돌린다 | SYS-11 |
| 활성 버전 전환 | **종류별 활성 버전이 정확히 1개**임을 화면이 보장한다. 새 버전을 활성화하면 이전 활성 버전이 함께 내려가고, **활성이 0개가 되는 조작을 막는다** — 활성 문서가 없으면 가입 자체가 성립하지 않으며 조회는 **system.terms_not_found/404**가 된다 | SYS-11 |
| 버전 비활성화 | **이미 동의에 참조된 버전은 삭제하지 않고 비활성화만 한다.** 삭제 시도는 **system.terms_in_use/409**로 되돌리고 비활성화 경로를 함께 안내한다 — 삭제하면 그 버전에 동의한 이력이 유령 참조가 된다 | SYS-11 |
| 개정·재동의 트리거 | 새 버전 발효는 **재동의 흐름을 트리거**한다. 필수 2종(TERMS·PRIVACY)은 미완료 사용자가 다음 로그인·주요 액션에서 동의 화면(PUB-CONSENT)으로 유도되고, **LOCATION 개정은 진입을 막지 않고 GPS 체크인만 다시 잠긴다**(D-19)는 사실을 발효 확인 단계에 표시한다 | SYS-11 |
| 동의 이력 영향 표시 | **재동의는 새 버전에 대한 신규 동의 이력으로 기록되고 기존 이력을 덮어쓰지 않는다**는 것을 발효 확인 단계에 함께 적는다 | SYS-11 |
| 참조 현황 표시 | 버전별로 동의 참조가 있는지 여부를 표시해 어느 버전이 비활성화만 가능한지 저장 전에 알 수 있게 한다 | SYS-11 |

**주요 UI 요소**: 종류 탭 3종, 검색 입력(버전·제목) + 활성 여부 검색형 콤보박스, 표 우상단 내보내기(listType system_terms_documents)·새로고침·N건·열 관리, 버전 표(제목 열이 남는 폭을 흡수한다 · §5-7 · 버전 · 제목 · 유효 시작일 · 활성 여부 · 동의 참조 유무), 활성 버전 배지, 본문 편집기, 게시 미리보기, 발효 확인 모달(입력 확인 → 재동의 영향 확인), 비활성화 확인, 재동의 영향 안내 블록.

**레이아웃·스크롤·모바일**: 2단 골격 안에서 상단 종류 탭 + 좌측 버전 표 + 우측 본문 편집·미리보기 영역으로 나눈다. 페이지 헤더 · 탭바 · 표 헤더 행 · 편집기 툴바는 스크롤 밖에 고정하고 **스크롤 소유자는 버전 표 본문과 본문 편집·미리보기 영역 둘로 분리**한다 — 본문은 길이가 길어 표와 같은 스크롤을 공유하면 어느 쪽도 읽히지 않는다. 두 영역 모두 조상에 스크롤을 중복 지정하지 않는다. 768 미만에서는 사이드바를 햄버거 드로어로 대체한다(§4-1). **좌우 2단 → 1열 스택 전환은 1024 미만**이며 버전 표 → 본문 순으로 흐르고, 편집기는 전체 폭 전환 뷰로 연다. 발효 확인 모달은 단일 레이어이며 입력 확인과 재동의 영향 확인을 같은 모달의 단계 전환으로 처리한다.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 버전 표는 동형 스켈레톤 행으로, 본문 영역은 문단 형태 스켈레톤으로 그린다. 종류 탭은 정적이라 즉시 렌더한다 |
| 빈 상태 | 종류 전체 0건은 "아직 등록된 문서가 없습니다"와 등록 CTA를 둔다. **버전은 있는데 그중 활성이 없으면** 빈 상태가 아니라 목록 위 **한 줄 고지**(NoticeLine · 결과가 달라지는 상태이므로 §3-10에 따라 상시 노출)로 "가입 동의가 성립하지 않는다"는 사실을 적는다 — 둘은 다른 조건이다. 이 화면에 진입한 사용자는 전원 ADMIN 이상이므로 등록 CTA를 조건부로 감추지 않는다 |
| 에러 | **system.terms_version_conflict/409** — 동일 종류·버전 중복을 버전 필드로 되돌린다 · **system.terms_in_use/409** — 동의에 참조된 버전의 삭제 시도이며 비활성화 경로를 안내한다 · **system.terms_not_found/404** — 활성 문서 부재이며 즉시 활성화가 필요한 상태로 표시한다 · common.validation_failed/400 — 제목·본문·유효 시작일 누락 · common.service_unavailable/503 |
| 권한거부 | **권한 안내**를 쓴다(§1-2). 미인증은 로그인 유도, **플랫폼 권한 자체 없음은 auth.platform_forbidden/403**으로 진입 차단이다. **플랫폼(VIEWER)·플랫폼(SUPPORT)는 이 화면에 진입하지 못한다** — 조회 표면 자체가 ADMIN 전용이고 VIEWER 권한 집합(사업장 · 사용자 · 구독 · 요금제 · 기준값의 조회·검색)에 약관 문서 키가 없다. 진입 시도는 **system.permission_denied/403**이며 부분 열람 모드를 두지 않는다. 사이드바에서도 ADMIN 미만에게 이 항목을 노출하지 않는다 |
| 세션 만료 | auth.token_invalid/401 · auth.csrf_token_invalid/403이면 **작성 중인 본문 전문과 종류·버전·유효 시작일 입력을 그대로 유지한 채** 재로그인 모달을 띄우고 복귀 후 사용자가 다시 제출한다. 약관 본문은 이 문서군에서 가장 긴 자유입력이라 유실 비용이 가장 크다. **활성 전환은 자동 재제출하지 않는다** — 만료 전 요청이 닿아 이미 활성이 바뀌었으면 재동의 흐름이 두 번 트리거된다(§1-4) |

**데이터 연동**

- 종류별 버전 목록·메타 조회(**본문 없음** · 검색·활성 필터 지원 · q·isActive는 B1 신설) → GET /v1/system/terms-documents?kind=&q=&isActive= → **terms_documents**
- 버전 상세·본문 조회 → GET /v1/system/terms-documents/{termsDocumentId}(#35 · 활성·비활성 무관 · TermsDocumentResponse = Summary + body)
- 버전 작성 → POST /v1/system/terms-documents → **terms_documents** · **audit_logs**
- 활성 전환 · 비활성화 → POST /v1/system/terms-documents/{termsDocumentId}/activate → **terms_documents** · **user_consents** · **audit_logs**
- 목록 내보내기(DSH-06 · listType system_terms_documents · 비민감) → POST /v1/system/list-exports → GET /v1/list-exports/download/{token} → **audit_logs**(list.export)
- 상세 정본은 [../06_api/14_system.md](../06_api/14_system.md)다.

**담은 기능ID**: SYS-11

**비고**: **이 화면은 조회조차 ADMIN 전용이다** — 버전 이력과 비활성본은 운영 정보이고, VIEWER 권한 집합에 약관 문서 키가 없어 부분 열람을 표현할 수단 자체가 없다. 조회를 VIEWER에게 열려면 권한 키를 새로 채번해야 하므로 v1은 등급을 단일화한다. **활성 버전이 종류별로 정확히 1개라는 불변식이 이 화면의 존재 이유**다. 0개면 가입 동의가 참조할 대상이 없어 가입 자체가 막히고, 2개면 어느 문서에 동의한 것인지 이력이 갈린다. 그래서 화면은 활성 전환을 교체 조작 하나로만 열고 활성 해제 단독 조작을 두지 않는다. **개정은 되돌릴 수 없는 작업이 아니라 새 버전 추가**이므로 재인증을 요구하지 않지만, **재동의 흐름을 트리거해 전 사용자에게 영향이 가므로 발효 확인 단계에서 그 영향을 반드시 표시**한다. 저장은 낙관적 갱신을 쓰지 않는다(§3-6) — 중복 버전과 참조 검사를 서버가 판정하므로 화면이 성공을 먼저 그리면 거부된 발효가 반영된 것처럼 보인다. **이전 버전 원문의 공개 게시는 v1에 두지 않으므로**(PUB-LEGAL) 이 화면이 과거 버전 원문을 보유해야 하는 의도상 유일한 표면이지만, **지금은 그 원문을 다시 읽을 표면이 없다**(D-12 · F-20 전) — 관리 목록(#30)이 본문을 싣지 않고 본문 읽기는 활성본 전용 공개 표면뿐이라, 비활성 버전을 고르면 차단 사유로 그 사실을 보여줄 뿐 원문을 보여주지 못한다. 데이터베이스 행 자체는 지우지 않으므로 값이 사라진 것은 아니고 **읽는 표면이 아직 채번되지 않은 것**이다. 동의 이력이 참조하는 한 그 행을 지우지 않는다.
