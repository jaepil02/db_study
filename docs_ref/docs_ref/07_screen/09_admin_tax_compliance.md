본 파일은 관리자 웹 사이드바 "신고·법정 준수" 섹션 6항목의 화면 명세다. 앞 세 화면은 **퇴사 한 건이 켜는 세 개의 시계**(4대보험 상실신고 · 이직확인서 · 금품청산과 퇴직금 지급)를 다루고, 뒤 세 화면은 **다른 도메인의 판정 전제**를 만든다. 특히 상시근로자 산정(ADM-EMPLOYEE-COUNT)은 5인·10인 분기의 유일한 근거이며 그 스냅샷이 없으면 근태 마감·급여 확정·연차 발생이 모두 차단되므로 이 섹션에서 유일하게 P0다.

**v1의 산출물은 자료 생성까지이며 홈택스·4대보험 EDI 직접 제출은 하지 않는다.** 신고서 데이터와 업로드용 파일을 만들어 주고 제출은 사용자가 수행한다. 그래서 이 섹션의 화면 문안은 "신고가 완료됩니다"가 아니라 "자료를 만들었습니다"로 적고, 제출 경로를 어디서 이어 가야 하는지 함께 안내한다. **만들지 않는 신고 자료는 부정형으로 명시**해 미지원이 미이행으로 이어지지 않게 한다(§3-7 미지원 고지).

**계산·판정 결과는 참고자료이며 신고·납부의 최종 책임은 사업주에게 있다**(REQ-GLB-20). 신고자료·이직확인서·기한 캘린더 화면에는 책임 한계 고지를 닫기 버튼 없이 상시 노출하고, 법정 판단이 필요한 지점(사업 단위 독립성)은 제품이 대신 판정하지 않고 사용자 선언 + 경고로 처리한다. 데이터 연동의 메서드 경로는 [../06_api/01_conventions.md](../06_api/01_conventions.md)의 자원 명명·사업장 스코프·멱등 규약을 따르며, 표면 전수와 요청·응답 규격의 정본은 [../06_api/10_tax.md](../06_api/10_tax.md) · [../06_api/11_compliance.md](../06_api/11_compliance.md)다.

## ADM-TAX-FILING — 4대보험 취득·상실 신고자료

| 항목 | 내용 |

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 신고 대상 목록 | **이미 만든** 취득·상실 신고자료를 직원·보험별로 보여준다. **이 목록은 생성 결과만 담는다** — 입사·퇴사 이벤트에서 파생되는 후보 피드가 아니므로 행 선택만으로는 첫 자료를 만들 수 없다(행 선택은 이미 있는 자료의 재생성에만 쓴다). **자료 생성까지가 제품의 범위이며 자동 제출은 하지 않는다** — 홈택스·4대보험 EDI에서 직접 제출해야 한다는 안내를 목록 상단에 상시 노출한다 | TAX-01 |
| 자료 생성 대상 선택 | **후보는 직원 원장에서 온다** — 첫 자료를 만드는 동선은 별도 모달이 열고, 대상 선택은 목록이 아니라 직원 원장(입사·퇴사 이력)의 직원 선택기가 맡는다. 신고 유형(자격취득·자격상실)을 먼저 고르고 그 유형에 해당하는 직원을 고른다. 자격취득·자격상실은 한 번에 만들 수 없다 | TAX-01 |

**레이아웃·스크롤·모바일**: 목록+상세 페인(MD) 배치다. 기준일 선택기 · 임계값 전환 · 표 헤더 행을 스크롤 밖에 고정하고 스냅샷 목록 표와 옆 판정 근거 페인이 각자 스크롤 소유자(ScrollRegion)다. 목록에서 고른 기준일의 판정 근거(제1항·제2항 대조 · 일자별 시계열)가 옆 페인에 자동 선택으로 열린다. 시계열 표는 자체 가로 스크롤 컨테이너를 갖고 날짜 열을 고정한다. 추이 표시는 포인터 전제 요소이므로 같은 수치를 담은 시계열 표를 대체 경로로 둔다(§5-1). 1024 미만에서는 분할이 스택되어(그 폭에서는 자동 선택을 끈다) 스냅샷 목록이 기준일당 카드로 전환되고, 시계열은 가로 스크롤 컨테이너를 유지한다.

| 빈 상태 | 3분기다 — ① 전체 0건: "아직 산정된 스냅샷이 없습니다" + 산정 실행 CTA와 **스냅샷이 없으면 마감·확정·연차가 차단된다**는 사실 병기 ② 권한: "열람할 수 있는 산정 결과가 없습니다" ③ 필터 0건: "조건에 맞는 기준일이 없습니다" + 필터 초기화 |
| 에러 | common.validation_failed/400 → 기준일·수동 정정 입력의 서버 필드 경로를 그대로 필드에 붙인다 · common.conflict/409 → 같은 기준일 **같은 산정 범위**의 스냅샷이 이미 있음을 알리고 기존 스냅샷을 보여준다 · common.not_found/404 → 스냅샷 부재를 알리고 목록으로 되돌린다 · 가동일수가 0인 산정기간은 산정 불가 사유로 안내하고 기간을 다시 고르게 한다 |
| 권한거부 | **권한 안내**다. MANAGER 미만은 사유와 다음 행동을 화면 안에서 안내한다 |

**데이터 연동**

- 스냅샷 목록·상세 조회 → GET /v1/workplaces/{workplaceId}/employee-count-snapshots → **workplace_employee_count_snapshots** · **employee_count_snapshot_days**
- 산정 실행·확정 → POST /v1/workplaces/{workplaceId}/employee-count-snapshots(Idempotency-Key 필수 · 기준일) → **workplace_employee_count_snapshots** · **employee_count_snapshot_days** · **audit_logs**
- 산정 대상 범위 조회 → GET /v1/workplaces/{workplaceId}/employees(근로자성 필터) → **employees**
- **기본 정렬**: 기준일 내림차순 · 식별자 내림차순이다 — §3-4 전역 기본값의 시간 축을 기준일로 잡는다
- 상세 정본은 [../06_api/11_compliance.md](../06_api/11_compliance.md)다.

**담은 기능ID**: CMP-01

**비고**: 이 섹션에서 유일한 **P0**이며 그 이유는 다른 화면의 전제를 만들기 때문이다 — 스냅샷이 없으면 5인 분기가 임의값으로 계산되고, 그러면 가산수당·연차·공휴일 유급이 통째로 틀린다. 그래서 차단을 완화하는 우회 경로(기본값 · 직전 기준일 값 재사용)를 화면에 두지 않는다. **경계 판정을 반올림 평균으로 보여주지 않는 것도 같은 이유**다 — 화면이 4.6명을 5명으로 그리면 사용자는 정수 비교 결과와 다른 결론을 갖게 된다. 산정 실행은 부수효과가 크므로 낙관적 갱신을 쓰지 않고 서버 확정 후에만 화면을 갱신한다(§3-6).

## ADM-BUSINESS-UNIT — 사업 단위 판정

| 항목 | 내용 |
|------|------|
| 화면코드 | ADM-BUSINESS-UNIT |
| 라우트 | web_front SPA /compliance/business-unit |
| 접근권한 | MANAGER(조회) / OWNER(독립성 선언) |
| 우선순위 | P1 |

**목적**: 동일 사업주의 복수 사업장이 실질적으로 하나의 사업인지 선언해 상시근로자 산정의 범위를 정한다.

**진입경로**: 사이드바 신고·법정 준수 > 사업 단위 판정 · ADM-WORKPLACE-CREATE에서 두 번째 사업장을 등록한 직후 판정 요청 안내 · ADM-EMPLOYEE-COUNT의 산정 범위 링크 · 미판정 위험 경고 알림 바로가기.

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 대상 사업장 그룹 표시 | 동일 사업주의 사업장을 한 그룹으로 묶어 보여주고 각 사업장의 인원과 현재 판정 상태를 표시한다. **사업자등록번호가 별개인지는 판단 기준이 아니라는 사실**을 그룹 설명에 명시한다 | CMP-08 |
| 볼 수 없는 사업장을 없는 것으로 두지 않는다 | 그룹의 **수**(groupSiteCount)와 **상세 목록**은 다른 축이다 — 사업장 조회가 멤버십 축이라 그룹의 다른 사업장에 멤버십이 없는 MANAGER 에게는 목록이 자기 자신 하나뿐이 된다. **목록 길이로 그룹 유무를 판정하지 않는다**: 그러면 "없다"와 "못 본다"가 같은 결론이 되어 화면이 사실과 다르게 단정한다. 수가 목록보다 크면 "같은 사업자등록번호로 등록된 사업장은 N곳입니다. 그중 M곳은 이 계정에 멤버십이 없어 상세를 표시하지 않습니다"를 적고, **상호·인원은 표시하지 않는다**(테넌트 경계) | CMP-08 |
| 독립성 체크리스트 4항 선언 | ① 인사·노무관리 독립 ② 예산·회계 독립 ③ 사업장별 경영담당자 존재 ④ 근로조건 결정권 전속을 **사용자가 선언**한다. 각 항목에 판단 근거를 텍스트로 남기고 근거 없이 체크만 하는 제출을 막는다 | CMP-08 |
| 자동 합산 불가 안내 | **자동 합산은 법적 판단이라 제품이 수행하지 않는다** — 선언 + 경고 방식임을 화면 상단에 명시하고, 체크 결과가 곧 법적 판정이 아니라는 점을 함께 적는다 | CMP-08 |
| 미판정 위험 경고 | 판정하지 않은 그룹에는 위험 경고를 상시 노출한다. **판정 축은 그룹의 수이고 보이는 목록이 아니다** — 위험은 요청자가 보든 못 보든 있으므로, 보이지 않는다는 이유로 경고를 접으면 이 기능의 존재 이유가 조회 권한 경계에서 무효화된다. **3인 매장 두 곳을 사업주가 직접 관리하면 실질 6인이라 5인 이상 규정이 적용되는데 사업장별로만 산정하면 5인 미만으로 잘못 판정된다**는 구체적 위험을 문안으로 적는다 | CMP-08 |
| 통합 운영 선언 시 합산 표시 | 통합 운영으로 선언되면 상시근로자를 합산 산정한다는 사실과 합산 시 예상되는 경계 판정 변화를 함께 보여주고 ADM-EMPLOYEE-COUNT로 잇는다 | CMP-08 |
| 선언 확정 | **OWNER 전용이다** — MANAGER는 체크리스트와 근거를 보되 확정할 수 없고 시도는 auth.workplace_forbidden/403이다. 확정 시 선언 내용과 근거가 감사 기록으로 보존된다는 사실을 확인 단계에서 명시한다 | CMP-08 |

**주요 UI 요소**: 사업장 그룹 카드(사업장별 인원·판정 상태), 미판정 위험 경고 배너, 독립성 체크리스트 4항 폼(항목별 근거 입력), 자동 합산 불가 안내, 합산 시 경계 변화 미리보기, 선언 확정 확인 단계, 선언 이력·감사 근거 목록.

**레이아웃·스크롤·모바일**: 섹션 화면(SN) 변형이다 — 왼쪽 세로 섹션 목록("사업장 그룹"·"독립성 선언") + 오른쪽 한 섹션이며 선택은 탭 쿼리 section이 소유한다. 페이지 헤더와 미판정 위험 경고 배너를 스크롤 밖에 고정하고 연 섹션 본문이 스크롤 소유자(ScrollRegion)가 된다. 체크리스트는 항목마다 근거 입력이 따라오므로 세로로 길어지며, 확정 액션은 "독립성 선언" 섹션을 보는 동안만 하단 액션 바로 고정해 스크롤 위치와 무관하게 도달할 수 있게 한다(그 폼이 없는 "사업장 그룹" 섹션에서는 액션 바를 내지 않는다). 확인 단계는 새 레이어를 열지 않고 같은 폼 안의 단계 전환으로 처리한다. 1024 미만에서는 섹션 목록 없이 전 섹션을 세로로 쌓고 본문이 스크롤한다. **판정할 그룹이 없는 빈 상태는 화면 영역 중앙에 둔다.**

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 그룹 카드와 체크리스트 폼의 자리를 그대로 잡는 스켈레톤을 깔고 진행을 상태 영역으로 알린다 |
| 빈 상태 | 3분기다 — ① 전체 0건(**groupSiteCount가 1**): "판정할 사업장 그룹이 없습니다" + "같은 사업자등록번호로 등록된 사업장이 이 한 곳뿐이라 사업 단위 판정 대상이 아닙니다" ② 권한: "열람할 수 있는 사업장 그룹이 없습니다" ③ 필터 0건: 해당 없음 — 이 화면은 필터 축을 두지 않고 그룹 전량을 보여준다. **①의 판정 축은 상세 목록의 길이가 아니다** — 목록이 비었어도 수가 둘 이상이면 빈 상태가 아니라 "못 보는 사업장이 있는 그룹"이다 |
| 에러 | common.validation_failed/400 → 체크 항목·근거 입력의 서버 필드 경로를 그대로 필드에 붙인다 · auth.workplace_forbidden/403 → 선언 확정이 OWNER 전용임을 밝히고 요청 경로를 안내한다 · common.not_found/404 → 대상 사업장 그룹 부재를 알리고 목록으로 되돌린다 · common.conflict/409 → 다른 사용자가 먼저 선언을 확정했음을 알리고 최신 상태를 다시 읽는다 |
| 권한거부 | **권한 안내**다. MANAGER는 화면을 열되 선언 확정 컨트롤이 비활성으로 보이고 사유와 OWNER 요청 경로가 함께 표시된다 — **컨트롤을 감추지 않는 것은 자기 권한 밖을 알아야 상위에게 요청할 수 있기 때문**이다(§4-1) |

**데이터 연동**

- 사업장 그룹·판정 상태 조회 → GET /v1/workplaces/{workplaceId}/business-unit-assessment → **business_units** · **workplaces**(상세는 멤버십 범위 · **수는 그 밖까지**)
- 독립성 선언·확정 → PUT /v1/workplaces/{workplaceId}/business-unit-assessment(**OWNER** · 사유·근거 필수) → **business_units** · **audit_logs**
- 합산 시 경계 변화 조회 → GET /v1/workplaces/{workplaceId}/employee-count-snapshots(합산 범위 파라미터) → **workplace_employee_count_snapshots**
- 상세 정본은 [../06_api/11_compliance.md](../06_api/11_compliance.md)다.

**담은 기능ID**: CMP-08

**비고**: **이 판정이 없으면 사용자를 법 위반에 노출시킨다** — 구독 등급이 복수 사업장을 허용하므로 유료 사용자에게 바로 발생하는 문제다. 그래서 미판정을 조용한 기본값으로 두지 않고 위험 경고를 상시 노출한다. 제품이 자동 판정하지 않는 것은 회피가 아니라 **법적 판단의 주체를 사업주로 고정하는 설계**이며, 그래서 선언 주체를 OWNER로 좁히고 근거를 감사에 남긴다. 선언은 되돌릴 수 있으나 이미 그 선언으로 산정된 스냅샷은 자동으로 다시 계산되지 않는다 — 재산정은 ADM-EMPLOYEE-COUNT에서 별도로 실행한다.

| 기한 과제를 만들지 않음 | **보존은 기한 과제로 관리하지 않는다** — compliance_tasks에 보존 유형을 두지 않으므로 이 화면에 완료·면제 전이 컨트롤이 없다. 보존기한의 단일 근거는 **각 보유처 행의 보존기한 열**이며 화면은 그 값을 읽어 목록으로 제시한다. 기한 과제 축은 신고·지급 기한 전용이고 그 표면은 ADM-DEADLINE-CALENDAR다 | CMP-04 |
| 문서 실체 참조 표시 | 파일 실체와 해시는 문서가 일원 보유한다는 사실을 표기한다. **파일이 없는 행이 정상이다** — 임금대장·근로자명부는 관리자가 PDF 를 내려받기 전까지 문서 행 자체가 없으므로 "내보낸 파일 없음"으로 적고, 그것을 결함이나 누락으로 보이게 하지 않는다 | CMP-04 |
| 조회 대상은 물리 보유처 4곳이다 | 목록의 원장은 문서함이 아니라 **계약 행 · 급여 실행 행 · 직원 행 · 명세서 행**이다(REQ-CMP-10). **문서함만 훑으면 임금대장과 근로자명부가 목록에서 통째로 빠진다** — 그 둘은 파일로 존재하기 전부터 보존 의무가 있는 서류다. 유형 축은 문서함 분류가 아니라 **보존 서류 4종**(근로계약서 · 임금대장 · 근로자명부 · 임금명세서)이며, 문서함 분류는 앞의 둘을 같은 값으로 접어 갈라 볼 수 없다 | CMP-04 |

**주요 UI 요소**: 유형·대상자 검색형 콤보박스 필터와 기한 기준일 선택기, 유형별 기산일 안내 표, 보존 대상 목록 표(유형·대상·기산일·보존기한·잔여일·상태), 기산일 미설정 경고 스트립, 보존기한 도달 안내 스트립, 소관 화면 이동 링크(문서함·근로계약·명세서).

**레이아웃·스크롤·모바일**: 필터 바 · 기산일 안내 표 · 목록 표 헤더 행을 스크롤 밖에 고정하고 보존 대상 목록 표만 스크롤한다. 목록은 유형·기산일·기한·잔여일 열이 붙어 넓어지므로 자체 가로 스크롤 컨테이너를 갖고 대상 열을 고정한다. **행 안에 실행 액션이 없으므로 인라인 확인 줄도 두지 않는다** — 이 화면의 모든 행 액션은 소관 화면으로의 이동뿐이다. 768 미만에서는 목록이 서류당 카드로 전환되고 기산일·보존기한이 카드 안 정의 목록이 된다.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 목록 표와 같은 열 구성의 스켈레톤을 깔고 조회 진행을 상태 영역으로 알린다 |
| 빈 상태 | 3분기다 — ① 전체 0건: "보존 관리 대상 서류가 없습니다" + 근로계약·임금대장·근로자명부·임금명세서가 대상을 만든다는 안내와 각 화면 링크 ② 권한: "열람할 수 있는 서류가 없습니다" ③ 필터 0건: "조건에 맞는 서류가 없습니다" + 필터 초기화 |
| 에러 | common.validation_failed/400 → 필터·기준일 등 서버가 준 필드 경로를 그대로 필드에 붙인다 · common.not_found/404 → 대상 서류 부재를 알리고 목록으로 되돌린다 · 기산일 미설정 건은 오류가 아니라 안내 상태로 표시하고 기산일 입력 경로를 둔다 |
| 권한거부 | **권한 안내**다. MANAGER 미만은 사유와 다음 행동을 화면 안에서 안내한다 |

**데이터 연동**

- 보존 대상 목록 조회 → GET /v1/workplaces/{workplaceId}/retention(유형 필터 documentType · 대상자 필터 employeeId · 자유검색 q(대상자명) — q·employeeId는 신설 · B1) → **contracts** · **payroll_runs** · **employees** · **payslips**(원장 4곳) + **documents**(파일 실체만 붙이는 바깥 조인)
- 보존기한 도달 목록 조회 → GET /v1/workplaces/{workplaceId}/retention/due(기준일만 받는다 — q · 쪽 나눔 파라미터가 없다) → 같은 원장 4곳. **전량 표면이다**(REQ-CMP-10) — 화면이 유형·대상자·검색을 받은 결과 안에서 클라이언트로 마저 거른다
- 목록 내보내기: POST /v1/workplaces/{workplaceId}/list-exports(listType=retention · 비민감)로 조건에 맞는 전 행을 파일로 낸다. 문서함 이동 링크 열은 싣지 않는다
- **쓰기 표면이 하나도 없는 완전 조회 전용 화면이다** — 파기 실행도, 기한 과제 상태 갱신도 두지 않는다. compliance_tasks를 읽지도 쓰지도 않는다.
- **기본 정렬**: 보존기한 오름차순(만료가 가까운 건이 위)이며 동률은 보유처 행 식별자 오름차순이다. 정렬 축은 보존기한 · 유형 · 기산일 셋이고 **기산일 미설정 건은 어느 방향이든 목록 맨 뒤**다(NULLS LAST) — 기한을 산정할 수 없는 행이 첫 쪽을 덮지 않는다. 별도 구획으로 갈라 모으지 않고 정렬 계약 하나로 처리한다(구획을 만들면 쪽 나눔과 정렬이 서로 다른 모집단을 보게 된다)
- 상세 정본은 [../06_api/11_compliance.md](../06_api/11_compliance.md)다.

**담은 기능ID**: CMP-04

**비고**: **v1은 파기를 실행하지 않는다 — 보유처 행의 보존기한을 읽어 목록으로 제시하는 것까지가 범위다**(REQ-CMP-10). 자동 파기 정기작업(purgeExpiredData)이 v1.1 이월이고 수동 파기 표면도 두지 않는다. **보존을 기한 과제로 승격하지 않은 것이 이 화면의 범위 판단**이다 — 과제로 만들려면 생성 주체와 기산 이벤트를 새로 채번해야 하는데, 보존기한은 이미 각 보유처 행이 결정론적으로 갖고 있어 두 번째 정본을 만들 이유가 없다. 기산일이 유형마다 다르고 근로계약서처럼 재직 중 기한이 미확정인 축이 있어서 **기산일 관리가 안정화되기 전의 파기는 그 자체가 위반**이 될 수 있기 때문이다. 파기가 필요해지면 v1에서는 문서함(ADM-DOCUMENTS)의 소관 경로와 운영 절차로 처리하고 실행 이력은 감사 로그가 받는다. 유형별 기산일 표를 화면 안에 두는 것은 장식이 아니라 **가장 자주 틀리는 지점을 목록과 나란히 보여주기 위한 설계**다. 문서 실체는 문서 테이블이 일원 보유하므로 이 화면은 보존기한 축의 뷰이며 파일 원문 열람 경로를 새로 만들지 않는다. **문서 테이블을 원장으로 삼지 않는 것과 파일을 그것이 보유하는 것은 같이 성립한다** — 원장은 무엇이 언제까지 남아야 하는가이고 문서 테이블이 드는 것은 그 서류의 파일이다.
