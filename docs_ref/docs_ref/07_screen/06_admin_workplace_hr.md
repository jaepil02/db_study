본 파일은 관리자 웹의 **홈 하나**(ADM-HOME)와 **사업장 축 넷**(사업장 설정 · 멤버 · 임포트 · 구독) · **인사 축 다섯**(직원 목록 · 직원 상세 · 퇴사 처리 · 근로계약 · 문서함)을 담는다. 사업장 축 넷은 테넌트 자체를 다루고 인사 축 다섯은 그 안의 사람을 다룬다. 사업장이 검증되지 않았거나 인원 한도가 막혀 있으면 인사 축의 화면은 열려도 실행이 차단되므로, 차단 사유를 인사 화면에서 다시 설명하지 않고 사업장 축 화면으로 되돌려 보낸다.

**홈이 이 파일에 있는 것은 어느 도메인도 홈을 소유하지 않기 때문이다.** 홈은 근태·휴가·급여·신고·검증·구독의 대기와 상태를 한 자리에 모으므로 도메인 파일 어디에 두어도 그 파일의 축을 넘어선다. 그중 **검증 상태(WRK-14)와 구독 한도(SUB-05)는 이 파일의 사업장 축이 소유하는 기능**이라, 홈이 다른 도메인에서 빌려 오는 것보다 여기서 나가는 것이 많다.

열 화면 중 넷이 **되돌릴 수 없는 작업 또는 민감정보 원문 접근**을 포함한다 — 사업장 폐쇄 · 임포트 확정 · 민감정보 원문 복호화 · 민감 문서 다운로드다. 확인 단계·재인증·멱등 규격의 정본은 [01_standards.md](./01_standards.md) §3-2이고 낙관적 갱신 금지 대상의 정본은 같은 문서 §3-6이며, 본 문서는 화면별 차이만 적는다.

접근권한 칸은 §1-1의 6값을 쓰고 액션별로 갈리면 함께 적는다. **MANAGER가 화면을 열 수 있으나 OWNER만 실행할 수 있는 액션은 항목을 감추지 않고 화면 안에서 비활성 컨트롤과 사유로 노출**한다(§4-1) — 감추면 MANAGER가 무엇을 상위에게 요청해야 하는지 알 수 없다.

## ADM-HOME — 관리자 홈

| 항목 | 내용 |
|------|------|
| 화면코드 | ADM-HOME |
| 라우트 | web_front SPA /home |
| 접근권한 | MANAGER |
| 우선순위 | P0 |

**목적**: 이 사업장이 한 달을 닫는 데 어디까지 왔는지 · 오늘 누가 나왔는지 · 지금 손이 필요한 것이 무엇인지를 한 화면에서 확인하고 그 화면으로 바로 간다.

**진입경로**: 로그인 후 사업장이 정해지면 도착하는 첫 화면 · 사이드바 홈 · 셸 로고 · 다른 화면을 모두 닫았을 때 남는 탭(§4-4).

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 마감 진행 보드 | 한 귀속월을 **근태 마감 → 급여 확정 → 명세서 교부 → 신고 기한** 네 칸으로 낸다. **대상 귀속월은 전월·당월 중 명세서 교부가 끝나지 않은 가장 이른 월**이다 — 교부가 끝났다는 것은 유효 실행(무효를 뺀 최고 버전)이 확정이고 교부 완료 명세서 수가 실행 인원에 닿았다는 뜻이다. 앞 달을 아직 읽는 중이면 대상을 정하지 않고 기다린다(뒤 달을 먼저 보였다가 앞 달로 바뀌면 보드가 튄다). 전월·당월 전환을 둔다. 칸마다 값과 판단에 쓰는 서버 값을 적는다 — ① 마감됨 · 미마감 + 차단 사유 **건수** · 마감 시각 ② 유효 실행의 상태(실행 없음 · 작성 중 · 계산됨·미확정 · 확정됨) · 대상 인원 · 지급일 · 지급 총액 ③ 교부 완료 수 / 실행 인원 + 진행 막대 ④ 기한 경과 · 임박 건수 + 가까운 기한 셋. 칸의 상태는 **바닥 라벨(완료 · 지금 할 일 · 대기 · 막힘)과 칸 톤 한 곳**이 말한다 — 첫 미완료 칸이 "지금 할 일", 차단·기한 경과 칸이 "막힘"이다. 머리에 상태 아이콘을 더하지 않는다(값 "마감됨"과 함께 같은 상태를 세 번 말하게 된다). 칸을 누르면 그 단계의 화면 탭이 열린다(ADM-ATTENDANCE-CLOSING · ADM-PAYROLL-RUN · ADM-PAYSLIP · ADM-DEADLINE-CALENDAR). **마감·확정·교부는 이 화면에서 하지 않는다** | ATT-08(상태 표시) · PAY-08(상태 표시) · SLP-03(상태 표시) · TAX-11(경고) |
| 오늘 출근 보드 | 재직 직원 한 사람씩 **지금 상태 7종**(휴가 · 근무 중 · 퇴근 · 승인 대기 · 미출근 · 출근 전 · 휴무)을 텍스트 라벨로 낸다. 기록이 있으면 기록 상태(정확도 초과 대기 → 승인 대기 · 퇴근 전 → 근무 중 · 퇴근), 없으면 오늘을 덮는 승인 휴가 → 휴가, 오늘 적용 편성(예외일이 주 패턴보다 우선)의 시작 + 허용오차가 지났으면 미출근 · 아직이면 출근 전, 편성이 없으면 휴무다. **지각·조퇴·결근을 판정하지 않는다** — 판정은 일 집계의 몫이다. 시각 비교는 KST 벽시계 분 단위이며 편성 시각 문자열과 견준다. 위쪽 상태 칩(0명 상태는 걷는다)을 누르면 그 상태만 남고, 미출근 · 승인 대기를 목록 위에 둔다. 한 줄은 **이름 · 시간 · 상태 세 칸**이다 — 시간 칸은 기록이 있으면 출근(· 퇴근) 시각, 휴가면 휴가 종류 · 반차, 기록이 없으면 오늘 편성이고 휴무면 비운다(이름 아래에 겹쳐 적지 않는다). **화면이 다시 보일 때**(탭 재활성 · 창 포커스) 새로 읽고 주기 조회는 두지 않는다 | ATT-10 |
| 인건비 추이 | 최근 12개월(당월 포함) 확정 급여를 **x축 귀속월 · y축 금액의 선 차트**로 낸다. 주 계열은 **월 지급 총액**이고, 인건비(지급 총액 + 사업주 부담) 계열은 값이 한 달이라도 있을 때만 긋는다 — 계열이 둘이면 범례를 두고 둘째 계열은 점선 · 네모 점으로 색만으로 가르지 않는다. y축은 0을 포함한 보기 좋은 눈금 3~5개(1 · 2 · 5 × 10^k, 만 단위로 줄여 적는다)와 가는 격자선, x축은 월 이름이 겹치지 않게 건너뛰되 당월은 늘 적는다. **달에 마우스를 올리거나 차트에 포커스한 뒤 ←/→로 옮기면 세로 안내선과 툴팁으로 그달의 정확한 값**("23,100,000원")을 낸다 — 보이는 툴팁과 같은 문장을 보조 기술에도 알린다. 카드 윗줄 읽기 칸은 가장 최근 확정 달의 지급 총액 · 사업주 부담 · 인건비다 — **사업주 부담과 인건비가 둘 다 비면 "인건비 산출 안 됨" 한 번**으로 줄이고 사유(사업주 부담 보험료 미산출)는 그 옆 ⓘ가 연다. **차트 ⇄ 표 보기 전환**을 둔다 — 표는 월 · 지급 총액 · 사업주 부담 · 인건비 네 열로 같은 값을 모두 담는 대체 경로다. **사업주 부담 보험료가 산출되지 않은 달은 부담분과 인건비를 "산출 안 됨"으로 적고 0으로 채우지 않는다** — v1은 사업주 부담분을 산출하지 않아 서버가 두 값을 싣지 않으므로 늘 값이 있는 지급 총액이 주 계열이다. **확정 급여가 없는 달은 선을 끊고 점을 찍지 않으며** 툴팁은 "확정 급여 없음", 표는 "—"다(0으로 이으면 0이었다고 읽힌다). **금액을 화면이 다시 계산하지 않고** 점의 위치와 눈금만 정수로 센다(금액이 부동소수점을 거치지 않는다) | DSH-03 |
| 업무 카드 | 한 카드의 **탭 둘**이다 — 할 일 · 알림. **기한 임박 탭을 두지 않는다** — 마감 진행 보드의 신고 기한 칸이 같은 과제 집합(열린 신고 과제 · 기한 경과 포함)을 경과 · 임박 건수와 가까운 기한 셋으로 이미 말하고 기한 캘린더로 잇는다. 탭 이름 옆 숫자가 어디에 손이 필요한지 먼저 알린다. 탭을 따로 카드로 세우면 0건일 때 카드가 사라져 격자에 구멍이 나므로 한 자리를 나눠 쓴다 | — |
| 할 일 탭 | **승인 대기 근태 수정 요청 수 · 대기 휴가 신청 수 · 정확도 초과 대기 체크인 수** 셋을 숫자로 낸다. 각 숫자를 누르면 해당 화면 탭이 열린다 — 근태 수정은 ADM-ATTENDANCE-APPROVAL · 휴가는 ADM-LEAVE-APPROVAL · 정확도 대기는 ADM-ATTENDANCE다. **0이면 그 줄을 내지 않고**, 셋 다 0이면 사실 한 줄만 적는다 | ATT-07(대기 표시) · LEV-03(대기 표시) |
| 알림 탭 | 최근 알림 **5건**을 제목·시각으로 낸다. 각 항목은 알림이 지목하는 화면으로 보낸다. **읽음 처리와 전체 목록은 헤더 알림 벨이 소유하고 홈은 읽기만 한다** | NTF-01(표시) |
| 검증 상태 경고 | 사업장이 검증 대기 상태면 **무엇이 막혀 있는지**(급여 확정 · 명세서 발행)와 자동 정지 예정일·남은 일수를 **한 줄 고지**로 적고 ADM-WORKPLACE-SETTINGS의 재검증으로 보낸다. 값이 없으면 날짜 자리를 비운다. 활성 상태에서는 줄을 내지 않는다 | WRK-14(경고) |
| 구독 경고 | 인원 한도 임박·초과와 구독 만료 임박을 사용량 대비로 **한 줄 고지**에 적고 ADM-SUBSCRIPTION으로 보낸다. **한도 초과(402)와 권한 부족(403)을 문안으로 구분**한다(§1-2). 여유가 있으면 내지 않는다 | SUB-05(경고) |

**주요 UI 요소**: 한 줄 고지 자리(검증 상태 · 구독 — 둘까지), 마감 진행 카드(머리의 귀속월 전환 · 다시 읽기 + 네 칸), 오늘 출근 보드(상태 칩 + 직원 목록), 인건비 추이 카드(차트 ⇄ 표 전환 + 최근 달 읽기 칸 + 기간 툴팁), 업무 카드(할 일 · 알림 탭).

**레이아웃·스크롤·모바일**: **대시보드 배치(DB)**다(§5-3) — 1024 이상에서 12열 × 2행 격자가 콘텐츠 영역을 정확히 채우고 **콘텐츠 영역은 스크롤하지 않는다.** 1행은 마감 진행 보드 8칸 · 오늘 출근 보드 4칸(2행에 걸친다), 2행은 인건비 추이 4칸 · 업무 카드 4칸이다. 넘치는 분량은 **카드 안의 이름 있는 스크롤 영역**(오늘 출근 직원 · 업무 탭 본문 · 마감 단계)만 스크롤한다. **툴바 줄을 두지 않는다** — 액션이 다시 읽기 하나라 세로 한 단이 비므로 다시 읽기는 귀속월 전환과 함께 마감 진행 카드 머리에 둔다. 한 줄 고지는 격자 위 스크롤 밖이다. 마감 진행 보드의 칸 수는 창 폭이 아니라 **카드 폭**으로 정한다(4칸 한 줄 ⇄ 2칸 두 줄). 1024 미만은 1열로 쌓고 본문이 스크롤하며 순서는 마감 진행 → 오늘 출근 → 인건비 추이 → 업무다(§5-2). **표를 두지 않으므로 §3-4 · §3-8의 표 축은 이 화면에 적용되지 않는다**(인건비 표 보기는 카드 안의 대체 표현이다).

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 카드마다 같은 레이아웃의 스켈레톤을 그리고 **먼저 온 카드부터 채운다** — 카드가 서로 다른 조회를 쓰므로 하나를 기다려 화면 전체를 덮지 않는다(§5-1) |
| 빈 상태 | **막을 것도 할 것도 없는 상태가 정상**이다 — 경고 줄은 내지 않고 정상임을 알리는 배너를 대신 두지 않는다(§8 · §3-10). 카드 자리는 늘 남는다: 할 일 0건은 "승인을 기다리는 요청이 없습니다", 알림 0건은 "아직 알림이 없습니다", 재직 직원 0명은 "재직 중인 직원이 없습니다", 확정 급여 0건은 "아직 확정된 급여가 없습니다"로 적는다 |
| 에러 | **카드 단위로 격리한다** — 한 조회가 실패해도 나머지 카드는 그대로 두고 실패한 카드 자리에 "불러오지 못했습니다"와 다시 시도를 둔다. 홈 전체를 실패 화면으로 바꾸지 않는다: 홈이 열리지 않으면 사용자가 다른 화면으로 갈 진입점까지 함께 잃는다. 429는 Retry-After를 존중해 재시도 시점을 안내한다 |
| 권한거부 | STAFF의 관리자 웹 진입은 §1-2 **권한 안내**이며 ADM-WORKPLACE-SELECT로 되돌린다. MANAGER에게 **OWNER 전용 값(구독)이 403으로 막히면 그 줄만 감추고** 나머지는 그대로 낸다 — 홈은 실행 표면이 아니라 그 줄이 없다고 해서 사용자가 잃는 조치가 없다. 인건비 추이가 403이면 카드 안에 권한 안내를 적는다 |

**데이터 연동**

- 근태 마감 상태 → GET /v1/workplaces/{workplaceId}/attendance/closings → **attendance_period_closings**(행이 LOCKED면 마감)
- 미마감 기간의 차단 사유 건수 → GET /v1/workplaces/{workplaceId}/attendance/closings/preflight(미마감 기간에만 부른다) → 서버 계산값(테이블 없음). 보드는 건수만 적고 사유 목록은 ADM-ATTENDANCE-CLOSING이 낸다

- 교부 완료 명세서 수 → GET /v1/workplaces/{workplaceId}/payslips(유효 실행 · 교부 완료 필터 · 오프셋 봉투의 총 건수만 읽는다 · 확정 실행이 있는 달에만 부른다) → **payslips**
- 신고 기한 과제(마감 진행 보드 ④ — 만료 14일 이내와 이미 경과한 열린 과제) → GET /v1/workplaces/{workplaceId}/compliance-tasks → **compliance_tasks**
- 오늘 근태 기록 → GET /v1/workplaces/{workplaceId}/attendance/records(오늘 하루 범위) → **attendance_records**
- 오늘 근무 편성 → GET /v1/workplaces/{workplaceId}/work-schedules(오늘 하루 범위) → **work_schedules**
- 오늘을 덮는 승인 휴가 → GET /v1/workplaces/{workplaceId}/leave/requests(승인 상태 · 오늘 하루 범위 — 서버가 기간 겹침으로 거른다) → **leave_requests**

- 인건비 추이 → GET /v1/workplaces/{workplaceId}/payroll/labor-cost-trend(최근 12개월 범위) → **payroll_runs** · **payroll_employee_results** — 계약 정본 [../06_api/08_payroll.md](../06_api/08_payroll.md) #30

- 홈이 부르는 표면 가운데 **인건비 추이 하나만 이 화면을 위해 생겼고** 나머지는 전부 다른 화면이 이미 쓰는 조회다. 상세 규격의 정본은 각 도메인 API 문서다. 홈은 조회 전용이라 변이 표면을 갖지 않는다

**비고**: **홈은 실행을 하지 않는다** — 오늘 출근 보드(ATT-10)와 인건비 추이(DSH-03)를 직접 보이는 주 표면이지만 둘 다 조회 전용이고, 나머지 기능은 대기·상태를 모아 그 화면으로 보낸다. 승인·마감·확정·교부는 각 기능의 주 표면이 한다. **추이는 확정 급여의 월별 인건비 요약 하나뿐이다** — 분포 · 예측 · 사업장 간 비교 같은 통계 표면을 두지 않는다(정본 [README.md](./README.md) v1에 두지 않는 화면). **숫자를 화면이 만들지 않는다**(§3-8 합계 행) — 건수는 서버 봉투의 값이고 금액은 서버 합계이며, 총 건수를 주지 않는 범위 조회는 센 범위를 문안에 밝힌다. **최근 알림은 알림함이 아니다** — 관리자 웹에 독립 알림함 화면을 두지 않는다는 결정은 그대로이고 읽음 처리·전체 목록은 헤더 알림 벨이 갖는다. **바로가기 카드를 두지 않는다** — 사이드바 · 명령 팔레트와 같은 진입점을 한 번 더 늘어놓던 자리였다. **입력이 없으므로 세션 만료 행을 두지 않는다**(§1-4) — 만료를 만나면 로그인 유도로 보낸다.

**레이아웃·스크롤·모바일**: **섹션 배치(SN)**다(§5-3) — 1024 이상에서 왼쪽 섹션 목록 + 오른쪽 **한 섹션만** 열고 콘텐츠 영역은 스크롤하지 않는다. 섹션 본문이 넘치면 그 본문(이름 있는 스크롤 영역)만 스크롤한다. 연 섹션은 탭 쿼리 section이 가져 새로고침·공유·탭 복원에서 같은 섹션이 열린다. 한 줄 고지와 페이지 헤더는 스크롤 밖이다. **폐쇄 위험 구역은 마지막 섹션**이라 무심코 스크롤한 끝에 놓이지 않고 목록에서 골라야 열린다. 저장 줄은 바뀐 값이 있을 때만 나오고 섹션 본문 아래에 붙는다. 1024 미만은 목록 없이 전 섹션을 세로로 쌓고 본문이 스크롤하며, 지도 미리보기 높이를 줄이되 반경 수치 입력은 유지한다(§5-2). 390에서도 폐쇄 2단 확인을 끝까지 수행할 수 있어야 한다.

**레이아웃·스크롤·모바일**: **목록 배치(L)**다(§5-3) — 1024 이상에서 표가 영역을 채우고 표 데이터 영역만 스크롤한다. **멤버·초대 탭은 표 머리 줄 왼쪽**에 둔다 — 탭 줄을 따로 세우면 표가 시작되기까지 한 단을 더 먹는다. 한도 고지 · 툴바 · 표 머리 줄 · 일괄 작업 바는 스크롤 밖이다. 좁아지면 열부터 걷고 넘치면 표 자체가 가로 스크롤 컨테이너를 갖는다 — **페이지 본문은 가로로 스크롤되지 않는다**. 1024 미만에서는 표를 카드 목록으로 전환해 이름·역할·상태를 한 카드에 담고 행 액션을 카드 하단 메뉴로 옮긴다. 모달은 단일 레이어이며 제외 확인의 선행조건 결과는 새 레이어가 아니라 같은 모달의 단계 전환으로 표시한다(§3-1).

CSV·Excel을 올리면 그 응답에 상태·집계 3종·실패 행이 함께 온다. **열 매핑 단계를 두지 않는다** — 서버가 머리글을 이름으로 찾으므로 열 순서가 달라도 되고 매핑을 물을 이유가 없다. 크기 초과는 common.payload_too_large/413으로 되돌리고 허용 크기를 문안에 함께 적는다. 업로드는 실제 전송량으로 진행률을 표시하고 중복 제출을 잠근다. 전체 건수 · 통과 · 실패를 요약하고 실패 행을 행 번호 · 필드 · 사유로 나열한다. 실패가 있으면 "N행을 등록할 수 없습니다 — 통과 행만 확정됩니다"를 **한 줄 고지**로 둔다. **이 단계에서는 아무것도 커밋하지 않는다**는 사실은 하단 확정 줄의 문장과 파일 올리기 카드 머리의 ⓘ 안내가 갖는다 | WRK-16 |

**레이아웃·스크롤·모바일**: **목록 + 상세 페인 배치(MD)**다(§5-3) — 1024 이상에서 콘텐츠 영역은 스크롤하지 않고 표 데이터 영역과 페인 본문만 스크롤한다. 고르기 전에는 목록이 폭을 다 쓰고, 고르면 옆 페인이 열리며 손잡이로 비율을 조절한다(열이 많은 표 중심 목록이라 첫 항목을 자동으로 열지 않는다). 툴바 · 표 머리 줄은 스크롤 밖이다. **열 우선순위는 관리 판단 순서다** — 1 이름 · 재직 상태 · 근로계약서(법정 교부 위험), 2 직위 · 고용형태 · 연락처 · 입사일 · 4대보험, 3 나머지(사번 · 임금 형태 · 주 소정근로 · 근속 · 퇴사일 · 계약 종료일 · 등록 완전성 · 연차 잔여 · 앱 계정 · 주소 · 주민등록번호 · 표식). 좁아지면 3부터 걷고 첫 흡수 열(이름)은 걷지 않는다 — 페인이 닫힌 1280에서 11열 · 1440에서 12열이 서고(나머지는 접힌 열), 페인이 열리면 1순위와 남는 2순위만 선다. 재직 상태 콤보박스는 "전체(퇴사 포함)"가 잘리지 않는 폭이다. 1024 미만에서는 표를 카드 목록으로, 페인을 목록을 덮는 전체 영역으로 바꾸고 헤더 액션 "근로자명부"를 상단 액션 메뉴로 접되 "직원 등록"은 밖에 남긴다 — 온보딩 직후 가장 자주 쓰는 액션이다. 390에서도 등록 모달의 전 단계를 완주할 수 있어야 한다.

## ADM-EMPLOYEE-RESIGN — 퇴사 처리

| 항목 | 내용 |
|------|------|
| 화면코드 | ADM-EMPLOYEE-RESIGN |
| 라우트 | web_front SPA /employees/[id]/resignation |

**목적**: 한 직원의 퇴사를 확정하고 그로부터 갈라지는 신고·정산 후속 작업의 기한과 진입점을 한 화면에서 확인한다.

**진입경로**: ADM-EMPLOYEE-LIST 행 액션 "퇴사 처리"(**같은 탭의 퇴사 페인으로 열린다** — §4-4) · ADM-EMPLOYEE-DETAIL 헤더 액션 · ADM-MEMBERS 제외 흐름의 퇴사 연동 안내 · 라우트 직접 진입(딥링크는 목록 탭을 열고 이 직원의 퇴사 페인을 연다).

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 퇴사 정보 입력 | 퇴사일 · 사유(자진 · 권고 · 계약만료 · 해고) · 최종 근무일 · 4대보험 상실일 · 정산 필요 여부를 입력한다. **퇴사일은 입사일보다 빠를 수 없으며** 달력 입력의 하한을 입사일로 잠그고 서버가 다시 판정한다 | HRM-04 |
| 상실일과 퇴사일 구분 | 4대보험 상실일은 퇴사일과 다른 날일 수 있으므로 **별도 필드로 받고** 기본값을 자동 채우되 수정 가능하게 둔다. 두 날짜의 의미 차이를 필드 설명으로 적어 같은 값으로 오인하지 않게 한다 | HRM-04 |
| 선행조건 점검 | 진행 중 급여 확정 · 미처리 휴가·근태 승인 · 대상자의 OWNER 역할 보유가 있으면 확정을 막는다. 막는 항목이 있으면 **페인 머리의 한 줄 고지**("확정을 막는 선행조건이 N건 있습니다. 먼저 정리해 주세요." — 같은 사유를 아래 확정 줄에서 되풀이하지 않는다)가 늘 보이고, hr.resignation_blocked/409의 **미충족 항목 상세를 배열 그대로 체크리스트로 렌더**해 항목마다 해소 화면으로 링크한다. 막는 항목이 없으면 체크리스트를 세우지 않는다(§3-10 충족 상태) | HRM-04 |
| 후속 트리거 예고 | 퇴사 확정이 **6갈래**로 갈라진다는 사실을 확정 전에 표로 보여준다 — 4대보험 상실자료 · 마지막 급여 · 연차수당 정산 · 퇴직금 판정 · **금품청산 14일** · **이직확인서 10일**이다. **금품청산**은 기산일이 퇴사일 그 자체라 기산일·만료일을 함께 적는다. **이직확인서**는 기산일이 근로자의 발급 요청 접수일이라 퇴사 확정 시점에는 알 수 없으므로, 요청이 아직 없으면 날짜를 만들지 않고 안내 문구만 둔다 | HRM-04 |
| 퇴사 확정 | 확인 단계에서 퇴사일 · 상실일 · 후속 트리거 6종을 요약해 보여주고 확정한다. 확정 시 멤버십을 이탈로 전이하고 근로계약을 서명 완료에서 보관으로 자동 전이한다 | HRM-04 |
| 확정 후 안내 | 확정 결과 화면에서 각 후속 작업의 진입점(4대보험 신고자료 · 퇴직 정산 · 이직확인서)으로 링크하고, **자동 신고는 하지 않고 자료 산출까지만 지원한다**는 사실을 책임 한계 한 줄 고지로 적는다(§3-10) | HRM-04 |

**주요 UI 요소**: 직원 요약 헤더, 퇴사 정보 폼(날짜 2종 · 사유 선택 · 정산 여부), 선행조건 체크리스트, 후속 트리거 6종 예고 표, 확정 확인 단계 영역, 확정 결과 카드 + 후속 링크 목록.

**레이아웃·스크롤·모바일**: 직원 요약 헤더 · 단계 표시 · 차단 한 줄 고지와 하단 확정 액션 바는 스크롤 밖에 고정하고 **폼·체크리스트·예고 표를 담은 본문(이름 있는 스크롤 영역)만 스크롤한다**(§5-3 — MD 배치의 페인 본문). 1920·1440에서는 입력 폼과 후속 트리거 예고를 2열로 두어 입력과 영향이 동시에 보이게 하고, 768 미만에서는 1열로 접되 예고 표를 입력 폼 **아래**가 아니라 확정 버튼 **바로 위**에 배치해 확정 직전에 반드시 지나가게 한다. 확정 확인은 같은 화면의 단계 전환이며 모달을 새로 띄우지 않는다(§3-1).

| 빈 상태 | 대상 직원이 진입 전제이므로 목록형 빈 상태가 없다. 선행조건이 0건이면 체크리스트를 세우지 않고 안심 문장도 두지 않는다 — 막는 항목이 없다는 사실은 "확인 단계로"가 활성인 것이 이미 말한다(§3-10) |
| 에러 | hr.resignation_blocked/409 → 미충족 항목을 체크리스트에 반영하고 "먼저 정리해야 확정할 수 있습니다"로 적으며 항목마다 해소 화면으로 링크한다. 퇴사일이 입사일보다 빠르면 common.validation_failed/400을 퇴사일 필드 인라인으로 되돌린다. attendance.period_closed/409 · leave.period_closed/409가 후속 정리 과정에서 나오면 어느 기간이 잠겨 있는지 적고 ADM-ATTENDANCE-CLOSING으로 링크한다 |
| 권한거부 | STAFF 진입은 §1-2 권한 안내로 ADM-WORKPLACE-SELECT로 되돌린다. 대상자가 OWNER면 권한거부가 아니라 선행조건 미충족이므로 체크리스트 항목으로 처리하고 403으로 그리지 않는다 |
| 세션 만료 | auth.token_invalid/401 · auth.csrf_token_invalid/403이면 퇴사일·사유·상실일 입력을 유지한 채 재로그인 모달을 띄운다. **퇴사 확정은 자동 재제출하지 않는다** — 여섯 갈래 트리거가 걸려 있어 중복 실행의 대가가 크므로 복귀 후 확인 단계를 다시 거친다(§1-4) |

- 상세 규격의 정본은 [../06_api/05_hr.md](../06_api/05_hr.md)다

**담은 기능ID**: HRM-04

**비고**: 퇴사 확정은 화면 하나에서 끝나지만 **결과는 6개 도메인으로 퍼진다** — 그래서 확정 전 예고 표가 이 화면의 핵심 계약이다. 금품청산 14일은 법정 기한이므로 남은 일수를 단정적으로 "안전하다"고 적지 않고 기산일·만료일과 함께 사실만 표시한다(§5-6). **이직확인서 10일은 기산일이 근로자의 발급 요청 접수일이라 이 화면이 계산하지 않는다** — 아직 일어나지 않은 접수를 퇴사일로 대신하면 확정되지 않은 기한을 확정된 것처럼 보이게 된다. 요청이 접수돼 실제 과제가 생기면 그 소유 표면(ADM-TAX-SEPARATION)이 서버가 준 기한을 그대로 보인다. 퇴사 후에도 본인은 임금명세서·근로계약서·급여이력을 보존기간 내 열람하며, 인가는 사업장 멤버십이 아니라 본인 소유권으로 판정된다 — 확정 결과 문안에 이 사실을 적어 관리자가 "접근이 끊긴다"고 오해하지 않게 한다. **이 화면은 ADM-EMPLOYEE-LIST 탭 안의 퇴사 페인으로 열린다**(§4-4) — 화면 코드·라우트·딥링크는 그대로다. 퇴사 정보는 여러 필드를 채우는 입력이므로 **미저장 가드가 목록 탭에 걸리고**, 세션 만료 행(§1-4)도 그대로 유지된다.

| 템플릿 선택·초안 생성 | 정규 · 기간제 · 단시간 · 일용 템플릿을 고르면 인사·근로조건 값으로 초안을 자동 채운다. 값이 근로조건과 어긋나면 경고를 띄우되 발송을 막지는 않는다 | HRM-06 |

PDF 미리보기는 자체 스크롤 컨테이너를 갖고 페이지 본문을 가로로 밀지 않는다.

| 에러 | subscription.workplace_limit_exceeded/402 → "소유할 수 있는 사업장 수를 모두 썼습니다" + 현재 사용량·필요 등급 + 문의 CTA. subscription.staff_limit_exceeded/402 → "이 사업장의 인원 한도를 넘습니다" + ADM-MEMBERS 링크. subscription.expired/402 → "구독이 만료되어 새 사업장 등록과 유료 기능이 멈춰 있습니다"와 함께 **기존 데이터 조회는 그대로 가능하다**를 적는다. subscription.upgrade_required/402 → 어떤 기능이 어떤 등급을 요구하는지 지목한다. subscription.plan_not_found/404 → 요금제 정보를 불러오지 못했음을 알리고 코드를 병기한다. **402는 등급을 올릴 일, 403은 관리자에게 문의할 일**이므로 문안과 CTA를 분리한다 |
| 권한거부 | STAFF 진입은 §1-2 권한 안내로 ADM-WORKPLACE-SELECT로 되돌린다. MANAGER 진입도 같은 권한 안내이며 섹션 목록을 세우지 않고 영역 가운데에 "구독은 사업장 OWNER의 계정 단위로 관리됩니다"를 적어 왜 자기 화면이 아닌지 알 수 있게 한다 |

**데이터 연동**

- **구독과 사용량은 두 표면이다** — 하나로 묶지 않는다.
- 구독 등급·상태 조회 → GET /v1/me/subscription → **subscriptions** · **plans**(등급 코드·상태·기간만 내며 **한도·사용량을 담지 않는다**)
- 요금제 목록 조회 → GET /v1/plans → **plans**
- 한도·사용량·사업장별 인원·등급 변경 안내 조회 → GET /v1/me/subscription/usage → **subscriptions** · **plans** · **workplace_members**(사업장별 인원은 **usage.workplaces 배열**에 한 번에 담겨 오며 화면이 사업장마다 팬아웃하지 않는다. 상호명이 없어 화면이 소속 사업장 목록과 workplaceId로 이어 붙인다)
- 상세 규격의 정본은 [../06_api/13_subscription.md](../06_api/13_subscription.md)이고 등록 한도의 강제 지점은 [../06_api/04_workplace.md](../06_api/04_workplace.md)다

**담은 기능ID**: SUB-02 · SUB-03(표시) · SUB-04(표시) · SUB-05 · WRK-11(표시)

**비고**: **구독 조회는 두 표면으로 갈린다** — 등급·상태·기간은 GET /v1/me/subscription이 내고 한도·사용량·사업장별 인원·등급 변경 안내는 GET /v1/me/subscription/usage가 낸다. 두 응답을 하나의 계약으로 묶어 읽으면 사용량 필드가 언제나 비어 사용량 게이지가 오류 없이 사라지므로 화면은 두 호출을 각각 부른다. **등급 변경 안내(upgradeGuidance)는 manual 플래그와 안내 문구만 낸다** — 문의 주소를 서버가 담지 않으므로 화면이 정적 값으로 문의 CTA를 채운다. **구독은 계정 단위이지 사업장 단위가 아니다** — 한도는 OWNER 측 두 축(소유 사업장 수 · 사업장당 활성 멤버 수)에만 걸리고 STAFF·MANAGER로서의 타 사업장 소속은 본인 구독과 무관하게 무료·무제한이다. 화면이 이 경계를 흐리면 사용자가 남의 사업장 소속을 자기 한도로 오해한다. **v1에 결제 화면·업그레이드 요청 워크플로를 두지 않으므로** 결제 수단 · 청구서 · 자동 갱신 같은 요소를 미리 만들지 않고 문의 CTA 하나로 수렴한다. 등급 조정은 플랫폼 관리자의 수동 경로에서 일어나며 그 표면은 SYS-SUBSCRIPTIONS다.
