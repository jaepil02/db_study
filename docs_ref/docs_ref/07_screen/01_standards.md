## 1. 접근권한 규약

### 1-1. 접근권한 값 집합

화면 명세의 접근권한 칸은 아래 **6값**만 쓴다. 사업장 역할은 OWNER ⊃ MANAGER ⊃ STAFF 누적이므로 STAFF라고 적으면 MANAGER·OWNER도 포함한다. 값과 최소 역할은 [../02_features/14_permission_matrix.md](../02_features/14_permission_matrix.md)와 문자 수준으로 일치시킨다.

| 값 | 정의 | 판정 근거 |
|----|------|----------|
| 비인증 | 인증 컨텍스트가 없는 접근. 공개 경로에서만 허용한다 | 서버가 판정한 인증 컨텍스트 부재(401 응답). 쿠키 유무를 클라이언트가 읽어 판정하지 않는다 |
| 본인 | 인증만 요구하고 사업장 멤버십을 요구하지 않는다. **본인 소유권**(직원 레코드의 사용자 식별자 = 요청자)으로 인가하며 퇴사·사업장 폐쇄 후에도 보존기간 내 유지된다(CMP-07) | 인증 사용자 식별자 일치 |
| STAFF | 활성 멤버십 + 역할 STAFF 이상. 본인 데이터만 읽고 쓴다 | (사용자, 사업장) 쌍의 멤버십 역할 |
| MANAGER | 활성 멤버십 + 역할 MANAGER 이상. 사업장 운영 전반 | 좌동 |
| OWNER | 활성 멤버십 + 역할 OWNER. 사업장당 정확히 1명이다 | 좌동 |
| 플랫폼({역할}) | 플랫폼 RBAC 보유. 괄호에 최소 역할을 적는다 — 플랫폼(VIEWER) · 플랫폼(SUPPORT) · 플랫폼(ADMIN) · 플랫폼(SUPER_ADMIN) | 시스템 관리자 레코드의 역할 레벨과 권한 키 |

- **사업장 RBAC와 플랫폼 RBAC는 완전히 별개다.** 사업장 OWNER라도 플랫폼 권한을 자동으로 얻지 않고, 플랫폼 관리자라도 사업장 업무 권한을 자동으로 얻지 않는다.
- 화면 안에서 액션별로 최소 역할이 갈리면 접근권한 칸에 함께 적는다 — 예: MANAGER(조회·수정) / OWNER(폐쇄).
- **ADVISOR는 v1에 없다**(WRK-13 이월). 사업장 데이터를 읽기 전용으로 보는 외부 역할을 화면에 두지 않는다.
- **동일 사용자가 사업장별로 다른 역할을 가질 수 있으므로** 역할 판정은 활성 사업장 단위로 매 요청 다시 수행한다(WRK-06).

### 1-2. 차단 시 이동 규칙

접근이 거부될 때의 처리는 **두 갈래**이며 화면 명세의 상태 처리 표 권한거부 행에 어느 쪽인지 명시한다.

| 규칙 | 적용 상황 | 처리 |
|------|----------|------|
| **로그인 유도** | 인증 컨텍스트가 없다 | 로그인 화면(PUB-LOGIN)으로 보내고 원래 요청 경로를 보존한다. 복귀 경로는 **내부 경로만 허용**해 오픈 리다이렉트를 막는다 |
| **권한 안내** | 인증은 됐으나 역할·멤버십이 부족하다 | 화면 안에서 사유와 다음 행동을 안내한다. 관리자 웹의 STAFF 접근은 사업장 선택 화면(ADM-WORKPLACE-SELECT)으로 되돌리고, 시스템 웹의 플랫폼 권한 부재는 진입 자체를 막는다 |
| **404 위장(존재 비노출)** | 대상의 존재 자체가 정보인 조회 경로 | 부재와 권한 부족을 **구분하지 않고 같은 부재 응답**으로 수렴시킨다. 403으로 답하면 "그 행이 있다"는 사실이 노출된다 |

**404 위장을 적용하는 화면은 셋이다** — 명세서 열람(APP-PAYSLIP · ADM-PAYSLIP, payslip.not_found/404) · 알림 조회(APP-NOTIFICATION, notification.not_found/404) · 타인 초대 조회(APP-INVITE). 그 밖의 화면은 권한 안내를 쓴다.

- **권한 부족(403)과 한도 초과(402)를 화면에서 분리 표시한다.** 전자는 관리자에게 문의할 일이고 후자는 등급을 올릴 일이라 사용자가 취할 조치가 다르다.
- **적용 대상 아님(403)과 전제 미충족(422)도 분리 표시한다**(REQ-GLB-19). 5인 미만 연차 미적용은 조치가 없는 정상 상태이므로 안내만 두고, 상시근로자 스냅샷 누락은 산정이라는 조치가 있으므로 실행 버튼을 함께 둔다.
- **429(요청 과다)를 인증 컨텍스트 부재(401)로 읽지 않는다.** 진입 가드는 서버 응답이 미인증(401 계열)일 때만 로그인 유도로 보내고, **429·5xx·네트워크 오류는 로그인 화면으로 보내지 않고 그대로 던져 화면·루트 에러 경계가 처리**하게 한다 — 연속 조회로 사용자당 요청 한도를 넘긴 429 한 번이 로그인 화면으로 튀면 사용자에게는 로그아웃처럼 보인다. 429는 Retry-After를 안내로 존중한다(§3-7).
- 화면 노출 제어는 판정이 아니다 — 내비게이션에서 감춘 화면도 직접 진입하면 서버와 2차 방어가 다시 거부한다.

**판정 계층은 클라이언트에 없다.** 웹은 서버 렌더 계층도 요청 경유 미들웨어 계층도 두지 않는 단일 SPA이므로(D-20), 라우트 진입 시점의 판정은 **클라이언트 라우터 가드가 수행하되 이는 신뢰 계층이 아니라 UX 보조**다 — 사용자가 볼 수 없는 화면을 열어 두고 빈 상태를 보여 주는 대신 §1-2의 이동 규칙으로 미리 보내는 장치일 뿐이다.

| 계층 | 지위 | 이 문서군에서의 취급 |
|------|------|---------------------|
| 클라이언트 라우터 가드 | **신뢰 계층 아님 — UX 보조** | 화면 명세의 접근권한·권한거부 칸이 기술하는 대상. 우회 가능함을 전제한다 |
| 서버 서비스 계층 검증 | 최종 강제 1차 | 화면은 서버 응답(401 · 403 · 402 · 404)을 받아 §1-2로 처리한다 |
| RLS · 제약·트리거 | 최종 강제 2·3차 | 화면 계약이 아니며 정본은 [../10_security/01_authn_authz.md](../10_security/01_authn_authz.md)다 |

**클라이언트 가드가 통과시킨 진입도 서버가 다시 거부할 수 있다** — 그래서 모든 화면 명세는 진입 성공을 전제하지 않고 권한거부 상태 행을 갖는다.

### 1-3. 미인증 공개 경로

공개 경로는 **랜딩 · 요금제 · 약관·개인정보·위치정보 문서 조회 · 회원가입 · 가입 동의(재동의 게이트 — 컨텍스트 발급 전 미인증 진입) · 로그인 · 비밀번호 재설정**으로 한정한다(아이디 중복 확인은 화면이 아니라 미인증 API 경로다). 화면으로는 순수 공개 3본(랜딩·요금제·법정 문서) + 인증 흐름 4본(로그인·회원가입·가입 동의·비밀번호 재설정) = **PUB 7본**이 여기 해당하며, 그 밖의 경로는 전부 인증을 요구한다.

동의 화면(PUB-CONSENT)은 **개정 재동의 게이트에서는 미인증**(로그인 ④가 차단한 컨텍스트 발급 전 — 가입 동의 자체는 PUB-SIGNUP 안에서 함께 받는다), APP-PRIVACY·체크인 유도 재진입에서는 인증 상태로 열린다 — **두 진입 모두 같은 화면 코드**이고 진입 맥락에 따라 제출 후 목적지가 갈린다.

### 1-4. 세션 만료 처리

**인증 컨텍스트는 화면을 여는 순간이 아니라 요청을 보내는 순간에 판정된다.** 화면을 열어 둔 채 세션이 만료되거나 다른 기기에서 비밀번호가 바뀌면, 사용자는 다 채운 폼을 제출하는 시점에야 만료를 만난다. 이때 **입력을 버리고 로그인 화면으로 보내는 처리를 금지한다** — 사업장 등록 9필드나 임포트 매핑을 다시 채우게 하는 비용이 재로그인 비용보다 훨씬 크기 때문이다.

| 축 | 규격 |
|----|------|
| 판정 신호 | 제출 응답이 **auth.token_invalid/401**(access token 만료·폐기·서명 불일치) · 세션 부재로 인한 401 · **auth.csrf_token_invalid/403**(웹 세션 채널의 CSRF 토큰 부재·불일치)인 경우다. 그 밖의 401·403은 §1-2의 권한거부 축으로 다룬다 |
| 입력 보존 | **화면을 이탈하지 않고 입력값을 그대로 유지한다.** 폼 상태를 비우거나 화면을 다시 마운트하지 않는다 |
| 재로그인 유도 | 같은 화면 위에 재인증 모달을 띄우거나 새 컨텍스트(새 탭·앱 인증 스택)로 로그인을 유도한다. **모달 단일 레이어 규약을 지키므로**(§3-1) 다른 오버레이가 열려 있으면 그 레이어 안에서 상태를 전환한다 |
| 복귀 후 처리 | 로그인이 끝나면 원래 화면으로 돌아와 입력값이 남아 있는 상태에서 **사용자가 다시 제출한다.** 화면이 자동으로 재제출하지 않는다 — 만료 전 요청이 서버에 이미 닿았을 수 있어 자동 재시도가 중복 실행을 만든다 |
| 되돌릴 수 없는 작업 | 급여 확정·근태 마감·명세서 발행·임포트 확정은 **자동 재제출을 절대 하지 않는다**(§3-2). 복귀 후 확인 단계를 처음부터 다시 거치게 하고, 멱등키는 재제출 시 새로 발급한다 |
| 앱 | 앱은 access token 만료가 임박하면 refresh로 회전 재발급하므로 이 상태가 드물다. refresh까지 실패한 경우에만 인증 스택으로 보내며 그때도 작성 중이던 시트 입력은 복귀 후 복원한다 |
| 조회 전용 화면 | 만료를 만나면 그대로 로그인 유도로 보낸다(§1-2). 잃을 입력이 없으므로 별도 처리를 두지 않는다 |

**상태 처리 표에 세션 만료 행을 두는 화면은 7본이다** — ADM-WORKPLACE-CREATE · ADM-EMPLOYEE-DETAIL · ADM-EMPLOYEE-RESIGN · ADM-CONTRACTS · ADM-IMPORT · ADM-PAYROLL-TERMS · **SYS-TERMS**다. 선정 기준은 **한 화면에서 여러 필드를 채우는 대형 폼이거나 장문 자유입력을 포함하는 화면**이다 — 앞의 여섯은 필드 수가 많고 SYS-TERMS는 약관 본문 전문이라는 이 문서군 최장 자유입력을 담는다. 나머지 화면은 위 규격을 공통 인용하고 행을 두지 않는다.

## 2. 화면 명세 템플릿

### 2-1. 화면 블록 (13필드)

각 도메인 파일의 화면 명세는 아래 블록 구조를 그대로 따른다. **H2는 화면코드와 화면명으로 고정**하고 블록 사이에는 구분선을 넣는다. 필드 순서를 바꾸거나 빼지 않는다.

```
## {화면코드} — {화면명}

| 항목 | 내용 |
|------|------|
| 화면코드 | {표면}-{의미} |
| 라우트 | web_front 산출물 + /경로 또는 app_front {드로어 섹션·스택} 논리 경로 + as-built 라우트명 |
| 접근권한 | §1-1의 6값. 액션별로 갈리면 함께 적는다 |
| 우선순위 | P0 · P1 · P2 (담은 기능의 최고 우선순위) |

**목적**: 한 줄 요약 — 이 화면이 사용자에게 무엇을 끝내게 하는가.

**진입경로**: 내비 경로 · 교차 진입 · 딥링크 · 알림 바로가기.

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 기능명 | 입력·검증·처리·차단을 셀 안에 인라인으로 | XXX-NN |

**주요 UI 요소**: 폼·목록·표·카드·차트·모달·시트 등 구성 요소 열거.

**레이아웃·스크롤·모바일**: 고정 요소와 스크롤 소유자(§5-3) · 브레이크포인트 전이(§5-2) · 앱은 안전 영역과 터치 타깃.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | … |
| 빈 상태 | … |
| 에러 | {domain}.{snake_case}/HTTP → 사용자 문안과 다음 행동 |
| 권한거부 | §1-2의 세 규칙 중 어느 것인지 명시 |
| 세션 만료 | §1-4. **입력이 있는 화면만 행을 둔다** — 조회 전용 화면은 생략한다 |

**데이터 연동**

- 액션 → 메서드 경로(API 표면) → **테이블**. 상세 정본은 [../06_api/{도메인 파일}]을 지목한다.

**담은 기능ID**: XXX-NN 열거. 서버·전역·배치 전용이면 (서버)·(전역)·(배치)를 병기한다.

**비고**: 엣지케이스 · 되돌릴 수 없는 작업의 화면 계약 · 설계 판단 근거 · 미확인 항목.
```

- **요구사항ID 열을 두지 않는다** — REQ 채번 정본은 [../03_requirements](../03_requirements/README.md)이며 화면 문서가 REQ를 채번하거나 추정하지 않는다.
- **상태 처리 4행(로딩 · 빈 상태 · 에러 · 권한거부)은 전 행을 채운다.** 해당 없으면 "해당 없음"과 사유를 적고 행을 지우지 않는다.
- **세션 만료 행은 선택 5번째 행**이다(§1-4). 사용자가 값을 입력하는 화면 — 특히 **한 화면에서 여러 필드를 채우는 대형 폼이거나 장문 자유입력을 포함하는 화면** — 은 이 행을 채우고, 조회 전용 화면은 두지 않는다. 4행과 달리 "해당 없음"으로 남기지 않고 행 자체를 생략한다.
- 화면 기능 표의 기능ID와 기능명은 [../02_features](../02_features/README.md) 도메인 파일과 **문자 그대로** 일치시킨다.
- 데이터 연동의 API 표면은 **메서드 경로 수준**으로만 적고 요청·응답 규격은 [../06_api](../06_api/README.md) 도메인 파일이 정본이다.

### 2-2. 화면 내 요소 블록 (H3 축약)

모달·시트·드로어처럼 화면 코드를 갖지 않는 요소는 라우트·진입경로 축이 없으므로 아래 축약 블록을 쓰고 소속 화면 블록 바로 뒤에 H3로 붙인다.

```
### {소속 화면코드} 내 요소 — {요소명}

**노출 위치**: 마운트 지점 + 노출 조건(역할·상태).

**기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|

**주요 UI 요소**: 구성 요소 열거.

**상태·에러**: 로딩·빈 상태·에러·권한거부를 한 단락으로 기술한다.

**데이터 연동**: 액션 → 메서드 경로 → **테이블**.
```

### 2-3. 화면 수 집계 기준

**화면 수 집계는 H2 블록만 센다. 화면 내 요소 H3는 세지 않는다.** 이 기준은 [README.md](./README.md) 고정 기준과 [../README.md](../README.md) 고정 기준이 공유하며, 두 축을 섞어 쓰지 않는다.

## 3. 공통 패턴

전 화면이 아래를 공통 인용한다. 개별 화면 명세는 이 표를 다시 설명하지 않고 화면별 차이만 적는다.

| 패턴 | 원칙 |
|------|------|
| 시각 표시 | 저장은 UTC이고 **표시·일 경계 판정은 KST**다. 근무일·급여월·기준일은 KST로 산출한 날짜를 그대로 보여준다(REQ-GLB-07) |
| 금액·시간 표시 | 금액은 정수 원, 근로시간은 정수 분을 시·분으로 환산해 표시한다. 클라이언트에서 금액을 재계산하지 않는다 — 서버가 내려준 값을 그대로 렌더한다 |
| 모달 단일 레이어 | §3-1 |
| 확인 다이얼로그 | §3-2 |
| 폼 검증 표시 | §3-3 |
| 목록 공통 | §3-4 |
| 빈 상태 3분기 | §3-5 |
| 낙관적 갱신 금지 | §3-6 |
| 토스트·에러 문안 | §3-7 |
| ERP 상호작용 | §3-8 — 관리자 웹·시스템 웹 전용이다. 직원 앱은 대상이 아니다 |
| 검색형 콤보박스 | §3-9 — 관리자 웹·시스템 웹 툴바 필터의 표준 컨트롤 |
| 안내 배치 | §3-10 — 늘 보이는 한 줄 고지 · 눌러 여는 안내 · 두지 않는 배너의 판정 |
| 탭 워크스페이스 | §4-4 — 관리자 웹·시스템 웹의 셸 골격(D-22) |
| 사업장 스코프 캐시 | 클라이언트 조회 캐시는 **활성 사업장 식별자 + 역할 단위로 격리**한다. 사업장을 전환하면 이전 사업장 데이터가 화면에 남지 않는다(WRK-06 · D-20) |
| 알림 벨 | 관리자 웹·시스템 웹은 독립 알림함 화면을 두지 않고 헤더 알림 벨 오버레이로 제공한다 — §4-1 |

### 3-1. 모달 단일 레이어

**모달 위에 모달을 띄우지 않는다.** 화면에 동시에 존재하는 오버레이 레이어는 항상 하나다.

| 항목 | 규격 |
|------|------|
| 중첩 금지 | 모달·시트·드로어가 열린 상태에서 다른 모달을 열지 않는다. 열려 있는 레이어를 닫고 여는 방식도 쓰지 않는다 |
| 확인 단계 | 모달 안에서 확인이 필요하면 **같은 모달의 상태 전환**으로 처리하고 제출 중 플래그로 중복 제출과 닫기를 함께 잠근다 |
| 보조 선택 | 날짜·직원·항목 같은 보조 선택은 인라인 확장 또는 팝오버로 처리하고 새 레이어를 만들지 않는다 |
| 넘침 처리 | 넘치는 분량을 모달 내부 스크롤로 흡수하지 않고 **단계 전환 · 탭 전환 · 담을 정보 축소**로 수납한다. 서버 목록의 페이지 번호 UI는 두지 않으며, 한 번에 메모리에 있는 작은 선택·계산 목록만 모달 내부 로컬 쪽 나눔을 예외로 허용한다 |
| 배경 | 배경 페이지 스크롤을 잠그고 포커스를 모달 안으로 트랩한다. Esc로 닫고 닫을 때 트리거로 포커스를 되돌린다 |

### 3-2. 확인 다이얼로그 — 되돌릴 수 없는 작업

**되돌릴 수 없는 작업은 2단 확인 + 재인증 + 멱등 처리를 화면 계약으로 갖는다.** 되돌릴 수 없다는 것은 취소 경로가 없다는 뜻이 아니라, 되돌리는 방법이 **원본 무효화 + 정정본 신규 생성**이라서 원상 복구가 아니라는 뜻이다.

| 작업 | 화면 | 확인 단계 | 재인증 | 멱등 처리 |
|------|------|----------|:------:|----------|
| **급여 확정** | ADM-PAYROLL-RUN | 2단 — 확정 대상 요약(인원·지급 총액·자기포함 여부) 확인 → 사유 없는 최종 확인 | 요구하지 않음 | 멱등키 + (사업장, 급여기간) 고유 제약. 중복 클릭은 제출 즉시 버튼을 잠그고 서버가 payroll.already_confirmed/409 또는 payroll.confirmation_conflict/409로 거른다 |
| **급여 원본 무효화·정정본 발행** | ADM-PAYROLL-RUN | 2단 — 차액 미리보기 확인 → **사유 필수 입력** 후 최종 확인 | 요구하지 않음(OWNER 전용 + 감사) | supersedes 연결. 원본은 삭제하지 않는다 |
| **근태 마감** | ADM-ATTENDANCE-CLOSING | 2단 — 차단 사유 0건 확인 → 마감 범위·대상 인원 확인 | 요구하지 않음 | 기간 단위 상태 전이가 멱등. 중복 클릭은 버튼 잠금 + attendance.period_closed/409 |
| **근태 마감 취소(재오픈)** | ADM-ATTENDANCE-CLOSING | 2단 — 급여 미확정 확인 → **사유 필수 입력** | 요구하지 않음(OWNER 전용 + 감사) | 상태 전이 멱등 |
| **사업장 폐쇄** | ADM-WORKPLACE-SETTINGS | 2단 — 선행조건 5종 충족 확인 + **법정 보존 안내 확인 체크** → 사업장명 재입력 확인 | **비밀번호 재인증 필수** | 상태 전이 멱등. 중복 요청은 workplace.closed/409 |
| **명세서 발행(일괄)** | ADM-PAYSLIP | 2단 — 대상 인원·재발행 정책 확인 → 최종 확인 | 요구하지 않음 | 멱등키. 진행 중 중복 실행은 payslip.bulk_in_progress/409 · 키 충돌은 payslip.bulk_conflict/409 |
| **명세서 정정본 발행** | ADM-PAYSLIP | 2단 — 원본과 정정본 대조 확인 → **정정 사유 필수 입력** | 요구하지 않음(OWNER 전용 + 감사) | supersedes 연결. 원본은 폐기하지 않는다 |
| **데이터 임포트 확정** | ADM-IMPORT | 2단 — 미리보기 검증 결과 확인 → 커밋 대상 건수 확인 | 요구하지 않음(OWNER 전용) | 작업 원장 단위 멱등. 부분 실패의 후속은 실패 행 리포트 다운로드 → 수정 → **새 업로드**이며 원클릭 재실행을 두지 않는다 |
| **민감정보 원문 복호화** | ADM-EMPLOYEE-DETAIL | 1단 — **사유 필수 입력** | **비밀번호 재인증 필수** | 서버 1회성 응답. 결과를 클라이언트에 캐시하지 않는다 |
| **민감 문서 다운로드** | ADM-DOCUMENTS | 1단 — 사유 필수 입력 | **비밀번호 재인증 필수** | 1회용 다운로드 토큰(단기 만료·1회 사용) |
| **계정 탈퇴** | APP-SETTINGS · ADM-ACCOUNT | 2단 — 차단 조건 확인 → 안내 확인 | **비밀번호 재인증 필수** | 상태 전이 멱등 |

- **중복 클릭 방지는 화면 계약이다.** 제출 즉시 버튼을 비활성화하고 진행 표시를 두며, 응답이 오기 전에는 같은 요청을 다시 보내지 않는다. 서버 멱등키는 그 위의 2차 방어이며 화면의 잠금을 대신하지 않는다.
- **확인 다이얼로그 문안에 "이 작업은 되돌릴 수 없습니다"를 명시**하고 되돌리는 방법(정정본 발행 · 재오픈)이 있으면 함께 적는다. 되돌릴 방법이 없으면 없다고 적는다.
- 사유 필수 액션은 사유를 비운 채 제출할 수 없게 막고, 서버가 감사 로그에 기록한다(REQ-GLB-17).

### 3-3. 폼 검증 표시

| 항목 | 규격 |
|------|------|
| 이중 검증 | 클라이언트와 서버가 같은 규칙으로 검증하되 **서버 판정이 최종**이다. 클라이언트 통과가 성공을 보장하지 않는다 |
| 표시 위치 | 필드 단위 오류는 필드 아래 인라인, 요청 단위 오류는 폼 상단 배너에 둔다 |
| 표시 시점 | 최초 입력 중에는 오류를 띄우지 않고 포커스 이탈 또는 제출 시점에 표시한다. 한 번 오류가 난 필드는 입력하는 동안 실시간으로 갱신한다 |
| 서버 검증 실패 | common.validation_failed/400 · common.invalid_format/400은 서버가 준 필드 경로를 그대로 해당 필드에 붙인다 |
| 경합 오류 | 사전 확인을 통과했어도 최종 제출에서 충돌할 수 있는 값(아이디 중복 · 유효기간 겹침 · 인원 한도)은 **제출 후 오류를 필드로 되돌린다** |
| 제출 잠금 | 제출 중 버튼을 비활성화하고 진행 표시를 둔다. 실패해도 입력값을 지우지 않는다 |

### 3-4. 목록 공통

| 항목 | 규격 |
|------|------|
| 표시 형태 | 관리자·시스템 웹 DataTable은 **표시 전용 스프레드시트형**이다. 셀 가로·세로 경계, sticky 헤더, 선택적 첫 열 고정, 숫자 우측 정렬을 사용한다. 헤더 36px · 행 32px **단일값**이다(밀도 선택 없음 · §5-7). 표는 놓인 영역을 채우고 **남는 가로 폭은 글자 열(grow)이 흡수**한다 — 글자 열은 한 줄 안에서 말줄임하고 마우스를 올리면 전체를 보여 주며, 나머지 열은 내용 폭 그대로 선다. 이름 + 보조 표기처럼 여러 줄인 셀은 행 높이가 내용만큼 늘어난다 |
| **상단 줄** | 표 위에 **늘 있는 한 줄**이다 — [보기 전환] … [내보내기] [처음부터 새로고침] **[N건] [열]**. 카드 표현은 [내보내기] [새로고침] [N건]이다. 보기 전환(일자별 ⇄ 월간 출근부처럼 이 표를 어떻게 볼지)만 왼쪽에 두고 **필터는 두지 않는다** — 필터는 화면 툴바의 몫이다(§3-5) |
| 비범위 | 스프레드시트형은 표시 밀도이지 스프레드시트가 아니다 — **범위 복사 · 수식 · 행 번호**를 제공하지 않는다. **셀 편집은 §3-8이 정하는 조건에서만 열린다**(전 열 편집이 아니라 지정한 열이며, 낙관적 갱신 금지 대상은 인라인으로 열지 않는다) |
| API 분류 | 오프셋 · 커서 · 범위 조회 분류는 유지한다. 오프셋 API도 화면에서는 페이지 번호 없이 이어 읽고, 시간 역순으로 증가하는 목록 4종(알림 · 감사 로그 · 위치정보 이용·제공 사실 확인자료 · 명세서 교부 이력)은 기존 커서 계약을 그대로 쓴다 |
| 이어읽기 단위 | 서버 목록 DataTable은 페이지 번호·크기 선택기를 두지 않고 **정확히 200건씩** 요청한다. API 기본값 20 · 상한 200의 정본은 [../06_api/01_conventions.md](../06_api/01_conventions.md)다 |
| 추가 조회 | **200건을 자동으로 이어 읽는다.** 데이터 영역 끝의 센티널이 끝 160px 전에 다음 묶음을 부르고, **하단에 "다음 200건" 버튼이나 건수 문구 줄을 두지 않는다.** 진행과 실패는 **격자 안의 행**이 알린다 — 읽는 중에는 붙을 자리에 스켈레톤 3행, 실패하면 기존 행을 유지한 채 그 자리에 사유와 [다시 불러오기] 행이다. **키보드는 마지막 행에 닿으면**(↓ · End · PageDown) 다음 묶음을 부르고 같은 키로 계속 내려간다(§3-8). 요청 중에는 중복 호출을 막는다. **센티널의 관찰 루트는 실제로 스크롤하는 데이터 영역**이며, 그 영역이 스크롤하지 않는 자리(내용만큼 자라는 컨테이너)에서는 뷰포트를 루트로 둔다 — 늘 교차 상태인 루트는 묶음이 붙을 때마다 다음 묶음을 불러 전 묶음을 연쇄 조회한다 |
| 누적 규칙 | items만 응답 순서대로 붙이고 안정 식별자로 중복 제거한다. summary · range · employees · registrationNumbers · totalUnfiltered 같은 부가 메타데이터는 첫 200건 응답을 기준으로 고정한다. 무한 목록은 getRowId가 필수다 |
| 초기화 | 검색·필터·정렬·사업장·역할 변경과 관련 변이 성공은 기존 누적을 버리고 첫 200건부터 시작한다. 창 포커스·네트워크 재연결만으로 쌓인 묶음을 연쇄 재조회하지 않고 **상단 줄의 처음부터 새로고침 아이콘**을 명시적으로 제공한다. 새로고침은 먼저 스크롤을 맨 위로 옮기고 완료 전 추가 조회를 잠그며, 실패하면 기존 행을 남긴 채 **격자 맨 위에 사유와 [다시 새로고침] 행**을 낸다 |
| 오프셋 한계 | 조회 중 외부 삽입·삭제가 있으면 경계 중복은 제거할 수 있어도 누락은 복원할 수 없다. 이 한계를 숨기지 않고 “처음부터 새로고침”으로 현재 모집단을 다시 읽게 한다 |
| 제외 | 범위 조회 · 작은 모달 선택 목록 · 로컬 계산 표는 공용 200건 누적 DataTable 대상이 아니다. 작은 로컬 목록은 화면 내부 쪽 나눔을 사용할 수 있으나 서버 목록 페이지네이션 컴포넌트를 다시 만들지 않는다 |
| **기본 정렬** | **명시가 없는 목록의 기본 정렬은 생성 시각 내림차순이고 동률은 식별자 내림차순**이다. 카탈로그성 목록(요금제 · 급여 항목 · 알림 타입처럼 표시 순서가 데이터에 있는 목록)만 표시 순서 오름차순 · 코드 오름차순을 기본으로 쓴다. 두 기본값 밖의 정렬을 쓰는 목록은 **화면 명세의 데이터 연동 절에 기본 정렬을 한 줄로 명시**한다 |
| 안정 정렬 | 모든 목록은 마지막 정렬 키로 식별자를 붙인다. 값이 같은 행의 순서가 요청마다 흔들리면 오프셋 쪽 나눔이 행을 흘린다 |
| 정렬 축 | 목록마다 정렬 축은 하나다. 다중 정렬을 두지 않고 허용 정렬 필드를 화이트리스트로 제한한다 |
| 검색 | 입력을 다듬고 길이를 제한하며 특수문자를 이스케이프한다. 검색어가 바뀌면 기존 누적과 커서를 버리고 첫 200건부터 시작한다 |
| 필터 | 필터 상태를 URL 쿼리에 반영해 새로고침·공유·뒤로가기에서 위치가 유지되게 한다(관리자 웹·시스템 웹). 앱은 화면 상태로만 보존한다 |
| 건수 표기 | **표 우상단 열 선택 바로 왼쪽의 N건**(천 단위 구분)이며 값은 **조건 결과 전체 건수**다 — 불러온 200이 아니다. 원천은 넷이다: 오프셋 목록의 총 건수 · **커서 목록의 첫 묶음 총 건수**(커서 목록도 조건 결과 총계를 첫 묶음에 싣는다 — 정본 [../06_api/01_conventions.md](../06_api/01_conventions.md)) · 범위 조회·로컬 목록의 행 수 · 범위 응답을 화면이 다시 거른 목록의 화면 산출 건수. 총계를 싣지 않는 커서 목록은 **다 읽기 전에는 N건을 적지 않는다**(불러온 수를 적으면 전체로 읽힌다). 필터 전 건수는 N건의 툴팁으로 남긴다. 불러온 건수 · 추가 로딩 · 추가 오류 · 완료는 스크린리더 상태 영역이 문장으로 알린다(§5-1) |
| 묶음 선택 | 신고자료처럼 “전체 선택”이 있는 목록은 **현재 불러온 N건 전체 선택**으로 표현한다. 이후 추가된 행은 자동 선택하지 않고 사용자가 다시 선택 범위를 결정하게 한다. 선택 조작과 일괄 작업의 규격은 §3-8이 정본이며 본 행은 **누적 목록에서 “전체”가 무엇을 뜻하는가**만 정한다 |
| 파생 열 | 행마다 조회하지 않고 고정 횟수 조회로 채운다 |
| 민감 열 | 목록은 가장 넓게 열리는 표면이므로 **급여·주민번호·계좌·상세 주소를 싣지 않는다**. 주민번호는 마스킹 값만 노출한다. **주소는 시·도 · 시·군·구까지만** 싣고(서버가 잘라 보낸다 — 원문이 응답에 실리지 않는다) 원문은 상세에서 본다. 연락처는 관리자가 직원에게 바로 연락하는 축이라 목록에 싣는다 |

### 3-5. 빈 상태 3분기

빈 상태는 **전체 0건 · 권한 · 필터 0건 셋을 문안으로 구분**한다. 셋을 같은 문안으로 처리하면 사용자가 "데이터가 없는 것"과 "볼 수 없는 것"을 구분하지 못한다.

| 분기 | 문안 방향 | 다음 행동 |
|------|----------|----------|
| 전체 0건 | "아직 {대상}이 없습니다" | 생성·등록 CTA를 함께 둔다. 생성 권한이 없으면 누가 만드는지 안내한다 |
| 권한 | "열람할 수 있는 {대상}이 없습니다" | 오류가 아니라 가시 범위가 빈 상태임을 밝힌다. 조치가 있으면(관리자 문의·역할 요청) 함께 안내한다 |
| 필터 0건 | "조건에 맞는 {대상}이 없습니다" | 필터 초기화 액션을 둔다 |

**필터 바는 한 줄이다.** 자리가 좁아 줄이 나뉠 때는 **검색 입력 · 콤보박스 · 초기화 · 액션이 한 흐름으로 줄을 나누고 액션은 줄 오른쪽 끝**에 선다 — 필터 묶음을 액션 옆 남은 폭 안에 가두면 좁은 목록 페인에서 필터가 하나씩 세로로 쌓였다(직원 목록 1440 · 세 줄). "적용된 조건" 칩 줄을 따로 두지 않는다 — 콤보박스는 고른 이름을, 검색 입력은 검색어를 이미 보이므로 칩은 같은 정보를 한 줄 더 쓰는 것이었고 표가 시작되기까지 한 단을 먹었다. **조건이 하나라도 걸려 있으면 필터 줄 끝에 인라인 "초기화"가 붙고**, 그것은 필터 0건 빈 상태의 "필터 초기화"와 **같은 동작**이다 — 둘이 갈리면 사용자가 빈 화면에서 빠져나오지 못한다.

**적용 대상이 아님(403)은 빈 상태가 아니라 안내 상태다** — 5인 미만 사업장의 연차 화면(ADM-LEAVE-BALANCE · APP-LEAVE)은 "적용 대상이 아닙니다"와 근거를 적고 조치 버튼을 두지 않는다.

### 3-6. 낙관적 갱신 금지

**서버 확정 후에만 화면을 갱신하는 화면군**이다. 이 목록의 화면은 낙관적 갱신을 쓰지 않는다 — 되돌릴 수 없거나, 서버 판정이 결과를 바꾸거나, 값이 법정 기록이기 때문이다.

| 금지 대상 | 사유 |
|-----------|------|
| 출퇴근 체크인(APP-CHECKIN) | 시각은 서버가 찍고 지오펜스도 서버가 재검증한다. 클라이언트가 성공을 먼저 그리면 반경 밖 체크인이 성공한 것처럼 보인다 |
| 근태 승인·마감(ADM-ATTENDANCE-APPROVAL · ADM-ATTENDANCE-CLOSING) | 승인은 재판정·재집계를 동반하고 마감은 차단 사유 6종을 서버가 판정한다 |
| 휴가 신청·승인(APP-LEAVE · ADM-LEAVE-APPROVAL) | 예약 차감과 확정 기록이 원장 트랜잭션이다 |
| 급여 계산·확정·정정(ADM-PAYROLL-PREVIEW · ADM-PAYROLL-RUN) | 계산은 서버 전용 결정론이며 확정은 값 동결을 동반한다 |
| 명세서 발행·정정(ADM-PAYSLIP) | 교부가 법정 사건이라 화면 표시가 사실보다 앞서면 안 된다 |
| 임포트 확정(ADM-IMPORT) | 부분 실패가 있고 커밋 결과가 행 단위로 갈린다 |
| 사업장 등록·폐쇄·검증(ADM-WORKPLACE-CREATE · ADM-WORKPLACE-SETTINGS) | 외부 API 판정과 선행조건 검사가 결과를 바꾼다 |
| 멤버 초대·역할 변경·제외(ADM-MEMBERS) | 인원 한도와 OWNER 단일성을 서버가 최종 판정한다 |
| 기준값·정책·약관 변경(SYS-RATES · SYS-POLICY · SYS-TERMS) | 유효기간 겹침을 DB 제약이 판정한다 |
| 제재 액션(SYS-WORKPLACES · SYS-USERS) | 마지막 SUPER_ADMIN 보호 등 서버 불변식이 있다 |

**낙관적 갱신을 허용하는 유일한 축은 읽기 상태 토글**이다 — 알림 읽음 표시(APP-NOTIFICATION)는 실패해도 손실이 없고 중복 읽음이 멱등 성공이라 즉시 반영하고 실패 시 되돌린다.

### 3-7. 토스트·에러 문안 톤

| 항목 | 규격 |
|------|------|
| 채널 | 성공·정보는 토스트, 폼 오류는 인라인, 화면 전체 실패는 본문 대체 영역에 둔다. 같은 사건을 두 채널로 중복 알리지 않는다 |
| 문안 구조 | "무엇이 안 됐는가 + 왜 + 다음에 무엇을 하면 되는가" 순으로 적는다. 서버 원문 오류·내부 식별자·스택을 노출하지 않는다 |
| 톤 | 평서·존중 톤을 일관되게 쓴다. 사용자를 탓하는 표현과 감탄부호를 쓰지 않는다 |
| 코드 병기 | 문의가 필요한 실패(외부 API 장애 · 내부 실패 · 내보내기 실패)만 에러 코드를 함께 노출한다. 사용자가 스스로 고칠 수 있는 검증 실패에는 코드를 붙이지 않는다 |
| **급여·법정 안내** | **단정적 표현을 쓰지 않는다.** "이 금액이 맞습니다" 대신 "계산 결과입니다"로 적고, **계산 결과가 참고자료이며 신고·납부의 최종 책임은 사업주에게 있음을 함께 고지**한다(REQ-GLB-20) |
| 책임 한계 고지 위치 | 급여 미리보기·확정·명세서·퇴직 정산·신고자료·**이직확인서**·기한 캘린더 **관리자 웹 7화면**에 상시 노출한다. 직원 앱은 APP-PAYROLL-HISTORY · APP-PAYSLIP에 같은 고지를 둔다. 닫기 버튼을 두지 않는다 |
| 적용 제외 고지 | **가사사용인·동거친족만 사용하는 사업은 근로기준법 적용 제외**라 계산 결과가 적용되지 않음을 온보딩(ADM-WORKPLACE-CREATE)에서 고지한다(REQ-GLB-20) |
| 미지원 고지 | v1이 만들지 않는 신고 자료(원천징수이행상황신고서 · 지급명세서 · 연말정산 · 두루누리 지원)는 **부정형으로 명시**하고 사용자가 직접 처리해야 함을 적는다 |
| 미확인 값 | 확인되지 않은 기준값은 확정 값처럼 그리지 않는다. 계산이 차단된 상태를 그대로 보여주고 무엇을 등록해야 하는지 안내한다 |

### 3-8. ERP 상호작용 표준

**대상은 관리자 웹과 시스템 웹이다.** 직원 앱은 한 사람이 자기 기록 하나를 다루는 표면이라 여기 해당하지 않는다.

이 절이 다루는 것은 **같은 처리를 여러 건에 반복하는 동선**이다. 관리자의 하루는 "목록을 훑으며 하나씩 처리"이고 그 반복이 20건·200건이 되면 건별 왕복이 곧 비용이 된다. 아래 **9축**은 그 반복을 줄이되 **서버 판정을 앞지르지 않는 범위**에서만 연다 — 축마다 왜 그런지를 함께 적는다.

검산: 행 선택 · 일괄 작업 바 · 표 키보드 동선 · 명령 팔레트 · 전역 단축키 · 저장 뷰 · 합계 행 · 열 표시 제어 · 인라인 셀 편집 = **9축**. 표 밀도 선택은 두지 않는다(D-24 · §5-7).

| 축 | 규격 | 왜 |
|----|------|-----|
| **행 선택** | 체크박스를 **첫 열 앞의 전용 열**로 두고 헤더 체크박스는 §3-4의 "현재 불러온 N건 전체 선택"이다. **Shift 클릭은 직전 선택 행부터 현재 행까지 범위를 선택**하고, 선택은 **동종 제한**을 갖는다 — 액션이 적용될 수 없는 상태의 행(이미 승인된 요청 · 확정된 실행)은 선택 대상에서 뺀다. 필터·정렬·사업장 전환·변이 성공은 선택을 해제한다 | 선택은 액션의 대상 집합이므로 **적용 불가 행이 섞이면 부분 실패가 기본값**이 된다. 모집단이 바뀐 뒤에도 선택이 남으면 사용자가 보지 않은 행에 액션이 걸린다 |
| **일괄 작업 바** | 선택이 1건 이상이면 목록 하단에 고정 바가 나타나 **선택 N건**과 액션 버튼을 낸다. **Esc로 선택을 해제**하고 바가 사라진다. 실행은 **행별 결과를 표로 되돌리며 부분 실패를 그대로 표시**한다 — 성공 건수·실패 건수·실패 사유를 행 단위로 적고 실패분만 다시 선택하는 액션을 둔다. **서버 확정 후에만 목록을 갱신한다**(§3-6). 되돌릴 수 없는 작업(§3-2)은 일괄 대상으로 두지 않는다 | 일괄 실행은 **전부 성공 아니면 전부 실패가 아니다** — 건별 권한·상태·경합이 갈리므로 하나의 토스트로 뭉치면 무엇이 남았는지 알 수 없다. 되돌릴 수 없는 작업을 묶으면 2단 확인이 N건을 한 번에 통과시키는 형태가 된다 |
| **표 키보드 동선** | ↑↓ 행 이동 · **Enter 상세 열기** · **Space 선택 토글** · Home/End 처음·끝 행 · PageUp/PageDown 화면 단위 이동이다. **누적 목록은 마지막 행에 닿으면 다음 200건을 이어 읽는다**(§3-4) — 키보드만 쓰는 사람은 스크롤을 굴리지 않는다. 포커스는 표 자체가 갖고 활성 행을 보조기술에 알린다(§5-1). **근태 일괄 승인과 급여 2단 확정은 마우스 없이 완결된다** | 키보드 완결은 접근성 요건이자 반복 처리의 속도 축이다. 20건 승인에서 포인터를 오가는 비용이 판단 비용보다 커진다 |
| **명령 팔레트** | **Ctrl+K**(macOS Cmd+K)로**만** 연다 — **헤더에 진입 버튼을 두지 않는다**(포인터 이동은 사이드바와 메뉴 검색이 맡고, 헤더 버튼은 같은 일을 하는 세 번째 입구이면서 탭 줄이 쓸 폭을 먹는다 · 목록의 전달 수단은 **?** 도움말이다). 검색 대상은 **메뉴(§4-1 초성 검색과 같은 엔진) · 현재 열린 탭 · 현재 화면이 등록한 액션** 셋이다. 화면은 자기 액션을 팔레트에 등록하되 **권한이 없는 액션은 등록하지 않는다**. 팔레트는 오버레이 단일 레이어 계수에 포함된다(§3-1) | 사이드바 26항목 + 탭 + 화면 액션을 포인터로만 오가면 이동이 곧 작업 시간이 된다. 권한 밖 액션을 노출하면 팔레트가 **실패할 명령의 목록**이 된다 |
| **전역 단축키** | **/** 검색 포커스 · **Alt+1~9** 탭 전환 · **Ctrl+S** 저장(현재 화면에 위임 — 저장 대상이 없으면 아무 일도 하지 않는다) · **?** 단축키 도움말이다. 입력·편집 중에는 /와 ?를 문자로 받는다. 도움말은 이 목록을 화면에서 그대로 보여 준다 | 외우지 못하는 단축키는 없는 것과 같으므로 **?가 목록의 유일한 전달 수단**이다. 입력 중 문자 가로채기는 값을 잃게 한다 |
| **저장 뷰** | 필터·정렬·검색을 **URL 쿼리 직렬화 그대로** 이름 붙여 저장한다. 저장 위치는 **기기별 클라이언트 영속**이며 **서버에 저장하지 않는다**. **표시는 필터 바 근처의 칩 줄**이다 — 각 칩이 저장된 뷰 하나이고 누르면 그 뷰를 적용해 활성 칩으로 강조하며, 칩마다 삭제(×) 컨트롤을 갖는다. 현재 조건을 새 칩으로 저장하는 입력도 같은 줄에 둔다. 뷰를 고르면 목록은 첫 200건부터 다시 읽는다(§3-4 초기화) | 뷰는 개인의 작업 습관이지 사업장 데이터가 아니다. 서버에 두면 테이블과 행 단위 격리 정책이 따라붙는데 v1이 그 비용을 치를 이유가 없다. 기기별이라는 사실을 화면이 밝힌다 |
| **합계 행** | 표 하단 고정 행에 **서버가 내려준 합계값만** 렌더한다. **화면이 행을 더해 합계를 만들지 않는다** — 누적 목록은 모집단의 일부만 갖고 있어 화면 합산은 "지금 불러온 것의 합"이 되며, 그것을 전체 합계로 읽으면 틀린다. 서버 합계가 없는 목록은 합계 행을 두지 않는다 | 금액은 서버가 내려준 값을 그대로 렌더한다(§3 공통 패턴). 합계는 그 규칙의 가장 어기기 쉬운 자리다 |
| **열 표시 제어** | 열 메뉴에서 열을 고정·숨김한다. **사용자 지정이 자동 접힘보다 우선**하며(자동 접힘은 폭이 모자랄 때의 기본값일 뿐이다) 접힌 열이 있으면 **"접힌 열 N개"를 표시하고 복원 경로를 준다.** 열 메뉴는 상단 줄 맨 오른쪽이고 N건이 바로 왼쪽이다(§3-4). 열 표시·정렬은 저장 뷰에 함께 실린다. 예전에 저장된 밀도 값은 읽고 버린다 | 자동 접힘이 사용자 지정을 덮으면 사용자는 자기가 고정한 열이 왜 사라졌는지 알 수 없다. 접힌 사실을 숨기면 값이 없는 것과 구분되지 않는다 |
| **인라인 셀 편집** | **Enter로 편집 진입 · Esc 취소 · Tab 다음 셀**이며 **서버 확정 후에만 값을 갱신한다.** 여는 열은 화면 명세가 지정하고 **§3-6 낙관적 갱신 금지 대상은 인라인으로 열지 않는다.** 편집 중 필터·정렬·추가 조회를 잠그고, 실패는 그 셀에 인라인으로 표시하며 이전 값을 되돌린다 | 서버 판정이 결과를 바꾸는 값(승인·확정·법정 기록)을 셀에서 고치면 **폼의 검증 계층 셋**(§6)을 우회하는 입력 경로가 생긴다. 열어도 되는 것은 그 셋을 모두 통과해도 결과가 같은 값뿐이다 |

- **지금 상태에서 성립하지 않는 전이는 버튼을 내지 않는다.** 비활성 + 사유는 **권한 축**만 쓴다 — 권한 밖 버튼은 무엇이 자기 권한 밖인지 알게 하는 정보지만, 상태 밖 버튼(열린 달의 마감 취소 · 정지되지 않은 계정의 정지 해제 · 발행할 것이 없는 기간 발행)은 누를 일이 없는 줄을 하나 더 세울 뿐이다. 상태가 바뀌면 그 전이가 선다.
- **이 절은 표시·조작 규격이지 인가가 아니다.** 선택·팔레트·단축키가 열어 준 경로도 서버가 다시 거부할 수 있으며 화면은 §1-2로 처리한다.
- **카드 표현(1024 미만 · 필수 열만 남겨도 자리에 안 들어가는 표)에서는 행 선택·일괄 작업 바·합계 행만 유지하고 키보드 동선·열 메뉴를 두지 않는다** — 열·행 격자가 사라지므로 축 자체가 성립하지 않는다(§5-2). 명령 팔레트는 표가 아니라 셸의 축이라 768 미만(드로어 표면)에서만 두지 않는다.

### 3-9. 검색형 콤보박스

**관리자 웹·시스템 웹 툴바의 필터 선택 컨트롤은 전부 검색형 콤보박스다**(D-24). 네이티브 선택 상자는 직원 250명 · 사업장 수천 곳을 스크롤로 찾게 하고 이름 일부나 초성으로 좁힐 수 없다. **네이티브 선택 상자는 폼 입력에만 남기며**, 선택지가 셋 이하인 상태 필터는 분할 버튼(세그먼트)을 써도 된다.

| 항목 | 규격 |
|------|------|
| 형태 | 컨트롤 앞에 필터 이름을 작게 적고 고른 값의 이름을 보인다. 조건 없음은 "전체" 선택지이며 목록 맨 위다. 필수 필터(급여월처럼 늘 값이 있는 축)는 "전체"를 두지 않는다 |
| 정적 선택지 | 화면이 가진 목록(상태 · 유형 · 분류)은 입력하면 **부분 문자열 + 초성**으로 거르고 걸린 구간을 굵게 + 밑줄로 강조한다. 매처는 메뉴 검색(§4-1)과 같은 엔진이다 |
| 서버 선택지 | 직원 · 행위자 · 사업장처럼 큰 목록은 입력 **250ms** 뒤 그 목록 표면의 검색어(부분 일치)로 **첫 50건**을 조회한다. 검색어가 바뀌면 이전 조회를 끊는다. 결과가 잘렸으면 "검색어를 더 입력하면 결과가 좁혀집니다"를 붙인다 |
| 초성 분기 | **초성만 입력하면**(ㄱㅊㅅ) 서버 검색어는 초성을 모르므로 조건 없는 첫 50건을 받아 화면이 초성으로 거른다. 그 밖의 사람은 이름 글자로 찾는다 |
| 선택값 이름 | 고른 값이 지금 선택지에 없으면(주소로 들어온 필터 · 첫 50건 밖) 그 값 하나의 이름만 상세 표면으로 읽는다. 선택지로 받은 이름은 다시 읽지 않는다 |
| 캐시 | 조회 캐시는 §3 사업장 스코프 캐시와 같은 축이다 — 사업장 + 역할(시스템 웹은 플랫폼 역할) 단위로 나누고 같은 검색어는 60초 동안 다시 조회하지 않는다 |
| 상태 | 팝업 안에 불러오는 중 · 조회 실패(사유 + 다시 시도) · 일치하는 항목 없음을 구분해 낸다. 필터가 URL에 남는 규칙(§3-4 필터)은 그대로다 |
| 키보드 | WAI-ARIA combobox + listbox 계약이다 — ↓ 열기·다음 · ↑ 이전 · Home/End 처음·끝 선택지 · Enter 고르기 · Esc 닫기 · Tab 닫고 이동. 한글 조합 중의 Enter는 고르기로 보지 않는다 |
| 자동완성 | 입력에 브라우저 자동완성과 비밀번호 관리자 채우기를 막는 속성을 단다 — 비활성 탭에 남은 로그인 폼 때문에 검색 입력에 아이디가 채워지던 결함이 있었다. 검색 입력(메인 검색창)도 같은 규칙이다 |

- **메인 검색창은 콤보박스가 아니다.** 목록 표면의 검색어(부분 일치)로 목록 자체를 좁히며 250ms 디바운스로 조회한다. 서버 검색어가 없는 목록을 화면이 불러온 200건 안에서 거르지 않는다 — 불러오지 않은 행이 조용히 빠진다. 범위 조회를 화면이 다시 거르는 목록만 예외이며 그 건수는 §3-4 건수 표기의 화면 산출 원천이다.

### 3-10. 안내 배치

화면 위 안내는 **판단에 필요한가**로 세 자리에 나눈다. 설명 배너를 표 위에 상시로 두면 매번 같은 문장을 읽게 하고 표를 한 단씩 밀어 내며, 정작 판단에 필요한 고지가 설명 사이에 묻힌다.

| 분류 | 자리 | 대상 |
|------|------|------|
| **늘 보여야 한다** | **한 줄 고지** — 툴바 위 한 줄 · 닫기 없음 · 화면당 **둘까지** | 차단 사유(마감을 막는 항목 N건 · 확정 불가) · 법정·책임 고지(REQ-GLB-20 책임 한계 고지 · 적용 제외 · 미지원) · 되돌릴 수 없음 · 결과가 달라지는 상태(한도 도달 · 스냅샷 부재 · 기한 임박) |
| **처음 쓰는 사람에게만 필요하다** | **툴바 끝 안내 아이콘(ⓘ) 팝오버** — 이름은 "{주제} 안내" | 화면이 무엇을 하는지 · 규칙의 배경 · 확정이 아님 같은 설명형 문장 |
| **충족 상태를 알릴 뿐이다** | **두지 않는다** | "막는 항목이 없습니다" 같은 안심 배너 — 차단 사유가 없다는 사실은 액션이 활성인 것이 이미 말한다 |

- 한 줄 고지는 **한 문장**이다. 두 문장이 필요하면 뒤 문장은 줄 끝 ⓘ로 뺀다. 목록(차단 항목 전수)은 고지가 아니라 본문의 몫이다 — 고지 줄 끝에 그 본문으로 가는 액션 하나만 둔다.
- 색만으로 알리지 않는다(§5-1) — 차단·경고·정보 고지는 톤 아이콘과 문장이 함께 사유를 말한다. 책임 한계 고지는 경고 색을 쓰지 않는 평문 한 줄이다(§3-7).
- **닫을 수 있는 고지를 만들지 않는다.** 닫아도 되는 문장은 판단 근거가 아니라 설명이고, 설명은 ⓘ로 간다.

## 4. 내비게이션

### 4-1. 관리자 웹 사이드바

관리자 웹은 **좌측 고정 사이드바 + 우측 콘텐츠 영역 2단**이고 콘텐츠 영역은 탭 워크스페이스다(§4-4). 사이드바는 섹션(1depth) + 항목(2depth) 구조이고 한 항목이 화면 2본을 묶으면 **3depth**를 편다. 상단에 활성 사업장 전환기, **맨 아래에 메뉴 검색**을 두고 **사이드바에 사용자 영역을 두지 않는다.** **콘텐츠 헤더는 탭 줄 한 벌이다** — 좌측·중앙을 탭 줄이 쓰고 우측 끝에 **알림 벨 · 프로필 메뉴**를 둔다(§4-4).

**6섹션 26항목**이다 — 검산: 1 + 4 + 5 + 6 + 6 + 4 = **26**. 근태·휴가 섹션의 "휴가·연차"가 화면 2본을 3depth로 묶으므로 항목 26 대비 화면은 27본이며, 여기에 사이드바 항목이 없는 ADM-EMPLOYEE-DETAIL · ADM-EMPLOYEE-RESIGN · ADM-WORKPLACE-SELECT · ADM-WORKPLACE-CREATE 4본을 더해 ADM **31본**이 된다.

- **홈은 사이드바 첫 항목이자 로그인 후 도착지**다(ADM-HOME). 사업장을 고른 뒤 처음 열리는 화면이며 다른 화면을 전부 닫아도 남는다(§4-4).
- **사이드바에 항목이 없는 ADM 화면 4본**은 상위 화면에서만 들어간다 — 사업장 선택·등록은 진입 분기와 구독 화면에서 열고, **직원 상세(ADM-EMPLOYEE-DETAIL)와 퇴사 처리(ADM-EMPLOYEE-RESIGN)는 직원 목록(ADM-EMPLOYEE-LIST) 탭 안의 페인으로 열린다** — 목록을 떠나지 않고 그 자리에서 상세·퇴사를 처리하는 것이 §7 동선이기 때문이다. **화면 코드·라우트·딥링크는 그대로다** — /employees/[id]와 /employees/[id]/resignation로 직접 들어오면 목록 탭이 열리고 그 페인이 선택된 상태가 된다. 세 화면이 한 탭을 공유하므로 **탭은 목록 하나이며 상세는 탭 파라미터**다(§4-4).
- **STAFF에게는 관리자 웹 자체를 열지 않는다**(WRK-06). 사이드바 항목별 노출 제어가 아니라 진입 단계에서 되돌린다.
- **OWNER 전용 액션은 항목을 감추지 않고 화면 안에서 컨트롤을 감춘다** — MANAGER가 화면을 열고 무엇이 자기 권한 밖인지 알 수 있어야 상위에게 요청할 수 있다.
- **섹션은 다중 확장이다.** 열린 섹션을 하나로 제한하지 않는다 — 근태와 급여를 오가는 작업이 흔해 단일 확장이면 이동마다 접힘·펼침이 반복된다.
- **사이드바는 자체 스크롤을 갖는다.** 다중 확장에서 항목이 뷰포트를 넘길 수 있으므로 사이드바 영역 안에서만 스크롤하고 콘텐츠 영역과 페이지 본문을 밀지 않는다(§5-3).
- **프로필은 헤더 우측 한 곳에만 둔다**(D-24). 트리거는 아바타 · 이름 · 역할 배지이고(역할 값은 대문자 · §5-6) 768 미만에서는 아바타만 둔다. 메뉴 머리는 **이름 · 아이디 · 역할 · 현재 사업장**이고 항목은 **계정 설정 · 테마(시스템 · 라이트 · 다크 중 하나를 고르는 라디오 항목) · 구분선 뒤 로그아웃** 순이다. 사이드바 하단 사용자 영역과 헤더의 별도 테마 토글을 두지 않는다 — 같은 조작이 두 자리에 있으면 어느 쪽이 정본인지 묻게 되고 사이드바 세로 한 단을 먹는다.
- **메뉴 검색을 사이드바 맨 아래에 둔다.** 입력이 있으면 섹션 위계를 접고 **평면 결과 목록**으로 바꾸며, 입력을 비우면 원래 트리로 되돌린다. **초성 검색을 지원한다**("ㄱㅇ" → 급여 기준 · 급여 실행 · 급여대장) — 26항목을 한글 전체 타이핑으로 좁히면 검색이 이동보다 느려진다. 같은 검색 엔진을 명령 팔레트가 재사용한다(§3-8).
- **메뉴 영역 우클릭에 컨텍스트 메뉴를 둔다** — 모든 메뉴 펼치기 · 모든 메뉴 접기 두 항목이다.
- **항목 우측에 하위 개수 배지를 두지 않는다.** 하위 개수는 업무 신호가 아니라 구조 정보라 상시 노출할 값이 아니다. **내비게이션 배지는 §4-2 직원 앱 드로어 항목에만 둔다.**
- **1·2·3depth 전부 좌측 아이콘을 갖는다.** 위계는 들여쓰기로만 표현하고 폰트·크기·행 높이는 depth와 무관하게 같다 — depth마다 크기를 달리하면 스캔 축이 둘로 갈린다.
- **콘텐츠 헤더에 화면 코드(ADM 접두) 칩을 노출하지 않는다.** 화면코드는 문서·추적성 축이지 사용자 어휘가 아니다. **브레드크럼도 두지 않는다** — 활성 탭이 "지금 어디"를 말하고 사업장은 사이드바 전환기가, 섹션은 사이드바 위계가 이미 말한다. 같은 말을 헤더가 다시 적으면 줄 하나를 더 쓰면서 탭 줄이 쓸 폭을 깎는다. **768 미만에서는 탭 줄이 없으므로**(§4-4) 그 자리에 **화면명 한 마디**만 둔다 — 화면 제목은 문서 구조용 sr-only 라 그것이 없으면 지금 어느 화면인지 말하는 자리가 사라진다.
- 768px 미만에서는 사이드바를 걷고 상단 앱바 + 햄버거 드로어로 대체하며 드로어에 같은 depth 구조를 세로로 펼친다.

### 4-2. 직원 앱 드로어

직원 앱은 **좌상단 햄버거 드로어 5섹션 8항목**이며 드로어 화면 위에 네이티브 스택으로 상세를 쌓는다.

| 섹션(수) | 항목 라벨 → 화면코드 | 스택 하위 | 배지 | 퇴사자 모드 |
|----------|---------------------|----------|------|------------|
| 홈(1) | 출퇴근 → APP-CHECKIN(초기 화면) | 없음 | 없음 | 잠금 |
| 근무(2) | 근무 기록 → APP-ATTENDANCE | 없음 | 미승인 수정 요청 수 | 잠금 |
| 근무(2) | 휴가 → APP-LEAVE | 없음 | 없음 | 잠금 |
| 급여(1) | 급여 → APP-PAYROLL-HISTORY | APP-PAYSLIP | 미열람 명세서 수 | 열림 |
| 알림(1) | 알림 → APP-NOTIFICATION | 없음 | **미읽음 수**(0이면 배지를 렌더하지 않는다) | 열림 |
| 내 정보(3) | 내 정보 → APP-SETTINGS | 없음 | 없음 | 열림 |
| 내 정보(3) | 내 문서 → APP-CONTRACT | 계약 상세 | 서명 대기 계약 수 | 열림 |
| 내 정보(3) | 개인정보 → APP-PRIVACY | 없음 | 없음 | 열림 |

**5섹션 8항목**이다 — 검산: 1 + 2 + 1 + 1 + 3 = **8**이며 드로어 화면 8본과 1:1 대응한다. 여기에 스택 하위 1본(APP-PAYSLIP)을 더해 드로어 셸이 담는 화면은 9본이고, 드로어 밖 인증 스택의 APP-INVITE까지 합해 APP 10본이 된다(정본 [README.md](./README.md)).

- 인증 스택(PUB-SIGNUP · PUB-LOGIN · PUB-PASSWORD-RESET · PUB-CONSENT · APP-INVITE)은 **드로어 밖**이며 인증·초대 수락이 끝나야 드로어 셸로 들어간다.
- 다중 소속 직원의 **사업장 전환은 APP-SETTINGS 안에서** 한다 — 드로어 머리에 전환기를 두면 상시 노출 축이 둘로 갈리고 전환 빈도도 낮다. 드로어 머리에는 현재 사업장명과 역할 배지를 읽기 전용으로만 보인다.
- **하단 탭바를 두지 않는다 — 상단 앱바가 유일한 상시 내비게이션이다.** 앱바는 좌측 햄버거 버튼(최소 44포인트) · 현재 화면 제목 · **배지 합이 0보다 클 때 햄버거에 얹는 점 표시**로 구성하고 우측은 비운다. 알림이 드로어 항목이므로 앱바에 벨을 중복해서 두지 않는다. 스택 하위 화면은 뒤로 제스처와 뒤로 버튼으로 되돌린다.
- **배지 축은 4종뿐이다** — 근무 기록(미승인 수정 요청 수) · 급여(미열람 명세서 수) · 알림(미읽음 수) · 내 문서(서명 대기 계약 수)다. 검산: 1 + 1 + 1 + 1 = **4**. 값이 0이면 어느 축이든 배지를 렌더하지 않으며, 배지 조회 실패는 0으로 수렴시켜 셸 장식이 화면 진입을 막지 않게 한다.
- **드로어가 열려 있는 동안 시트·모달을 띄우지 않는다**(§3-1) — 항목을 고르면 드로어가 먼저 닫히고 이동한다. 드로어 자체는 오버레이 단일 레이어 계수에서 제외한다.
- **퇴사자 모드에서는 3항목을 잠근다** — 소속 사업장이 0인 상태에서 출퇴근 · 근무 기록 · 휴가는 사업장 컨텍스트가 있어야 성립하므로 **비활성으로 표시하고 누르면 사유를 토스트로 알린다**. 항목을 감추지 않는 이유는 §4-1과 같다 — 무엇이 왜 닫혔는지 보여야 다음 행동을 고를 수 있다. 나머지 5항목은 본인 소유권으로 열린다(CMP-07 · §1-1 본인). **알림도 열린다** — 계정 단위 자원이라 멤버십 없이 성립하며 계정 정지·플랫폼 공지를 놓치면 안 된다.
- **드로어 표시 라벨은 직원 눈높이로 순화하되 정본 화면명은 바꾸지 않는다.** 대응은 아래 표가 정본이며 화면코드가 두 축을 잇는다.

| 드로어 라벨 | 정본 화면명 | 화면코드 |
|------------|------------|----------|
| 출퇴근 | 출퇴근 체크인 | APP-CHECKIN |
| 근무 기록 | 내 근태 내역 | APP-ATTENDANCE |
| 휴가 | 휴가 신청·잔여 연차 | APP-LEAVE |
| 급여 | 내 급여 이력 | APP-PAYROLL-HISTORY |
| 알림 | 알림함 | APP-NOTIFICATION |
| 내 정보 | 내 정보·설정 | APP-SETTINGS |
| 내 문서 | 내 문서 — 근로계약·서류 | APP-CONTRACT |
| 개인정보 | 개인정보·위치정보 관리 | APP-PRIVACY |

- **드로어에도 화면 코드 칩을 노출하지 않는다**(§4-1과 같은 규칙). 화면코드는 문서·추적성 축이며 사용자 어휘가 아니다.

### 4-3. 시스템 웹

시스템 웹은 관리자 웹과 같은 2단 골격을 쓰되 사업장 전환기가 없다 — 플랫폼 운영은 특정 사업장 컨텍스트를 갖지 않는다.

| 섹션 | 섹션 id | 항목 | 화면코드 | 최소 역할 |
|------|---------|------|----------|----------|
| 운영(2) | operations | 사업장 | SYS-WORKPLACES | 플랫폼(VIEWER) · 제재는 플랫폼(ADMIN) |
| 운영(2) | operations | 사용자 | SYS-USERS | 플랫폼(VIEWER) · 제재는 플랫폼(ADMIN) · 강제 삭제는 플랫폼(SUPER_ADMIN) |
| 상품(1) | product | 구독·요금제 | SYS-SUBSCRIPTIONS | 플랫폼(VIEWER) · 변경은 플랫폼(ADMIN) |
| 기준(3) | standards | 기준값 | SYS-RATES | 플랫폼(VIEWER) · 변경은 플랫폼(ADMIN) |
| 기준(3) | standards | 규모별 정책 | SYS-POLICY | 플랫폼(VIEWER) · 변경은 플랫폼(ADMIN) |
| 기준(3) | standards | 약관 문서 | SYS-TERMS | **플랫폼(ADMIN)** — 조회도 VIEWER에는 열지 않는다 |
| 감사(1) | audit | 감사 로그 | SYS-AUDIT | **플랫폼(ADMIN)** — VIEWER에는 열지 않는다 |

**4섹션 7항목**이다 — 검산: 2 + 1 + 3 + 1 = **7**이며 SYS 화면 7본과 1:1 대응한다. **섹션 id 4종은 operations · product · standards · audit**이며 이 문서가 채번 정본이다 — 시스템 웹은 사업장 컨텍스트가 없어 섹션 축이 곧 최상위 축이라 식별자를 문서에 고정한다.

- **사이드바 UX는 관리자 웹과 같다**(§4-1) — 섹션 다중 확장 · 사이드바 자체 스크롤 · 사이드바 맨 아래 메뉴 검색 · 메뉴 영역 우클릭 펼치기·접기 · 1·2·3depth 전 depth 좌측 아이콘이다. **콘텐츠 헤더에 화면 코드(SYS 접두) 칩을 노출하지 않는 것도 같다.** 프로필 메뉴도 같은 자리 · 같은 구성이며 메뉴 머리에 사업장이 없고 항목은 **관리자 웹으로 · 테마 · 로그아웃**이다.
- **감사 로그와 약관 문서 항목은 플랫폼(VIEWER)에게 렌더링하지 않는다.** 감사 로그는 조회 권한을 넓게 열면 그 자체가 개인정보 열람 경로가 되고, 약관 문서는 VIEWER 권한 집합에 해당 키가 아예 없어 부분 열람을 표현할 수단이 없다.
- **플랫폼 역할 임명·회수 화면을 두지 않는다**(SYS-02 이월).
- **콘텐츠 영역은 관리자 웹과 같은 탭 워크스페이스다**(§4-4). 시스템 웹은 홈 화면을 두지 않으므로 마지막 탭을 닫으면 빈 워크스페이스가 되고, 그때는 무엇을 열 수 있는지 안내한다.

### 4-4. 탭 워크스페이스 (관리자 웹 · 시스템 웹)

**관리자 웹과 시스템 웹의 콘텐츠 영역은 브라우저 탭형 다중 문서 셸이다**(D-22). 화면을 열면 탭이 하나 생기고, 다른 화면으로 가도 **이전 화면은 닫히지 않고 그대로 남는다.** 근태 승인을 보다가 직원 상세를 확인하고 급여 실행으로 돌아오는 동선에서, 매번 목록·필터·스크롤 위치를 다시 만드는 비용을 없애는 것이 목적이다.

| 축 | 규격 |
|----|------|
| **탭 동일성** | **탭 id는 화면 코드다.** 같은 화면의 탭은 언제나 하나이며 같은 화면을 다시 열면 새 탭이 아니라 기존 탭이 활성화된다. **상세는 탭이 아니라 그 탭의 파라미터**다 — 직원 상세·퇴사(§4-1)와 급여 실행 상세가 그렇다 |
| **주소** | **URL은 언제나 활성 탭의 경로**다. 탭을 바꾸면 주소가 그 탭의 경로로 바뀌고, 주소로 직접 들어오면 그 화면의 탭이 열리며 활성화된다. **딥링크·새로고침·공유가 탭 도입 전과 같게 동작한다** |
| **비활성 탭** | 비활성 탭은 **DOM에 남긴 채 감춘다** — 다시 눌렀을 때 필터·스크롤·펼친 행이 그대로여야 탭을 유지하는 의미가 있다. 탭이 많아지면 오래 쓰지 않은 탭부터 언마운트하고 탭 줄에는 남긴다(다시 누르면 처음부터 읽는다) |
| **탭 스코프 상태** | **화면은 라우터의 위치 훅을 직접 쓰지 않고 탭 스코프 훅으로 자기 탭의 파라미터·쿼리를 읽고 쓴다.** 라우터 훅은 언제나 활성 탭의 주소를 돌려주므로, 감춰진 탭이 그것을 읽으면 **남의 필터를 자기 것으로 읽어 잘못된 목록을 다시 부른다.** 비활성 탭의 변경은 주소를 바꾸지 않고 탭에만 남았다가 활성화될 때 복원된다 |
| **세션 복원** | 열린 탭 집합과 활성 탭은 **브라우저 세션 동안** 복원된다. 사업장·표면이 바뀌면 별개의 워크스페이스이며 서로의 탭을 물려받지 않는다(§3 사업장 스코프 캐시) |
| **미저장 가드** | 저장되지 않은 입력이 있는 탭은 **닫을 때 확인**을 받는다. 화면이 자기 미저장 여부를 셸에 알리고 셸이 가드를 건다 — 탭이 있으면 "다른 화면으로 이동"이 더 이상 화면 이탈이 아니라서, 브라우저 이탈 경고만으로는 입력이 조용히 사라진다 |
| **닫기** | 탭은 개별로 닫는다. **관리자 웹은 홈(ADM-HOME)이 마지막에 남는다** — 전부 닫아도 빈 화면이 되지 않는다. 시스템 웹은 홈이 없어 빈 워크스페이스를 허용하고 안내를 낸다 |
| **키보드** | Alt+1~9로 탭을 전환하고 명령 팔레트가 열린 탭을 검색 대상에 포함한다(§3-8) |

- **탭 폭은 화면명 길이를 따른다.** 내용 폭으로 서되 하한(클릭 타깃) 아래로 줄지 않고 상한을 넘는 제목만 말줄임한다 — 값 정본은 [../08_tech_stack/07_design_tokens.md](../08_tech_stack/07_design_tokens.md)다. 모든 탭을 같은 폭으로 두면 탭 줄이 이름이 아니라 칸으로 읽히고, 짧은 이름이 자리를 낭비해 넘침이 일찍 온다.
- **탭은 박스형이다**(D-24). 비활성 탭도 옅은 바탕과 테두리로 **자기 칸**을 갖고 탭 사이에 간격을 두며, 활성 탭은 콘텐츠와 같은 바탕으로 아래 워크스페이스에 이어지고 위쪽에 강조선이 선다. 탭마다 화면 아이콘을 붙인다. 높이 · 글자 크기 · 간격 값의 정본은 [../08_tech_stack/07_design_tokens.md](../08_tech_stack/07_design_tokens.md)다 — 비활성 탭이 바탕 없이 작은 글자만이던 동안 탭 경계가 보이지 않아 열린 화면이 몇 개인지 셀 수 없었다.
- **탭 줄이 곧 콘텐츠 헤더다.** 헤더의 좌측·중앙을 탭 줄이 쓰고 우측 끝에 액션 묶음(알림 · 프로필)이 선다. 탭은 헤더 **바닥선에 붙어** 활성 탭의 바탕이 아래 워크스페이스로 이어진다 — 브라우저 탭과 같은 읽기다. 탭 줄을 헤더 아래 자기 줄로 내리지 않는다: 세로 한 단을 더 먹고, 헤더 좌측은 결국 탭과 같은 말을 반복하게 된다.
- **탭바는 스크롤 밖 고정 요소**이며 사이드바·페이지 헤더와 함께 스크롤 소유자가 아니다(§5-3).
- **768 미만에서는 탭 줄을 두지 않는다** — 폭이 탭 3개도 담지 못해 탭 자체가 스크롤 대상이 되고, 모바일에서는 한 번에 한 화면을 끝내는 동선이다. 사이드바를 걷은 햄버거 드로어가 이동을 맡는다(§5-2). 탭 줄이 서던 자리에는 **화면명 한 마디**가 선다 — 탭도 브레드크럼도 없는 폭이라 두지 않으면 지금 어느 화면인지 말하는 자리가 없다.
- **직원 앱은 탭 워크스페이스를 쓰지 않는다** — 드로어 + 네이티브 스택이다(§4-2).

## 5. UI/UX 품질 기준

### 5-1. 상태·접근성

| 항목 | 기준 |
|------|------|
| 상태 완비 | 로딩·빈 상태·에러·권한거부 **4종은 전 화면이** 설계하고, **세션 만료는 입력이 있는 화면이** 추가로 설계한다(§1-4). 화면 명세의 상태 처리 표가 그 계약이다 |
| **스켈레톤 동형** | 스켈레톤은 실제 콘텐츠와 **같은 레이아웃**을 잡아 로딩이 끝날 때 레이아웃이 흔들리지 않게 한다. 스피너 하나로 화면 전체를 덮지 않는다 |
| 키보드 도달 | 조작 가능한 전 요소가 키보드로 도달·실행 가능하다. 지도 위 마커·달력 셀처럼 포인터 전제 요소에는 키보드 대체 경로를 함께 둔다 |
| 포커스 트랩 | 모달·시트는 열릴 때 포커스를 안으로 옮기고 트랩하며 Esc로 닫고 트리거로 되돌린다 |
| **색 단독 의존 금지** | 상태·구분을 색상만으로 표현하지 않는다. 근태 판정 8종 · 급여 상태 · 명세서 상태 · 위험 플래그 · 5인 미만 표시는 **텍스트 라벨 또는 아이콘을 색과 함께** 표시한다. **상태 채움색에는 텍스트를 얹지 않는다** — 채움은 점 · 막대 · 진행 표시 전용이고 텍스트가 있는 배지는 표면 · 경계 · 전경 조합을 쓴다. 이 규칙이 있어야 배지가 색과 라벨을 함께 갖는다. 텍스트를 얹는 유일한 채움은 파괴적 액션 버튼이다 |
| 스크린리더 라벨 | 아이콘 단독 버튼에 접근 가능한 이름을 붙이고, 목록 건수·진행률·검증 결과 같은 비동기 갱신은 상태 영역으로 알린다. 표에는 열 구성을 설명하는 캡션을 둔다 |
| 데이터 영역 | 표·카드의 내부 스크롤 소유자와 이름 있는 스크롤 영역(§5-3)은 이름 있는 region으로 만들고 키보드 포커스를 허용한다. 카드 전환 시 정렬 가능한 열과 방향을 조작하는 44px 이상 대체 컨트롤을 제공한다 |
| 누적 목록 상태 | 자동 센티널은 보조기술에서 숨긴다. 수동 추가 조회 버튼을 두지 않는 대신 **키보드는 마지막 행 도달이 이어 읽기다**(§3-4). 불러온 건수 · 추가 로딩 · 추가 오류 · 완료는 **화면에 보이지 않는 상태 영역**(role=status · aria-atomic)이 문장으로 알리고, 실패 행의 다시 불러오기 버튼은 격자 안에서 키보드로 닿는다. 새 행 추가 뒤 포커스를 강제로 옮기지 않는다 |
| 대비 | 본문·라벨·상태 배지는 **4.5:1**, 컨트롤 경계와 상태 지시자는 **3:1**을 충족한다. 값과 검산의 정본은 [../08_tech_stack/07_design_tokens.md](../08_tech_stack/07_design_tokens.md)이며 화면 명세는 그것을 인용한다. **장식 구분선(카드 테두리 · 표 격자 · 배지 테두리)은 검산 대상이 아니다** — 요소의 존재를 알리는 지시자가 아니라 구획 장식이고, 그 자리에 3:1을 요구하면 고밀도 표가 격자 그물이 된다. 비활성 컨트롤도 무엇인지 읽을 수 있어야 하므로 3:1을 함께 충족한다 |
| 중복 제출 방지 | 제출 중 버튼을 비활성화하고 진행 표시를 둔다(§3-2) |

### 5-2. 반응형 (웹)

**1024 이상에서 관리자 웹·시스템 웹의 콘텐츠 영역은 스크롤하지 않는다**(D-24). 표 · 분할 페인 · 섹션 · 대시보드 격자가 사이드바와 헤더를 뺀 자리를 나눠 채우고, 넘치는 분량은 그 안의 스크롤 소유자(§5-3)만 스크롤한다. **1024 미만은 표가 카드로 · 분할이 스택으로 · 섹션이 세로 쌓기로 바뀌고 본문 스크롤을 허용한다.**

**크기는 비율로 잇고 경계만 브레이크포인트로 끊는다.** 폭 · 여백 · 타이포는 clamp와 뷰포트 단위로 잇고 브레이크포인트는 레이아웃이 전환되는 자리에만 둔다. 루트 폰트는 rem 기준이라 브라우저 글꼴 설정을 존중한다. 브레이크포인트 **7단**(390 · 768 · 1024 · 1440 · 1920 · 2560 · 3840)의 값 정본은 [../08_tech_stack/07_design_tokens.md](../08_tech_stack/07_design_tokens.md)이며 화면마다 임의 픽셀값을 만들지 않는다.

| 뷰포트 | 성격 | 기준 |
|--------|------|------|
| 390 | 모바일 기준 | 전 화면이 사용 가능하다. 관리자 웹의 마감 · 확정 같은 되돌릴 수 없는 작업도 모바일에서 끝낼 수 있다 |
| 768 | 사이드바와 드로어의 경계 | 사이드바를 걷고 햄버거 드로어로 대체한다. 탭 줄을 두지 않는다(§4-4) |
| 1024 | **뷰포트 고정 · 표 · 상세 병치 시작** | 콘텐츠 영역이 스크롤하지 않는다. 목록은 표로, 목록 옆 상세 페인을 연다. **이보다 좁으면** 표는 카드 목록, 2단 배치는 1열, 상세는 페인이 아니라 목록을 덮는 전체 영역이며 첫 항목을 자동으로 열지 않는다. 표와 카드를 동시에 DOM에 누적하지 않고 현재 표현 하나만 렌더한다 |
| 1440 | 광폭 노트북 | 표 열을 줄이지 않고 그대로 유지한다 |
| 1920 | 기준 데스크톱 | 남는 폭은 열 수와 글자 열(grow)이 쓴다 |
| 2560 · 3840 | QHD · UHD | 루트 폰트와 사이드바 폭이 화면에 비례해 오른다. 남는 폭은 표의 글자 열 · 분할 페인 · 대시보드 격자가 나눠 쓰며 숫자·상태 열은 늘어나지 않는다 |

- **전환 판단은 창 폭이 아니라 콘텐츠가 놓인 자리다.** 사이드바와 상세 페인이 폭을 먹으므로 같은 창 폭에서도 남는 자리가 다르다 — 창 폭으로 판정하면 사각지대가 반드시 생긴다.
- **좁아지면 열부터 걷고 그래도 안 되면 카드로 간다.** 바로 카드로 보내면 폭이 남는데 정보 밀도가 표보다 낮아지는 역전이 생긴다. 걷힌 열은 열 표시 제어가 복원하고 값은 행 확장이나 상세에서 본다. 열을 걷는 판정은 글자 열을 **늘어난 폭이 아니라 최소 폭**으로 센다 — 자리를 채우느라 늘어난 폭을 자연 폭으로 재면 열을 걷을수록 글자 열이 더 늘어나 더 걷는 되먹임이 생긴다. 1024 미만은 자리와 무관하게 카드다.
- **임의 폭에서 깨지지 않아야 한다.** 브레이크포인트는 검증 지점이 아니라 전환점이며, 320~3840 전 구간 훑기가 화면 밖 이탈과 과다 넘침을 검사한다.
- **콘텐츠 영역에 폭 상한을 두지 않는다.** 예외는 단일 폼 카드를 가운데 정렬하는 **미인증 인증 화면 4본**(PUB-SIGNUP · PUB-LOGIN · PUB-PASSWORD-RESET · PUB-CONSENT)과 공개 콘텐츠 3본(PUB-LANDING · PUB-PRICING · PUB-LEGAL)이며, 인증 이후 화면에는 이 예외가 없다.

### 5-3. 스크롤 소유자

**데이터가 많아지면 스크롤은 그 데이터 영역 안에만 생긴다.**

| 항목 | 기준 |
|------|------|
| 소유자 | **1024 이상에서 콘텐츠 영역의 세로 스크롤은 표 데이터 영역과 이름 있는 스크롤 영역(ScrollRegion)만 갖는다.** 스크롤 영역은 상세 페인 본문 · 섹션 본문 · 대시보드 카드 안 목록 · 달력 칸처럼 **넘칠 수 있는 구획 하나**에 이름을 붙인 것이며 region · 키보드 포커스 · 탭 스크롤 기억 표식을 갖는다. 페이지 본문 · 조상 요소에 스크롤을 중복 지정하지 않는다. 1024 미만은 본문이 스크롤 소유자다. 사이드바는 콘텐츠 영역과 겹치지 않는 **별도 스크롤 컨테이너**다(§4-1 · §4-3) |
| 배치 | 관리자 웹·시스템 웹 화면은 배치 5종 중 하나다 — **L 목록**(툴바 + 영역을 채우는 표) · **MD 목록 + 상세 페인** · **SN 섹션**(왼쪽 섹션 목록 + 한 섹션 · 선택은 탭 쿼리 section · 1024 미만 전 섹션 세로) · **DB 대시보드**(12열 × 2행 격자가 영역을 채우고 카드 안 목록만 스크롤 · 1024 미만 1열) · **W 위저드**(단계 본문 스크롤 영역 + 고정 푸터). 화면 명세는 배치 이름을 적고 차이만 기술한다 |
| 고정 요소 | 페이지 헤더 · 탭바 · 필터 바 · 표 헤더 행 · 하단 액션 바는 스크롤 밖에 고정한다 |
| 목록 · 섹션 · 대시보드 머리 | **요약 배지 줄을 두지 않는다** — 화면 제목은 숨긴 제목(스크린리더)이고 "분류 19종 · 기준일 · 플랫폼 역할" 같은 요약은 표 건수 · 필터 값 · 헤더 프로필과 같은 사실을 두 번 말한다. 목록 · 섹션 · 대시보드 골격은 제목 옆 배지 자리를 갖지 않으며, 상태 배지는 상세 페인 머리에만 선다 |
| 상세 페인 머리 | **한 줄이다** — 고른 항목의 제목(보이는 글자) · 상태 배지 · 액션 · 닫기. 닫기만 든 줄을 따로 두지 않고, 화면 제목처럼 숨기지 않는다 — 탭 이름은 화면 이름이지 고른 항목이 아니어서 숨기면 머리가 오른쪽 배지만 남은 빈 줄이 된다. 1024 미만 스택에서는 "목록으로" 줄이 위에 선다 |
| 가로 스크롤 | 넓은 표(급여대장 · 근태 8버킷 · 감사 로그)는 자체 가로 스크롤 컨테이너를 갖고 첫 열을 고정한다. **페이지 본문이 가로로 스크롤되지 않게 한다** |
| 누적 목록 | 자동 센티널은 데이터 스크롤 컨테이너 끝에 둔다. 컨테이너가 실제로 스크롤하지 않으면 뷰포트를 관찰 루트로 둬 연쇄 조회를 막는다(§3-4). 하단 수동 버튼을 두지 않으며 센티널 관찰이 조상 스크롤을 만들지 않게 한다 |
| 모달 | 모달 내부에 스크롤을 만들지 않는다(§3-1) |
| 앱 | 화면 본문이 스크롤 소유자이며 상단 앱바는 스크롤 밖에 고정한다. **안전 영역(상단 노치 · 하단 홈 인디케이터) 밖으로 콘텐츠가 잘리지 않게** 하고 하단 고정 액션은 안전 영역 위에 띄운다(§5-4). 드로어는 콘텐츠 영역과 겹치지 않는 별도 스크롤 컨테이너다(§4-2) |

### 5-4. 직원 앱 고유 기준

| 항목 | 기준 |
|------|------|
| 안전 영역 | 상단 노치·하단 홈 인디케이터 영역을 침범하지 않는다. 하단 고정 액션 버튼은 안전 영역 위에 띄운다 |
| 터치 타깃 | 최소 **44포인트**를 확보한다. 목록 행·체크박스·달력 셀처럼 작아지기 쉬운 요소는 행 전체를 터치 영역으로 넓힌다 |
| 백 제스처 | 스택 화면은 좌측 스와이프 백을 막지 않는다. **되돌릴 수 없는 작업의 확인 단계에서만 제스처를 잠그고** 그 사실을 화면에 알린다 |
| 위치 권한 | 권한 요청은 체크인 시도 시점에 맥락과 함께 띄운다. 거부 상태는 오류가 아니라 안내로 표시하고 설정 이동 경로를 둔다(§5-5) |
| **오프라인** | **v1은 오프라인 기록을 지원하지 않는다**(ATT-14 이월). 네트워크 실패를 큐에 쌓아 나중에 보내지 않고 **실패를 즉시 표시**하며 재시도 액션만 둔다 — 큐에 쌓은 뒤 실패하면 근무는 했는데 기록이 없는 상태가 조용히 만들어진다 |

### 5-5. 위치 관련 상태 처리 (APP-CHECKIN 전용 규격)

체크인 화면은 위치 상태가 여섯으로 갈리며(아래 표) 각각 다르게 처리한다. 개별 화면 명세는 이 표를 다시 쓰지 않고 참조한다.

| 상황 | 처리 | 근거 |
|------|------|------|
| **위치정보 동의 없음** | 체크인 시도를 차단하고 동의 화면으로 유도한다 — privacy.location_consent_required/403 | 위치정보법 §18 별도 동의 |
| **기기 위치 권한 거부** | 오류 배너가 아니라 안내 카드로 표시하고 기기 설정 이동 경로를 둔다. 재시도 버튼을 함께 둔다 | 사용자가 스스로 고칠 수 있는 상태다 |
| **좌표 미수신** | 차단한다 — attendance.accuracy_too_low/422. 실내·지하 등 수신 실패 가능성을 안내하고 재시도와 관리자 문의 경로를 둔다 | 좌표가 없으면 판정 자체가 불가능하다 |
| **위치정확도 한계값 초과** | **차단하지 않는다.** 대기 상태로 저장하고 "관리자 승인 대기"로 표시한다 | 차단하면 근무는 했는데 기록이 없는 상태가 된다 |
| **지오펜스 반경 밖** | 차단한다 — attendance.out_of_geofence/422. 현재 거리와 허용 반경을 함께 보여주고 예외 요청 경로(근태 수정 요청)를 안내한다 | 서버가 좌표와 반경을 재검증한다 |
| 모의위치 의심·시각 차이·비정상 이동거리 | **차단하지 않고** 위험 플래그로 기록한다. 직원 화면에는 별도 경고를 띄우지 않고 관리자 화면(ADM-ATTENDANCE)에만 표시한다 | 오탐이 정상 근로자의 기록을 막으면 안 된다 |

### 5-6. 한국어 카피 톤

| 항목 | 기준 |
|------|------|
| 문체 | 평서·존중 톤을 일관되게 쓴다. 화면 간 톤 차이를 만들지 않는다 |
| **급여·법정 안내** | **단정적 표현을 쓰지 않는다.** "정확합니다" · "문제없습니다" · "신고가 완료됩니다" 같은 확언을 쓰지 않고, 계산 결과·자료 산출까지가 제품의 범위임을 밝힌다 |
| **책임 한계 고지** | 급여·명세서·신고 자료 화면에 **계산 결과는 참고자료이며 신고·납부의 최종 책임은 사업주에게 있음**을 상시 고지한다(REQ-GLB-20). 닫기 버튼을 두지 않는다 |
| 위반 안내 | 최저임금 미달 · 휴게시간 미달 · 연소자 배치 위반 · 기한 경과는 사용자를 탓하지 않고 **무엇이 기준이고 지금 값이 무엇이며 무엇을 하면 되는지**를 적는다 |
| 규모 표기 | 5인 미만 사업장에 **가산 미적용 사실과 근거**를 함께 표기한다. "가산이 없다"만 적으면 실근로분도 무급인 것으로 오해된다 |
| 용어 | 사업장 · 직원 · 멤버 · 임금명세서(명세서) · 급여 확정 · 근태 마감 · 기준값 · 상시근로자 수 산정 · 진위확인 · 검증 상태 · 정기작업으로 고정한다. 동의어를 만들지 않는다 |
| 역할 표기 | 역할 값은 항상 대문자로 적는다 — OWNER · MANAGER · STAFF / VIEWER · SUPPORT · ADMIN · SUPER_ADMIN. **예외는 직원 앱 하나다** — 직원 앱은 역할 값 배지를 한글로 적고(사장 · 관리자 · 직원) 안내문에서 역할 보유자를 "사장님이나 관리자"로 지칭한다. 원시 역할 값은 관리자 웹·시스템 웹의 표기이며, 직원 표면에 영문 상수를 그대로 노출하지 않는다 |
| 표면 명칭 | 직원 앱 · 관리자 웹 · 시스템 웹 · 공개 페이지로 고정한다 |

### 5-7. 정보 밀도 (웹)

**이 제품의 주 화면은 표다.** 밀도는 취향이 아니라 한 화면에 담기는 행과 열의 수이며, 그것이 곧 한 번에 판단할 수 있는 양이다. 값의 정본은 [../08_tech_stack/07_design_tokens.md](../08_tech_stack/07_design_tokens.md)이고 본 절은 그 값을 **언제 쓰는가**를 정한다.

| 항목 | 기준 |
|------|------|
| 본문 크기 | 본문 14 · 표 본문 13 · 라벨 12 · 배지와 캡션 11이다. 크기 7단 밖의 값을 만들지 않는다 |
| 가중치 | 400 · 500 · 600 세 단이다. 표에서 굵기로 위계를 세 단 나누지 않는다 — 500은 라벨과 표 헤더, 600은 제목과 합계다 |
| 표 높이 | 헤더 36 · 행 32 **단일값**이다. **밀도 선택을 두지 않는다**(D-24) — 3단 선택은 한 화면에 담기는 행 수를 사용자마다 갈라 열 걷기·카드 전환 경계와 스크린샷 기준을 흔들었다. 헤더는 정렬 표시 · 열 메뉴 · 선택 체크박스가 들어가는 최소 높이다 |
| 숫자 열 | 금액 · 시간 · 일수 · 건수는 **등폭 숫자**로 우측 정렬하고 단위를 값에 붙인다. 자릿수가 흔들리면 열이 정렬돼 보이지 않는다 |
| 표의 크기 | **표는 놓인 영역을 채운다**(D-24) — 가로는 자리 폭 전부, 세로는 남는 높이 전부다. **남는 가로 폭은 글자 열(grow)이 흡수**하고 숫자 · 상태 열은 내용 폭 그대로 선다. 글자 열 선언이 없으면 걷히지 않는 열 중 숫자가 아닌 첫 열이 흡수한다. **행이 적으면 표 안이 빈다** — 표 밖이 비어 화면의 세로선이 표마다 달라지는 것보다 읽기 흐름이 끊기지 않는다 |
| 구획 | **구획은 경계선이 내고 그림자는 띄우는 것에만 쓴다.** 카드 · 표 · 툴바에 그림자를 얹으면 고밀도 화면이 층층이 떠 보여 무엇이 실제로 위에 있는지 알 수 없게 된다. 그림자는 2단뿐이며 팝오버 계열과 모달 · 드로어다 |
| 여백 | 4px 격자 위에서만 값을 고른다. 표 셀 좌우 12 · 카드 안쪽 16 · 페이지 좌우 24가 기본이다 |
| 색의 양 | **강조색은 액션 하나를 가리킨다.** 한 화면에 기본 버튼은 하나이고 나머지는 중립 또는 조용한 버튼이다. 상태색은 상태에만 쓰고 장식에 쓰지 않는다 |
