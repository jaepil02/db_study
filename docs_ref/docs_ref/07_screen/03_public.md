# 03. 공개 페이지 (PUB)

> **대상**: PUB-LANDING · PUB-PRICING · PUB-LEGAL
> **작성일**: 2026-08-03
> **개정일**: 2026-09-07 — PUB-PRICING 데이터 소스의 GET /v1/plans 반환 열거에서 **활성 여부를 걷는다**. REQ-SUB-01이 미인증 응답을 코드 · 이름 · 한도 2축 · 가격 · 표시 순서로 **한정**하고, 이 표면은 애초에 활성분만 반환하므로 필드로 나갈 이유가 없다(계약 정본 [../06_api/13_subscription.md](../06_api/13_subscription.md) #1). **화면 수 · 요소 · 표면 귀속은 전건 불변**
> **개정일**: 2026-08-08 — 웹 전환 반영: 랜딩·요금제는 빌드 프리렌더 셸 + 클라이언트 조회, 법정 문서는 프리렌더 제외 클라이언트 조회로 정정(D-20). 라우트 표기를 산출물 축으로 치환
> **원천**: 확정 결정 D-20(웹 프론트엔드 전환 · ADR-24) · D-02(최소 공개 페이지 + SEO — 수단은 D-20으로 개정) · [../02_features/11_subscription.md](../02_features/11_subscription.md)(SUB-01 요금제) · [../02_features/12_system.md](../02_features/12_system.md)(SYS-11 문서 버전) · [01_standards.md](./01_standards.md)

공개 페이지 중 **순수 공개 콘텐츠 표면은 본 문서의 3본**이다 — 미인증 상태에서 시작하는 인증 흐름 4본(로그인·회원가입·가입 동의·비밀번호 재설정)은 [04_auth_onboarding.md](./04_auth_onboarding.md)가 담는다. 3본은 D-02가 정한 최소 집합 — 서비스 소개 랜딩 · 요금제 안내 · 약관·개인정보·위치정보 문서다. 본격 콘텐츠 마케팅은 v1에 두지 않는다.

**랜딩(/)과 요금제(/pricing) 2본만 빌드 시점 프리렌더로 정적 HTML을 굽고, 법정 문서(PUB-LEGAL)는 프리렌더하지 않는다**(D-20). 프리렌더 2본은 메타데이터·구조화 데이터·사이트맵을 갖추며 요금제 수치는 **프리렌더 셸 + 클라이언트 조회**로 최신을 보장한다. 법정 문서는 **클라이언트 조회로 활성 버전을 항상 최신 표시**한다 — 활성 버전 전환(SYS-11) 시 재빌드·재검증이 불필요해지고 게시 문안과 동의 이력 버전이 갈릴 위험이 원천 제거된다. 렌더링 모드의 정본은 [../04_architecture/05_rendering_seo.md](../04_architecture/05_rendering_seo.md)이며 본 문서는 화면 계약만 담는다. **업무 데이터를 부르지 않으므로 사업장 스코프도 인증 컨텍스트도 없다** — 세 화면의 데이터 원천은 요금제 정의와 약관 문서 두 가지뿐이다.

**약관·개인정보·위치정보 문서의 게시 자리가 이 세 화면에 있어야 한다는 것이 D-02의 핵심 근거**다. 문서 버전과 동의 이력이 제품 데이터베이스에 있는데 게시 표면이 밖에 있으면 활성 버전이 두 곳에서 갈리고, 문서 활성화(SYS-11)와 동의 연동(PRV-02)이 끊긴다.

## PUB-LANDING — 서비스 소개 랜딩

| 항목 | 내용 |
|------|------|
| 화면코드 | PUB-LANDING |
| 라우트 | web_front 정적 / (빌드 프리렌더) |
| 접근권한 | 비인증 허용. 인증 사용자도 그대로 열람하며 강제 이동을 두지 않는다 |
| 우선순위 | P0 |

**목적**: 소상공인이 근태부터 명세서 교부까지 무엇을 이 제품으로 끝낼 수 있는지 이해하고 가입 또는 로그인으로 진입한다.

**진입경로**: 검색 유입 · 직접 URL · 다른 공개 페이지의 브랜드 링크 · 로그아웃 후 이동.

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 가입 진입점 | 상단·본문·하단 세 자리에 가입 유도를 둔다. 클릭은 PUB-SIGNUP으로 보낸다 | AUT-01(진입점) |
| 로그인 진입점 | 헤더 우측에 로그인 링크를 둔다. 이미 인증된 사용자에게도 같은 링크를 노출하고 클릭 시 진입 분기(AUT-10)가 목적지를 정한다 | AUT-02(진입점) |
| 요금제 요약 | 등급별 한도(소유 가능 사업장 수 · 사업장당 최대 인원)를 요약해 보이고 상세는 PUB-PRICING으로 보낸다. 값은 하드코딩하지 않고 활성 요금제에서 읽는다 | SUB-01(진입점) |
| 기능 소개 | 근태 → 급여 자동계산 → 명세서 교부 → 법정 신고 자료의 마감 경로를 순서대로 보인다. **계산 결과가 참고자료임을 함께 고지**한다 | — |
| v1 범위 고지 | 제품이 대신 하지 않는 일을 부정형으로 밝힌다 — 신고 자동 제출을 하지 않고 자료 산출까지이며, 원천징수이행상황신고·지급명세서·연말정산은 v1이 만들지 않는다 | — |
| 법정 문서 링크 | 푸터에 약관·개인정보 처리방침·위치기반서비스 이용약관 링크를 상시 노출한다 | SYS-11(진입점) |
| 검색 노출 | 페이지 제목·설명·구조화 데이터·사이트맵 항목을 갖춘다. 정본은 [../04_architecture/05_rendering_seo.md](../04_architecture/05_rendering_seo.md) | — |

**주요 UI 요소**: 헤더(브랜드 · 요금제 링크 · 로그인 링크 · 가입 버튼), 히어로 영역(가치 제안 · 가입 버튼), 마감 경로 4단계 섹션, 기능 카드 격자, 요금제 요약 카드 3장, 범위 고지 블록, 푸터(법정 문서 링크 · 사업자 정보 · 문의 경로).

**주요 UI 요소 각각은 정적 콘텐츠이며 사용자 입력을 받지 않는다** — 폼은 두지 않고 전 상호작용이 다른 화면으로의 이동이다.

**레이아웃·스크롤·모바일**: 페이지 본문이 유일한 스크롤 소유자이며 헤더만 상단에 고정한다. 콘텐츠 폭은 읽기 편한 상한을 두고 가운데 정렬한다 — 인증 이후 화면의 폭 상한 금지 원칙(§5-2)이 공개 콘텐츠 3본에는 적용되지 않는 예외다. 1920·1440에서는 기능 카드를 3열, 768 경계에서 2열, 390에서 1열로 접고 요금제 요약 카드는 768 미만에서 세로 스택으로 흐른다. 헤더 내비게이션은 768 미만에서 브랜드와 가입 버튼만 남기고 나머지를 햄버거 메뉴로 접는다.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 프리렌더 페이지라 최초 페인트에 콘텐츠가 이미 들어 있다. 요금제 요약만 **프리렌더 셸 값으로 먼저 그리고 클라이언트 조회 결과로 교체**한다 — 셸이 이미 값을 갖고 있으므로 스켈레톤을 두지 않는다 |
| 빈 상태 | 해당 없음 — 정적 콘텐츠이며 0건이 될 수 있는 목록이 없다. 요금제 요약은 활성 요금제가 0개면 요약 블록 자체를 렌더하지 않고 상세 링크만 남긴다 |
| 에러 | 클라이언트 요금제 조회가 실패하면 **프리렌더 셸 값을 그대로 유지**하고 오류를 노출하지 않는다. 빌드 시 요금제 조회 실패는 배포 실패로 드러나고 직전 배포본이 계속 서빙된다 — 공개 페이지의 가용성이 최신성보다 우선한다 |
| 권한거부 | 해당 없음 — 비인증 공개 경로이며 어떤 역할도 차단되지 않는다 |

**데이터 연동**

- 빌드 시점 활성 요금제 조회 → GET /v1/plans → **plans**. 프리렌더 셸에 값을 굽고, 같은 표면을 **클라이언트가 한 번 더 조회해 최신 값으로 교체**한다(D-20). 상세 정본은 [../06_api/13_subscription.md](../06_api/13_subscription.md)다.

**담은 기능ID**: AUT-01(진입점) · AUT-02(진입점) · SUB-01(진입점) · SYS-11(진입점)

**비고**: 이 화면은 **자체 기능ID를 소유하지 않는다** — 네 기능 모두 다른 화면이 계약의 소유자이고 여기서는 진입점만 제공한다. 추적성 표에서 진입점 병기분을 화면 기준 집계에는 포함하되 기능 기준 유일 집계에서는 소유 화면 쪽을 정본으로 삼는다.

## PUB-PRICING — 요금제 안내

| 항목 | 내용 |
|------|------|
| 화면코드 | PUB-PRICING |
| 라우트 | web_front 정적 /pricing (빌드 프리렌더) |
| 접근권한 | 비인증 허용. 인증 사용자도 그대로 열람한다 |
| 우선순위 | P0 |

**목적**: 등급별 한도와 가격을 비교해 어떤 등급이 필요한지 판단하고 가입 또는 문의로 진입한다.

**진입경로**: PUB-LANDING 헤더·요금제 요약 카드 · 검색 유입 · ADM-SUBSCRIPTION의 등급 비교 링크.

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 등급별 한도 비교 | 활성 요금제를 표시 순서대로 나열하고 **소유 가능 사업장 수 · 사업장당 최대 인원 · 가격**을 비교 표로 보인다. 값은 활성 요금제에서 읽으며 문서에 박지 않는다 | SUB-01 |
| 한도의 뜻 설명 | 사업장당 인원 한도는 OWNER·MANAGER·STAFF **전원**을 세며, **어떤 등급도 30명을 넘지 못한다**(상품 전역 상한)는 사실을 표에 병기한다 | SUB-01 |
| 직원 소속은 무료임을 고지 | **직원으로 소속되는 경우는 본인 구독과 무관하게 무료·무제한**이며 한도는 사업장을 소유하는 쪽에만 적용됨을 명시한다 — 이 오해가 가입 전 가장 흔한 이탈 사유다 | SUB-01 |
| 복수 사업장 안내 | 동일 사업자등록번호라도 별도 사업장으로 등록하면 각각 한도 1개를 소진하며, 복수 사업장 등록 시 **사업 단위 판정이 필요**함을 안내하고 근거를 밝힌다 | SUB-01 · CMP-08(고지) |
| 유료 전환 경로 안내 | **v1의 유료 전환은 수동 처리**이므로 결제 버튼을 두지 않고 문의 경로만 노출한다. 자동 결제·업그레이드 요청 워크플로를 두지 않는다 | SUB-01 |
| 가입 진입점 | 등급마다 가입 버튼을 두고 PUB-SIGNUP으로 보낸다. 등급 선택은 가입 시점에 반영하지 않는다 — 미설정 계정은 FREE로 간주하며 등급 조정은 플랫폼 관리자가 수행한다 | AUT-01(진입점) |

**주요 UI 요소**: 페이지 헤더, 등급 비교 표(등급 3열 × 항목 행), 등급 카드 3장(모바일 전환용), 한도 해설 블록, 유료 전환 문의 블록, 자주 묻는 질문 목록, 푸터.

**레이아웃·스크롤·모바일**: 페이지 본문이 스크롤 소유자이며 비교 표 헤더 행만 스크롤 안에서 상단에 붙는다. 1920·1440에서는 등급 3열을 한 표에 담고, 768 경계에서 **표를 등급 카드 3장의 세로 스택으로 전환**한다 — 비교 표를 가로 스크롤로 밀면 등급 간 비교라는 화면 목적이 깨진다. 390에서도 카드 안 항목 라벨과 값이 한 줄에 들어오도록 라벨을 위, 값을 아래로 쌓는다.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | 프리렌더 페이지이며 최초 페인트에 요금제가 들어 있다. 클라이언트 조회가 끝나면 값을 교체하며 별도 스켈레톤을 두지 않는다 |
| 빈 상태 | 활성 요금제가 0개면 "요금제 준비 중입니다"와 문의 경로를 보인다. **가격을 임의 기본값으로 채우지 않는다** |
| 에러 | 클라이언트 조회 실패는 프리렌더 셸 값을 그대로 유지한다. 사용자에게 오류를 노출하지 않는다 |
| 권한거부 | 해당 없음 — 비인증 공개 경로다 |

**데이터 연동**

- 프리렌더 시점 활성 요금제 조회 → GET /v1/plans → **plans**(코드 · 이름 · 소유 가능 사업장 수 · 사업장당 최대 인원 · 가격 · 표시 순서). **활성분만 반환하므로 활성 여부를 필드로 내지 않는다** — 값이 언제나 참인 필드는 정보가 아니라 오해의 근거이고, 클라이언트가 그것으로 거를 수 있다고 읽는다. 같은 표면을 클라이언트가 다시 조회해 셸 값을 교체한다. 상세 정본은 [../06_api/13_subscription.md](../06_api/13_subscription.md)다.

**담은 기능ID**: SUB-01 · AUT-01(진입점) · CMP-08(고지)

**비고**: **요금제 값을 문서와 코드 어디에도 박지 않는다** — 요금제는 새 버전 + 유효 시작일로 관리되므로 화면이 활성 버전을 읽어야 과거 구독의 적용 한도와 현재 판매 한도가 갈리지 않는다. 시드 3등급은 FREE(사업장 1 · 인원 5) · PRO(3 · 15) · ULTRA(5 · 30)이며 이 값의 정본은 [../02_features/11_subscription.md](../02_features/11_subscription.md)다.

## PUB-LEGAL — 약관·개인정보·위치정보 문서

| 항목 | 내용 |
|------|------|
| 화면코드 | PUB-LEGAL |
| 라우트 | web_front SPA /legal/[type] — CSR · 프리렌더 제외. type은 문서 종류 3종에 대응한다 |
| 접근권한 | 비인증 허용. 인증 사용자도 그대로 열람한다 |
| 우선순위 | P0 |

**목적**: 이용약관·개인정보 처리방침·위치기반서비스 이용약관의 활성 버전을 상시 게시하고, 동의 화면과 같은 원문을 보여 준다.

**진입경로**: 전 화면 푸터의 법정 문서 링크 · 동의 화면(PUB-CONSENT)의 전문 보기 · APP-PRIVACY의 동의 이력 항목 · 검색 유입.

**화면 기능**

| 기능 | UI/처리 | 기능ID |
|------|---------|--------|
| 활성 버전 게시 | 문서 종류별 **활성 버전 정확히 1개**를 읽어 본문·버전·유효 시작일과 함께 게시한다. 활성 문서가 없으면 오류로 처리하고 임의 문안으로 대체하지 않는다 | SYS-11 |
| 문서 종류 분리 | **위치정보 문서를 약관·개인정보와 별도 종류로 게시**한다 — 위치정보법 §18이 별도 동의를 요구하므로 문서도 분리되어야 동의 이력이 버전 단위로 정합해진다 | SYS-11 · PRV-02 |
| 버전 표기 | 화면 상단에 버전과 유효 시작일을 표시한다. 사용자가 자기 동의 이력의 버전과 대조할 수 있어야 한다 | PRV-02(대조) |
| 종류 간 이동 | 세 문서를 오가는 탭을 두고 현재 문서를 표시한다 | SYS-11 |
| 목차 이동 | 긴 문서는 조항 목차를 두고 본문 위치로 이동한다. 조항마다 고유 위치를 부여해 링크로 특정 조항을 지목할 수 있게 한다 | — |
| 동의 화면 연계 | 동의 화면에서 전문 보기로 들어오면 되돌아갈 경로를 유지한다. 이 화면에서 동의를 받지 않는다 — **게시와 동의는 다른 사건**이다 | PRV-02(연계) |

**주요 UI 요소**: 페이지 헤더(문서 제목 · 버전 · 유효 시작일), 문서 종류 탭 3개, 조항 목차, 본문 영역, 이전 버전 안내 블록, 푸터.

**레이아웃·스크롤·모바일**: 페이지 본문이 스크롤 소유자이며 문서 종류 탭만 스크롤 안에서 상단에 붙는다. 1920·1440에서는 좌측 목차 + 우측 본문 2단으로 배치하고 목차가 현재 위치를 따라간다. 768 경계에서 목차를 본문 위 접이식 블록으로 접고 1열로 흐른다. 390에서 본문 글자 크기를 줄이지 않고 좌우 여백만 좁혀 읽기 밀도를 유지한다. 본문에 가로 스크롤을 만들지 않으며 표가 들어가면 그 표만 가로 스크롤 컨테이너를 갖는다.

**상태 처리**

| 상태 | 처리 |
|------|------|
| 로딩 | **프리렌더하지 않는 클라이언트 조회 화면**이므로 본문 스켈레톤을 두고 활성 버전 응답이 오면 교체한다. 개정본은 재빌드 없이 다음 진입에서 즉시 반영된다 |
| 빈 상태 | 해당 없음 — 활성 버전은 종류별로 정확히 1개이므로 0건 목록이 발생하지 않는다. 활성 문서 부재는 빈 상태가 아니라 에러로 다룬다 |
| 에러 | 활성 문서 부재는 system.terms_not_found/404로 "문서를 준비 중입니다"와 문의 경로를 보인다. 존재하지 않는 문서 종류로 접근하면 같은 응답으로 수렴시킨다. **임의 문안이나 직전 버전으로 대체하지 않는다** — 게시된 문안과 동의 이력이 어긋나면 동의 자체의 입증이 깨진다 |
| 권한거부 | 해당 없음 — 비인증 공개 경로다 |

**데이터 연동**

- 진입 시 클라이언트가 문서 종류별 활성 버전 조회 → GET /v1/terms/{kind}/active(현재 탭의 종류를 호출) → **terms_documents**(종류 · 버전 · 제목 · 본문 · 유효 시작일 · 활성 여부). **빌드 산출물에 문안을 굽지 않으므로** 활성 버전 전환 즉시 반영되며 재빌드·재검증 트리거가 없다(D-20). 상세 정본은 [../06_api/14_system.md](../06_api/14_system.md)다.

**담은 기능ID**: SYS-11(공개 게시) · PRV-02(대조)

**비고**: **이 화면을 프리렌더하지 않는 이유는 게시 문안과 동의 이력 버전이 갈리지 않게 하기 위해서다** — 빌드 산출물에 문안을 구우면 활성 버전 전환과 재배포 사이에 구 문안이 게시되는 창이 생기고, 그 창에서 받은 동의는 이력 버전과 원문이 어긋난다. 검색 노출 대상이 아니므로 프리렌더를 뺀 대가도 없다(SEO 계약은 랜딩·요금제 2본 한정). **이전 버전 원문의 공개 게시는 v1에 두지 않는다.** 동의 이력은 버전을 참조하므로 자기 동의 버전을 확인하는 경로는 APP-PRIVACY에 있고, 과거 버전 원문이 필요하면 플랫폼 지원 경로로 처리한다. 다만 개정 사실과 유효 시작일은 이 화면에 남겨 사용자가 자기 동의 시점과 대조할 수 있게 한다.
