SLP는 **마감 경로의 종점**이다. 급여 확정(PAY-08)이 명세서 생성을 트리거하고, 교부가 완료되어야 근기법 §48② 의무가 이행된다. **미교부는 최대 500만원 과태료**이며 규모 무관 적용이라 7기능 중 6개가 법정의무 태그를 받았다.

**전자교부는 적법하다.** 교부 시점은 채널에 따라 갈린다 — 사내 전산망·앱 게시는 **근로자가 열람할 수 있는 상태로 입력된 때**, 이메일·메신저는 **발송된 때**를 교부로 본다. 따라서 **교부와 열람은 다른 사건**이며 각각 별도 이벤트로 기록한다. 교부만 하고 직원이 열지 않아도 의무는 이행된 상태다. **성립 시점이 채널마다 다르므로 교부 이력도 채널마다 한 건씩 남는다** — 명세서당 한 건으로 묶으면 앱 게시가 그 자리를 차지해 이메일 교부 사실을 기록할 수 없다.

**자동 파이프라인의 종점은 GENERATED이고 교부는 관리자의 게시 행위다.** 급여 확정(PAY-08)이 트리거하는 자동 경로는 PDF 렌더링과 문서 등록까지 수행하며 **DELIVERED로 전이시키지 않는다**. 게시(단건 또는 일괄)를 관리자가 실행한 시점에 ISSUED 교부 이벤트를 기록하고 상태를 DELIVERED로 전이한다 — 필수항목 누락·오산 발견 시 게시 전에 멈출 수 있어야 하고(SLP-02), 게시하지 않은 파일이 교부된 것으로 기록되면 §48② 이행 시점이 사실과 달라지기 때문이다.

**인가는 사업장 멤버십이 아니라 본인 소유권으로 판정한다.** 명세서는 지급일 + 3년 보존·교부 대상인데 사업장 RBAC로만 막으면 퇴사하는 순간 본인 명세서에 접근할 수 없게 되고 그 자체가 위반 소지다. 그래서 퇴사·사업장 폐쇄·계정 탈퇴 전 보존기간 내 모두 본인 열람이 열린다(CMP-07).

**정정은 재발급이 아니다.** 재발급은 같은 원본을 다시 내려받는 행위라 새 행을 만들지 않고, 정정은 원본을 보존한 채 supersedes로 연결된 정정본을 새로 발행한다. **정정본 발행은 OWNER 전용**이며 MANAGER는 조회만 한다.

## 기능 목록

| 기능ID | 기능명 | 설명 | 우선순위 |
|--------|--------|------|:--------:|
| **SLP-01** | 명세서 자동 생성 | 급여 확정(PAY-08) 직후 직원별 생성 작업을 큐에 등록하고 서버가 확정 결과·근로시간·수당 계산방법·공제 내역을 PDF로 렌더링한다. **자동 트리거는 원본 최초 생성만 담당**하고 정정본은 SLP-07 단일 경로로만 발행한다. 대상 급여 실행이 확정 상태가 아니면 거부하고, 사업장이 검증 대기 상태면 발행을 차단한다. 중복 생성은 (급여실행, 직원) 부분 유니크와 멱등키로 막는다. **PDF 생성 실패는 급여 확정을 롤백하지 않고** 명세서를 실패 상태로 두고 사유를 기록한다 — 명세서 렌더링 오류로 확정된 급여가 되돌아가면 훨씬 큰 혼란이 생긴다. **PDF 렌더는 확정 트랜잭션이 아니라 정기작업 retryPayslipAndPush(15분 주기)가 수행한다** — 확정은 행을 PENDING으로 만들어 큐에 올리고 그 작업이 렌더해 GENERATED로 올린다(브라우저 풀 대기 중에 급여월 잠금을 쥐거나 렌더 실패가 확정을 되돌리는 것을 막는 분리다). 같은 작업이 실패분도 재큐잉한다. **확정 시점 데이터와 적용 기준값 버전을 스냅샷으로 보관**해 이후 기준값이 바뀌어도 명세서는 불변이다 | P1 |
| **SLP-02** | 법정 필수항목 | 근기법 시행령 §27의2 **6개 호**를 포함한다 — ①근로자 특정정보(성명, 생년월일 또는 사번) ②임금 지급일 ③임금 총액 ④기본급·수당 등 임금 구성항목별 금액 ⑤출근일수·총 근로시간·연장/야간/휴일 근로시간 등 계산에 필요한 사항 ⑥공제 항목별 금액과 공제 총액이다. **사업자등록번호·상호는 법정 기재사항이 아니다** — 포함해도 무방하나 필수 검증 대상으로 두지 않는다. 연장·야간·휴일수당과 주휴수당은 **시간 · 단가 · 가산율을 포함한 계산식**을 표기한다. **5인 미만 사업장은 가산 미적용 사실과 근거를 계산방법에 정확히 반영**하되 실제 근로시간 기록은 내부 급여 결과에 그대로 보존한다 — 가산 미적용이지 근로시간 미기록이 아니다. 필수항목 데이터가 누락되면 명세서를 실패 상태로 두고 **보완해야 할 항목 목록**을 급여 담당자에게 안내하며 **누락 상태로는 교부하지 않는다**. 목록은 오류 응답으로만 지나가지 않고 **명세서 행에 보존**해 나중의 보완 화면이 다시 안내하며, 이 실패는 재시도로 해소되지 않으므로 **정기작업 재큐잉 대상에서 제외**하고 보완 후 재생성으로만 푼다. 법정 기재사항 6개 호 중 **근로자 특정정보만 확정 급여 결과의 동결 축을 따로 요구한다** — 나머지는 확정 결과와 항목 라인에 이미 값으로 얼어 있으나 성명·생년월일·사번은 인사 레코드의 현재값이라 사후 정정이 과거 표기를 바꾼다 | P1 |
| **SLP-03** | 명세서 교부/열람 | 임금명세서 교부 의무의 실행 지점이다. **교부는 관리자가 실행하는 게시 행위**이며 그 시점에 명세서가 GENERATED → DELIVERED로 전이하고 ISSUED 이벤트가 남는다 — 단건 게시와 일괄 게시(SLP-05) 둘 다 같은 전이·기록 계약을 쓴다. 교부 사실을 **채널별로** 이벤트에 기록하고 **교부(게시 완료)와 열람(직원이 실제로 연 시각)을 구분**해 남긴다. 같은 채널의 재발송은 교부 이력을 중복 생성하지 않고, 다른 채널의 교부는 별개 사건으로 각각 남는다. **열람·다운로드 기록도 대상 명세서의 소유자·사업장을 다시 대조한 뒤에만 남긴다** — 기록하는 사람이 본인인지만 보면 남의 명세서를 가리키는 기록이 통과해 법정 증거 원장이 오염되고 행 존재 은닉도 뚫린다. 열람·다운로드는 **1회용 다운로드 토큰 + 서버 스트리밍**으로 처리하며 토큰은 단기 만료·1회 사용이고 세션·IP·기기 정보를 보조 바인딩해 복사 재사용을 차단한다. 열람·다운로드 시각·IP·기기를 기록한다. **미존재 명세서와 타인 명세서는 동일하게 404로 응답해 행 존재 자체를 숨긴다** — 403으로 답하면 "그 명세서가 있다"는 사실이 노출된다. 인가는 멤버십이 아니라 **본인 소유권**으로 판정하므로 퇴사·폐쇄 후에도 보존기간 내 열람이 유지되며 쓰기·재발행은 불가하다 | P1 |
| **SLP-04** | 명세서 보관 | **지급일 + 3년** 보존한다. PDF는 사업장·급여실행·직원 단위 경로에 저장하고 **파일 실체와 해시 메타는 문서 테이블이 일원 보유**하며 명세서 행은 문서 식별자로 참조한다 — 실체 소유를 한 곳에 모아야 보존·감사·파기 경로가 갈라지지 않는다. **보존기한만은 두 곳이 함께 갖되 사본 관계가 아니다** — 명세서 행이 PDF보다 먼저 생기므로 문서에서 값을 가져올 수 없고, 양쪽이 지급일 + 3년이라는 같은 산식에서 각각 파생해 **발행 시점에 일치를 검증**하며 불일치는 발행을 중단시킨다. **퇴사·탈퇴·사업장 폐쇄 후에도 보존기간 내 열람 권한 정책을 유지**한다. 플랫폼 관리자는 고객지원 목적의 **메타 조회만** 기본 허용하고 PDF 원문 접근은 별도 권한·사유·감사를 요구한다 | P1 |
| **SLP-05** | 일괄 발행 | 확정된 급여월의 전 직원 명세서를 한 번에 생성·교부한다. 1명씩 발행하면 실사용이 불가능하므로 제품성립 축이다. 동일 급여 실행의 일괄 작업이 진행 중이면 거부하고 멱등키 충돌도 별도 코드로 구분한다 — **진행 중 판정의 축이 대상 급여 실행이므로 명세서 일괄 작업은 그 값을 반드시 갖는다**. 작업 원장에 전체·성공·실패 건수와 실패 사유를 저장하고 화면에 진행률과 재시도를 노출한다. 재발행 정책은 **이미 발행된 직원 건너뛰기(SKIP_ISSUED)** 와 **원본 누락분만 생성(GENERATE_MISSING)** 두 가지이며 이미 원본이 발행된 직원은 건너뛴다. **기존 발행분의 재발행은 정정본 경로(SLP-07)로만 가능**하다. 재시도는 실패 건만 대상으로 하며 이미 교부된 명세서의 교부 이력을 중복 생성하지 않는다 | P1 |
| **SLP-06** | 발행 알림 | 교부 사실을 직원에게 통지한다. **발화 시점은 관리자 게시(GENERATED → DELIVERED 전이) 트랜잭션의 부수효과**이며 **생성 완료(GENERATED) 시점이 아니다** — 게시되지 않은 명세서의 도착 알림이 나가면 직원이 열 수 없는 문서를 통지받는다. 인앱 알림을 생성하되 **본문에 금액 상세를 포함하지 않고 명세서 화면 링크만** 담는다 — 알림 본문은 잠금화면에도 뜨므로 급여액이 그대로 노출된다. **앱 미설치·미로그인 직원에게는 이메일 등 대체 교부 경로를 제공**하고 그 발송 사실도 **채널을 달리하는 교부 이력**으로 기록한다 — 이메일은 발송된 때가 교부이므로 앱 게시와 별개의 교부 사건이다. **직원이 알림 수신을 거부해도 법정 교부 알림과 명세서 목록 생성은 생략하지 않는다** — 필수 알림은 어떤 설정으로도 끌 수 없다 | P1 |
| **SLP-07** | 명세서 재발급/정정 | 잘못 발행한 명세서를 고칠 유일한 경로다. **재발급과 정정은 다른 조작**이다. 재발급은 동일 원본의 재교부이며 **명세서 행을 새로 만들지 않고** 다운로드 이력만 남긴다 — 부분 유니크가 원본 1건을 보장한다. 정정은 급여 정정과 한 쌍으로, 원본 급여 실행을 무효화해 **보존**한 뒤 supersedes로 연결된 새 실행과 정정본(버전·정정사유)을 발행한다. **원본 무효화 시점에 대기·실패 상태인 명세서는 생성을 중단하고 실패로 고정**하며 정정본은 새 실행 확정 후 이 경로로만 발행한다. 직원 화면에 **최신본과 원본 이력을 함께** 표시하고 정정 사유와 새 명세서 링크를 알리며 교부 이력을 별도 기록한다. **원본은 폐기하지 않는다.** **정정본 발행은 OWNER 전용**이고 재발급은 STAFF 본인분을 포함한다. OWNER 전용과 정정 사유 필수는 서비스 검증에만 두지 않는다 — 정정본은 상태 전이가 아니라 새 행 생성이라 전이 가드가 닿지 않으므로 **생성 시점에 역할·사유·원본 상태를 다시 확인하는 가드**를 둔다. **원본 무효화의 연쇄도 트리거가 수행한다** — 서비스 순서에 맡기면 누락 시 무효 급여의 명세서가 정기작업으로 되살아난다 | P2 |

**7기능이다** — SLP-01 · 02 · 03 · 04 · 05 · 06 · 07. 우선순위 분포는 P1 6(SLP-01 · 02 · 03 · 04 · 05 · 06) · P2 1(SLP-07)이며 6 + 1 = 7이다. 결번은 없다.

## 명세서 상태와 교부 이벤트 개요

상태 머신의 정본은 [../09_glossary/03_enums_state_machines.md](../09_glossary/03_enums_state_machines.md)이고 계약의 정본은 [../03_requirements/08_payslip.md](../03_requirements/08_payslip.md)다.

| 상태 | 의미 | 다음 |
|------|------|------|
| PENDING | 생성 작업 큐 등재 완료, PDF 미생성. **큐의 소비자는 정기작업 retryPayslipAndPush다** | → GENERATED · → FAILED |
| GENERATED | PDF 생성 완료, 아직 게시 전. **자동 파이프라인은 여기까지** | → DELIVERED(관리자 게시) · → CORRECTED |
| DELIVERED | 교부 완료(열람 가능 상태로 입력됨) | → CORRECTED |
| FAILED | PDF 생성 실패 또는 필수항목 누락. 사유를 보존한다 | → PENDING(재큐잉) |
| CORRECTED | 정정본으로 대체됨. **원본은 삭제하지 않는다** | 없음(종단) |

교부 이벤트는 세 종류를 구분해 기록한다.

| 이벤트 | 의미 | 법적 효과 |
|--------|------|----------|
| ISSUED | 게시·발송 완료 | **교부 성립 시점**. 사내 전산망·앱은 입력된 때, 이메일은 발송된 때 |
| VIEWED | 직원이 열람 | 교부 성립과 **무관**. 통지 도달 확인용 |
| DOWNLOADED | **명세서 소유자 본인이 내려받음** | 본인 재발급 이력의 등재처. **관리자 다운로드는 이 원장이 아니라 audit_logs**(document.download_sensitive)가 담는다 — 이 원장은 §48② 교부 증적이다 |

- **정정본 체인은 GENERATED·DELIVERED 명세서에만** 성립한다. 아직 생성되지 않았거나 실패한 명세서는 정정 대상이 아니라 재생성 대상이다.
- **버전 개념은 재발급이 아니라 정정본 체인이 담당한다.** 재발급을 버전으로 취급하면 같은 내용의 행이 무한히 늘어난다.

## 관련 테이블

**payslips**(명세서 본체 — 급여실행·직원·문서 식별자·상태·발행 시각·정정 체인·정정 사유) · **payslip_deliveries**(교부·열람·다운로드 이벤트 — 시각·채널·IP·기기) · **batch_jobs**(일괄 발행 작업 — 전체·성공·실패 건수·실패 사유) · **documents**(PDF 실체·저장 경로·해시·보존기한 — HRM 도메인 테이블) · **payroll_runs** · **payroll_employee_results**(확정 급여 스냅샷 입력) · **notifications**(발행 알림). 명세 정본은 [../05_database/11_payslip.md](../05_database/11_payslip.md)이며 문서 테이블은 [../05_database/03_hr.md](../05_database/03_hr.md), RLS 정책은 [../05_database/08_rls_policies.md](../05_database/08_rls_policies.md)가 정본이다.

**명세서 행은 별도의 저장 경로 컬럼을 갖지 않는다** — 파일 실체와 해시는 문서 테이블이 일원 보유하고 명세서는 문서 식별자로 참조한다. 두 곳이 경로를 각각 들면 파기·이관 시 한쪽만 갱신되어 유령 참조가 남는다.

**보존기한은 예외이며 두 곳이 같은 산식으로 각각 파생해 대조한다.** 명세서 행이 PDF보다 먼저 생기는 순서 때문이며, 대조 실패가 곧 발행 중단이라 괴리가 남지 않는다. 보존 목록 조회(CMP-04)에서 명세서 축의 대상은 명세서 행이다.

## 에러 코드

| 코드 | HTTP | 발생 조건 |
|------|:----:|----------|
| payslip.not_found | 404 | 명세서 부재 또는 접근 불가. **타인 명세서도 같은 코드로 응답해 행 존재를 숨긴다**(SLP-03) |
| payslip.run_not_confirmed | 409 | 대상 급여 실행이 확정 상태가 아님(SLP-01) |
| payslip.missing_required_field | 422 | 법정 필수 기재사항 데이터 누락. 보완 항목 목록을 함께 반환한다(SLP-02) |
| payslip.generation_failed | 422 | PDF 생성 실패. 명세서는 실패 상태로 남고 급여 확정은 롤백하지 않는다(SLP-01) |
| payslip.already_issued | 409 | 누락분 생성 대상이 이미 발행됨. 재발행은 정정본 경로로만 가능하다(SLP-05) |
| payslip.bulk_in_progress | 409 | 동일 급여 실행의 일괄 작업이 진행 중(SLP-05) |
| payslip.bulk_conflict | 409 | 일괄 발행·정정본 발행의 멱등키 충돌(SLP-05 · SLP-07) |
| payslip.download_token_expired | 410 | 1회용 다운로드 토큰 만료 또는 사용 후 재사용(SLP-03 · SLP-07) |
| payslip.forbidden | 403 | 명세서 관리 액션(발행·재발급·정정) 권한 부족 — 열람 대상의 비소유 접근은 payslip.not_found/404로 존재를 은닉한다(SLP-03) |
| payslip.correct_forbidden | 403 | 정정본 발행 권한 없음 — OWNER 전용이며 MANAGER 시도가 여기 걸린다(SLP-07) |
| workplace.verification_pending | 409 | 검증 대기 사업장에서 명세서 발행 시도(SLP-01) — 정본 네임스페이스는 workplace이며 등재는 [02_workplace.md](./02_workplace.md)다 |
| notification.mandatory_pref | 409 | 법정 교부 알림의 수신 거부 시도(SLP-06) — 정본 네임스페이스는 notification이며 등재는 [10_notification.md](./10_notification.md)다 |

- **payslip.not_found(404)와 payslip.forbidden(403)의 사용 지점이 다르다** — 존재를 숨겨야 하는 조회 경로는 404로 수렴시키고, 권한 판정 결과를 알려도 되는 관리 경로에서만 403을 쓴다.
- payslip.download_token_expired는 **민감 문서 다운로드(HRM-09)와 규약을 공유**한다.
- 전수 정본은 [../09_glossary/02_error_codes.md](../09_glossary/02_error_codes.md)다.
