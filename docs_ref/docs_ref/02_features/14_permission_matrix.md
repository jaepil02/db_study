> **이 문서의 지위**: 본 매트릭스는 RLS 정책 정본([../05_database/08_rls_policies.md](../05_database/08_rls_policies.md))에서 파생한 **요약 뷰**다. 두 문서가 어긋나면 05_database가 우선하며 **본 문서를 근거로 정책을 구현하지 않는다**. 기능ID와 기능명의 정본은 같은 폴더의 도메인 파일 13본이다.

권한은 **세 층위**로 분리된다 — 인증 경계(미인증은 공개 경로만) · **사업장 RBAC**(사업장 내 업무 전반) · **플랫폼 RBAC**(플랫폼 운영)다. 사업장 RBAC와 플랫폼 RBAC는 **완전히 별개**여서 사업장 OWNER라도 플랫폼 권한을 자동으로 얻지 않고, 플랫폼 관리자라도 사업장 업무 권한을 자동으로 얻지 않는다.

사업장 역할은 **OWNER ⊃ MANAGER ⊃ STAFF 누적 3종**이다. 아래 섹션 제목은 그 기능을 수행할 수 있는 **최소 역할**을 뜻하므로, MANAGER 섹션의 기능은 OWNER도 전부 수행한다. **ADVISOR(외부 세무사·노무사 읽기 전용 역할)는 v1에 두지 않는다**(WRK-13 이월) — 따라서 v1에는 사업장 데이터를 읽기 전용으로 보는 외부 역할이 존재하지 않으며, 원천 문서의 ADVISOR 조회 서술은 v1 범위에서 제외된다.

**동일 사용자가 사업장별로 다른 역할을 가질 수 있다.** 역할 판정은 계정 단위가 아니라 (사용자, 사업장) 쌍 단위이며 사업장 전환(WRK-06) 때마다 서버가 다시 검증한다.

## 역할 정의

역할은 사업장 RBAC와 플랫폼 RBAC 두 축으로 나뉘며 서로를 포함하지 않는다. 아래 두 절이 각 축의 값과 부여 경로, 그리고 그 역할이 할 수 없는 것을 함께 고정한다.

### 사업장 RBAC

| 역할 | 부여 | 권한 요약 |
|------|------|-----------|
| **STAFF** | 초대 수락(WRK-05) 또는 임포트 등록(WRK-16) | 본인 데이터만 읽고 쓴다 — 본인 체크인·휴게·근태 수정 요청·휴가 신청·잔여 연차·급여 이력·명세서 열람·근로계약 전자서명이다. 승인·확정·인사 수정은 하지 않는다 |
| **MANAGER** | OWNER의 역할 부여(WRK-07) 또는 MANAGER 역할 초대 | STAFF 권한 + 사업장 운영 전반 — 인사·근태·휴가·급여·명세서·신고자료·법정 준수 운영이다. **다른 OWNER·MANAGER를 제외하거나 역할을 바꿀 수 없고** MANAGER를 초대할 수도 없다 |
| **OWNER** | 사업장 등록자(WRK-01). **사업장당 항상 정확히 1명** | MANAGER 권한 + 소유자 전용 액션(아래 표). 역할 변경 · 폐쇄 · 임포트 확정 · 근태 마감 취소 · 급여 무효화·정정 · 명세서 정정본 · 구독과 한도 관리가 여기 속한다 |

- **OWNER 단일성은 불변식**이다. 마지막 OWNER 강등 · 본인 권한 자가 제거로 0명이 되는 조작 · MANAGER의 OWNER 역할 변경을 서비스 레이어와 DB 제약 양쪽에서 차단한다.
- **v1에서 OWNER는 고정**이다 — OWNER 이전은 양도 경로로만 가능한데 양도가 v1.1 이월이라 역할 직접 변경으로 OWNER를 만들 수 없다.
- **ADVISOR는 v1에 없다.** 세무사에게 자료를 넘기는 실무는 v1에서 내보내기 결과물 전달로 대체하며, 계정 공유를 방지하는 읽기 전용 역할은 v1.1에 도입한다.

### 플랫폼 RBAC

권한 키는 **자원과 액션을 결합한 명시적 화이트리스트**로 부여하고 **미정의 키는 기본 거부**한다. 와일드카드형 부여를 두지 않는 이유는 새 자원이 추가될 때 의도치 않게 권한이 열리기 때문이다.

| 역할 | 레벨 | 권한 요약 |
|------|:----:|-----------|
| VIEWER | 1 | 사업장·사용자·구독·요금제·기준값 조회와 검색만. **감사 조회·내보내기는 포함하지 않는다** |
| SUPPORT | 2 | VIEWER + 지원 액션 · **보조 비밀번호 재설정** |
| ADMIN | 3 | SUPPORT + 계정·사업장 정지/해제·강제 폐쇄 · 구독 등급 조정 · 기준값 갱신 · 약관 관리 · 감사 조회·내보내기 |
| SUPER_ADMIN | 4 | ADMIN + 관리자 역할 임명·회수 · **계정 강제 삭제** |

- **만료일이 지난 역할은 무효**로 처리한다.
- **권한 키는 정책 표면에서 실제로 소비되어야 한다** — 사용자 조회(user:view/search)는 계정·프로필 SELECT 정책이, 제재 3종(workplace:suspend/unsuspend/close)은 사업장 UPDATE 정책이 인용한다. **analytics:view/export 2키는 v1에 소비처가 없다**(DSH 대시보드 4종이 v1 제외라 통계 표면 자체가 없다) — 화이트리스트에는 남기되 **예약 키**로 표기하고, 소비 정책이 생기기 전까지 어떤 표면도 이 키로 열리지 않는다.
- **플랫폼 권한 자체가 없는 상태와 역할 레벨이 부족한 상태를 다른 코드로 구분**한다 — 전자는 시스템 웹 진입 자체가 막히고 후자는 진입 후 특정 액션만 막힌다.
- **v1은 역할 임명 화면을 두지 않는다**(SYS-02 이월). 초기 SUPER_ADMIN은 시드가 아니라 서버 기동 시 환경변수 1회성 부트스트랩으로 만들고(정본: 05_database/10_migrations_seed.md) 이후 부여·회수는 운영 절차로 처리한다.
- PII·급여 원문 접근은 어느 레벨에서도 자동으로 열리지 않는다 — 별도 권한 + 사유 + 감사를 함께 요구한다.

## 최소 역할 × 기능 매트릭스

98기능을 최소 역할 축으로 재배열한 뷰다. 섹션 제목이 곧 그 기능을 수행할 수 있는 최소 역할이며, 누적 체계상 상위 역할은 하위 섹션을 전부 수행한다.

### §1 공개 (미인증)

| 기능ID | 기능명 | 접근 범위·비고 |
|--------|--------|---------------|
| **AUT-01** | 회원가입 | 미인증 공개. **약관·개인정보 2종 동의**가 성립 조건이다 — 위치정보는 별도 선택 동의(D-19) |
| **AUT-02** | 로그인 | 미인증 공개. 정지·삭제 계정은 인증 성공 직후 차단된다 |
| **AUT-04** | 아이디 중복 확인 | 미인증 공개. 가용 여부 boolean만 반환한다 |
| **AUT-07** | 비밀번호 재설정 | 미인증 공개. 응답이 계정 존재 여부와 무관하게 동일하다 |

**4기능이다.** 공개 경로는 이 넷과 약관·개인정보·위치정보 문서 조회 · **활성 요금제 조회**(SUB-01의 파생 읽기 — 공개 요금제 페이지와 가입 전 안내가 소비한다) · **CSRF 토큰 발급**(AUT-03의 파생 공개 — 로그인이 상태 변경이라 토큰이 선행해야 하는 순환 방지다, §2 · REQ-AUT-08)로 한정하며 그 밖의 경로는 인증을 요구한다.

- **행 가시성이 공개인 것과 응답 표면이 공개인 것은 다르다.** DB에서 SELECT 술어가 true인 전역 마스터는 **5종**(약관 문서 · 알림 타입 카탈로그 · 요금제 · 법정 기준값 · 간이세액표)이지만, 그중 **미인증 응답 표면을 갖는 것은 약관 문서와 활성 요금제 둘뿐**이다. 나머지 셋은 계산 엔진이 서버 API 경유로 읽는 값이며 공개 경로가 아니다 — 정책이 열려 있다는 사실이 경로를 만들지 않는다.
- 아이디 중복 확인과 비밀번호 재설정은 계정 원장에 직접 닿지 않는다 — 반환 타입이 boolean·void인 서버 전용 함수가 그 경로이며, 응답이 계정 존재 여부와 무관하게 동일하다는 계약을 DB 층에서 보장한다.

## OWNER 전용 액션

기능ID 단위로는 MANAGER 이상이 수행하지만 **그 안의 특정 액션만 OWNER로 제한**되는 경우다. 서비스 레이어와 RLS 양쪽에서 OWNER를 강제한다.

| 액션 | 소속 기능 | 추가 요건 |
|------|----------|----------|
| 사업장 폐쇄 | WRK-10 | 선행조건 5종(미완 급여·미발행 명세서·미처리 승인 없음 · 보존 안내 확인 · 재인증) |
| 멤버 역할 변경 | WRK-07 | OWNER 단일성 불변식. MANAGER는 수행 불가 |
| 데이터 온보딩 확정(임포트 커밋) | WRK-16 | 미리보기 검토 후 확정 · 부분 실패 리포트 · 감사 |
| 근태 마감 취소 | ATT-08 | **급여 미확정 기간 한정** · 사유 · 감사 |
| 급여 무효화·정정 | PAY-08 | 확정 원본을 삭제하지 않고 무효화 · 사유 · 감사 · supersedes 연결 |
| 자기포함 급여 확정 | PAY-08 | 본인이 대상자로 포함된 런의 확정 — MANAGER 시도는 auth.workplace_forbidden/403 |
| 명세서 정정본 발행 | SLP-07 | 원본 보존 + supersedes 연결. 재발급은 STAFF 본인분 포함 |
| 구독·등록 한도 관리 | SUB-02 · SUB-03 · SUB-04 | v1의 등급 변경 자체는 플랫폼 관리자 수동 처리(SYS-05) |
| 사업 단위 독립성 선언 | CMP-08 | 법적 판단이므로 자동 합산 불가 · 근거 감사 보존 |

- **사업장 양도(OWNER 이전)와 ADVISOR 초대·범위 지정·회수는 v1에 없다** — 각각 WRK-10 양도분과 WRK-13이 v1.1 이월이기 때문이다. **업종 프리셋 온보딩·재적용(WRK-12)도 마찬가지**다.
- 위 액션은 모두 **감사 로그 사유 필수 대상**과 겹친다. 되돌리기 어렵거나 법정 기록을 바꾸는 조작이라는 공통점이 있다.

## 2단 방어 원칙

권한은 한 곳에서만 판정하지 않는다. **애플리케이션 서비스 레이어가 1차로 멤버십·역할·사업장 스코프를 검증하고, PostgreSQL RLS가 2차 심층방어로 행 단위 격리를 보장**한다. 클라이언트 가드는 보조 장치이며 최종 판단은 항상 서버다.

| 계층 | 역할 | 실패 시 |
|------|------|--------|
| 클라이언트 | 화면 노출 제어·입력 사전 검증 | 사용성 저하에 그친다. 우회해도 서버가 다시 막는다 |
| 서비스 레이어(1차) | 멤버십·역할·사업장 스코프·상태 전이·선행조건 판정 | 도메인 에러 코드로 거부한다 |
| **RLS(2차)** | 행 단위 격리. 모든 업무 테이블이 사업장 스코프 술어를 강제한다 | 조회는 0행, 변이는 거부. **1차가 뚫려도 남의 사업장 행에 닿지 않는다** |
| 정책 판정 헬퍼 | 멤버십·역할·소유권 판정을 함수로 분리한다. **정의자 롤이 BYPASSRLS를 갖되 접속 경로가 없어**(NOLOGIN) 그 권한이 함수 본문 밖으로 나가지 않는다 | 강제 옵션 아래에서 정책 ↔ 헬퍼 재귀가 끊기지 않으면 판정 자체가 성립하지 않는다 |
| DB 제약·트리거 | 불변식(OWNER 단일성 · 유효기간 겹침 · 확정 중복) | 제약 위반으로 트랜잭션을 되돌린다 |

- **2차 방어를 "혹시 모를 보험"으로 두지 않는다.** 서비스 레이어의 스코프 누락은 코드 리뷰로 100% 잡히지 않으므로 RLS가 실제 방어선이며, 이 전제 위에서 새 테이블은 정책 없이 배포하지 않는다.
- 권한 판정 함수는 정책이 대상 테이블을 직접 서브쿼리하지 않도록 헬퍼로 분리한다 — 자기 정책과의 재귀를 피하기 위해서다. 구조의 정본은 [../04_architecture/03_multitenancy_rls.md](../04_architecture/03_multitenancy_rls.md)다.
- **본인 소유권 인가는 멤버십 술어와 별개 축**이다(CMP-07). 멤버십으로만 정책을 쓰면 퇴사·폐쇄 순간 본인 법정문서가 잠기므로, 명세서·급여이력·근로계약에는 소유권 술어를 함께 둔다.
- **화면 노출 제어는 판정이 아니다.** 네비게이션에서 감춘 화면도 직접 진입하면 서버와 정책이 다시 거부한다.
