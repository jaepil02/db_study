AUT는 제품의 **유일한 진입 경계**다. 사업장·근태·급여의 어떤 기능도 인증 컨텍스트 없이는 시작하지 않으므로, 이 도메인이 없으면 나머지 12도메인이 통째로 도달 불가능해진다. 원천이 AUT-01·02·04를 제품성립 태그로 분류한 근거가 그것이다.

인증 채널은 표면에 따라 둘로 갈린다. **관리자 웹·시스템 웹은 서버 세션**(HttpOnly·Secure 쿠키 + CSRF 토큰)이고 **직원 앱은 JWT**(access + refresh)다. 채널을 하나로 통일하지 않은 이유는 위협 모델이 다르기 때문이다 — 브라우저는 XSS로 토큰이 탈취되므로 access token을 JS에 노출하지 않아야 하고, 앱은 쿠키 자동 전송이 없어 Bearer 전송이 자연스럽다. 이 분기의 정본은 [../04_architecture/02_authn_session.md](../04_architecture/02_authn_session.md)다.

계정은 사업장과 **분리된 상위 개념**이다. 한 계정이 여러 사업장에 서로 다른 역할로 소속될 수 있고(AUT-10), 계정 상태(AUT-08)와 사업장 상태는 별개 축으로 전이한다. 따라서 인증 성공은 접근 허용을 뜻하지 않으며, 사업장 컨텍스트 판정은 항상 WRK 도메인이 다시 수행한다.

**AUT-05(프로필 관리)는 2026-09-16 v1로 채택했다**(D-23). 이름·연락처·복구 이메일을 본인이 바꾸되 **복구 이메일이 비밀번호 재설정 링크의 수신처**라는 점이 설계를 정한다 — 세션을 탈취한 사람이 이 값을 바꾸면 재설정으로 계정 탈취가 완성되므로 재인증과 이전 주소 알림을 함께 둔다. 아바타 이미지는 v1에 두지 않는다.

## 기능 목록

| 기능ID | 기능명 | 설명 | 우선순위 |
|--------|--------|------|:--------:|
| **AUT-01** | 회원가입 | 아이디·비밀번호 통합 가입이다 — 직원과 관리자를 가입 단계에서 가르지 않고, 소속·역할은 사업장 등록(WRK-01)이나 초대 수락(WRK-05)이 결정한다. 입력 필드와 검증 규칙은 여섯이다 — **아이디**(4~20자 · 영소문자와 숫자 · 첫 글자는 영문 · 예약어 금지) · **비밀번호**(8자 이상 · 영문·숫자·특수문자 중 2종 이상) · **이름**(2~50자) · **연락처**(국내 휴대폰 또는 E.164) · **복구 이메일**(선택) · **약관·개인정보 동의**(필수 — 두 문서의 활성 버전에 모두 동의해야 가입이 성립한다) · **위치정보 동의**(선택 — 가입 요건이 아니며 GPS 체크인 사용 전 필수, 미동의 시 체크인만 차단된다, D-19)이다. 클라이언트와 서버가 같은 규칙으로 검증하되 **서버 판정이 최종**이다. 동의 이력은 버전과 시각까지 PRV-02가 기록한다 — 동의를 받았다는 사실만으로는 입증되지 않기 때문이다. 자격증명(users)과 프로필(profiles)은 **단일 트랜잭션**으로 생성하고 실패 시 전부 롤백한다. 비밀번호는 적응형 해시로 저장하며 원문·해시를 로그·응답·감사 전후값 어디에도 남기지 않는다. 가입 직후 소속 사업장이 0개면 온보딩(사업장 등록 또는 초대 대기)으로 보낸다 | **P0** |
| **AUT-02** | 로그인 | 아이디·비밀번호를 해시 검증한 뒤 표면별 인증 컨텍스트를 발급한다 — 관리자 웹·시스템 웹은 서버 세션, 직원 앱은 access·refresh 토큰 쌍이다. 인증 성공 **직후 계정 상태를 다시 조회**해 DELETED는 컨텍스트를 즉시 폐기하고, SUSPENDED는 정지 사유·해제 예정일을 담아 차단한다. 자격증명 오류는 아이디 미존재와 비밀번호 불일치를 **하나의 코드로 통일**해 사용자 열거를 막는다. (IP, 아이디) 조합의 실패 횟수를 제한하고 초과 시 재시도 가능 시각을 함께 반환한다 | **P0** |
| **AUT-03** | 세션 관리 | 인증 컨텍스트의 검증·갱신·폐기다. 직원 앱은 시작 시 토큰을 검증하고 만료가 임박하면 refresh로 **회전 재발급**해 재실행 자동 로그인을 성립시킨다. 관리자 웹·시스템 웹은 서버 세션 유효성을 검증·연장하고 상태변경 요청마다 CSRF 토큰을 확인한다. 폐기 트리거는 로그아웃 · 계정 정지 · 비밀번호 변경(전체 로그아웃 선택 시) · 탈퇴이며, 폐기는 세션 무효화와 refresh token revoke를 함께 수행한다 — Redis 블랙리스트가 revoke의 실행 지점이다. **인증이 유효한 중에 계정 상태가 바뀌면 다음 요청의 서버 검증이 차단**하므로 토큰 유효기간이 제재를 무력화하지 않는다 | **P0** |
| **AUT-04** | 아이디 중복 확인 | 가입 성립 조건인 아이디 유일성을 사전 확인한다. 형식 검증을 통과한 값만 조회하고 **가용 여부 boolean만** 반환한다 — 계정 상태·프로필을 함께 내려주면 그 자체가 계정 열거 경로가 된다. 입력 디바운스 **약 400밀리초** 후 표시하고 호출 빈도를 제한한다. 클라이언트는 비밀번호 강도를 약함·보통·강함 3단계로 실시간 표시한다. 사전 확인을 통과했더라도 **가입 트랜잭션에서 유일성을 재확인**한다 — 확인과 가입 사이의 경합으로 중복이 성립할 수 있어 최종 판정은 DB 제약이다 | **P0** |
| **AUT-05** | 프로필 관리 | 본인 계정의 **이름 · 연락처 · 복구 이메일**을 바꾼다. 이름만 바꾸면 재인증 없이 반영하고, **연락처 · 복구 이메일을 바꾸면 현재 비밀번호 재인증을 선행**한다 — 복구 이메일은 재설정 링크(AUT-07)의 수신처라 세션 탈취자가 바꾸면 계정 탈취 경로가 완성된다. 복구 이메일이 바뀌고 이전 값이 있었으면 **이전 주소로 변경 알림**을 보내(새 주소는 마스킹) 소유자가 알아차리게 하고, 모든 변경을 보안 이벤트로 기록한다. 검증 규칙은 가입(AUT-01)과 같고 연락처 중복은 탈퇴 계정을 뺀 유일성으로 판정한다. **아이디와 계정 상태는 이 경로로 바꾸지 않는다.** 사업장이 소유한 인사 레코드의 성명·연락처와는 별개 축이며, 직원의 인적사항 변경은 그 레코드의 변경 요청 경로를 따른다 | **P2** |
| **AUT-06** | 비밀번호 변경 | 현재 비밀번호로 재인증한 뒤 신규 비밀번호를 가입과 동일한 정책 + **현재와 상이함**으로 검증해 재해시한다. 변경 후 현재 세션 유지와 모든 기기 로그아웃 중 하나를 선택할 수 있고, 시각·IP·기기 정보를 보안 이벤트로 기록하되 원문·해시는 남기지 않는다. 계정 보안의 기본 수단이므로 플랫폼요건으로 채택했다 | **P0** |
| **AUT-07** | 비밀번호 재설정 | 복구 이메일이 등록된 계정에는 재설정 링크를 발송하고, 미등록 계정은 플랫폼 지원 담당(SUPPORT 이상)의 보조 재설정을 안내한다. **응답은 계정 존재 여부와 무관하게 동일**하며 발송 빈도를 제한한다 — 응답이 갈리면 존재 확인 경로가 된다. 토큰은 **해시로 저장**하고 **만료(1시간)** 와 사용 여부를 검증하며, 성공 시 기존 세션과 refresh token을 전부 폐기한다. 반복 실패는 호출 빈도 제한과 보안 이벤트 기록 대상이다. 메일 발송 실패는 v1에서 재시도하지 않고 실패 로그만 남기며 사용자 응답은 성공과 동일하게 유지한다. 계정 잠김이 곧 이탈이고 지원 부담으로 직결되므로 제품성립 축이다 | P1 |
| **AUT-08** | 계정 상태 머신 | ACTIVE · SUSPENDED · DELETED 3상태와 정지 만료일·정지 사유·삭제 시각을 관리한다. 전이는 제재(ACTIVE → SUSPENDED) · 해제(SUSPENDED → ACTIVE) · 탈퇴·강제삭제(ACTIVE·SUSPENDED → DELETED)이며 **DELETED에서 다른 상태로는 전이하지 않는다**. 정지 주체는 플랫폼 관리자이고 정지 즉시 기존 세션을 폐기하며 정지 중에는 모든 권한 판정이 거부를 반환한다. 정지 만료는 접근 시점 복귀와 정기작업(autoUnsuspendAccounts) 양쪽으로 처리한다. 상태 변경은 전후 상태·사유·처리자를 감사 기록하고 **마지막 SUPER_ADMIN 계정의 정지·삭제는 차단**한다 | P1 |
| **AUT-09** | 계정 삭제(탈퇴) | 개인정보 파기 요구에 대응하는 본인 탈퇴 경로다. 비밀번호 재인증을 선행하고, **OWNER로 소유한 사업장이 하나라도 있으면 차단**해 폐쇄(WRK-10) 경로를 안내한다 — 소유자가 남은 채 계정만 사라지면 그 사업장이 관리 불능이 된다. 판정 대상은 활성·검증 대기·정지 사업장이며 **이미 폐쇄된 사업장은 제외**한다. 실행은 상태 DELETED 전이 · 프로필 비식별화 · 세션과 refresh token 전체 폐기 · 전 멤버십 비활성화를 **단일 트랜잭션**으로 수행한다. **급여·근태·근로계약·명세서·임금대장 등 법정 보존 대상은 삭제하지 않으며**, 보존 데이터의 본인 열람권은 CMP-07이 정한다. DELETED 계정은 로그인·재설정·초대 수락을 모두 차단하고 동일 아이디 재사용은 기본 금지다 | P1 |
| **AUT-10** | 진입 컨텍스트 분기 | 하나의 계정이 직원 앱·관리자 웹·시스템 웹 중 어디로 들어가는지 판정한다. 판정 축은 셋이다 — 직원 앱은 STAFF 이상 멤버십, 관리자 웹은 OWNER·MANAGER 멤버십, 시스템 웹은 **플랫폼 RBAC 보유 여부**다. **사업장 OWNER라도 플랫폼 권한은 별개**이므로 시스템 웹 진입을 허용하지 않는다. 멤버십 수에 따라 0개는 온보딩, 1개는 자동 선택, 2개 이상은 사업장 선택 화면(WRK-06)으로 분기하고, PENDING 초대만 있으면 초대 수락 화면으로 보낸다. **동일 사용자가 사업장별로 다른 역할을 가질 수 있으므로** 역할 판정은 선택된 사업장 단위로 다시 수행한다 | P1 |

**10기능이다** — AUT-01 · 02 · 03 · 04 · 05 · 06 · 07 · 08 · 09 · 10. 우선순위 분포는 P0 5(AUT-01 · 02 · 03 · 04 · 06) · P1 4(AUT-07 · 08 · 09 · 10) · P2 1(AUT-05)이며 5 + 4 + 1 = 10이다. 결번은 없다.

## 계정 상태와 인증 채널

계정 상태 머신의 정본은 [../09_glossary/03_enums_state_machines.md](../09_glossary/03_enums_state_machines.md)이고, 채널별 계약의 정본은 [../04_architecture/02_authn_session.md](../04_architecture/02_authn_session.md)다. 아래는 기능 서술에 필요한 요약이다.

| 상태 | 의미 | 허용 전이 |
|------|------|----------|
| ACTIVE | 정상 | → SUSPENDED(제재) · → DELETED(탈퇴·강제삭제) |
| SUSPENDED | 플랫폼 제재. 전 권한 판정이 거부를 반환하고 기존 세션은 즉시 폐기된다 | → ACTIVE(만료·해제) · → DELETED(강제삭제) |
| DELETED | 논리 삭제. 로그인·재설정·초대 수락 전부 차단. 법정 보존 데이터는 유지된다 | 없음(종단) |

| 축 | 관리자 웹·시스템 웹 | 직원 앱 |
|------|------------------|---------|
| 자격 보관 | 서버 세션 + HttpOnly·Secure 쿠키 | access·refresh 토큰(기기 보안 저장소) |
| 전송 | 쿠키 자동 전송 + CSRF 토큰 | Authorization Bearer |
| 갱신 | 세션 연장 | refresh 회전 재발급 |
| 폐기 | 세션 무효화 | refresh revoke(블랙리스트) |
| 재인증 | 민감 작업 단위 소비(단기 유효) | 좌동 |

**재인증이 필요한 작업은 넷이다** — 민감정보 원문 복호화(HRM-01) · 사업장 폐쇄(WRK-10) · 계정 탈퇴(AUT-09) · 민감 문서 다운로드(HRM-09). 재인증 결과는 **5분간 유효**하며 작업 단위로 1회 소비한다(REQ-AUT-25).

**공개 경로는 여섯으로 한정한다** — 로그인 · 회원가입 · 가입 동의(재동의 게이트 — 컨텍스트 발급 전 미인증 진입) · 아이디 중복 확인 · 비밀번호 재설정 · 약관·개인정보·위치정보 문서 조회다(REQ-AUT-12). 그 밖의 경로는 전부 인증을 요구하며 미인증 접근은 로그인으로 유도한다.

## 관련 테이블

**users**(자격증명·계정 상태·정지 만료일) · **profiles**(이름·연락처·복구 이메일·마지막 로그인) · **password_reset_tokens**(해시 저장·만료·사용 여부) · **account_status_events**(상태 전이 이력) · **security_events**(로그인 성공·실패 · 비밀번호 변경·재설정 · 재인증. **아이디가 존재하지 않는 로그인 실패도 시도된 아이디를 축으로 기록한다**) · **terms_documents**(약관·개인정보·위치정보 문서 버전) · **user_consents**(버전별 동의 이력 — PRV-02 소관). 명세 정본은 [../05_database/01_auth.md](../05_database/01_auth.md)이며 RLS 정책은 [../05_database/08_rls_policies.md](../05_database/08_rls_policies.md)가 정본이다.

세션 스토어와 refresh token 블랙리스트는 관계형 테이블이 아니라 Redis에 둔다 — 만료가 곧 삭제인 데이터라 보존·감사 대상이 아니고, 폐기 판정이 요청 경로마다 일어나 지연에 민감하기 때문이다. 상세는 [../04_architecture/02_authn_session.md](../04_architecture/02_authn_session.md)가 정본이다.

## 에러 코드

| 코드 | HTTP | 발생 조건 |
|------|:----:|----------|
| auth.username_taken | 409 | 아이디 중복 — 사전 확인 단계와 가입 트랜잭션 재확인 양쪽에서 발생한다(AUT-01 · AUT-04) |
| auth.phone_taken | 409 | 휴대폰 번호 중복. 삭제된 계정은 판정 대상에서 제외한다(AUT-01) |
| auth.weak_password | 422 | 비밀번호 정책 미충족(AUT-01 · AUT-06) |
| auth.invalid_credentials | 401 | 아이디 미존재·비밀번호 불일치를 통일한 응답 — 열거 방지(AUT-02) |
| auth.password_unchanged | 422 | 새 비밀번호가 현재 비밀번호와 동일(AUT-06) |
| auth.token_invalid | 401 | access·**refresh** token 만료·폐기·서명 불일치(AUT-03) |
| auth.csrf_token_invalid | 403 | 웹 세션 채널 상태변경 요청의 CSRF 토큰 부재·불일치. 앱 JWT 채널에는 적용하지 않는다(AUT-03) |
| auth.account_suspended | 403 | 정지 계정의 로그인·접근 시도(AUT-02 · AUT-08) |
| auth.account_deleted | 403 | 삭제 계정의 로그인·접근 시도(AUT-02 · AUT-08 · AUT-09) |
| auth.consent_required | 422 | 필수 약관·개인정보 동의 또는 개정 재동의 누락 — 위치정보는 별도 선택 동의라 가입 요건이 아니다(D-19)(AUT-01) |
| auth.reset_token_invalid | 400 | 재설정 토큰 만료·사용완료·불일치(AUT-07) |
| auth.reauth_required | 401 | 재인증 대상 작업(민감정보 복호화 · 사업장 폐쇄 · 계정 탈퇴 · 민감 문서 다운로드 · 프로필 연락처·복구 이메일 변경)에서 재인증 미충족 또는 재인증 토큰 검증 실패(만료·이미 소비·불일치)(AUT-05 · AUT-09 · WRK-10 · HRM-01 · HRM-09). 대상 작업 전수는 [../10_security/01_authn_authz.md](../10_security/01_authn_authz.md) 재인증 통제 절이 센다 |
| auth.workplace_forbidden | 403 | 요청 사업장과 멤버십·역할 불일치(AUT-10) |
| auth.platform_forbidden | 403 | 시스템 웹 진입 시 플랫폼 권한 자체가 없음(AUT-10) |
| auth.owner_must_transfer | 409 | OWNER 소유 사업장이 남아 있어 탈퇴 차단(AUT-09) |
| common.rate_limited | 429 | 로그인 실패 누적·재설정 발송 빈도 초과(AUT-02 · AUT-07) |

- **auth.invalid_credentials는 401이고 auth.account_suspended는 403이다.** 전자는 자격증명 자체가 성립하지 않은 상태, 후자는 자격증명은 맞았으나 계정 상태가 접근을 막는 상태다. 두 응답을 하나로 합치면 정지 사유·해제 예정일을 안내할 수 없다.
- **auth.platform_forbidden(플랫폼 권한 자체가 없음)과 system.permission_denied(권한은 있으나 역할 레벨 부족)를 구분한다** — 후자의 정본은 [12_system.md](./12_system.md)다.
- 전수 정본은 [../09_glossary/02_error_codes.md](../09_glossary/02_error_codes.md)다.
