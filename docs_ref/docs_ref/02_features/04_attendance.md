> **원천**: docs_ref2/features_p0.md §3 · §4-3 · docs_ref2/features.md §3 · §4-3 · docs_ref2/requirements_p0.md ATT 절 · §2.1

ATT는 **급여 계산의 원천 데이터를 만드는 도메인**이다. 체크인(ATT-01)이 원본 이벤트를 만들고, 판정(ATT-04)과 분해(ATT-05)가 법정 시간 단위로 정리하며, 마감(ATT-08)이 그 결과를 **잠가서 급여의 확정 입력으로 넘긴다**. 마감 없이는 급여 계산이 시작되지 않으므로 이 세 단계가 하나라도 빠지면 마감 경로가 끊긴다.

원본과 판정은 **분리해서 보존**한다. 체크인 이벤트는 삭제하지 않고, 수정 요청(ATT-06)과 승인(ATT-07)도 원본을 덮어쓰는 대신 보정 이력을 남긴다. 관리자의 수동 보정 역시 원본을 직접 고치지 않고 대리 작성 + 즉시 승인 경로를 거친다 — 근태는 임금 분쟁의 1차 증거라 "무엇이 원래 기록이었는가"가 지워지면 안 되기 때문이다.

**자기승인 차단의 판정 축은 "대상 직원 본인 = 승인자"다.** 관리자가 직원을 대신해 제출한 건은 **대리 제출자와 승인자가 같아도 허용**하며, 대신 대리 사실 표시 · 사유 입력 · 감사 기록을 필수로 요구한다. 이 예외가 없으면 관리자가 한 명뿐인 사업장에서 미퇴근 레코드를 해소할 경로가 사라져 마감 차단 사유 ①이 영구히 남는다. 계약 정본은 [../03_requirements/05_attendance.md](../03_requirements/05_attendance.md)(REQ-ATT-16)와 [../03_requirements/01_global_rules.md](../03_requirements/01_global_rules.md)(REQ-GLB-16)다.

**시각은 클라이언트가 아니라 서버가 찍는다.** 기기 시각은 별도 필드로 보존해 차이를 위험 플래그 판정에 쓴다. 지오펜스도 마찬가지로 **서버가 좌표와 반경을 다시 계산**한다(ATT-02) — 클라이언트 판정을 믿으면 근태가 조작된다.

**ATT-12(휴게시간 준수 검증)는 기록이 아니라 검증이다.** ATT-03이 휴게를 기록만 하므로 이 검증이 없으면 8시간 근무·휴게 0분 근태가 그대로 마감된다. 위반은 2년 이하 징역 또는 2천만원 이하 벌금이며 **전 규모 적용**이라 5인 미만도 예외가 아니다.

**ATT-11(QR·키오스크 체크인) · ATT-14(오프라인 기록) · ATT-15(위치 조작 방지)는 v1에 두지 않는다.** 따라서 v1의 체크인 경로는 앱 GPS 단일 경로이며, 모의위치·비정상 이동거리 같은 의심 신호는 차단이 아니라 위험 플래그 표시로만 처리한다.

## 기능 목록

| 기능ID | 기능명 | 설명 | 우선순위 |
|--------|--------|------|:--------:|
| **ATT-01** | 출근/퇴근 체크인 | 급여 계산의 원천 데이터를 만든다. 사업장·직원·근무지·근무일(KST)·출근 시각·퇴근 시각·입퇴근 좌표·위치정확도(미터)·상태·**출처(GPS·MANUAL·IMPORT)**·위험 플래그를 기록하며 **시각은 클라이언트 시각이 아니라 서버 시각**이다. 기기 시각은 별도로 보존해 차이를 위험 판정 입력으로 쓴다. 순서 검증이 셋을 차단한다 — 같은 근무일에 미퇴근 레코드가 있는 상태의 중복 출근 · 출근 없는 퇴근 · 퇴근 시각이 출근보다 이른 경우다. 퇴근 누락은 미퇴근으로 플래그하고 보정 요청(ATT-06) 대상으로 넘긴다. **자정을 넘는 야간 교대는 출근 일자 기준 1개 레코드로 관리하되 실제 시간대 기준으로 날짜 귀속을 분할해 집계**한다 — 경계분의 손실·중복이 생기면 총 근로시간이 어긋난다. 앱 전용이며 **위치정보 동의(PRV-02)가 선행**한다 | P1 |
| **ATT-02** | 지오펜스 검증 | 서버가 전송 좌표와 근무지 좌표(WRK-03)의 거리를 계산해 설정 반경 이내인지 **재검증**한다. **클라이언트 판정은 신뢰하지 않는다** — 클라이언트를 믿으면 근무지 밖 체크인이 그대로 통과해 근태가 조작된다. 반경 밖은 차단하고 예외 요청 경로를 안내한다. 정확도 처리는 두 갈래로 갈린다 — **좌표 자체를 못 받으면 차단**하지만 **정확도가 기준보다 나쁜 경우는 차단하지 않고 대기 상태로 저장**해 관리자 승인 대상으로 넘긴다. 출근을 막으면 근무는 했는데 기록이 없는 상태가 되어 근태·급여 누락으로 직결되기 때문이다. 모의위치 의심·기기와 서버의 시각 차이 초과·비정상 이동거리는 **탐지하되 차단하지 않고** 위험 플래그로 표시한다 | P1 |
| **ATT-03** | 휴게시간 기록 | 휴게 시작·종료를 기록하거나 사업장 자동 차감 정책을 적용한다. **실근로분 = 재실분 − 휴게분**이며 휴게가 근로시간에서 빠져야 급여가 맞는다. 출근 전·퇴근 후 휴게와 중복 시작은 차단하고, 휴게가 재실시간보다 길거나 음수면 마감을 막는다. **이 기능은 기록만 담당하며 법정 최소 휴게 부여 여부의 판정은 ATT-12가 한다** — 둘을 하나로 합치면 기록이 없는 상태와 위반 상태를 구분할 수 없다 | P1 |
| **ATT-04** | 지각/조퇴/결근 판정 | 스케줄(ATT-09)의 시작·종료·허용오차 대비 **NORMAL · LATE · EARLY_LEAVE · ABSENT · MISSING_CLOCKOUT · ON_LEAVE · HOLIDAY · WEEKLY_HOLIDAY 8종**을 판정해 일 집계에 저장한다. 지각분은 실제 출근시각에서 스케줄 시작시각과 허용오차를 뺀 값, 조퇴분은 스케줄 종료시각에서 실제 퇴근시각을 뺀 값이며 둘 다 음수는 0으로 둔다. **주휴일 · 관공서 공휴일(5인 이상) · 승인된 휴가일은 결근으로 판정하지 않는다** — 공휴일을 결근 처리하면 급여가 잘못 깎인다. **스케줄이 없으면 실측만 기록하고 지각·결근 판정을 생략**한다. 일 경계는 KST다 | P1 |
| **ATT-05** | 연장/야간/휴일 집계 | 실근로시간을 **상호배타 8버킷**으로 분해해 일·주·월로 집계한다(아래 절). 원시 실근로분을 함께 보존해 주휴·주연장을 ISO 주 단위로 재합산할 수 있게 하며 **버킷 합 = 원시 실근로분**이 불변식이다. 연장 판정은 1일 8시간 초과 또는 1주 40시간 초과이되 **중복 계상을 금지**한다 — 일 초과분을 먼저 확정하고 남은 소정분을 ISO 주로 누적해 40시간 초과분만 추가 전환하며, 전환 대상을 **그 주의 시간 순 후순위 근로분부터**로 고정해 결정성을 보장한다. 단시간근로자는 소정근로시간 초과분도 연장이고, 연소자는 1일 7시간·주 35시간이 기산이다. **5인 미만이면 가산 대상 플래그만 false로 두고 실근로시간은 그대로 집계**한다 — 가산이 없는 것이지 근로가 없는 것이 아니다. **출퇴근 시각을 15분·30분 단위로 절사해 근로시간을 줄이는 처리는 임금체불이므로 사업장 설정으로도 허용하지 않는다** | P1 |
| **ATT-06** | 근태 수정 요청 | 누락·오류를 정정할 경로다. 이 경로가 없으면 틀린 근태로 급여가 확정되므로 계산정확성 축이다. STAFF가 대상 일자·요청 출퇴근 시각·사유·증빙을 제출하고 **PENDING → APPROVED · REJECTED · CANCELLED**로 전이한다. **동일 직원·동일 일자의 대기 요청은 1건만** 허용해 중복 요청으로 판정이 갈리는 상태를 막는다. **원본 이벤트는 삭제하지 않고 보존**한다 | P1 |
| **ATT-07** | 근태 승인 | OWNER·MANAGER가 사유를 입력해 출퇴근·수정요청을 승인·반려한다. **사유는 승인·반려 어느 쪽이든 필수**이며 요청 사유와는 별개 값이다 — 관리자가 대신 제출하고 스스로 승인하는 경로가 열려 있어 승인 사유가 비면 보정의 근거가 사라진다. 승인 시 근태 이벤트와 일 집계를 **원자적으로 갱신하고 재판정·재집계**하며 주 경계 재합산까지 함께 수행한다 — 일 단위만 고치면 주 40시간 연장 판정이 어긋난다. **차단 축은 "대상 직원 본인 = 승인자"다** — 직원 본인이 낸 요청을 본인이 승인할 수 없다. 반면 **관리자가 대신 제출한 건은 그 관리자가 즉시 승인할 수 있으며**(대리 사실 표시 · 사유 · 감사 기록 필수) 이 예외가 단일 관리자 사업장의 마감 데드락을 막는다. 마감되었거나 급여가 확정된 기간은 승인 대상이 아니다 | P1 |
| **ATT-08** | 근태 마감 | 급여 계산의 입력을 확정·잠근다. **차단 사유는 여섯이며 배열로 함께 반환**한다 — 미퇴근 레코드 · 미승인 수정 요청 · 판정에 필요한 스케줄 누락 · **상시근로자 산정 스냅샷 누락**(CMP-01) · **휴게시간 미달**(ATT-12) · 휴게가 재실을 넘는 데이터 모순이다. 근로시간 한도 위반(ATT-13)은 경고로 표시하되 마감 차단 여부는 사업장 정책으로 둔다. 마감하면 해당 기간의 근태 수정·휴가 반영·스케줄 변경을 제한하고 급여의 확정 입력으로 제공한다. 마감 상태는 **LOCKED**이고 취소는 **LOCKED → REOPENED → LOCKED**(재마감) 경로이며 **급여 미확정 기간에 한해 OWNER가 사유를 입력해야** 가능하다. 오입력 마감은 **LOCKED → CANCELLED**로 닫으며 **그 마감 건이 종결될 뿐 그 급여월이 종결되는 것은 아니다** — 같은 급여월은 새 마감 건으로 다시 마감할 수 있어야 한다. 이 경로가 막히면 오입력 하나로 그 달의 급여 확정까지 영구히 불가능해진다. **모든 전이는 감사 로그 필수**다. **마감된 기간은 재오픈 없이 재판정·재집계하지 않으며 일 롤업 정기작업도 건너뛴다** — 확정 급여의 입력이 사후에 바뀌면 재현성이 깨진다 | P1 |
| **ATT-09** | 근무 스케줄 | 직원별 근무일·시작/종료·휴게·근무장소를 편성한다. 반복 패턴(주 고정)과 단일 예외일을 지원하고 겹침과 종료가 시작보다 이른 편성을 차단한다. **겹침 차단은 데이터베이스 제약이 맡는다** — 겹치는 편성이 남으면 "어느 스케줄로 판정했는가"에 답이 둘이 되어 지각·조퇴 판정이 비결정적이 된다. **원천에서 P2였으나 ATT-04 지각·결근 판정이 스케줄을 요구하므로 판정 기준 자체가 없어지는 문제 때문에 v1 필수로 끌어올렸다** — 스케줄이 없으면 마감 차단 사유 3번이 영구히 해소되지 않는다. 연소자·임신 중 근로자의 배치 제약(ATT-13)을 **편성 단계에서** 반영해 위반 근무표가 애초에 만들어지지 않게 하며, 그 차단도 데이터베이스 가드가 함께 맡는다 — 판정 입력은 생년월일과 임신 보호기간·임신기 근로시간 단축 구간(LEV-01)이고 코드는 **attendance.assignment_forbidden/422**다 | P2 |
| **ATT-10** | 실시간 근태 현황 | 관리자 홈에서 **오늘(KST) 재직 직원 각자가 지금 어떤 상태인지** 한눈에 본다 — 휴가 · 근무 중 · 퇴근 · 승인 대기 · 미출근 · 출근 전 · 휴무. 상태는 **서버 기록만으로** 정한다(출퇴근 기록 · 스케줄 · 승인된 휴가). 미출근은 스케줄 시작 시각에 허용오차를 더한 시각이 지났는데 기록이 없는 경우다. **지각·조퇴·결근은 판정하지 않는다** — 판정은 일 집계(ATT-04)의 몫인데 당일 집계는 다음 날 새벽에 만들어지므로, 보드가 판정을 흉내 내면 같은 날에 값이 둘 생긴다. 실시간 푸시가 아니라 **조회 시점의 상태**이며 화면이 다시 보일 때 새로 읽는다. 체크인 경로를 늘리지 않는다(ATT-11 · 14 이월 유지) | **P2** |
| **ATT-12** | 휴게시간 준수 검증 | 근기법 §54를 **미달 방향으로** 검증한다 — 실근로 8시간 이상이면 휴게 60분 이상, 4시간 이상 8시간 미만이면 30분 이상이며 미달이면 위반으로 표시하고 **월 마감을 차단**한다. 판정 기준은 재실분이 아니라 **실근로분**이다. **전 규모 적용**이라 5인 미만도 예외가 없고 위반 시 2년 이하 징역 또는 2천만원 이하 벌금이다. ATT-03은 기록만 하므로 이 검증이 없으면 8시간 근무에 휴게 0분인 근태가 그대로 마감된다. 경계는 **이상으로 해석**한다(확인 완료 — 정확히 4시간 → 30분 · 정확히 8시간 → 60분 · 4시간 미만 의무 없음. 확인값 정본 [../01_overview/05_priorities_roadmap.md](../01_overview/05_priorities_roadmap.md)). §54 개정(2026-12-10 시행)은 법 개정 감시 대상이다 | P1 |
| **ATT-13** | 근로시간 한도 경고 | 넷을 사전 경고·차단한다 — **연장 주 12시간 초과**(§53①, **5인 이상에만 경고**) · **연소자 1일 7시간·주 35시간**(§69, 전 규모) · **연소자 야간·휴일 근로**(§70②, 전 규모, 배치 차단) · **임신 중 근로자 연장근로 금지**(§74⑤, 전 규모, 배치 차단)다. **규모 분기가 필수**인 이유는 5인 미만에 연장 한도 오경고를 내면 사용자가 경고 전체를 무시하게 되기 때문이며, 반대로 **근기법 제5장(여성과 소년)은 규모 무관 적용**이라 5인 미만에서 이 경고를 끄면 법 위반을 방치한다. 한도값은 기준값으로 관리한다 | P1 |

**12기능이다** — ATT-01 · 02 · 03 · 04 · 05 · 06 · 07 · 08 · 09 · 10 · 12 · 13. 우선순위 분포는 P1 10(ATT-01 · 02 · 03 · 04 · 05 · 06 · 07 · 08 · 12 · 13) · P2 2(ATT-09 · 10)이며 10 + 2 = 12이다. **ATT-11 · 14 · 15는 결번**이며 v1.1 이월이다.

## 8 법정 시간버킷 개요

분해 규칙의 정본은 [../03_requirements/05_attendance.md](../03_requirements/05_attendance.md)이고 버킷별 지급배수는 [../03_requirements/07_payroll.md](../03_requirements/07_payroll.md)가 정본이다. 아래는 ATT-05가 만드는 출력의 형태 요약이다.

| # | 버킷 | 조건 |
|---|------|------|
| 1 | 소정 | 비휴일 · 비연장 · 비야간 |
| 2 | 야간 | 비휴일 · 비연장 · 야간(22:00~06:00) |
| 3 | 연장 | 비휴일 · 연장 · 비야간 |
| 4 | 연장야간 | 비휴일 · 연장 · 야간 |
| 5 | 휴일(8시간 이내) | 휴일 · 당일 누적 8시간 이내 · 비야간 |
| 6 | 휴일야간(8시간 이내) | 휴일 · 당일 누적 8시간 이내 · 야간 |
| 7 | 휴일연장(8시간 초과) | 휴일 · 당일 누적 8시간 초과분 · 비야간 |
| 8 | 휴일연장야간 | 휴일 · 당일 누적 8시간 초과분 · 야간 |

- 배정은 **시간대 단위(분)** 로 수행하며 겹침·누락이 없어야 한다. 예를 들어 휴일 20:00~24:00 근무 4시간 중 22:00~24:00은 버킷 6, 20:00~22:00은 버킷 5다.
- 휴일은 **주휴일**(직원별 지정 요일)과 (**5인 이상인 경우**) **관공서 공휴일** 둘뿐이며 공휴일 목록은 기준값에서 조회한다. **약정휴일은 v1에 두지 않는다** — 도입 시 휴일 축 확장으로 대응한다.
- 휴일근로의 "연장"은 주 40시간 초과가 아니라 **그 휴일의 8시간 초과분**을 뜻한다.
- 야간·휴일·연장은 서로 겹칠 수 있으므로 시간대를 분리해 상호배타 버킷에 배정한다. 하나의 시간대가 두 버킷에 들어가면 총 근로시간이 부풀려진다.

## 마감 차단 조건 개요

마감(ATT-08)은 급여의 유일한 입력 관문이므로 차단 조건이 계산 정확성의 최종 방어선이다. 정본은 [../03_requirements/05_attendance.md](../03_requirements/05_attendance.md)다.

| # | 차단 사유 | 해소 방법 |
|---|-----------|----------|
| 1 | 미퇴근 레코드 존재 | 수정 요청(ATT-06) 제출 후 승인 또는 **관리자 대리 작성 + 즉시 승인**(대리 사실·사유·감사 기록 필수 — 대리 제출자와 승인자가 같아도 허용한다) |
| 2 | 미승인 수정 요청 존재 | 승인·반려 처리(ATT-07) |
| 3 | 판정에 필요한 스케줄 누락 | 스케줄 편성(ATT-09) |
| 4 | **상시근로자 산정 스냅샷 누락** | 스냅샷 산정(CMP-01). 이것이 없으면 5인 분기를 결정할 수 없다 |
| 5 | **휴게시간 미달** | 휴게 기록 보정(ATT-03) 또는 실제 부여 후 재기록. 검증은 ATT-12 |
| 6 | 휴게가 재실을 초과하는 등 데이터 모순 | 원본·보정 이력 점검 |

- 4번이 없으면 **근태 마감 자체가 데드락**이 된다 — 그래서 CMP-01이 구현 순서 0단계에 놓인다.
- 한도 위반(ATT-13)은 차단이 아니라 경고다. 이미 발생한 근로를 마감하지 못하게 막으면 임금 지급이 지연되기 때문이며, 예방은 스케줄 편성 단계(ATT-09)에서 한다.

## 에러 코드

| 코드 | HTTP | 발생 조건 |
|------|:----:|----------|
| attendance.invalid_sequence | 409 | 중복 출근 · 출근 없는 퇴근 · 퇴근이 출근보다 이른 기록 · **휴게 순서 위반**(출근 전·퇴근 후 휴게 · 중복 휴게 시작 · 진행 중 휴게 없는 휴게 종료)(ATT-01 · ATT-03) |
| attendance.out_of_geofence | 422 | 서버 재검증에서 좌표가 설정 반경 밖(ATT-02) |
| attendance.accuracy_too_low | 422 | **좌표 자체를 수신하지 못한 경우.** 정확도가 나쁜 경우는 차단하지 않고 대기 저장한다(ATT-02) |
| attendance.change_request_pending | 409 | 동일 직원·동일 일자에 대기 중 수정 요청이 이미 존재(ATT-06) |
| attendance.self_approval_forbidden | 403 | **대상 직원 본인**이 자기 수정 요청·자기 PENDING 체크인 레코드를 승인하려는 시도(ATT-01 · ATT-07). **관리자 대리 제출 건의 즉시 승인은 이 코드에 걸리지 않는다** |
| attendance.period_closed | 409 | 마감·급여 확정된 기간의 근태 수정·승인·**스케줄 변경·삭제** 시도(ATT-07 · ATT-08 · ATT-09) |
| **attendance.assignment_forbidden** | **422** | **법정 보호 대상자의 금지 시간대 편성 시도** — 연소자의 야간·주휴일 배치 · 임신 중 근로자의 소정근로 초과 배치(ATT-09 · ATT-13). **전 규모 적용**이다 |
| attendance.closing_blocked | 409 | 마감 차단 사유 존재. **사유를 배열로 반환**한다(ATT-08 · ATT-12 · CMP-01) |
| privacy.location_consent_required | 403 | 위치정보 별도 동의 없이 GPS 체크인 시도(ATT-01) — 정본 네임스페이스는 privacy이며 등재는 [13_privacy.md](./13_privacy.md)다 |

- **attendance.accuracy_too_low는 "정확도가 나쁘다"가 아니라 "좌표가 없다"에 대응한다.** 이름과 판정 조건이 어긋나 보이지만, 정확도 미달을 차단하지 않는 것이 의도된 설계다 — 차단하면 근무는 했는데 기록이 없는 상태가 만들어진다.
- **attendance.closing_blocked는 사유 배열을 함께 반환한다.** 단일 사유만 알려주면 사용자가 여섯 조건을 하나씩 발견하며 반복 시도하게 된다.
- 전수 정본은 [../09_glossary/02_error_codes.md](../09_glossary/02_error_codes.md)다.
