금액·시간·일수의 단위와 시간대 경계를 단일하게 규정한다. 급여 계산이 재현되지 않는 사고는 대부분 **부동소수점**과 **일 경계 오판** 둘에서 나오므로, 두 축의 규칙을 여기에 모아 다른 문서가 각자 정의하지 않게 한다.

핵심은 셋이다 — **금액은 정수 원 · 기간은 정수 분** · **저장은 UTC, 일 경계는 KST** · **기준값 선택 단위는 연도가 아니라 귀속 기준일**이다.

## 단위

컬럼 타입·제약의 정본은 [../05_database](../05_database/README.md)이며(공통 컬럼 규약은 [../05_database/07_constraints_integrity.md](../05_database/07_constraints_integrity.md)), 아래는 그 타입을 **어떤 단위로 읽고 계산하는가**의 계약이다.

| 대상 | 타입 | 단위·규칙 |
|------|------|----------|
| 금액 | bigint | **원(KRW) 정수**. numeric·float를 쓰지 않는다. 중간 몫만 numeric으로 두고 **항목 최종 금액에서 1회 반올림 후 bigint 저장**한다(REQ-GLB-02 · REQ-GLB-03) |
| 기간·근로시간 | integer | **분(minute) 정수**. 초 단위는 절사한다(work_minutes). **시각을 15·30분 단위로 절사하는 컬럼·제약을 두지 않는다** — 근로시간을 줄이는 절사는 임금체불이다(REQ-ATT-14) |
| 휴가 일수 | numeric(6,1) | **0.1일 단위**. 반차는 0.5다. 시간 단위 휴가 신청은 v1 범위 밖이다 |
| 비율 | numeric | 가산율 numeric(5,3) · 임금률 numeric(5,2) · 요율 값은 statutory_rates.value jsonb에 **십진 문자열**로 담는다 |
| 반올림 금지 값 | numeric(18,4) · numeric(12,6) | 평균임금 일액(average_daily_wage) · 최저임금 환산시급(min_wage_converted_hourly · min_wage_reference)은 **numeric(18,4)**, 통상시급 환산시간 divisor(ordinary_wage_divisor)는 **numeric(12,6)**이다. **셋 다 반올림 없이 저장**한다 — 절사하면 과다 경고, 절상하면 미달을 놓친다(§1.1 min_wage_conversion) |
| 좌표 | numeric(9,6) 위도 · numeric(10,6) 경도 | 저장 결정성을 확보하고 **거리 계산 시점에만** double로 캐스팅한다 |
| 위치 정확도 | numeric(8,2) | 미터 단위 **numeric(8,2)** — 정수가 아니다(attendance_records의 in_accuracy_m · out_accuracy_m). 직렬화는 **문자열**이며 부동소수점으로 역직렬화하지 않는다. 판정 한계값 location_accuracy_limit_m · geofence_radius_m만 미터 단위 integer다 |
| 시각 | timestamptz | **UTC 저장**. 표시·경계 판정은 KST(Asia/Seoul) |
| 일자 | date | 근무일·급여월·효력일·기준일·지급일은 **KST로 산출해 date 컬럼에 물리 저장**한다. 급여월·통계월은 해당 월 1일로 정규화한다 |
| 건수·일수 | integer | 근로일수 · 소정근로일수 · 출근일수 · 가동일수 · 연인원(total_worker_days). 안전 정수 범위 내 |
| 평균 근로자 수 | numeric | 표시·감사용 실수값. **경계 판정에는 쓰지 않는다** — 판정은 연인원과 임계값 × 가동일수의 정수 비교다(REQ-CMP-04) |

### 부동소수점 금지 — 타입이 맞아도 매핑 선언이 깬다

**PostgreSQL 타입이 맞아도 애플리케이션이 부동소수점(IEEE754 double)으로 역직렬화하면 REQ-GLB-02가 조용히 깨진다.** 단위 규약은 저장 계층이 아니라 애플리케이션 표현까지 관통해야 성립한다. **역직렬화 계약이 결정되는 자리는 셋이다 — 엔티티 필드 타입 · 매퍼 결과 매핑 · DTO 필드 타입**(D-21 · ADR-26).

| PG 타입 | 애플리케이션 표현 | 강제 방법 |
|---------|------------------|----------|
| bigint (금액) | **long**(또는 Long) | 세 자리 전부를 정수 타입으로 선언한다. **float · double 변환 금지**이며 컴파일 시점 정적 분석이 차단한다 |
| numeric (비율·평균근로자수·휴가일수·평균임금·환산시급·divisor) | **BigDecimal**. **double 금지** | **부동소수점으로 BigDecimal을 생성하는 호출을 금지**한다(십진 문자열 또는 정수로만 생성) · **doubleValue 사용 금지** · **나눗셈은 스케일과 반올림 모드를 호출부가 명시**한다 |
| integer (분·일수·건수) | **int** 허용 | 안전 정수 범위 내 |
| timestamptz | **OffsetDateTime**(또는 Instant) | UTC로 다루며 응답 직렬화는 **UTC ISO-8601** 고정 |
| date | **LocalDate** | **시간대를 갖지 않는 타입이라 하루 밀림 함정이 성립하지 않는다.** 대신 **시간대를 끌고 들어오는 구형 날짜·시각 타입(java.sql.Date · java.util.Date · Calendar) 사용을 금지**한다 |
| jsonb | 객체 또는 문자열. 동결 필드의 수치는 **문자열로 직렬화**해 저장한다 | resolved_rate_values · calc_detail에 부동소수점을 넣지 않는다 |

- **date를 문자열로 다루던 우회를 폐기한 것은 근거가 사라졌기 때문이다.** 이전 계약("조회 계층 변환 함수가 KST 일자 문자열 YYYY-MM-DD로 고정한다")의 근거는 **JavaScript가 date를 UTC 자정으로 파싱해 KST 일자가 하루 밀리는 것**이었다. **LocalDate는 시간대 개념을 갖지 않으므로 그 함정의 성립 조건 자체가 없고**, 문자열을 거치면 오히려 날짜 연산이 파싱·포맷 왕복으로 흩어진다. 같은 목적은 **LocalDate 고정 + 구형 날짜·시각 타입 금지**로 달성한다 — 그 셋은 기본 시간대로 해석되므로 한 자리라도 들어오면 밀림이 그대로 되살아난다.
- **전역 타입 파서를 재정의하지 않는다는 계약도 자리를 옮겼다.** JDBC에는 컬럼 타입별 파서를 애플리케이션이 전역으로 갈아 끼우는 축이 없으므로 위험 지점은 드라이버 설정이 아니라 **매핑 선언**이다 — 위 세 자리 중 하나라도 double · float로 선언되면 그 자리에서 값이 부동소수점이 되며, 두 데이터 접근 축을 각각 검사해야 한다(같은 컬럼이 한 축에서만 어긋날 수 있다).
- **금액 컬럼의 평균은 SQL AVG에 맡기지 않고 합계와 건수를 받아 애플리케이션이 나눈다.** 중간 몫은 BigDecimal이며 스케일·반올림을 호출부가 명시한다 — AVG는 그 둘을 데이터베이스 기본값에 맡겨 반올림 1회 원칙(§1.1)의 적용 지점을 흐린다.

역직렬화 규약의 상세 설계는 [../04_architecture/06_payroll_engine.md](../04_architecture/06_payroll_engine.md)와 백엔드 스택 결정 D-21([../01_overview/06_design_decisions.md](../01_overview/06_design_decisions.md) · 기술 근거 ADR-25~29)이 갖는다. 컬럼 축의 매핑 표 정본은 [../05_database/README.md](../05_database/README.md)의 타입 매핑·역직렬화 규약 절이다.

## 시간 축

저장은 UTC, **모든 일(日) 경계 판정과 표시는 KST(Asia/Seoul)**다. 단일 국가 서비스이므로 사용자별 시간대 축을 두지 않는다 — 시간대는 KST 하나이며, 이것이 DayLog류 다국가 서비스와 갈리는 지점이다.

| 항목 | 규칙 |
|------|------|
| 저장 | 시각은 timestamptz로 UTC 저장한다. 절대 시각이 진실이다 |
| 표시·경계 | 표시와 일 경계 판정은 KST로 환산한다. 사용자별 시간대 설정을 두지 않는다 |
| 일자 물리 저장 | 근무일(work_date) · 급여월(pay_period) · 효력일(effective_from/to) · 기준일(base_date) · 지급일(pay_date)은 **KST로 산출한 값을 date 컬럼에 그대로 저장**한다 |
| 조회 술어 | 저장된 date 컬럼을 **범위 술어로 직접 비교**한다. 조회 시 컬럼에 시간대 변환·캐스팅을 씌우지 않는다 — 인덱스를 못 타고 세션 시간대에 의존하는 표현식이 된다. timestamptz 범위 조회는 서버가 KST 경계를 UTC instant로 변환해 바인드 파라미터로 넘긴다 |
| 자정 경과 근무 | work_date 경계를 넘는 야간 교대는 **출근 일자 기준 1개 레코드**로 관리하되, 집계는 **실제 시간대 기준으로 날짜에 귀속을 분할**한다. 경계분(23:59↔00:00)의 손실·중복이 없어야 하며, 검증은 일 집계 재계산 전후의 **총 분(minute) 합 일치**로 한다(REQ-ATT-05) |
| 야간 시간대 | 야간은 **22:00~익일 06:00**의 실근로 시간대이며 KST 벽시계 기준이다. 자정을 넘으므로 하루 안에서 두 구간으로 갈린다 |
| 프로세스 TZ | 서버·스케줄러 프로세스의 TZ는 **Asia/Seoul로 고정**한다. 정기작업 스케줄 표기도 KST다 |
| 클라이언트 시각 | 출퇴근 시각은 **클라이언트 시각이 아니라 서버 시각으로 기록**한다. 기기 시각은 별도 필드로 보존해 차이를 위험 플래그 판정에 쓴다(REQ-ATT-01) |
| 주 경계 | 주 단위 집계(주 40시간 연장 판정 · 주휴 개근)는 **ISO 주(월요일 시작)**를 쓴다. 급여월 경계와 주 경계는 어긋나므로 raw 실근로분을 보존해 주 단위로 재합산한다(REQ-ATT-10 · REQ-ATT-11) |

- **일 경계를 UTC로 판정하면 KST 09:00 이전 근무가 전날로 밀린다.** date 컬럼을 KST로 산출해 물리 저장하는 이유가 이것이며, 저장된 date를 다시 환산하지 않는 이유이기도 하다.
- **자정 경과 분할은 레코드 분할이 아니다.** 근태 레코드는 출근일 하나에 남기고 집계 단계에서만 일자별로 나눈다 — 레코드를 쪼개면 출퇴근 쌍의 순서 검증(REQ-ATT-02)이 성립하지 않는다.

## 기준일 4종

**기준값 조회 단위는 연도가 아니라 귀속 기준일(date)**이다(REQ-GLB-08). 같은 연도 안에도 경계가 있다 — 국민연금 기준소득월액 상·하한은 **매년 7월 1일**에 바뀌고, 간이세액표 개정 별표는 **지급일** 기준으로 적용된다. 연 단위로 기준값을 등록하면 이 두 경계에서 값이 통째로 틀린다.

조회 술어는 effective_from ≤ 기준일 AND (effective_to IS NULL OR 기준일 < effective_to)이며, 동일 (category, key)의 기간 겹침은 DB 제약(btree_gist EXCLUDE)이 차단한다 — system.statutory_rate_overlap/409.

| 기준일 | 정의 | 왜 이 축인가 |
|--------|------|-------------|
| **귀속 근로일** | 근로를 제공한 날(work_date) | 그 날의 법령이 그 날의 근로를 규율한다. 최저임금·가산율·공휴일·규모 정책·근로시간 한도가 이 축이다 |
| **귀속월** | 급여가 귀속되는 월(pay_period, 해당 월 1일로 정규화) | 보험료·보수월액·비과세 한도는 월 단위로 부과·정산된다 |
| **지급일** | 임금을 실제 지급하는 날(pay_date) | 소득세는 **지급 시점에 원천징수**한다(소득세법 **§134①** — "매월분의 근로소득을 지급할 때에는"). 개정 간이세액표도 시행일 이후 **지급분**부터 적용된다 |
| **사건 발생일** | 법정 의무를 촉발한 사건의 날(compliance_tasks.trigger_date) — 취득일 · 상실일 · 퇴직일 · 원천세 귀속월 종료일 | 신고 기한은 계산이 아니라 **의무 이행 축**이다. 앞의 셋이 "무엇으로 계산하는가"를 고르는 축이라면 이 축은 "언제부터 며칠 안에 해야 하는가"를 고른다 |

**기준일 축은 넷이며 앞의 셋과 넷째는 성격이 다르다.** 귀속 근로일·귀속월·지급일은 **계산 입력을 고르는 축**이고, 사건 발생일은 **기한을 파생시키는 축**이다. FILING_DEADLINE만 이 축을 쓴다.

- **사건 발생일을 기존 축에 흡수하지 않는 이유는 사건마다 날이 다르기 때문이다.** 4대보험 상실 신고는 상실일, 취득 신고는 취득일, 원천세는 귀속월 종료일이 기산점이며 어느 것도 근로일·급여월·지급일과 일치하지 않는다. 귀속월에 밀어 넣으면 "그 달에 귀속된 급여"와 "그 달에 일어난 사건"이 한 이름을 쓰게 되어 축의 정의가 흐려진다.
- 이 축은 **물리 컬럼으로 이미 존재한다** — compliance_tasks.trigger_date가 그 날이고 due_date가 파생 결과이며, 둘 다 불변이라 기한 감지 배치의 재실행 결정성을 보장한다.

### 영업일과 지급일 조정

**영업일은 토요일·일요일과 기준값 HOLIDAY_CALENDAR의 관공서 공휴일(대체공휴일 포함)을 제외한 날**이다. 사업장 휴무일·약정휴일은 영업일 판정에 넣지 않는다 — 영업일은 지급 실행이 가능한 달력 축이고 휴일은 근로 제공 의무 축이라 서로 다른 판정에 쓰인다.

| 상황 | 조정 |
|------|------|
| 지정 지급일이 영업일이 아니다 | **직전 영업일**에 지급한다. 익영업일로 미루면 임금 지급이 늦어지므로 앞으로 당긴다 |
| 지정 지급일이 그 달에 없다 | **말일**로 조정한다(예: 31일 지정에 30일까지인 달) |
| 조정 후 지급일 | **실제 지급일이 간이세액표 버전 선택의 입력**이다. 지정 지급일이 아니라 조정된 날로 TAX_TABLE을 조회하고 그 값을 결과에 동결한다 |

- 조정은 **지급일 축에만** 적용한다. 귀속 근로일·귀속월은 영업일 여부와 무관하게 달력대로 산출한다.
- 공휴일 판정 근거가 HOLIDAY_CALENDAR 기준값이므로, **해당 연도 공휴일이 적재되어 있지 않으면 지급일 조정도 성립하지 않는다** — 기준값 누락 차단(payroll.missing_reference_value/422)의 대상이다.
- 지급일 조정 계약의 정본은 [../03_requirements/07_payroll.md](../03_requirements/07_payroll.md) REQ-PAY-04이며, 용어 정의는 [01_domain_terms.md](./01_domain_terms.md) §5다.
- **사건 발생일 축에는 조정을 두지 않는다.** 신고 기한은 조문이 정한 날 그대로이고 **말일이 공휴일일 때의 보정(민법 §161)을 v1이 적용하지 않는다** — 지급일은 제품이 실행하는 날이라 앞으로 당길 근거가 있지만 기한은 법이 정한 마지막 날이라 제품이 옮길 자리가 아니다. 보정 도입은 **별건 부채**이며 도입하면 compliance_tasks.due_date의 파생이 HOLIDAY_CALENDAR에 의존하게 되므로 그 의존을 함께 정한다.

### 기준값 카테고리별 기준일 배정

카테고리 목록과 조회 키의 정본은 [../03_requirements/01_global_rules.md](../03_requirements/01_global_rules.md) §1.3이다. 아래는 그 표를 기준일 축으로 재배열한 것이며 새 카테고리를 만들지 않는다.

| 기준일 | 기준값 카테고리 | 카테고리 수 |
|--------|----------------|:---------:|
| 귀속 근로일 | MIN_WAGE · MIN_WAGE_SCOPE · PREMIUM_RATE · HOLIDAY_CALENDAR · SIZE_POLICY · WORK_HOUR_LIMIT · **STANDARD_WORK_HOURS** | **7** |
| 귀속월 | PENSION_RATE · HEALTH_RATE · LTC_RATE · EMPLOYMENT_RATE · INDUSTRIAL_ACCIDENT_RATE · WAGE_BASE_LIMIT · INSURANCE_WAGE_BASE_SCOPE · NONTAX_LIMIT · ROUNDING_POLICY · ORDINARY_WAGE_RULE | 10 |
| 지급일 | TAX_TABLE | 1 |
| **사건 발생일** | **FILING_DEADLINE** | **1** |

검산: 7 + 10 + 1 + 1 = **19카테고리**. §1.3의 표는 4대보험 요율 4종(PENSION_RATE · HEALTH_RATE · LTC_RATE · EMPLOYMENT_RATE)을 한 행에 묶어 표기하므로 **16행 · 19카테고리**다.

- **STANDARD_WORK_HOURS가 귀속 근로일인 이유**는 법정 근로시간 상한이 바뀌면 그 날의 근로를 그 날의 법령이 규율하기 때문이다 — 연차 비례 산정의 분모도 산정 대상 기간의 법령을 따른다.
- **FILING_DEADLINE만 사건 발생일 축**이며 그 축을 신설한 근거는 위 기준일 절에 있다.
- **TAX_TABLE만 지급일 축**이다. 나머지를 지급일로 조회하거나 간이세액표를 귀속월로 조회하면 개정 경계에서 소득세가 통째로 틀린다.
- **WAGE_BASE_LIMIT은 귀속월이되 7월 경계로 분할 등록**한다 — 연 단위 등록을 금지한다(REQ-GLB-08).
- 필요한 기준값이 하나라도 없거나 확인자(confirmed_by)가 비어 있으면 계산을 차단한다 — payroll.missing_reference_value/422. **임의 기본값·직전 연도 값 대체·0 처리를 금지**한다(REQ-GLB-09).
- 확정 시에는 기준값 **행 ID와 실제 적용된 값을 결과에 동결**한다. effective date 이력만으로는 재현이 깨진다(REQ-GLB-10 · §1.4).

## 단수 처리 요약

**정본은 [../03_requirements/01_global_rules.md](../03_requirements/01_global_rules.md) §1.1(ROUNDING_POLICY)**이며 여기서 규칙을 다시 정의하지 않고 **종수도 다시 세지 않는다**. 단위 규약과 직결되는 원칙만 요약한다.

| 원칙 | 내용 |
|------|------|
| 1회 적용 | 반올림은 **항목별 최종 금액에서 딱 1회**만 한다. 중간 단계에서 반올림하지 않으며 **항목 합계를 다시 반올림하지 않는다** — 합계는 이미 반올림된 정수들의 합이다 |
| 방향 | **지급 항목은 올림 · 무급공제는 절사 · 법정공제는 10원 미만 절사**. 지급 절사는 근로기준법 §43①(임금 전액 지급)과 충돌 소지가 있어 상향으로 통일한다 |
| 규칙의 출처 | 반올림 규칙 자체도 기준값 테이블에 effective date로 등록하고 **확정 결과에 규칙 버전을 동결**한다. 사업장별 개별 설정 UI를 v1에 두지 않는다 |
| 단위와 직결되는 예외 | work_minutes는 **초 단위 절사 1분** · leave_days는 **올림 0.1일** · min_wage_conversion(최저임금 환산시급)은 **반올림하지 않는다** — 절사하면 미달을 과다 경고하고 절상하면 실제 미달을 놓친다 |
| 나눗셈 | 나눗셈이 일어나는 지점은 §1.2가 **전수 열거**한다(**지점 수를 여기서 세지 않는다** — 정본이 갖는다). 열거되지 않은 새 나눗셈을 도입하면 반올림 키를 함께 정의한다. **몫을 중간 변수로 반올림해 저장한 뒤 재사용하는 구현을 금지**하며, 예외인 통상시급도 divisor를 결과에 함께 보존해야 재현된다 |

적용 순서 불변식은 **원시 분 집계 → 단가 × 시간 곱 → 항목 최종 금액에서 1회 반올림 → 항목 합계**다.
