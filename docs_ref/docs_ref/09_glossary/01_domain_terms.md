노무·세무 도메인의 용어를 단일하게 정의한다. 다른 문서는 정의를 다시 쓰지 않고 본 사전을 가리킨다. **표제어의 표기가 곧 전 문서군의 표기 정본**이며, 동의어를 만들지 않는다.

주제 그룹 10개로 나누고 **그룹 안은 개념 의존 순서**로 배열한다 — 선행 개념이 위에 온다. 가나다순이 아니므로 위에서 아래로 읽으면 그 도메인의 개념 사슬이 그대로 이어진다.

정의 셀은 네 가지를 담는다 — **무엇인가 · 근거(테이블·REQ·법령) · 혼동하면 안 되는 것 · 제약**이다. 값·수치의 정본은 각 정본 문서이며 본 사전은 그 개념이 무엇인지만 고정한다.

## 1. 계정·권한·테넌시

| 용어 | 정의 |
|------|------|
| 계정 | users의 한 행. username·비밀번호 해시·status(account_status 3값)를 갖는 **전역 개체**이며 사업장에 속하지 않는다. **사업장 권한은 계정이 아니라 멤버십이 갖는다** — 계정에 역할 컬럼을 두지 않는다. 상태 전이는 [03_enums_state_machines.md](./03_enums_state_machines.md) §1이며 DELETED는 종단이다 |
| 프로필 | profiles의 한 행. id = users.id인 1:1 확장이며 이름·휴대폰·복구 이메일·마지막 로그인 시각을 담는다. 휴대폰은 **DELETED 계정을 제외한 부분 유니크**라 탈퇴한 번호가 재사용될 수 있다(REQ-AUT-04) |
| 사업장 | workplaces의 한 행이자 **모든 업무 데이터의 테넌트 단위**다. 표기는 사업장으로 고정하며 회사·업체·워크플레이스로 부르지 않는다. **근로기준법의 적용 단위인 "사업 또는 사업장"과 이 행은 1:1이 아니다** — 여러 사업장 행이 하나의 사업으로 합산될 수 있고, 그 판정은 사업 단위 판정(§2)이 한다 |
| 멤버십 | workplace_members의 한 행. **사용자와 사업장을 잇는 소속 관계**이며 역할(workplace_role)과 상태(member_status)를 갖는다. 인사 레코드인 직원과 별개 개체다 — 멤버십은 "이 사업장에 접근할 수 있는가", 직원은 "이 사업장에 고용되어 있는가"를 담는다. 상태 전이는 [03_enums_state_machines.md](./03_enums_state_machines.md) §2 |
| 직원 | employees의 한 행. 이름·생년월일·직위·재직 상태(employee_status)를 담은 **인사 레코드**다. user_id는 nullable이라 **계정 없이도 직원을 등록할 수 있다**(임포트·초대 전 상태). 고용 관계 일반을 가리키는 보통명사로도 쓰며, 역할 값 STAFF와는 다른 축이다 — MANAGER도 직원이다 |
| 사업장 역할 | workplace_role 3값 — OWNER · MANAGER · STAFF. 멤버십이 보유하며 **동일 사용자가 사업장마다 다른 역할을 가질 수 있다**(REQ-AUT-24). **ADVISOR는 v1에 두지 않는다**(WRK-13 이월). 역할 값은 항상 대문자로 표기한다 |
| 역할 누적 | 상위 역할이 하위 역할의 권한을 포함하는 관계 — **OWNER ⊃ MANAGER ⊃ STAFF**. 권한을 역할마다 따로 열거하지 않고 누적으로 판정한다는 뜻이며, **OWNER 전용 액션**(정정본 발행 · 임포트 확정 · 역할 변경 · 사업장 폐쇄)은 누적의 예외가 아니라 상위 역할에만 부여된 권한이다 |
| OWNER 단일성 불변식 | **사업장당 ACTIVE OWNER는 항상 정확히 1명**이라는 제약(REQ-WRK-22). 0명이 되는 전이(마지막 OWNER 강등·제외·탈퇴)와 2명이 되는 전이(역할 변경으로 OWNER 생성) 양쪽을 막는다. **OWNER 권한 부여·회수는 양도 경로로만** 하며 역할 직접 변경으로 OWNER를 만들 수 없다. 다만 **v1은 사업장 양도를 구현하지 않으므로**(WRK 양도 기능 이월) 마지막 OWNER의 실질 해소 경로는 **사업장 폐쇄뿐**이다 — workplace.last_owner/409 · auth.owner_must_transfer/409의 안내가 폐쇄를 가리키는 이유다. 서비스 레이어와 DB 제약 양쪽이 강제한다 |
| 초대 | workplace_invitations의 한 행. 대상 username 또는 휴대폰번호·역할·만료시각·토큰 해시를 담으며 **토큰은 해시로만 저장**한다. 초대의 상태(invitation_status)와 멤버십의 상태(member_status)는 **별개 축**이다 — 수락은 초대를 ACCEPTED로 두면서 멤버십 ACTIVE를 새로 만든다 |
| 공유 코드 | 미가입자에게 발송하는 **1회용 초대 수단**. 수락 시 초대 대상 phone·username 일치 검증을 필수로 하고 불일치는 거부한다. v1은 관리자 최종 승인 우회 경로를 제공하지 않는다(REQ-WRK-16) |
| 컨텍스트 전환 | 사용자가 소속 사업장 중 하나를 활성 workplace_id로 선택하는 것. 이후 모든 업무 요청에 그 값이 실리며 **서버는 매 요청 멤버십·역할을 재검증**한다. **클라이언트 캐시는 workplace_id + 역할 단위로 격리**해 전환 시 타 사업장 데이터가 잔존하지 않게 한다(REQ-WRK-20) |
| 플랫폼 RBAC | system_admins가 보유하는 **사업장과 완전히 별개인 권한 축**. 시스템 웹 진입과 운영 API를 규율한다. **사업장 OWNER라도 플랫폼 권한은 별개**이며, 권한 자체가 없으면 auth.platform_forbidden/403, 있으나 역할별 권한 키가 부족하면 system.permission_denied/403으로 구분한다(REQ-SYS-03) |
| 플랫폼 역할 | system_role 4값과 레벨 — VIEWER(1) · SUPPORT(2) · ADMIN(3) · SUPER_ADMIN(4). 사업장 역할과 이름이 겹치지 않게 설계했다. **마지막 SUPER_ADMIN은 정지·삭제·회수할 수 없다**(system.last_super_admin/409). 초기 SUPER_ADMIN은 시드가 아니라 서버 기동 시 환경변수 1회성 부트스트랩으로 만든다 |
| 권한 화이트리스트 | 플랫폼 권한을 resource:action 형식으로 **명시 열거**하고 역할별 권한 집합을 정적 상수로 선언하는 방식. **알 수 없는 권한 키는 기본 거부**한다. 와일드카드형 권한을 두지 않으므로 audit:view·audit:export는 VIEWER에 포함되지 않는다(REQ-SYS-02) |
| 2단 방어 | 테넌트 격리를 **서비스 레이어 1차 검증 + PostgreSQL RLS 2차 심층방어**로 이중 강제하는 설계. 클라이언트 가드는 보조이며 방어 층으로 세지 않는다. 어느 한 층이 뚫려도 다른 층이 행 단위 격리를 지킨다 |
| 테넌트 스코프 | 업무 테이블 **39종**이 workplace_id NOT NULL FK를 갖고 그 값으로 격리된다는 규약. **선택 스코프 5종**(business_verification_logs · notifications · audit_logs · location_usage_records · export_jobs)은 nullable이며, **미보유 17종**은 **일곱 부류**로 갈린다 — 계정 도메인 7 + 전역 마스터 4 + 테넌트 루트(workplaces) 1 + 상위 그룹(business_units) 1 + 계정 단위 자원(subscriptions · system_admins) 2 + 플랫폼 운영 원장(scheduled_job_runs) 1 + 다형 스코프(idempotency_records) 1이다. **부류와 합계를 여기서 다시 세지 않는다** — 집계 정본은 [../05_database/README.md](../05_database/README.md) 접근 모델 절이다 |
| 본인 소유권 인가 | 명세서·급여 결과·근로계약을 **멤버십이 아니라 소유권으로 인가**하는 규칙 — 판정 조건은 employees.user_id = 요청자이며 workplace_members의 존재·상태를 요구하지 않는다(REQ-SLP-09 · CMP-07). 이것이 없으면 **퇴사·사업장 폐쇄 순간 본인 명세서 접근이 끊기는데, 명세서는 지급일 + 3년 보존·교부 대상이라 그 자체가 위반 소지**다. 읽기 전용이며 쓰기·재발행 권한을 주지 않는다 |
| 재인증 | 민감 작업 직전에 비밀번호를 다시 확인하는 절차. 대상은 **민감정보 원문 복호화 · 사업장 폐쇄 · 계정 탈퇴 · 민감 문서 다운로드 · 프로필의 연락처·복구 이메일 변경** 5종이며 결과는 **5분 유효·작업 단위 1회 소비**다. 미충족은 auth.reauth_required/401(REQ-AUT-25 · REQ-AUT-26) |

## 2. 사업장·검증

| 용어 | 정의 |
|------|------|
| 사업자등록번호 | workplaces.business_no. 10자리이며 형식과 체크섬을 서버가 검증한다. **동일 사업자등록번호로 복수 사업장 등록을 허용**한다(부가가치세법 §8 사업자단위과세·종사업장 제도). 차단하는 것은 (business_no, site_label) 완전 중복뿐이다(REQ-WRK-06) |
| 진위확인 | 국세청 진위확인 API에 사업자등록번호·대표자명·개업일자를 보내 **일치 여부**를 판정하는 절차. API 키는 서버 비밀로만 보관한다. 불일치는 workplace.business_invalid/422다. 상태조회와 다른 호출이며 둘을 뭉뚱그려 "사업자 조회"로 부르지 않는다(REQ-WRK-04) |
| 상태조회 | 국세청 상태조회 API로 **계속사업자·휴업·폐업·과세유형·폐업일자**를 확인하는 절차. 결과는 business_verification_logs에 result ∈ {MATCH, MISMATCH, SUSPENDED, CLOSED, ERROR}로 기록한다. **폐업만 신규 등록을 차단하고 휴업은 경고 후 허용**한다 — 휴업 중에도 근로관계·휴업수당·퇴직금 의무가 존속하기 때문이다(REQ-WRK-05) |
| 검증 상태 | workplaces.status(workplace_status 4값)가 나타내는 사업장의 수명주기 — PENDING_VERIFICATION · ACTIVE · SUSPENDED · CLOSED. 계정 상태(account_status)와 값 이름이 일부 겹치지만 **다른 enum**이며 서로 캐스팅하지 않는다 |
| PENDING_VERIFICATION | **국세청 API 장애** 또는 **개업 준비 중(사업자등록 신청 전)** 두 경우에 생성하는 사업장 상태. **근태·인사 입력은 허용하고 급여 확정·명세서 발행만 차단**하는 반쪽 제약이다(workplace.verification_pending/409). 근태까지 막으면 실제 근무가 기록되지 않아 나중에 임금 산정이 불가능해진다. N일 미검증 시 자동으로 SUSPENDED가 된다(REQ-WRK-08) |
| 사업장 식별명 | workplaces.site_label. 같은 사업자등록번호 아래 여러 사업장을 구분하는 지점명이다. 상호(company_name)와 다른 필드이며 중복 판정의 두 번째 축이다 |
| 사업장 그룹·주 사업장 | 동일 사업자등록번호를 가진 사업장들의 묶음과 그중 site_role = PRIMARY로 지정한 하나. 나머지는 SUB다. **그룹은 상시근로자 합산의 후보일 뿐 합산 여부를 결정하지 않는다** — 결정은 사업 단위 판정이 한다(REQ-WRK-06) |
| 과세 단위 | workplaces.tax_unit_type(tax_unit_type 2값) — GENERAL(개별과세) · BUSINESS_UNIT(사업자단위과세). **v1 기본은 GENERAL이며 BUSINESS_UNIT은 v1에 두지 않는다** |
| 사업 단위 판정 | 여러 사업장을 **하나의 사업으로 합산할지**를 정하는 절차(REQ-CMP-08). 근로기준법의 적용 단위는 "사업 또는 사업장"이며 장소가 분리되면 원칙적으로 별개지만 독립성이 없으면 합산한다. **사업자등록번호가 별개인지는 판단 기준이 아니다.** 독립성 체크리스트 4항(인사·노무관리 독립 · 예산·회계 독립 · 사업장별 경영담당자 존재 · 근로조건 결정권 전속)을 **사용자가 선언**하고 근거를 감사 보존한다 — **자동 합산은 법적 판단이라 하지 않는다**. 미판정 상태는 위험 경고를 노출한다 |
| 상시근로자 수 | 근로기준법 시행령 §7조의2의 산정 결과. **평균 근로자 수 = 산정기간 근로자 연인원 ÷ 가동일수**이며 산정기간은 **법 적용 사유 발생일 이전 1개월**이다. **사업장의 고정 속성이 아니라 기준일의 함수**이므로 사유마다·기준일마다 다시 산정한다. 활성 멤버 수·직원 레코드 수와 다른 값이다 — 근로자 아닌 자는 제외한다(REQ-CMP-01 · REQ-CMP-03) |
| 연인원·가동일수 | 연인원(total_worker_days) = 산정기간 일자별 근로자 수의 합 · 가동일수(operating_days) = 시계열의 길이. **일자별 근로자 수 시계열이 반드시 필요**하며 월 평균값 하나로는 제2항 보정을 계산할 수 없다(REQ-CMP-02) |
| 제2항 보정 | 제1항 평균값이 임계값을 넘거나 못 넘어도 **미달일수 비율로 판정을 뒤집는** 규칙(REQ-CMP-04). 임계값 T · 가동일수 D · 미달일수 U에 대해 ①연인원 < T × D 이고 2U < D면 T 이상으로 본다 ②연인원 ≥ T × D 이고 2U ≥ D면 T 미만으로 본다 ③그 외는 제1항을 따른다. **경계 판정은 반올림된 평균이 아니라 정수 비교**로 한다 |
| 상시근로자 스냅샷 | workplace_employee_count_snapshots의 한 행. 기준일·산정기간·연인원·가동일수·평균 근로자 수(실수)·일자별 시계열·확정자·산정 범위(scope ∈ WORKPLACE·BUSINESS_UNIT)를 담으며 (workplace_id, base_date, scope) 유일이다. **5인·10인 분기의 유일한 근거**이며(REQ-GLB-11) **단일 is_under_five 플래그만 저장하지 않는다** — 취업규칙·성희롱 예방교육은 10인 경계를 쓰므로 임계값별 경계를 실수값과 시계열에서 파생한다. 스냅샷이 없으면 급여 확정·근태 마감·연차 발생을 차단한다(REQ-CMP-06) |

## 3. 근태·시간

| 용어 | 정의 |
|------|------|
| 소정근로시간 | 근로계약으로 정한 근로시간. employment_terms.contractual_minutes에 **주 단위 분 정수**로 저장한다. 실제 근로시간(실근로분)과 다른 축이며, 소정근로시간 초과분이 연장의 기산이 된다. 주 15시간 미만은 주휴·퇴직금·일부 보험의 적용 예외 후보가 된다(REQ-HRM-06 · REQ-HRM-07) |
| 근무 스케줄 | work_schedules의 편성. 직원별 근무일·시작/종료·휴게·근무장소를 반복 패턴(주 고정)과 단일 예외일로 관리한다. **지각·조퇴·결근 판정과 소정근로 분해의 기준**이므로 **스케줄이 없으면 판정 자체가 성립하지 않는다** — 그 경우 실측만 기록하고 판정을 생략한다(REQ-ATT-08 · REQ-ATT-09) |
| 허용오차 | 스케줄 시작·종료 대비 지각·조퇴 판정에 두는 유예 분(grace minutes). 지각분 = max(0, 실제 출근시각 − 스케줄 시작시각 − 허용오차)로 쓰인다. **근로시간 절사와 다른 개념**이다 — 허용오차는 판정에만 쓰이고 근로시간 산정을 줄이지 않는다 |
| 체크인 | 직원이 출퇴근을 기록하는 행위이자 attendance_records의 한 행. 근무일(KST)·출퇴근 시각·좌표·위치 정확도·상태·source(GPS·MANUAL·IMPORT)·위험 플래그를 담는다. **시각은 클라이언트 시각이 아니라 서버 시각으로 기록**하고 기기 시각은 별도 필드로 보존한다. 출퇴근·출근기록으로 혼용하지 않는다(REQ-ATT-01) |
| 지오펜스 | 근무지 기준 좌표와 반경(geofence_radius_m, 50~500)으로 정의한 체크인 허용 구역. **서버가 좌표 거리를 재검증하며 클라이언트 판정을 신뢰하지 않는다.** 반경 변경은 **변경 시각 이후 체크인부터** 적용하고 과거 판정을 소급하지 않는다. v1은 사업장당 단일 근무지다(REQ-ATT-03 · REQ-WRK-10) |
| 위치 정확도 | 기기가 보고한 좌표 오차 반경(미터). **좌표 미수신은 차단**(attendance.accuracy_too_low/422)하지만 **정확도 저하만으로는 차단하지 않고 PENDING으로 저장**해 관리자 승인 대상으로 넘긴다 — 출근을 막으면 근무는 했는데 기록이 없는 상태가 되어 근태·급여 누락으로 직결된다(REQ-ATT-04) |
| 위험 플래그 | attendance_records.risk_flags. mock location 의심·기기와 서버 시각 차이 초과·비정상 이동거리를 **탐지하되 차단하지 않고** 표시하는 장치다. 차단 사유와 혼동하지 않는다 |
| 휴게시간 | 근로시간 도중 부여하는 휴게(근로기준법 §54). 기록하거나 사업장 자동 차감 정책으로 적용한다. **실근로분 기준으로 미달을 판정**한다 — 실근로 480분 이상이면 60분 이상, 240분 이상 480분 미만이면 30분 이상이며 **전 규모 적용**이다. 미달은 월 마감을 차단한다(REQ-ATT-07) |
| 재실분·실근로분 | 재실분은 출근부터 퇴근까지의 분, **실근로분 = 재실분 − 휴게분**이다. 급여 계산의 입력은 실근로분이며 재실분이 아니다. 휴게가 재실보다 길거나 음수면 마감을 차단한다(REQ-ATT-06) |
| 시간 버킷 | 일자별 실근로 시간대를 **상호배타 8종 중 정확히 하나**에 배정한 분해 결과 — 소정 · 야간 · 연장 · 연장야간 · 휴일 · 휴일야간 · 휴일연장 · 휴일연장야간. **버킷 합 = raw 실근로분이 불변식**이며 배정은 시간대 단위(분)로 수행한다. 8버킷·법정 시간버킷으로도 부르되 표제어는 시간 버킷이다(REQ-ATT-10 · [../03_requirements/05_attendance.md](../03_requirements/05_attendance.md)) |
| 연장근로 | 성인 기준 **1일 8시간 초과 또는 1주 40시간 초과** 근로. **중복 계상하지 않는다** — 일 8시간 초과분을 먼저 확정하고 남은 소정분을 ISO 주로 누적해 40시간 초과분을 추가 전환하며, 전환 대상은 **그 주의 시간 순 후순위 근로분부터**로 고정해 결정성을 보장한다. 단시간근로자는 소정근로시간 초과분도, 연소자는 1일 7시간·주 35시간 초과분도 연장이다(REQ-ATT-11) |
| 야간근로 | **22:00~익일 06:00**의 실근로 시간대. 자정을 넘으므로 하루 안에서 두 구간으로 갈린다. 연장·휴일과 겹칠 수 있으므로 시간대를 분리해 상호배타 버킷에 배정한다(REQ-ATT-12) |
| 휴일근로 | **주휴일**과 **5인 이상인 경우** 관공서 공휴일의 근로 — 휴일 판정 축은 이 둘뿐이며 약정휴일은 v1에 없다(REQ-ATT-12). **휴일근로의 "연장"은 주 40시간 초과가 아니라 그 휴일의 8시간 초과분**을 뜻한다(근로기준법 §56③) — 여기서 주 40시간 축을 끌어오면 배수가 틀린다 |
| 지각·조퇴·결근 판정 | 스케줄 대비 attendance_day_status 8값(NORMAL · LATE · EARLY_LEAVE · ABSENT · MISSING_CLOCKOUT · ON_LEAVE · HOLIDAY · WEEKLY_HOLIDAY)을 일 집계에 저장하는 처리. **승인된 휴가일은 결근으로 판정하지 않는다.** 지각·조퇴는 임금 공제의 근거이지만 **결근으로 환산하지 않는다** — "지각 3회 = 결근 1일" 약정은 무효다(REQ-ATT-09 · REQ-LEV-03) |
| 근태 수정 요청 | attendance_change_requests의 한 행. STAFF가 대상 일자·요청 시각·사유·증빙을 제출한다. **동일 직원·동일 일자 PENDING은 1건만** 허용하고 **원본 이벤트는 삭제하지 않는다**. 관리자 수동 보정도 원본을 직접 고치지 않고 대리 작성 + 즉시 승인 경로를 거친다. **자기승인 차단의 판정 축은 대상 직원 본인 = 승인자**이며, **대리 제출자 = 승인자는 예외로 허용**한다 — 대리 사실·사유·감사 기록이 필수다(REQ-ATT-16 · REQ-ATT-17 · REQ-GLB-16) |
| 근태 마감 | 급여월 근태를 검토·확정해 attendance_period_closings를 LOCKED로 두는 처리. **마감은 근태에만 쓰는 말**이며 급여에는 확정을 쓴다. 마감 후에는 해당 기간의 근태 수정·휴가 반영·스케줄 변경이 제한되고 **급여 계산의 확정 입력으로 제공**된다. 차단 사유 6종은 배열로 반환한다(REQ-ATT-18) |
| 마감 잠금·재오픈 | LOCKED → REOPENED(급여 미확정 기간에 한해 OWNER가 사유 입력) → LOCKED(재마감)의 흐름과, 오입력 마감을 종결하는 LOCKED → CANCELLED. **마감된 기간은 재오픈 없이 재판정·재집계하지 않으며** 일 롤업 배치도 LOCKED 기간을 건너뛴다 — 어기면 확정 급여의 입력이 사후에 바뀌어 재현성이 깨진다(REQ-ATT-19 · REQ-ATT-20) |

## 4. 휴가·연차

| 용어 | 정의 |
|------|------|
| 연차유급휴가 | 근로기준법 §60의 법정 유급휴가. **5인 이상 사업장에만 적용**되며 5인 미만 기간은 산정하지 않는다(leave.not_applicable/403 — 정상 상태). 회사 약정 휴가는 v1 범위 밖이다. 표제어는 연차이며 연차휴가·유급휴가로 혼용하지 않는다(REQ-LEV-01) |
| 연차 발생 | 기산일(hire_date)을 기준으로 연차 일수를 산정해 leave_grants에 적립하는 처리. ①입사 1년 미만은 1개월 개근당 1일(최대 11일) ②1년간 출근율 80% 이상은 15일 ③1년 이상이나 80% 미만은 1개월 개근당 1일 ④3년 이상은 15 + floor((계속근로연수 − 1) ÷ 2), **한도 25일**이다. **v1은 입사일 기준 고정이며 회계연도 일괄 산정은 범위 밖**이다(REQ-LEV-02) |
| 출근율 | 출근일수 ÷ 소정근로일수(**산정 대상 기간의 연간 축** — 1일 소정근로시간 도출에 쓰는 **주 소정근로일수**(work_days 집합 크기)와 다른 값이다). **80% 판정은 반올림하지 않고 출근일수 × 5 ≥ 소정근로일수 × 4 정수 비교**로 한다. 소정근로일수는 연간 달력일에서 법정휴일·주휴일 등(**약정휴일은 v1에 없다** — REQ-ATT-12) 근로제공 의무가 없는 날을 뺀 날이다(REQ-LEV-03) |
| 개근 | 해당 월 소정근로일의 **결근 0일** 상태. **지각·조퇴·외출로 일부만 근로한 날은 결근으로 취급하지 않는다.** 판정 입력은 마감된 근태 결과다 |
| 출근 간주 기간 | 실제 근로가 없어도 **소정근로일수와 출근일수 양쪽에 포함**하는 기간(근로기준법 §60⑥) — 업무상 부상·질병 휴업 · 출산전후휴가 등 · 육아휴직 · 육아기 근로시간 단축분 · 임신기 근로시간 단축분. **뒤 둘은 시행일 2025-10-23 이후 기간에만 적용**하므로 기간별로 분기한다(REQ-LEV-04) |
| 비례 산정 | 단시간근로자의 연차를 통상근로자 대비 비례로 계산하는 처리 — 시간 = 통상근로자 연차일수 × (단시간 주 소정 ÷ 통상 주 소정) × 8 → 일수 = 시간 ÷ 그 직원의 1일 소정근로시간, **0.1일 올림**이다(근로기준법 §18② · 시행령 별표 2). **초단시간(주 15시간 미만)은 제외**한다(REQ-LEV-05) |
| 연차 원장 | leave_transactions의 append-only 이력. 거래 유형은 leave_txn_type 5값(GRANT · USE · RESTORE · EXPIRE · ADJUST)이다. **원장이 진실 원천**이고 요약 잔액은 재계산 가능해야 한다. 발생(leave_grants) · 원장(leave_transactions) · 요약 잔액(leave_balances)의 **3단 구조**이며 사용은 **FIFO**다(REQ-LEV-06) |
| 예약 차감 | 휴가 신청 제출 시점에 잔액을 미리 빼두는 처리(확정 차감이 아니다). 반려·취소 시 복원한다. **예약 차감이 없으면 동시 신청으로 잔액이 음수가 된다**(REQ-LEV-09 · REQ-GLB-15 잠금 대상) |
| 잔여 | leave_balances의 역정규화 요약값. **원장과 불일치하면 조회 API가 경고를 반환하고 관리자 재계산 액션을 제공**한다 — 요약을 진실로 삼지 않는다 |
| 유급 휴가·무급 휴가 | 승인된 **유급 휴가는 근로일·유급일 계산에 포함**하고 결근 판정에서 제외하며 주휴 개근 판정에서도 결근으로 보지 않는다. **무급 휴가·결근은 공제 후보로 급여에 전달**한다(REQ-LEV-11) |
| 연차미사용수당 | 미사용 일수 × 1일 통상임금. 반올림은 지급 항목 올림 1원이다. **5인 미만 법정 미발생 기간은 산출하지 않는다.** **v1은 연차 사용촉진(LEV-07)을 지원하지 않으므로 보상 의무 면제를 적용할 수 없다** — 미사용 연차는 항상 보상 대상으로 계산하고 촉진 미지원 사실을 결과에 표기한다(REQ-LEV-12) |

## 5. 급여·임금

| 용어 | 정의 |
|------|------|
| 급여 항목 | pay_items의 한 행. 코드·이름·유형(EARNING·DEDUCTION)·계산방법(FIXED·RATE·FORMULA·STATUTORY)·과세 여부·통상임금 산입 여부·비과세 한도·정렬 순서를 갖는다. 항목 라인의 합산 순서는 (sort_order, code)로 고정한다(REQ-GLB-06) |
| 세 가지 산입 축 | **과세 여부 · 통상임금 산입 여부 · 최저임금 산입 여부 · 4대보험 보수 포함 여부는 서로 다른 축**이며 하나의 불리언으로 겸용하지 않는다. 이 넷을 하나로 묶는 것이 급여 오구현의 대표 유형이다(REQ-PAY-01 · REQ-PAY-03 · REQ-PAY-26) |
| 통상임금 | **소정근로의 대가로서 정기적·일률적으로 지급하기로 정한 임금**. **'고정성' 요건은 적용하지 않는다** — 2024-12-19 대법원 전원합의체(2020다247190 · 2023다302838)로 폐기되어 재직조건부·근무일수조건부 정기상여도 포함될 수 있다. 평균임금과 다른 개념이며 서로 대체하지 않는다(REQ-PAY-07) |
| 통상임금 규칙 버전 | 통상임금 판단 규칙을 기준값 ORDINARY_WAGE_RULE으로 버전 관리하고 **확정 결과에 동결**하는 장치. 위 판결이 **장래효**라 버전이 없으면 판결 이전 귀속분 재계산이 틀어진다 |
| 주휴시간 | 주휴일에 유급으로 인정하는 시간 — **min(주 소정근로시간, 40) ÷ 40 × 8**이다. **주 15시간 미만은 0**(주휴 미발생)이고 **주 40시간 이상은 8시간으로 상한**한다. divisor의 구성 요소이자 주휴수당의 시간 성분이며 **둘은 같은 비례 축**이라 같은 값을 쓴다 — **소정근로일 개근 주에 한해** 주휴수당 = 주휴시간 × 통상시급으로 분해된다. **결근 주는 주휴시간이 divisor 산정에는 그대로 쓰이되 주휴수당은 0이다** — divisor는 계약상 소정근로의 월 환산이라 실제 개근 여부에 흔들리지 않아야 하고, 주휴수당은 발생 요건을 충족한 주에만 생긴다(발생 요건 정본 REQ-PAY-15). **주휴수당(금액)과 혼동하지 않는다** — 주휴시간은 시간 축이라 divisor·최저임금 환산시급의 분모에 들어가고 금액 반올림 대상이 아니다. 두 곳의 산식이 갈리면 통상시급과 주휴수당이 서로 다른 주휴 기준으로 계산된다. 산식 정본은 [../03_requirements/01_global_rules.md](../03_requirements/01_global_rules.md) §1.2다 |
| divisor | 월 소정근로 환산시간 — **(주 소정근로시간 + 주휴시간) × 365 ÷ 7 ÷ 12**. 통상시급의 분모다. 중간 몫을 반올림하지 않으며 **적용한 divisor를 결과에 함께 보존**해야 통상시급이 재현된다. **주 40시간의 209시간 관행은 확정값이 아니라 기준값**이다(REQ-PAY-08 · §1.2 2번) |
| 주휴 환산시간 | 주휴시간의 **월 환산분**. **별도 산식이 아니라 월 환산 기준시간에 이미 포함된 성분**이며, 월 환산 기준시간 = (주 소정근로시간 + 주휴시간) × 365 ÷ 7 ÷ 12 = **divisor와 같은 산식**이다. **최저임금 환산시급의 분모가 바로 이 월 환산 기준시간**이므로 통상시급과 환산시급은 같은 분모를 공유한다 — 주휴 몫을 따로 계산해 더하는 구현은 이중 계상이다. **주휴시간(주 단위)과 월 환산분을 같은 수로 쓰지 않는다.** 산식 정본은 [../03_requirements/01_global_rules.md](../03_requirements/01_global_rules.md) §1.2 2번·6번이다 |
| 통상시급 | Σ(통상임금 산입 항목의 월액) ÷ divisor. 반올림은 **올림 1원**이다 — 절사하면 모든 가산수당이 과소 지급되고 최저임금 미달 위험이 생긴다. **몫을 중간 변수로 반올림해 재사용하지 않는다는 원칙의 허용된 예외 중 하나**이며(전수·건수의 정본은 [../03_requirements/01_global_rules.md](../03_requirements/01_global_rules.md) REQ-GLB-05), 그래서 divisor 보존이 필수다 |
| 1일 통상임금 | 통상시급 × 1일 소정근로분 ÷ 60. 결근 공제와 연차미사용수당의 단가이며 **퇴직금 하한 비교의 축**이다. 일급(base_wage의 DAILY 단위)과 다른 값이다. **여덟 자리는 항목 최종액 직전의 중간 단가로만 쓰고 퇴직급여 판정만 정수로 저장**하는데, **저장하는 그 자리 때문에 §1.2 #15의 지점이 되고 ordinary_daily_wage 올림 1원이 걸린다** |
| 평균임금 | 산정사유 발생일 이전 **3개월간 임금총액 ÷ 그 기간의 총일수(역일)**. **창은 달력 역산 3개월이고 완결 급여월 3개가 아니다** — 분모가 89~92일로 달라진다. 상여·연차수당 등 연 단위 임금은 3개월분으로 안분해 포함한다(근로기준법 시행령 §2). **1일 통상임금이 평균임금 일액보다 크면 그것을 평균임금으로 본다**(하한 — **비교 축은 둘 다 일액**이며 월액·시급 축이 아니다). 일액은 **반올림하지 않고 numeric으로 유지**하며 퇴직금 최종액에서만 1회 반올림한다. **v1은 개산 수준이며 정밀 안분은 범위 밖**이다(REQ-PAY-09) |
| 기본급 | 급여 유형별로 산식이 다르다 — 월급제는 월 고정액, 시급제는 실근로시간 × 시급, 일급제는 근무일수 × 일급이다. 시급제의 실근로시간은 **마감된 시간 버킷의 raw 실근로분**을 환산해 쓴다(REQ-PAY-10~12) |
| 일할 계산 | 월 중 입·퇴사 등 부분월의 기본급 산출 — **월급 × 재직 역일수 ÷ 해당월 역일수(달력일)**. 곱을 먼저 하고 나눗셈을 나중에 하며 지급 항목 올림 1원이다. 분모는 급여 귀속기간에서 달력으로 결정론적으로 유도되므로 별도 저장 없이 재현된다(REQ-PAY-10) |
| 주휴수당 | 발생 요건은 **주 소정근로시간 15시간 이상 + 그 주 개근**(ISO 주 기준)이다. (주 소정근로시간 ÷ 40) × 8 × 통상시급이며 주 40시간 이상은 8시간으로 상한한다. **사업장 규모와 무관하게 적용**한다(근로기준법 §55①). 미발생 시 사유를 결과에 명시하고, 월급제는 포함 여부를 급여 기준에 명시해 이중 지급·누락을 막는다(REQ-PAY-15) |
| 가산수당 | 연장·야간·휴일 근로에 법정 할증을 더한 임금(근로기준법 §56). **가산율은 하드코딩하지 않고 기준값 PREMIUM_RATE에서 조회**한다. 표제어는 가산수당이며 할증수당·법정수당으로 혼용하지 않는다 |
| 버킷별 지급배수 | 시간 버킷 8종 각각에 대한 실근로분 배수 + 가산 배수의 합. **월급제는 소정근로시간대의 실근로분이 이미 기본급에 포함**되어 있어 추가 지급 배수가 다르다. **휴일 8시간 초과분에 연장 가산을 중복 적용하지 않아 총 배수가 2.5가 아니라 2.0**이며(대법원 2018.6.21. 2011다112391 전합) 이것이 가장 흔한 오구현 지점이다. 표의 정본은 [../03_requirements/07_payroll.md](../03_requirements/07_payroll.md)다 |
| 최저임금 산입범위 | 최저임금 준수 여부를 계산할 때 포함하는 임금의 범위(기준값 MIN_WAGE_SCOPE). **세법상 과세·비과세와 완전히 별개 축**이며 현물·소정근로 외 임금·법령상 미산입 항목을 제외한다(REQ-PAY-26) |
| 환산시급 | 최저임금 비교용으로 환산한 시급 — **월 산입 임금 ÷ 월 환산 기준시간**(= divisor와 같은 산식). 분자와 분모가 **모두 월 단위**여야 비교 축이 맞으며, **분자는 무급공제 반영 전의 소정근로 대가**다 — 분모가 실근로가 아니라 소정근로 기준이라 분자도 결근을 반영하지 않아야 축이 맞는다. **반올림하지 않는다** — 절사하면 미달을 과다 경고하고 **절상하면 실제 미달을 놓친다**. 통상시급과 다른 값이며 서로 대체하지 않는다 |
| 수습 감액 | 수습 기간 임금을 최저임금 미만으로 낮출 수 있는 예외. **3요건을 모두 충족할 때만** 허용한다 — ①1년 이상의 기간을 정한 근로계약 ②수습 시작일부터 3개월 이내 ③한국표준직업분류 대분류 9(단순노무)가 **아닐 것**(최저임금법 §5② · 시행령 §3). 하나라도 미충족이면 감액을 차단하고 100% 지급으로 강제한다 — 편의점·카페 아르바이트는 대부분 감액 불가다(REQ-HRM-09) |
| 급여 기준 | payroll_terms의 한 행. 직원별 기본임금·급여 유형·고정수당·비과세 항목·**지급일**을 유효기간 이력으로 관리한다. 기간 겹침은 DB 제약으로 차단한다. **지급일이 없으면 간이세액표 버전을 결정할 수 없어 소득세 계산이 성립하지 않는다**(REQ-PAY-04 · REQ-PAY-05) |
| 급여 실행 | payroll_runs의 한 행. 한 사업장·한 귀속기간의 계산 단위이며 상태는 payroll_status 4값(DRAFT · CALCULATED · CONFIRMED · VOIDED)이다. 급여 계산·급여 배치로 혼용하지 않는다 |
| 급여 확정 | 급여 실행을 CONFIRMED로 전이하는 처리. **확정은 급여에만 쓰는 말**이며 근태에는 마감을 쓴다. (workplace_id, pay_period) 원본 정규 급여 고유 제약으로 중복 확정을 막고, **CONFIRMED를 CALCULATED로 되돌리지 않는다**. 확정 진행 중에는 해당 기간의 근태·인사 수정을 잠근다(REQ-PAY-27 · REQ-PAY-28) |
| 미리보기 | 확정 전 직원별 예상 지급·공제·실수령을 산출하는 조회. **미마감 근태·기준값 누락·스냅샷 미확정을 차단이 아니라 경고로 표시**하는 것이 확정과 다른 점이다. **미리보기 결과는 잠금·명세서·임금대장에 사용하지 않는다**(REQ-PAY-30) |
| 임금대장 | 근로기준법 §48① · 시행령 §27의 법정 장부. 성명·식별정보·고용 연월일·업무·임금 계산기초·근로일수·근로시간수·연장/야간/휴일 근로 시간수·항목별 금액·공제 내역을 담는다. **5인 미만은 근로시간수와 연장/야간/휴일 근로 시간수 기재를 생략할 수 있다.** 급여대장으로도 부르되 표제어는 임금대장이며 **보존은 마지막 기입일 + 3년**이다(REQ-PAY-31) |
| 퇴직급여 | 퇴직금·DB·DC를 아우르는 추상(severance_plan_type 3값). 대상은 **계속근로 1년 이상 + 4주 평균 주 15시간 이상**이며 **5인 미만 포함 전 사업장 의무**다(근로자퇴직급여보장법 §4①). 퇴직금 개산액 ≈ 평균임금(일액) × 30 × (재직일수 ÷ 365)이고 **지급 기한은 퇴직 후 14일**이다. **v1 범위는 대상 판정 + 개산액 + 기한 경보까지**이며 개산임을 결과에 명시한다(REQ-PAY-33 · REQ-PAY-34) |
| 귀속기간·귀속월 | 급여가 귀속되는 기간과 그 월(payroll_runs.pay_period, 해당 월 1일로 정규화). **보험료·보수월액·비과세 한도·반올림 규칙이 이 축으로 기준값을 조회**한다. 지급일과 다른 축이며 둘을 섞으면 개정 경계에서 값이 틀린다([05_units_and_time.md](./05_units_and_time.md)) |
| 귀속 근로일 | 근로를 제공한 날(work_date). **최저임금·가산율·공휴일·규모 정책·근로시간 한도가 이 축으로 기준값을 조회**한다 — 그 날의 법령이 그 날의 근로를 규율하기 때문이다 |
| 지급일 | 임금을 실제 지급하는 날(pay_date). **간이세액표만 이 축을 쓴다** — 개정 별표는 시행일 이후 지급분부터 적용된다(소득세법 **§134①**). 명세서 보존기간의 기산일이기도 하다. 지급일이 영업일이 아니면 **직전 영업일**에 지급하고, 지정 지급일이 그 달에 없으면(예: 31일 지정에 30일까지인 달) **말일**로 조정한다 |
| 영업일 | 토요일·일요일과 기준값 HOLIDAY_CALENDAR의 관공서 공휴일(**대체공휴일 포함**)을 제외한 날. 지급일 조정의 기준이며 사업장 휴무일·약정휴일과 다른 축이다 — 영업일은 달력 축이고 휴일은 근로 제공 의무 축이라 휴일 가산 판정에 쓰지 않는다. **조정 후 실제 지급일이 간이세액표 버전 선택의 입력**이므로 조정 결과를 결과에 동결한다. 계약 정본은 [../03_requirements/07_payroll.md](../03_requirements/07_payroll.md) REQ-PAY-04이다 |

| 1회용 다운로드 토큰 | 명세서·민감 문서 다운로드에 발급하는 단기 만료·1회 사용 토큰. 세션·IP·user agent 보조 바인딩으로 복사 재사용을 차단하며 만료·재사용은 payslip.download_token_expired/410이다. **명세서와 인사 민감 문서가 같은 규약을 공유**한다(REQ-SLP-08 · REQ-HRM-24) |
| 법정 보존 기산일 | 문서 유형마다 다른 보존기간의 시작점(REQ-GLB-18) — **근로계약서는 근로관계 종료일 + 3년 · 임금대장은 마지막 기입일 + 3년 · 근로자명부는 퇴직일 + 3년 · 명세서는 지급일 + 3년**이다. 근로계약서는 **재직 중 만료되지 않도록** 종료 시점에 확정·연장한다. **기산일 없이 파기 배치를 돌리는 것 자체가 위반**이다 |
| retention_until·retention_basis | 보존 만료일과 기산 근거 코드 컬럼. **retention_until이 NULL이면 미확정이며 파기하지 않는다** — 파기 배치는 NOT NULL이고 기준일보다 이른 행만 대상으로 한다. retention_basis는 EMPLOYMENT_END_PLUS_3Y · LAST_ENTRY_PLUS_3Y · RESIGNATION_PLUS_3Y · PAY_DATE_PLUS_3Y다 |

## 8. 법정 준수·규모

| 용어 | 정의 |
|------|------|
| 5인 분기 | 상시근로자 5인을 경계로 적용 조문이 갈리는 것. 근거는 **상시근로자 스냅샷 단 하나**이며 사업장 속성·수동 플래그·활성 멤버 수로 분기하지 않는다(REQ-GLB-11). 5인 미만이면 연장·야간·휴일 **가산만 0이 되고 실근로분 1.0배는 반드시 지급**한다 — 무급 처리하면 임금체불이다(REQ-PAY-20) |

| 화이트리스트 | 근로기준법 시행령 **[별표 1]은 5인 미만에 적용되는 조문만 열거하는 목록**이라는 사실. **목록에 없으면 미적용**이며, 이를 "적용 제외 목록"(블랙리스트)으로 오해하면 분기가 통째로 뒤집힌다(REQ-GLB-12) |

| 금품청산 | 퇴직 후 **14일 이내**에 임금·퇴직금·연차미사용수당 등 금품을 지급할 의무(근로기준법 §36 · §109). **5인 미만에도 적용**된다. 마감시계를 운영하고 미지급 항목 체크리스트를 제시하며 임박·경과를 일 배치로 경보한다 — **소상공인이 가장 자주 어기는 조항**이다(REQ-PAY-35) |
| 해고예고 | 근로기준법 §26의 예고 의무. **5인 미만에도 적용**되는 조문이며 SIZE_POLICY의 LB-26 키로 관리한다. v1은 규모 정책 등재와 기한 안내까지 다루고 해고 처리 워크플로는 두지 않는다 |
| 연소자 | 만 18세 미만 근로자. birth_date로 **자동 감지**하고 **가족관계증명서(또는 연령 증명서)·친권자 동의서 비치**를 확인한다 — 미비치는 500만원 이하 과태료(근로기준법 §66)이며 hr.minor_document_missing/422로 차단한다. **1일 7시간·주 35시간 한도**와 **야간·휴일 배치 금지**가 적용되며 **제5장(여성과 소년, §64~74)은 규모 무관 적용**이라 5인 미만에서도 동일하게 강제한다(REQ-HRM-26 · REQ-HRM-27 · REQ-ATT-15) |
| 근로자 아닌 자 | 근로기준법 적용 대상이 아닌 자(§11① 단서) — **대표자 본인 · 동거하는 친족만을 사용하는 사업 · 가사사용인**. employees.worker_type 4값으로 구분하고 **상시근로자 산정·법정수당·연차·4대보험 근로자 취급에서 제외**한다. **구분 없이 계산하면 결과가 틀리며** 온보딩에서 해당 여부를 고지·확인받는다(REQ-HRM-28 · REQ-CMP-03) |
| 법정 준수 과제 | compliance_tasks의 한 행. 유형은 compliance_task_type 6값(취득·상실 신고 · 이직확인서 · 금품청산 · 퇴직급여 지급 · 원천징수 신고)이고 상태는 OPEN · COMPLETED · WAIVED다. **임박·경과는 상태로 저장하지 않고 기한(due_date)에서 파생**한다 — 저장하면 배치 재실행 결과가 실행 시각에 의존하게 된다 |
| 신고 기한 캘린더 | 월별·연별 신고 의무 일정을 통합해 사전 알림을 보내는 기능. 최소 포함은 4대보험 취득신고 · 4대보험 상실신고(둘 다 적용 보험 중 가장 이른 기한) · 이직확인서(요청일 + 10일) · 금품청산(퇴직일 + 14일) · 퇴직금 지급(퇴직일 + 14일) · 원천징수이행상황신고(매월 10일) **6종**이다. **기한 감지 배치는 실행 시각이 아니라 기준일 파라미터로 동작**해 재실행 시 동일 결과를 낸다(REQ-TAX-03 · REQ-TAX-04) |

| 동시성 잠금 | 경합을 막는 트랜잭션 잠금(행 잠금 또는 advisory lock). 최소 대상 6종은 같은 근태 건의 동시 승인 · 급여 확정 중 근태·인사·휴가 수정 · 같은 (workplace_id, pay_period)의 동시 확정 · 연차 원장 동시 차감 · 초대 수락 시 인원 한도 재검증 · 사업장 등록 시 소유 한도 재검증이다. **멱등키로 대체할 수 없다**(REQ-GLB-15) |
| 감사 로그 | audit_logs의 행. 행위자·역할·액션·대상·전후값·**사유**·IP를 **INSERT 전용**으로 기록한다. **before/after에 PII 원문을 저장하지 않는다**(마스킹 값·참조 ID·변경 분류만). 사유 필수 액션은 **전수 17종**(정본 [../05_database/15_system.md](../05_database/15_system.md) — 제재 · 역할 변경 · PII 복호화 · 급여 VOID/정정 · 기준값 변경 · 감사 내보내기 · **사업장 폐쇄**(자발·강제) · 최저임금 미달 강행 · 스냅샷 확정·정정 · 임포트 확정 · 근태 마감·재오픈·무효화 · 자기포함 급여 확정 · SUPER_ADMIN 부트스트랩 · 민감 문서 다운로드 · 원좌표 파기 실행 · **계정 구독 수동 조정** · **민감 목록 내보내기**)이다 |
| 목록 내보내기 | 관리자 웹 · 시스템 웹의 목록 표를 **화면에 걸린 검색 · 필터 · 정렬 · 표시 열 그대로** 서버가 XLSX로 만들어 내려보내는 것(DSH-06). 발급은 **조건을 1회용 토큰에 봉인**하고 파일은 **내려받는 순간** 만든다 — 파일을 저장하지 않는다. 열은 목록이 선언한 화이트리스트 안에서만 고르고 주민등록번호는 선언하지 않는다. **민감 목록**(개인 식별 · 연락 · 임금 · 신고 정보가 한 파일에 모이는 목록)은 사유가 필수이고 list.export_sensitive로, 그 밖은 list.export로 감사에 남는다. 임금대장 · 근로자명부 · 신고자료 · 감사 로그의 **전용 내보내기와 다른 것**이다 — 그쪽은 법정 서식이나 별도 계약을 갖는다 |
| 감사 action 키 | audit_logs.action에 쓰는 {domain}.{verb} 문자열(pii.decrypt · payroll.void · workplace.suspend). **에러 코드가 아니다** — HTTP 상태를 갖지 않으며 성공한 행위의 기록이다([02_error_codes.md](./02_error_codes.md)) |
| 정기작업 | 일정에 따라 자동 실행하는 서버 작업. 이름은 camelCase 동사구이며(expireInvitations · autoUnsuspendAccounts · checkSubscriptionExpiry · retryPayslipAndPush 등) **v1 필수 8건**의 정본은 [../02_features/15_scheduled_jobs.md](../02_features/15_scheduled_jobs.md)다. 크론·배치잡으로 부르지 않는다 — **배치라는 말은 실행 방식을 설명할 때만** 쓴다. 모든 정기작업은 멱등해야 하고 분산락으로 중복 실행을 막으며 **실행 시각이 아니라 기준일 파라미터로 동작**한다 |
| SSE | 서버가 클라이언트로 알림을 밀어 보내는 단방향 스트림(Server-Sent Events). v1의 실시간 알림 채널이며 **다중 서버 인스턴스 fan-out**을 전제로 한다. **미연결 중 발생분은 재접속 시 목록 조회로 보충**하고 **알림 생성 실패가 원 이벤트를 롤백하지 않는다** — 급여 확정이 알림 실패로 되돌아가서는 안 된다(REQ-NTF-02) |
| 세션 | 관리자 웹·시스템 웹의 인증 컨텍스트. **HttpOnly·Secure 쿠키 + CSRF 토큰**으로 유지하며 access token을 JavaScript에 노출하지 않는다. 직원 앱의 JWT와 다른 방식이며 섞어 쓰지 않는다(REQ-AUT-08) |
| JWT | 직원 앱의 인증 컨텍스트 — access token + refresh token을 기기 보안 저장소에 보관하고 Bearer로 전송한다. 만료 임박 시 refresh로 회전 재발급한다. **CSRF 토큰 검증 대상이 아니다** — 쿠키 자동 전송 채널이 아니기 때문이다 |
| CSRF 토큰 | 웹 세션 채널의 상태변경 요청에 요구하는 토큰. 부재·불일치는 auth.csrf_token_invalid/403이며 **앱 JWT 채널에는 적용하지 않는다**. CORS 위반과 구분한다 — CORS는 브라우저가 프리플라이트에서 막아 응답 본문이 서버에 도달하지 않으므로 전용 에러 코드를 두지 않는다 |
| 데이터 임포트 | import_jobs 단위의 초기 데이터 적재. 유형은 EMPLOYEES · OPENING_BALANCE이며 **VALIDATED 단계까지 아무것도 커밋하지 않는다**. 확정은 OWNER 전용이고 부분 실패는 통과 행만 커밋한 뒤 실패 리포트를 남긴다(REQ-WRK-32 · REQ-WRK-33) |
| 기초값 적재 | 전환 시점 이전의 근태·급여·**연차 잔액**을 적재하는 처리(opening balance). **이미 사용한 연차를 적재할 경로가 없으면 잔액이 0부터 시작해 연차 계산이 처음부터 틀린다.** 적재분은 source = IMPORT로 표시하고 **명세서 자동 생성 대상에서 제외**한다(REQ-WRK-34 · REQ-LEV-07) |
| 알림 타입 카탈로그 | notification_types lookup. 코드·우선순위·딥링크 대상·표시 문구 키·민감정보 포함 금지 여부·**필수 여부**·활성 여부를 관리한다. **미사용 타입은 삭제하지 않고 비활성화**하며 미정의·비활성 타입 생성은 notification.unknown_type/400이다. **법정 교부·보안·계정 정지·사업장 정지 알림(필수 4종)은 어떤 설정으로도 끌 수 없다**(REQ-NTF-05 · REQ-NTF-06) |

용어 수 검산: 계정·권한·테넌시 18 + 사업장·검증 13 + 근태·시간 17 + 휴가·연차 11 + 급여·임금 28 + 공제·세무 14 + 명세서·보존 12 + 법정 준수·규모 11 + 개인정보·위치정보 13 + 플랫폼·기술 17 = **154항목**.

## 표기 규칙

전 문서군이 아래 표기를 그대로 쓴다. **동의어를 만들지 않는다** — 같은 개념에 두 이름이 생기면 검색·대조·검수가 모두 새기 시작한다.

| 대상 | 표기 |
|------|------|
| 테넌트 단위 | **사업장**. 회사·업체·워크플레이스를 쓰지 않는다 |
| 소속 관계 | **멤버십**(관계) · **멤버**(그 관계를 가진 사람). 사업장 소속을 뜻하며 인사 레코드와 구분한다 |
| 고용된 사람 | **직원**. 고용 관계 일반을 가리키는 보통명사이며 **STAFF는 역할 값**이다 — MANAGER도 직원이다 |
| 사업장 역할 값 | **OWNER · MANAGER · STAFF** — 항상 대문자. **ADVISOR는 v1에 두지 않는다**(WRK-13 이월) |
| 플랫폼 역할 값 | **VIEWER · SUPPORT · ADMIN · SUPER_ADMIN** — 항상 대문자. 사업장 역할과 별개 축이다 |
| 요금제 등급 | **FREE · PRO · ULTRA** — 항상 대문자 |
| 표면 명칭 | **직원 앱 · 관리자 웹 · 시스템 웹 · 공개 페이지** 4종으로 고정한다. 모바일앱·어드민·백오피스·랜딩을 쓰지 않는다 |
| 명세서 | **임금명세서**(첫 등장 시 병기) 이후 **명세서**. **급여명세서를 쓰지 않는다** |
| 급여의 확정 | **급여 확정**. 급여 마감을 쓰지 않는다 |
| 근태의 마감 | **근태 마감**. **마감은 근태에만 쓴다** |
| 법령 수치 | **기준값**. 기준율·마스터데이터·설정값을 쓰지 않는다 |
| 규모 산정 | **상시근로자 수 산정** · **상시근로자 스냅샷**. 직원 수·인원 수로 대체하지 않는다 |
| 국세청 확인 | **진위확인**(일치 여부) · **상태조회**(계속·휴업·폐업). 둘을 사업자 조회로 뭉뚱그리지 않는다 |
| 사업장 상태 값 | **PENDING_VERIFICATION · ACTIVE · SUSPENDED · CLOSED** — enum 값은 대문자 원문 그대로 |
| 자동 실행 작업 | **정기작업**. 크론·배치잡을 쓰지 않으며 **배치는 실행 방식을 설명할 때만** 쓴다 |
| 시간 분해 | **시간 버킷**(8종). 8버킷은 개수를 밝힐 때만 병기한다 |
| 식별자 표기 | 코드·경로·테이블/컬럼명·enum 값은 **평문 또는 굵게**. **인라인 백틱을 쓰지 않는다** — 여러 줄 펜스 블록(mermaid 등)만 허용한다 |
| 열거·날짜·변화 | 열거는 가운뎃점( · ) · 날짜는 YYYY-MM-DD · 방향은 → · 수치 변화는 A → **B** |
| ID 형식 | [04_id_conventions.md](./04_id_conventions.md) 규약을 따른다 |
| 시제 | 설계 정본 시제 — "~한다" 평서체 현재형. 미구현·범위 밖은 부정형으로만 쓴다 |
