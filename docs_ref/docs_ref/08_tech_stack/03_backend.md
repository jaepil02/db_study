backend/는 업무 판정의 유일한 소유자다. 인가·계산·확정·발행·정기작업을 전부 서버에서 수행하고, 클라이언트는 결과를 표시할 뿐이다. 웹(web_front)과 앱(app_front)이 같은 REST 표면을 공유하되 인증 축만 다르다 — 웹은 세션 쿠키, 앱은 토큰이다.

데이터베이스 명세(테이블 · 제약 · RLS 정책 · 함수)의 정본은 [../05_database/README.md](../05_database/README.md)이고, API 표면의 정본은 [../06_api/README.md](../06_api/README.md)다. 본 문서는 스택 관점의 구성만 담는다.

**Java 25와 Spring Boot 4.1.1 두 값만 확정 버전이다.** 나머지 백엔드 라이브러리는 2026-09-06 전환에서 레지스트리 버전 대조를 하지 않았으므로 추정 버전을 쓰지 않고, 프레임워크가 관리하는 축은 **Spring Boot 관리 버전**으로, 그 밖은 **구현 착수 시점 최신 안정판 고정**으로 등재한다([README.md](./README.md) 고정 기준).

## 모듈 구조

패키지 루트는 kr.insadesk.backend이고 그 아래 **common · core · modules 3축**이다(ADR-25).

- **common** — 응답 봉투 · 에러 코드 · 페이지네이션 · 멱등키 · 금액과 시간 값 객체 · 자체 검증 애노테이션 같은 횡단 공통이다. **도메인 지식과 인프라 의존을 갖지 않는다** — 이 경계가 순수 함수 계층이 인프라를 의존하지 않는다는 보장의 근거다.
- **core** — 인프라 관심사 **9**종이다.
- **modules** — 문서 도메인 **13**과 1:1이며 각 모듈이 **controller · dto · service · repository 4계층**을 갖는다. 다섯째 계층은 **이름이 둘로 닫혀 있다** — 순수 함수 계층 **calc**와 필터 체인 계층 **security**이며 **어느 모듈이 그 계층을 두는지는 세지 않는다.** 닫는 축이 모듈 목록이 아니라 계층 이름이라 이름을 맞춰 지으면 구조 검사가 자동으로 따라붙는다(실행 규약 정본은 저장소 .claude/rules/backend-architecture.md).

**모듈 수 검산의 대상은 core와 modules다** — common은 단일 횡단 패키지라 모듈로 세지 않는다. 검산: core 9 + modules 13 = **22**.

도메인 13종의 정본은 [../README.md](../README.md) 고정 기준이며 모듈 경계가 이를 그대로 따른다. **패키지를 계층 우선으로 나누지 않는다** — controller를 한 패키지에 모으면 도메인 경계가 구조에 드러나지 않아 모듈 간 직접 호출을 막을 근거가 사라진다(ADR-25).

- 도메인 모듈은 인프라 모듈을 소비하지만 **다른 도메인 모듈의 리포지토리를 직접 부르지 않는다** — 도메인 간 협력은 공개 서비스 인터페이스로만 한다. 급여(payroll)가 근태(attendance) 테이블을 직접 조회하면 마감 잠금 판정이 두 곳에 생긴다. 이 금지와 4계층 건너뛰기 금지는 아키텍처 테스트의 검사 항목이다(ADR-25).
- 급여 계산은 payroll 모듈 안의 **순수 함수 계층**으로 격리한다. 입출력이 값 객체뿐이라 데이터베이스·시각·난수에 접근할 수 없고, 이것이 REQ-GLB-01 결정론을 구조로 강제하는 장치다. **이 계층이 payroll 전용이라는 뜻이 아니다** — 확정된 결과의 근거가 사후에 달라지면 안 되는 계산이면 어느 도메인이든 같은 이름의 계층에 둔다. 파이프라인 정본은 [../04_architecture/06_payroll_engine.md](../04_architecture/06_payroll_engine.md)다.

## 데이터 접근

| 항목 | 내용 |
|------|------|
| 축 분리 | **쓰기와 단순 조회는 Spring Data JPA 단일 축**이고 **복잡 조회(동적 정렬·필터 · 1:N 중첩 매핑 · 재귀 CTE · 대량 집계)만 MyBatis 읽기 전용**이다(ADR-26). **MyBatis를 쓰기 경로에 두지 않는다** — 영속성 컨텍스트가 아직 반영하지 않은 변경을 직접 SQL이 보지 못하는 문제의 성립 조건 자체를 없앤다. 매퍼에 삽입·수정·삭제 구문이 등장하면 아키텍처 테스트가 실패시킨다 |
| 스키마 소유 | 데이터베이스가 정본이고 엔티티는 그 사본이다(D-21이 승계한 D-05의 핵심). 엔티티를 수기로 작성하고 **스키마 자동 생성 설정을 생성이 아니라 검증으로 고정**한다 — 생성으로 두면 정책·배제 제약·부분 인덱스·가드 트리거·보안 정의자 함수가 다음 적용에서 조용히 사라진다 |
| 마이그레이션 | 루트 **db_migration/V{NNNN}__{name}.sql**을 Flyway가 **애플리케이션 프로세스 밖의 선행 실행 단계**에서 번호순 적용한다(ADR-27). db_migration/은 backend/ 밖이라 클래스패스가 아니므로 **파일 시스템 위치로 지정**하고 배포 이미지가 그 경로를 담는다. **적용 이력 테이블은 업무 스키마 밖에 둔다** — 기본값대로 두면 테이블 **61종** 검수 기준이 즉시 깨진다. 하위 provisioning/ · seed/ 는 적용 대상이 아니다. 번호 구간 배치 정본은 [../05_database/10_migrations_seed.md](../05_database/10_migrations_seed.md) |
| RLS 적용 | **데이터소스 프록시가 트랜잭션에 커넥션이 바인딩되는 순간** set_config(name, value, true)로 세션 컨텍스트를 **트랜잭션 지역 설정**으로 주입한다(ADR-28). 값은 바인드 파라미터로 넘긴다. 주입 변수는 **5종**(현재 사용자 · 시스템 컨텍스트 · 트랜잭션 컨텍스트 3 — 초대 수락 · 사업장 폐쇄 · 사업자 재검증)이며 **활성 사업장과 역할은 세션 변수로 싣지 않는다** — 활성 사업장은 경로 변수로 받아 서비스가 판정하고 행의 사업장 열로 평가한다. 두 접근 축이 같은 데이터소스를 지나므로 주입이 한 자리에 걸린다 |
| 주입 우회 차단 | **프록시 밖에서 연결 · 영속성 컨텍스트 · SQL 세션을 직접 얻는 코드를 아키텍처 테스트가 차단**한다. 값의 출처는 인증 컨텍스트 하나이며 요청 스레드 밖(비동기 · 실시간 팬아웃 · 정기작업)으로 전파되지 않는 것이 기본이므로, 서버 전용 경로는 **명시적 진입점 한 곳**을 쓴다 |
| 트랜잭션 경계 | **모든 업무 쿼리는 트랜잭션 안에서만 실행한다.** 영속성 컨텍스트를 요청 범위로 여는 설정을 끄고 서비스 계층 진입에 트랜잭션 경계를 요구하며, 트랜잭션 밖 쿼리는 아키텍처 테스트가 막는다. 읽기 전용 조회에도 경계가 필요해지므로 **읽기 전용 표시**를 붙여 불필요한 반영을 막는다 |
| 접속 롤 | 애플리케이션 롤은 NOSUPERUSER · NOBYPASSRLS · 비소유자다. RLS를 우회할 수 있는 롤로 접속하지 않는다. 마이그레이션 롤과 애플리케이션 롤을 분리한다 |
| 직접 SQL | 재귀 CTE · EXCLUDE 제약 활용 · 대량 집계는 읽기 축의 매퍼 SQL로 쓴다. **파라미터 바인딩만 쓰고 문자열 치환 표기를 쓰지 않는다** — 동적 정렬 키처럼 치환이 필요한 자리는 허용 목록으로 좁혀 서버가 값을 고른다. 문자열 결합으로 SQL을 만들지 않는다 |
| 신뢰 순서 | 프록시는 **보조선**이고 주 방어선은 FORCE RLS + 우회 불가 롤이다. 프록시가 정상 동작한다는 전제로 서비스 검증을 생략하지 않는다(ADR-08) |
| 커넥션 풀 | 단일 인스턴스 기준 풀 크기를 데이터베이스 max_connections보다 작게 고정한다. 정기작업 워커 몫을 별도로 남긴다 |

### 타입 매핑·역직렬화

**PostgreSQL 타입이 맞아도 값이 부동소수점 타입으로 매핑되면 REQ-GLB-02가 데이터 접근 계층에서 조용히 깨진다.** 원천 규약은 docs_ref2/schema_p0.md의 타입 매핑·역직렬화 절이며, 열 정의의 정본은 [../05_database/README.md](../05_database/README.md)다.

**매핑 계약의 축은 드라이버 설정이 아니라 선언된 자바 타입이다.** JDBC 드라이버의 전역 옵션으로 타입 해석을 바꾸려 하지 않는다 — 두 접근 축이 같은 드라이버를 공유하므로 전역 변경은 의도하지 않은 경로까지 함께 바꾸고, 어느 축이 그 설정을 전제하는지가 코드에서 보이지 않는다.

| PostgreSQL 타입 | 애플리케이션 표현 | 강제 방법 |
|----------------|------------------|----------|
| bigint(금액 · 원) | **long** 또는 문자열 | 엔티티·DTO 필드를 long으로 선언한다. double·float로 받지 않는다. **금액 열에 평균 집계를 걸지 않는다** — 합계·건수는 정수로 오지만 평균은 부동소수점으로 내려온다. 평균이 필요하면 합계와 건수를 받아 서버가 나눈다 |
| numeric(비율 · 평균근로자수 · 휴가일수 · 평균임금 · 환산시급) | **BigDecimal** 또는 문자열 | 스케일을 컬럼 정의와 맞춰 선언한다. **부동소수점에서 BigDecimal을 만드는 생성·변환 호출을 쓰지 않는다** — 문자열이나 정수에서만 만든다. double·float로 되돌리지 않는다 |
| integer(기간 · 분) | **int** | 시·분 환산 과정에서 소수 타입을 거치지 않는다 |
| date(근무일 · 급여월 · 효력일) | **LocalDate** | **java.sql.Date · java.util.Date를 쓰지 않는다** — 시간대를 끌고 들어와 KST 일자가 하루 밀린다. LocalDate는 시간대를 갖지 않으므로 문자열 우회가 필요 없다(ADR-17 개정). 응답 직렬화는 ISO 8601 날짜 문자열이다 |
| timestamptz | **OffsetDateTime** | 응답 직렬화는 UTC 고정 ISO 8601이다. 표시 환산은 클라이언트가 한다 |
| jsonb 안의 동결 수치 | **문자열** | 확정 결과에 동결하는 금액·비율은 문자열로 담는다(D-17). JSON 수치로 담으면 직렬화·역직렬화 왕복에서 부동소수점으로 내려앉아 재출력 값이 원본과 갈린다 |

- 기동 스모크 테스트의 검증 대상은 설정값이 아니라 **실제 반환값의 자바 타입**이다 — 금액이 long인지, 비율이 BigDecimal인지, date가 LocalDate인지, 구형 날짜·시각 타입이 어느 경로에도 없는지를 단언한다. 급여 골든 케이스가 이 규약을 회귀 검증한다([05_tooling_devops.md](./05_tooling_devops.md)).
- 금액·비율 경로의 float · double 사용과 부동소수점에서 십진 타입을 만드는 호출은 **정적 분석 규칙**으로 차단한다. **다만 타입 선언 검사는 집계 반환 타입까지 닿지 않으므로 금액 열 평균 집계 금지를 같은 규칙 안의 판정 항목으로 하나 더 둔다** — 규칙 수는 **4종** 그대로다([05_tooling_devops.md](./05_tooling_devops.md)).

### 십진 연산

| 항목 | 표현 | 내용 |
|------|------|------|
| 금액 | long(원) | 중간 단계에서 반올림하지 않는다. 항목별 최종 금액에서 1회만 단수 처리한다 |
| 비율·요율 | BigDecimal | 요율·세액표·한도는 기준값 테이블 조회값만 쓴다. 코드에 상수로 박지 않는다 |
| 시간 | int(분) | 시·분 환산 과정에서 소수를 만들지 않는다 |
| 나눗셈 | BigDecimal | **스케일과 반올림 모드를 호출마다 명시한다.** 둘을 생략한 나눗셈은 무한소수에서 예외로 끝나므로, 그 예외를 우회하려 부동소수점으로 갈아타지 않고 나눗셈 지점을 규칙표에서 확인한다. 나눗셈 지점과 반올림 키는 [../03_requirements/01_global_rules.md](../03_requirements/01_global_rules.md)가 전수 열거하며 열거되지 않은 나눗셈을 도입하지 않는다 |

**IEEE754 부동소수점 연산을 어떤 경로로도 쓰지 않는다.** 표시용 파생값도 예외가 아니다 — 화면에서 계산한 값과 서버 확정값이 어긋나면 사용자는 어느 쪽이 맞는지 알 수 없다.

## 인증·세션

| 항목 | 표면 | 내용 |
|------|------|------|
| 세션 | web_front | Spring Session Data Redis + Spring Security 필터 체인. 쿠키는 HttpOnly · Secure · SameSite=Lax · Domain=.{domain}(D-03). 로그인 성공 시 세션 식별자를 재생성한다. CSRF 토큰을 상태 변경 요청에 요구한다 |
| 토큰 | app_front | JOSE 라이브러리로 발급·검증한다. access + refresh 2종이며 Authorization 헤더로 전송한다. 폐기는 Redis 블랙리스트다 |
| 재인증 | 양쪽 | 민감정보 평문 열람·중요 설정 변경 전 단기 재인증 토큰을 요구한다. 토큰은 Redis에 두고 데이터베이스에 저장하지 않는다 |
| 인가 | 양쪽 | Spring Security 필터 체인과 메서드 수준 인가가 1차로 멤버십·역할·활성 사업장 스코프를 검증하고, PostgreSQL RLS가 2차 심층방어로 행 단위 격리를 강제한다(ADR-08) |

**Spring Security를 쓰되 자격 증명 전략 계층을 그 위에 얹지 않는다.** 소셜 로그인·외부 OAuth 프로바이더가 없어 자격 증명은 로컬 하나뿐이고, 실제 분기는 "세션 쿠키냐 토큰이냐"라는 표면 축이다. 전략 계층 라이브러리를 얹으면 이 표면 분기가 전략 콜백 안으로 숨어 필터 체인만 보고는 어느 경로가 어떤 자격 증명을 신뢰하는지 읽을 수 없게 된다. **표면별 필터 체인 2벌을 명시적으로 선언**하고 세션 인증과 토큰 인증을 각 체인 안에서 조립한다 — 프레임워크를 필터 체인과 인가 결정 지점으로 쓰는 것과 그 위에 추상 계층을 하나 더 얹는 것은 다른 선택이다(ADR-05 개정).

계약 상세(만료·회전·강제 로그아웃·다기기)의 정본은 [../04_architecture/02_authn_session.md](../04_architecture/02_authn_session.md)다.

| 요청 검증 | 컨트롤러 진입에서 DTO에 선언된 제약을 검증한다. 위반은 전역 예외 처리기가 에러 규격으로 정제해 내려보낸다 |
| 미선언 필드 | 스키마에 없는 키는 통과시키지 않는다 — 역직렬화에서 미선언 속성을 실패로 다루고 관대한 기본값을 두지 않는다 |
| 수치 필드 | 금액·비율은 문자열로 받아 문자열로 검증하고, 도메인 경계에서 long · BigDecimal로 변환한다. 요청 바인딩 단계에서 부동소수점 타입으로 파싱하지 않는다(REQ-GLB-02) |
| 반복 규칙 | 금액 문자열 · 사업자등록번호 · 기간 겹침처럼 반복되는 규칙은 **자체 제약 애노테이션**으로 common에 둔다. 같은 규칙을 도메인마다 다시 쓰지 않는다 |
| 응답 계약 | 응답 DTO의 같은 선언에서 OpenAPI 문서가 생성되므로 **선언과 생성물이 갈리지 않게 할 책임이 DTO 한 곳에 모인다**(ADR-10 개정). 손으로 쓴 스키마를 병행하지 않는다 |
| 최종 판정 | 형식 검증은 Bean Validation이, 업무 규칙은 서비스 계층이, 무결성은 데이터베이스 제약과 RLS가 판정한다. 세 층 중 하나를 다른 층의 대체로 쓰지 않는다 |

## OpenAPI와 프론트 타입 생성

```plain
backend/ 컨트롤러·DTO 선언(검증 애노테이션 포함)
  → springdoc-openapi(문서 버전 3.1.0 명시)
  → backend/openapi.json (Gradle 태스크 산출물)
  → openapi-typescript 7.13
  → web_front/src/lib/api/schema.d.ts · app_front/src/lib/api/schema.d.ts
```

- **문서 버전 3.1.0을 명시 설정한다.** 기본값에 기대면 표현 일부가 3.0 어휘로 내려앉아 생성 타입이 실제 계약보다 느슨해진다.
- **문서 생성을 빌드 산출물로 고정한다.** 실행 중인 애플리케이션에서 문서를 받아오는 경로만 두면 CI가 매번 애플리케이션을 기동해야 하므로, 생성 단계를 Gradle 태스크로 두고 결과를 파일로 떨어뜨린다.
- 생성물은 각 클라이언트 저장소에 커밋한다. 생성 스크립트·CI 검증 절차의 정본은 [05_tooling_devops.md](./05_tooling_devops.md)다.
- 생성 타입은 요청·응답의 **형태**만 담는다. 권한·페이지네이션·에러 코드 계약의 정본은 [../06_api/01_conventions.md](../06_api/01_conventions.md)와 [../09_glossary/02_error_codes.md](../09_glossary/02_error_codes.md)다.
- 손으로 쓴 타입과 생성 타입을 병행하지 않는다.

## Redis 키 네이밍

키 형태는 **insadesk:{용도}:{식별자}**다. 세그먼트 구분자는 콜론이고 용도 세그먼트는 lower_snake이며 식별자(UUID · 해시 · 토큰 식별자)는 원문을 유지한다. 접두 insadesk를 두는 이유는 하나의 Redis 인스턴스를 다른 용도와 공유해도 키가 섞이지 않게 하기 위함이다.

| 용도 세그먼트 | 형태 | 담는 것 | 수명 |
|------|------|--------|------|
| session | insadesk:session | 웹 세션 스토어 네임스페이스 | 세션 수명 |
| blacklist:access | insadesk:blacklist:access:{jti} | 앱 access 토큰 폐기 표시 | **토큰 잔여 수명** |
| reauth | insadesk:reauth:{토큰 SHA-256 hex} | 재인증 토큰 바인딩 | **5분 · 1회 소비** |
| channel | insadesk:channel:user:{userId} · insadesk:channel:workplace:{workplaceId} | 실시간 팬아웃 **채널명**(키가 아니다) | — |
| lock:schedule | insadesk:lock:schedule:{환경}:{작업명} | 정기작업 분산락 | lockAtMostFor |
| ratelimit | insadesk:ratelimit:{축}:{대상} | rate limit 카운터 | 창 길이 |
| download | insadesk:download:{토큰 SHA-256 hex} | 1회용 다운로드 토큰 바인딩 | **5분 · 1회 소비** |
| retry | insadesk:retry:notification | 알림 생성 실패분 재시도 큐 | 재시도 정기작업이 비운다 |

검산: ADR-11이 한정한 Redis 채택 범위 5종(세션 · 블랙리스트 · 재인증 · 채널 · 락) + rate limit 1 + 다운로드 토큰 1 + 재시도 큐 1 = **8**. 뒤의 셋은 ADR-11의 열거에 없으나 각자 다른 문서가 Redis 보관을 규정한다 — rate limit은 이 문서의 위 절, 1회용 다운로드 토큰은 [../04_architecture/10_realtime_files.md](../04_architecture/10_realtime_files.md), 알림 재시도 큐는 [../05_database/13_notification.md](../05_database/13_notification.md)와 REQ-NTF-02다. **열거 밖의 세그먼트를 만들려면 그 근거 문서를 먼저 갖는다** — 세그먼트를 닫아 두는 것은 업무 데이터 캐시를 막기 위한 것이지 근거 있는 새 용도를 막기 위한 것이 아니다.

- **업무 데이터 캐시 세그먼트를 만들지 않는다.** RLS 판정을 거치지 않은 값이 캐시에 남으면 격리가 캐시 계층에서 뚫린다. 용도 세그먼트를 8종으로 닫는 것이 ADR-11의 "업무 캐시로 쓰지 않는다"를 키 공간에서 강제하는 자리다.
- **키에 비밀값 원문을 담지 않는다.** 재인증 토큰은 클라이언트가 자격 증명으로 들고 있는 값이므로 SHA-256 hex로 바꿔 넣는다 — Redis를 읽을 수 있는 주체가 그 값을 그대로 재사용할 수 있으면 저장 자체가 자격 증명 유출이다. 반대로 jti는 비밀이 아니라 토큰 식별자이므로 원문을 넣는다. **가르는 기준은 그 값으로 인증이 되느냐이지 길이나 형태가 아니다.**
- **세션 스토어의 프레임워크 기본 접두는 이 규약 밖이다.** 세션 구현이 자기 네임스페이스(spring:session) 아래에 키 구조를 만들므로, 애플리케이션 설정에서 네임스페이스를 insadesk:session으로 지정해 규약을 한 축으로 맞춘다. 지정하지 않으면 세션만 다른 키 공간에 남는다.
- **스케줄 락의 환경 세그먼트는 락 구현이 접두와 작업명 사이에 끼운다.** 하나의 Redis를 여러 환경이 공유하면 작업명이 겹치기 때문이다. 현재 값은 구현 기본값이고 설정 축으로 바인딩하는 것은 core/config의 자리다.
- 채널은 키가 아니라 Pub/Sub 채널명이라 만료를 갖지 않는다. 사용자·사업장 스코프 분리가 **서버 내부 개념**이라는 계약은 위 SSE 절이다.
- 빈 세그먼트와 구분자를 품은 식별자를 거부한다. 식별자가 콜론을 품으면 키 공간이 조용히 한 단계 깊어져 다른 용도의 키를 밟는다.

**이 절이 규약의 정본이다.** backend의 core/redis 상수(경로 backend/src/main/java/kr/insadesk/backend/core/redis/RedisKeys.java)가 문자열을 조립하는 유일한 자리이며, 키 문자열을 다른 자리에서 다시 조립하지 않는다.

## PDF 생성

| 항목 | 내용 |
|------|------|
| 대상 | 임금명세서(SLP-01) · 근로계약서 교부본(HRM-07) |
| 방식 | 서버 HTML 템플릿(Thymeleaf)을 headless Chromium(Playwright for Java)이 렌더해 PDF로 출력한다 |
| 근거 | 명세서는 법정 필수항목을 담은 표 레이아웃이고 관리자 웹 미리보기와 같은 템플릿을 공유해야 한다. 좌표·셀 폭을 코드로 조립하는 PDF 라이브러리는 항목이 늘 때마다 레이아웃을 다시 맞춰야 하고 한글 폰트 임베딩·줄바꿈을 라이브러리 규약대로 따로 해결해야 한다 |
| 폰트 | 컨테이너 이미지에 한글 폰트를 포함한다. 렌더 시점에 외부 폰트를 내려받지 않는다. **담는 것만으로는 부족하다** — 브라우저 설치가 끌고 온 중문 서체가 fontconfig 우선순위에서 앞서면 PDF가 **생성에 성공하면서 중문 자형으로 렌더된다**. 이미지가 매칭 규칙을 명시해 총칭 서체(sans-serif · serif · monospace)와 템플릿 논리명(Noto Sans KR)을 한국어 자형에 결속한다. 확정값은 아래 이미지 구성 절 |
| 자원 통제 | 브라우저 인스턴스는 pdf 모듈이 풀로 관리하고 **동시 실행 수에 상한**을 둔다. 요청마다 브라우저를 새로 띄우면 메모리가 인스턴스 한도를 넘긴다 |
| 실행 위치 | 명세서 대량 생성은 요청 응답 경로가 아니라 일괄 실행 경로에서 수행한다. 실패분은 정기작업이 재시도한다 |
| 저장·배포 | 생성물은 S3에 두고 **1회용 다운로드 토큰 + 서버 스트리밍**으로만 내려준다. 공개 URL을 만들지 않고 저장소 서명 URL을 클라이언트에 전달하지 않는다(ADR-16) |

| init | tini (PID 1) | Chromium이 렌더마다 남기는 자식 프로세스를 거둔다. 없으면 프로세스 표가 컨테이너 수명 내내 자란다 |
| 브라우저 | Playwright가 이미지 빌드 시점에 설치 | 런타임에 내려받으면 첫 명세서 발행이 외부 가용성에 걸린다. 의존 라이브러리도 Playwright가 선언한다 — 목록을 우리가 열거하면 베이스 배포판이 바뀔 때마다 따라다녀야 한다 |
| 한글 폰트 | fonts-noto-cjk + **매칭 규칙 파일** | 규칙 파일은 conf.d/52에 둔다. **번호가 계약이다** — 총칭 서체의 우선순위는 60번대에서 정해지므로 그보다 늦으면 규칙이 진다 |
| 실행 권한 | **cap-add=SYS_ADMIN** | Chromium 샌드박스를 켠 채로 돌리기 위한 것이다. 컨테이너 기본 seccomp가 사용자 네임스페이스 생성을 막아 샌드박스가 서지 못하고, 그때 브라우저는 **기동 자체를 거부한다** |

- **샌드박스를 끄는 것과 실행 권한을 주는 것은 다른 선택이다.** 끄면 렌더 대상 HTML이 컨테이너 안에서 임의 코드로 이어질 표면이 열린다. 권한을 주면 샌드박스가 실제로 서고 그 표면이 닫힌 채로 남는다.
- **한글 폰트 부재는 렌더 오류가 아니라 조용한 오식이다.** 생성은 성공하고 파일도 정상이라 실패로 드러나지 않는다 — 이미지에 담고 매칭을 확정하는 것 말고 사후에 알아챌 자리가 없다.

## 발송 경로

v1의 발송 채널은 **인앱 알림과 메일 2종**이다. 검산: 인앱 1 + 메일 1 = **2**.

| 항목 | 수단 | 내용 |
|------|------|------|
| 인앱 알림 | SSE + Redis Pub/Sub | 알림 목록의 정본은 서버다. 전달 실패가 기록 누락이 되지 않게 저장을 먼저 하고 발행한다 |
| 메일 | Spring Boot Mail + SMTP | 명세서 교부·계약서 교부·기한 안내. 발송 이력을 기록해 교부 의무 이행 증빙으로 쓴다 |
| 푸시 | **v1 범위 밖** | 푸시 알림(NTF-02)은 v1.1 이월이다. 발송 모듈·토큰 저장 구조·발송 자격을 만들지 않는다 |
| 문자(SMS) | **v1 범위 밖** | 문자 대체 발송은 v1 알림 범위 밖이다. 도입 시 **발송 어댑터 인터페이스 + HTTP API 호출**로 붙이고 사업자 SDK를 코드에 직접 박지 않는다. 사업자 선정은 계약·요율이 걸린 조달 사안이며 선정 기준은 국내 사업자 · 발신번호 사전등록 지원 · HTTP API 제공 · 발송 결과 조회 지원 **4가지**다 |

- 모든 발송은 멱등키를 가진다. 재시도가 중복 발송이 되지 않게 한다.
- 발송 본문에 개인정보를 담지 않는 규칙은 채널 공통이다. 상세는 [../10_security/04_pii_protection.md](../10_security/04_pii_protection.md).
- 앱 미설치·미로그인 직원에 대한 도달은 도메인별 대체 경로가 담당한다(명세서는 이메일 교부 — SLP-06). 알림 채널 범위의 정본은 [../02_features/10_notification.md](../02_features/10_notification.md)다.

## 미지정 구현 영역 지정

계약만 서술되고 구현 수단이 비어 있던 영역을 지정한다. 버전이 적히지 않은 항목은 **Spring Boot 관리 버전** 또는 **구현 착수 시점 최신 안정판 고정**이다.

| 영역 | 지정 | 단서 |
|------|------|------|
| 마이그레이션 적용 | **Flyway**(애플리케이션 프로세스 밖 선행 단계) | 자체 러너를 두지 않는다(ADR-27). 파일 시스템 위치 지정 · 이력 테이블은 업무 스키마 밖 · provisioning/ 과 seed/ 는 적용 대상 아님. 계약 정본은 [../05_database/10_migrations_seed.md](../05_database/10_migrations_seed.md) |
| 시드 적용 | **기동 경로 밖의 명시적 실행** | 기준값 시드는 확인 절차를 동반하므로 마이그레이션과 같은 자동 경로에 두지 않는다. 미확인 기준값을 임의로 채우지 않는다 |
| 스케줄 락 | **ShedLock** + Redis 락 저장소 | 스케줄 등록 지점에 물린다. 업무 경합은 트랜잭션 잠금이 담당한다(ADR-13) |
| 구조화 로그 | **SLF4J · Logback** + JSON 인코더 | JSON 단일 형식. 관측 범위의 정본은 ADR-23 |
| 에러 추적 | **Sentry Spring Boot 스타터** | 관측 범위는 구조화 로그 + 에러 추적으로 좁힌다(ADR-23) |
| 비밀번호 해싱 | **Spring Security 비밀번호 인코더**(argon2id) | 파라미터는 OWASP 권고 조합을 채택하고 값의 정본은 [../10_security/01_authn_authz.md](../10_security/01_authn_authz.md)에 둔다 |
| PII 필드 암호화 | **JCA AES-256-GCM** + HMAC 블라인드 인덱스 | 별도 암호화 라이브러리를 두지 않는다. 키 버전·논스 관리 계약의 정본은 [../10_security/04_pii_protection.md](../10_security/04_pii_protection.md) |
| rate limit | **Bucket4j** + Redis 저장소 | 인스턴스 메모리 저장을 쓰지 않는다. 축·한도의 정본은 [../04_architecture/02_authn_session.md](../04_architecture/02_authn_session.md) |
| CSRF | **Spring Security의 CSRF 토큰**(세션 결합) | 직접 구현하지 않는다. 상태 변경 요청에서 토큰을 대조하고 세션 무효화와 함께 회전시킨다 |
| 환경변수 검증 | **설정 속성 바인딩 + Bean Validation** | 기동 시 검증하고 누락이면 부팅을 실패시킨다. 개별 주입 지점에서 값을 읽지 않는다 |
| 보안 헤더 | **Spring Security 헤더 설정**(애플리케이션) + nginx(전송 계층) | 두 계층의 역할 분담은 [04_data_infra.md](./04_data_infra.md) |
| 파일 업로드 | **Spring Multipart** + 자체 매직넘버 검증 | 확장자·선언 MIME을 신뢰하지 않고 허용 4계열의 시그니처를 서버가 확인한다 |
| CORS | **Spring Security CORS 설정** | 허용 오리진 1개 · 자격 증명 허용(D-03) |
| 국세청 사업자등록 API | **RestClient**(프레임워크 표준 동기 HTTP 클라이언트) | 별도 HTTP 클라이언트 라이브러리를 두지 않는다. 타임아웃·재시도·PENDING 폴백 계약의 정본은 [../04_architecture/07_batch_scheduling.md](../04_architecture/07_batch_scheduling.md) |
| Chromium 브라우저 풀 | **브라우저 재사용 · 동시 상한 2 · 주기 재기동** | 요청마다 브라우저를 띄우지 않는다. **샌드박스 비활성화 옵션을 쓰지 않는다** — 대신 컨테이너에 실행 권한을 준다(아래 이미지 구성 절). 좀비 프로세스 정리용 init 프로세스를 두고 한글 폰트 패키지와 매칭 규칙을 포함한다. **상한 수치는 부하 실측 후 확정**한다 |
| PDF 템플릿 엔진 | **Thymeleaf** + 공유 CSS 토큰 | 웹 컴포넌트를 서버에서 재사용하지 않는다 — 재사용하면 웹 빌드 산출물이 백엔드 빌드에 묶인다. 공유하는 것은 디자인 토큰 CSS까지다 |
| 백엔드 시각·시간대 | **java.time**(LocalDate · OffsetDateTime · ZoneId) | 시간대를 끌고 들어오는 구형 날짜·시각 타입을 쓰지 않는다. 프로세스 시간대 고정 계약은 ADR-17 |
| XLSX·CSV | **Apache POI** | 대량 시트는 스트리밍 방식으로 쓴다. 착수 시 유지보수 상태를 재확인한다 |
| 헬스체크·그레이스풀 셧다운 | **Spring Boot Actuator** | DB·캐시 연결이 성립해야 준비 상태로 보고한다. 종료 시 진행 중인 요청과 PDF 렌더를 마치고 내려간다 |
| 구조 검사 | **ArchUnit** | 모듈 간 리포지토리 직접 호출 · 4계층 건너뛰기 · 프록시 밖 연결 획득 · 트랜잭션 밖 쿼리 · 읽기 축 매퍼의 쓰기 구문을 검사한다(ADR-25 · ADR-26 · ADR-28). **매퍼 SQL의 도메인 경계 침범은 검사 대상이 아니다** — 자바 참조를 읽으므로 문자열 안의 조인 대상이 보이지 않는다(ADR-26 파급) |
