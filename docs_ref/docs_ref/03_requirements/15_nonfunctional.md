기능 요구사항(REQ-{도메인})과 별개로 **전 시스템이 충족해야 할 품질 목표(REQ-NFR)**와 **기술·운영 요구사항(REQ-TEC)**을 정의한다. 검증 수단이 없는 정성 목표를 두지 않고 **측정·조회·산출물 확인으로 참·거짓을 가릴 수 있는 조건**으로만 서술한다.

**수치는 [../04_architecture](../04_architecture/README.md)의 정본과 같은 값**이다. 어긋나면 아키텍처 정본을 고친 같은 변경 단위에서 본 문서를 함께 고친다 — 성능 예산은 [../04_architecture/05_rendering_seo.md](../04_architecture/05_rendering_seo.md), rate limit은 [../04_architecture/02_authn_session.md](../04_architecture/02_authn_session.md), 백업·로그 보존은 [../04_architecture/08_deployment_topology.md](../04_architecture/08_deployment_topology.md)가 정본이다.

접근 권한 열의 값 정의는 [README.md](./README.md) 접근 권한 표기 절을 따른다. 비기능 요구사항은 대부분 **서버**(요청 처리 중 서버가 강제·산출) 또는 **시스템**(사용자 요청 없이 성립해야 하는 조건)이며, 사용자가 체감하는 항목만 **본인**으로 표기한다.

| REQ-TEC-09 | 정기작업 운영 요건 | 정기작업 **8건**을 시각 표현식으로 등록하고 프로세스 시간대를 **Asia/Seoul**로 고정한다. 작업 이름별 **분산락**을 획득한 실행만 진행하며 인스턴스가 하나여도 락을 생략하지 않는다. 각 작업은 **멱등**하고 대상 일자를 인자로 계산해 재실행이 같은 대상을 잡게 한다. 항목 단위로 실패를 격리하고 **재시도 상한 5회 · 지수 백오프 1분 → 2 → 4 → 8 → 16분**을 적용하며, 상한 초과 시 **실패 상태를 유지 + dead_letter_at 기록 + 운영 통보**를 수행하고 재시도 대상에서 제외한다(재개는 담당자의 명시 조작) — **조용한 성공 처리를 하지 않는다**. 실행 이력·재시도 회차·dead_letter_at의 물리 저장처는 **scheduled_job_runs**(테이블 60)이며, 작업명 분산락은 그 테이블의 부분 UNIQUE (job_name, base_date) WHERE status IN ('RUNNING','SUCCEEDED')가 백스톱한다. 이 수치는 **설계 재량값이며 기준값 테이블 대상이 아니다**(법정값이 아니다). **운영 통보의 수단은 인앱 알림이 아니라 관측 채널**(에러 추적·로그 경보 — ADR-23)이다. 수신자가 사용자가 아니라 운영자이고 notifications는 recipient_user_id 축이라 운영자 집단을 담을 수 없기 때문이다(REQ-NTF-05). 다만 **사용자의 업무가 멈추는 사건**(사업장 자동 정지 등)은 그와 별개로 인앱 필수 알림을 함께 보낸다. 실행 이력에 시작·종료 시각·대상 수·성공/실패 수·실패 사유를 남긴다. 작업 간 실행 순서에 의존하지 않는다 | 시스템 | P0 |
| REQ-TEC-10 | 배포 파이프라인·품질 게이트 | 푸시·풀 리퀘스트에서 **락 파일 그대로 설치 → 타입 검사 → 정적 분석 → 테스트 → API 타입 차이 검사** 순으로 공통 게이트를 실행하고 실패 시 배포 산출물을 만들지 않는다. 웹은 저장소 연동 자동 배포가, 서버는 이미지 레지스트리 경유 재기동이 담당한다. 앱은 검사까지만 수행하고 **스토어 배포 자동화를 v1에 두지 않는다**. **무중단 배포를 v1에 두지 않으며** 배포 창을 업무 시간 밖으로 둔다 | 시스템 | P0 |
| REQ-TEC-11 | 환경 분리·환경변수 | 환경은 **운영 단일 + 로컬 개발**이며 **상시 스테이징을 v1에 두지 않는다**. 운영 환경변수는 호스트 환경 파일과 배포 플랫폼 대시보드에서 관리하고 저장소에는 **키 이름만 담은 예시 파일**을 둔다. **클라이언트 노출 접두가 붙은 변수만 클라이언트 번들에 들어가며** 서버 시크릿을 웹·앱에 두지 않는다 — 앱 번들은 리버스 엔지니어링이 가능하므로 노출돼도 무해한 값만 담는다. **기동 시 환경변수 스키마를 검증해 필수 값 누락이면 부팅을 실패**시킨다. 프리뷰 배포는 실데이터에 접근하지 않는다 | 시스템 | P0 |
| REQ-TEC-12 | 백업 실행·복원 검증 | **논리 백업 일 1회**를 호스트 스케줄로 실행해 서울 리전 오브젝트 스토리지에 업로드하고 서버 측 암호화를 적용한다. **업로드 성공을 백업 성공으로 간주하지 않고** 복원 가능 여부를 정기적으로 확인한다. 보존 일수는 **미확인 — 운영 비용 확정 전 임의 값 고정 금지**이며, 확정 전에도 일일 백업과 장기 보관을 분리해 운영한다. 시점 복구를 v1에 두지 않으므로 **RPO 24시간을 인정**하고 복구 절차에 **손실 구간 파악과 재입력 안내**를 필수 단계로 포함한다(ADR-22) | 시스템 | P0 |
| REQ-TEC-13 | 시드 규약 | 초기 시드 대상은 **요금제 등급과 알림 타입 카탈로그 둘뿐**이며 기준값은 **확인된 값만** 넣는다. **약관·개인정보·위치정보 문서는 시드하지 않는다** — 법무 검토를 거친 본문을 출시 전 운영 절차로 등록하며, **필수 2종(TERMS·PRIVACY)**의 활성 버전이 없으면 가입이 auth.consent_required/422로 차단되는 것이 **정상 동작**이다(LOCATION 부재는 가입을 막지 않는다 — D-19 · REQ-SYS-15). 최초 SUPER_ADMIN도 시드가 아니라 **환경변수 부트스트랩**으로 만든다(정본 [../05_database/10_migrations_seed.md](../05_database/10_migrations_seed.md)) — 관리자 계정을 마이그레이션에 박으면 모든 환경이 같은 계정을 갖게 된다. **미확인 기준값을 임의로 채워 넣지 않는다** — 계산이 차단되는 것이 정상 동작이며, 잘못된 시드는 모든 직원의 공제액을 틀리게 하고 최저임금 미달 사업장을 통과시킨다(REQ-GLB-09). 확인자 필드가 빈 행은 미확인으로 간주한다. 시드는 **멱등**이며 재실행이 중복 행을 만들지 않는다 | 시스템 | P0 |
| REQ-TEC-14 | 개발 환경 데이터 통제 | **운영 데이터를 로컬·개발 환경에 내려받지 않는다.** 주민번호·계좌가 담긴 데이터를 옮기는 순간 그 환경이 유출 경로가 된다 — 개발 환경은 접근 통제·감사·암호화가 운영 수준이 아니다. 로컬은 컨테이너로 데이터베이스·캐시를 띄우고 **운영과 같은 메이저 버전**을 쓰며 시드 데이터만 사용한다. 실데이터가 필요한 검증은 비식별 표본으로 대체한다 | 시스템 | P0 |

검산: REQ-TEC-01 ~ REQ-TEC-14 = **14건**.

본 문서 신설 요구사항 총계 — 검산: REQ-NFR 16 + REQ-TEC 14 = **30건**.

## 에러 코드

본 문서가 참조하는 코드는 전부 다른 도메인이 소유한 **공통 코드**이며 여기서 신설하지 않는다. 전수 정본은 [../09_glossary/02_error_codes.md](../09_glossary/02_error_codes.md)다.

| 에러 코드 | HTTP | 발생 조건 |
|-----------|:--:|----------|
| common.rate_limited | 429 | 인증 경로·일반 API 호출 한도 초과(REQ-NFR-14) |
| common.service_unavailable | 503 | 외부 의존 일시 실패 — 메일·진위확인 API 장애(REQ-NFR-07) |
| common.payload_too_large | 413 | 업로드·임포트 파일 허용 크기 초과 |
| common.validation_failed | 400 | 요청 검증 실패 |

**본 절은 타 도메인이 정의한 코드의 인용이며 여기서 신설하지 않는다.** 채번 정본은 [../09_glossary/02_error_codes.md](../09_glossary/02_error_codes.md)이고 common 7종의 정의처는 [01_global_rules.md](./01_global_rules.md)다.

**분류되지 않은 서버 내부 실패에는 도메인 코드를 두지 않는다.** 카탈로그에서 500을 갖는 코드는 export.failed 하나뿐이므로, 위 표의 어느 분기에도 걸리지 않은 실패는 **500 폴백**으로 응답하고 원문 예외·스택 트레이스는 로그에만 남긴다 — 응답 본문에는 내부 식별자·원문 오류를 싣지 않는다(REQ-GLB-19). 폴백 규칙의 정본은 [../06_api/02_errors.md](../06_api/02_errors.md)의 SQLSTATE·제약 위반 매핑 계약 ⑤단계다.
