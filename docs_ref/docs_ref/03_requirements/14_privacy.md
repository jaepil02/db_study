# REQ-PRV — 개인정보·위치정보 요구사항

> **대상**: 위치정보 이용·제공 사실 확인자료 자동 기록과 조회·파기 · 위치정보 별도 동의 · 버전별 동의 이력 · 동의 철회와 재동의
> **작성일**: 2026-08-03
> **개정일**: 2026-09-08 — 원좌표 파기의 실행 순서를 **"마감 트랜잭션의 자동 후속 처리" → "마감 트랜잭션 안에서 잠금 확정에 선행해 실행한다"**로 고친다(실측 — 그 순서로는 동작하지 않는다). guard_locked_period()가 attendance_records UPDATE를 보고 그 급여월이 LOCKED이면 거부하는데 **잠금 행은 같은 트랜잭션이 방금 쓴 행이라 이미 보인다** — 잠금 뒤에 파기하면 통째로 실패한다. **"후속"이 담으려던 뜻은 유지된다** — 같은 트랜잭션이라 마감이 되돌아가면 파기도 함께 되돌아간다. **그 말이 담으려던 것은 순서가 아니라 같은 트랜잭션 안이었다.** 정기작업 8건 · 파기 계약·감사 축은 전건 불변
> **개정일**: 2026-08-08 — DB 커버리지 감사 반영 — 동의 게이트와 확인자료 선행 기록의 2차 방어(가드·조건부 CHECK) 등재 · 철회 대상을 선택 동의로 한정하는 강제 위치 명시 · 파기 미실행 감지의 운영 점검 축 등재
> **개정일**: 2026-08-08 — 원좌표 파기의 목적 달성 판정 시점(귀속월 근태 마감 확정)과 실행 경로(마감 트랜잭션 자동 후속 · 전용 배치 없음) 확정
> **원천**: docs_ref2/requirements_p0.md PRV 절(REQ-PRV-01~05) · docs_ref2/features_p0.md(PRV 2기능) · docs_ref2/schema_p0.md privacy·auth 테이블

GPS 출퇴근을 제공하는 이상 **위치정보법 §16② 이용·제공 사실 확인자료의 자동 기록·보존 의무는 회피할 수 없다.** 이 기록은 부수 처리가 아니라 **위치정보 처리의 필수 선행 단계**이며, 기록에 실패하면 그 처리 자체를 중단한다.

동의에 관한 원칙도 하나다 — **"동의를 받았다"는 사실만으로는 입증이 되지 않는다. 어느 버전에 언제 동의했는지가 법적 증거다.** 그래서 동의 이력은 append-only이며 철회도 행을 지우지 않고 철회 시각만 기록한다.

**원좌표와 확인자료의 보존 정책은 분리**한다. 목적 달성 시 확인자료를 제외한 개인위치정보(원좌표)는 즉시 파기하고, 확인자료 자체는 법정 보존기간까지 유지한다. 전역 계약은 [01_global_rules.md](./01_global_rules.md)를 전제한다.

## PRV-01 위치정보 이용·제공 사실 확인자료  P0

| 요구사항ID | 요구사항명 | 설명 | 접근 권한 | 우선순위 |
|-----------|-----------|------|----------|----------|
| REQ-PRV-04 | 확인자료 자동 기록 | 개인위치정보를 수집·이용·제공할 때마다 **위치정보법 §16② 확인자료를 자동 기록**한다. 필드는 정보주체(user_id) · 이용·제공 일시 · 이용·제공 목적(예: 출퇴근 지오펜스 검증) · 이용·제공 주체 · 제공받은 자(있는 경우) · 수집 경로다. **기록은 부수 처리가 아니라 위치정보 처리의 필수 선행 단계**이며 **기록 실패 시 해당 처리를 중단**한다 — **GPS 소스 근태에는 확인자료 참조가 반드시 있어야 한다는 조건부 CHECK가 그것을 강제한다**(nullable 참조만으로는 존재가 강제되지 않는다 — 정본 [../05_database/16_privacy.md](../05_database/16_privacy.md)). 근거 동의도 kind = LOCATION인지 가드가 재검증한다. 자동 기록·보존은 서버 전용이고 사용자·관리자 조작으로 삭제·수정할 수 없다 | 시스템 | P0 |
| REQ-PRV-05 | 확인자료 조회 제공·파기 | **정보주체가 본인의 위치정보 이용·제공 사실 확인자료를 조회**할 수 있는 경로를 제공한다(기간 필터·페이지네이션). **목적 달성 시 확인자료를 제외한 개인위치정보(원좌표)는 즉시 파기**하고 확인자료 자체는 법정 보존기간까지 유지한다 — **원좌표와 확인자료의 보존 정책을 분리**한다. **목적 달성의 판정 시점은 해당 귀속월 근태 마감(LOCKED) 확정 시점**이다 — 그 시점에 지오펜스 판정 결과가 근태 레코드에 확정 보존되므로 원좌표의 이용 목적이 달성된다. **실행은 마감 트랜잭션 안에서 잠금 확정에 선행한다**(같은 트랜잭션이므로 마감이 되돌아가면 파기도 함께 되돌아간다 — **묶는 것은 순서가 아니라 트랜잭션이다**. 잠금 뒤에 두면 읽기 전용 가드가 같은 트랜잭션이 방금 쓴 잠금 행을 보고 좌표 갱신을 거부해 마감 자체가 실패한다) 이며 **전용 파기 배치를 두지 않는다**(정기작업 8건 불변 — purgeExpiredData는 v1.1 이월). 파기 실행은 감사 로그를 남긴다(action 코드 attendance_record.purge_coords · 사유 필수). **미실행 감지는 잔여 좌표 부분 인덱스로 좁힌 운영 점검 항목**이며 — 마감된 급여월에 잔여 행이 0인지를 본다 — DB CHECK는 파기했다고 표시한 행의 완결성만 강제한다 | 본인 · 시스템 | P0 |

## PRV-02 동의 이력 관리  P0

| 요구사항ID | 요구사항명 | 설명 | 접근 권한 | 우선순위 |
|-----------|-----------|------|----------|----------|
| REQ-PRV-01 | 위치정보 별도 동의 | 개인위치정보 수집·이용·제공은 **약관·개인정보 동의와 분리된 별도 동의**를 받는다(위치정보법 §18). **동의 없이는 GPS 출퇴근 체크인을 제공하지 않는다** — 미동의 상태의 체크인 요청은 **privacy.location_consent_required/403**으로 차단하고 동의 화면으로 유도한다. **강제는 서비스와 DB 가드 2단이다** — RLS 정책은 본인·멤버십·사업장 쓰기 가능만 보므로 kind = LOCATION이고 철회되지 않은 동의를 재검증하는 가드가 체크인 INSERT에 붙는다(정본 [../05_database/16_privacy.md](../05_database/16_privacy.md)). 동의 시 수집 항목·목적·보유기간을 고지한다 | 본인 | P0 |
| REQ-PRV-02 | 동의 이력 스키마 | user_consents(user_id · kind ∈ TERMS·PRIVACY·LOCATION · terms_document_id · version · agreed_at · revoked_at(nullable) · ip · user_agent · source)에 **버전별 동의 시각**을 기록한다. **"동의를 받았다"는 사실만으로는 입증이 되지 않는다 — 어느 버전에 언제 동의했는지가 법적 증거다.** 이력은 **append-only**이며 갱신·삭제하지 않는다. 동일 (user_id, kind, version)의 중복 동의 기록은 **privacy.consent_version_conflict/409**로 멱등 처리한다 | 본인 · 서버 | P0 |
| REQ-PRV-03 | 동의 철회·재동의 | 사용자는 선택 동의(위치정보 등)를 **철회**할 수 있고 철회 시각을 revoked_at에 기록한다. **철회는 기존 동의 행을 삭제하지 않고 철회 시각만 기록**한다. 위치정보 동의 철회 시 이후 GPS 체크인을 차단하되 **이미 수집된 이용·제공 사실 확인자료는 법정 보존기간까지 유지**한다. 필수 동의(약관·개인정보) 철회는 곧 탈퇴 경로로 안내한다(REQ-AUT-20) — **철회 전이를 여는 조건이 kind = LOCATION 하나이며 가드가 그것을 강제한다**(정본 [../05_database/01_auth.md](../05_database/01_auth.md)). 필수 동의가 철회 상태가 되면 재동의 게이트의 판정 입력이 오염된다. 본인은 자신의 동의·철회 이력 전체를 조회할 수 있다 | 본인 | P0 |

## 관련 테이블

| 테이블 | 역할 |
|--------|------|
| location_usage_records | 위치정보 이용·제공 사실 확인자료 — 서버 전용 기록 · 사용자·관리자 삭제·수정 불가(REQ-PRV-04·05) |
| user_consents | 동의 이력 — kind별 버전·시각·철회 시각 · append-only(REQ-PRV-02·03) |
| terms_documents | 동의 대상 문서 버전 — LOCATION은 별도 kind(REQ-SYS-15) |
| attendance_records | 위치정보 처리의 발생 지점 — 체크인 좌표와 정확도(REQ-ATT-01·03) |
| audit_logs | 원좌표 파기 실행의 감사 기록(REQ-PRV-05) |

| 화면 코드 | 화면명 |

| PUB-SIGNUP | 회원가입 |
| PUB-LOGIN | 로그인 |
| PUB-CONSENT | 약관·개인정보·위치정보 동의 |
| APP-PRIVACY | 개인정보·위치정보 관리 |
| APP-SETTINGS | 내 정보·설정 |

검산: 6본 — PUB 4 · APP 2. **확인자료 자동 기록(REQ-PRV-04)과 원좌표 파기(REQ-PRV-05)는 화면 없는 (서버) 종점**이며 APP-PRIVACY는 정보주체 본인 조회 경로만 담는다 — 사용자가 기록을 만들거나 지울 수 있으면 법정 의무 이행 자체가 증명되지 않는다.

## 에러 코드

| 에러 코드 | HTTP | 발생 조건 |
|-----------|:--:|----------|
| privacy.location_consent_required | 403 | 위치정보 별도 동의 없이 GPS 체크인 시도(REQ-PRV-01) |
| privacy.consent_version_conflict | 409 | 동일 (user_id, kind, version) 동의 중복 기록 — 멱등 처리(REQ-PRV-02) |
