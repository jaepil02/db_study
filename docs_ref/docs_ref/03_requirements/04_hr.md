인사 데이터는 급여 계산의 **입력 원천**이다. 부양가족 수·8~20세 자녀 수가 없으면 소득세 계산이 시작조차 되지 않고, 근로조건(pay_type · base_wage · 주 소정근로시간)이 없으면 기본급을 낼 수 없으며, 보험별 가입 대상 판정이 없으면 공제액이 틀린다. 그래서 인사 도메인의 요구사항 대부분은 **누락 시 계산을 차단하는 계약**이다.

민감정보(주민등록번호 · 급여계좌)는 **AES-GCM 암호화 + HMAC blind-index + 화면 마스킹**이 기본이며, 원문 열람은 재인증 · 사유 · 감사 · 서버 1회성 응답 넷을 모두 충족해야 한다. **원문은 응답·로그·감사 전후값에 절대 남기지 않는다.**

근로계약은 **서버 보관만으로 교부 의무가 이행되지 않는다** — 근로자 정보처리시스템(등록 이메일 또는 앱)으로 발송해야 근로기준법 §17② 교부가 성립한다. 상태 전이 정본은 [../09_glossary/03_enums_state_machines.md](../09_glossary/03_enums_state_machines.md)다. 전역 계약은 [01_global_rules.md](./01_global_rules.md)를 전제한다.

| REQ-HRM-04 | 마스킹·복호화 통제 | 목록·상세는 **마스킹 값만** 노출한다(예: 901201-1로 시작하는 뒷자리 마스킹 형태). STAFF는 본인 마스킹 정보만 조회한다. MANAGER 이상의 원문 복호화는 **① 재인증(REQ-AUT-25) ② 사유 입력 ③ 감사 로그 기록 ④ 서버 1회성 응답**을 모두 충족해야 허용한다. 미충족은 **hr.decrypt_forbidden/403**, 1회성 응답 envelope 등록 충돌은 **hr.decrypt_envelope_conflict/409**다. 복호화 결과를 클라이언트에 캐시하지 않는다 | 본인 · MANAGER | P1 |

| employees | 인사 레코드 — workplace_id 스코프 · status · source · worker_type · 부양가족 수 · 8~20세 자녀 수 · **career_history**(근로자명부 이력 · REQ-HRM-25) |
| employee_personal_infos | 민감정보 — AES-GCM 암호문 · blind index · 마스킹 값 · 키 버전 2종(REQ-HRM-03) |
| employment_terms | 근로조건 버전 이력 — effective_from/to 겹침 차단(REQ-HRM-06) |
| employee_insurance_infos | 보험별 자격 기간 이력 — 가입 여부 · 취득/상실일 · 보수월액 · 예외 사유. 상실되지 않은 자격만 종류당 1건(REQ-HRM-17) |
| employee_insurance_histories | 보험 정보 변경 이력 — log_insurance_history() 기록 · 소급 금지(REQ-HRM-18) |
| contract_templates | 고용형태별 근로계약 템플릿(REQ-HRM-19) |
| contracts | 근로계약 — DRAFT·SENT·SIGNED·ARCHIVED·CANCELLED(REQ-HRM-20) |
| contract_signatures | 전자서명 증적 — 시각 · IP · user agent · PDF 해시(REQ-HRM-21) |
| documents | 문서 메타·보존기한 — 계약 완료본·문서함·명세서 PDF 실체의 단일 보유처(REQ-HRM-23 · REQ-SLP-02) |
| workplaces | 사업장관리번호 계열별 3컬럼의 보유처 — insurance_mgmt_no(고용·산재) · pension_mgmt_no(국민연금) · health_mgmt_no(건강보험). 직원 행에 복제하지 않는다(REQ-HRM-17) |
| workplace_members | 멤버십 연계 — 입사·퇴사와 상태를 함께 전이하며 사유↔종료 상태 매핑을 DB가 검증(REQ-HRM-10·12·14) |
| notifications | STAFF 정보 변경 요청의 저장소(REQ-HRM-05) |
