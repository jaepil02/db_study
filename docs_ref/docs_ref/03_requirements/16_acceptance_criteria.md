# 인수 기준 (Acceptance Criteria)

> **대상**: insadesk v1 — 인수 기준 15항목(AC-01~15)의 Given/When/Then 수용 조건과 검증 방법
> **작성일**: 2026-08-03
> **개정일**: 2026-08-03 — 기대값 산정 선행 조건(미확인 전량 확인) 충족 반영
> **원천**: docs_ref2/requirements_p0.md 골든 케이스 최소 세트(G-01~G-15) · 본 폴더의 REQ 정본 · [../README.md](../README.md) 고정 기준

인수 기준은 **실제 API 호출·실브라우저 조작 + DB 행 대조**로 판정한다 — 화면과 API에서 실제로 실행하고, 그 결과로 남아야 할 행·컬럼 값을 조회로 확인한다. 화면 표시만으로 통과시키지 않고 DB 대조만으로도 통과시키지 않는다. 둘 중 하나만 맞고 다른 하나가 어긋나는 결함이 가장 오래 살아남기 때문이다.

**본 문서는 to-be 설계 정본이다.** 아직 구현이 없으므로 여기 실린 것은 검증 결과가 아니라 **구현 완료 후 이 절차로 판정한다**는 계약이다. 각 항목의 기대값에 요율·세액 수치를 박지 않고 **기준값 픽스처를 주입해 계산**한다 — 수치를 박으면 기준값이 개정되는 순간 테스트가 전부 오답이 된다(REQ-GLB-09 · [13_system.md](./13_system.md) 미확인 절).

판정 규칙 셋을 공통으로 둔다.

- **샘플링 금지** — 대상이 여러 건이면 대표 1건만 보고 통과시키지 않는다. 권한 축이 여럿인 항목은 역할별로 각각 확인한다.
- **미확인은 통과가 아니다** — 확인하지 못한 단계는 "확인 못 함"으로 남기고 완료로 처리하지 않는다.
- **부정 확인을 포함한다** — 되어야 하는 것뿐 아니라 **되지 않아야 하는 것**(0행 · 차단 · 미노출 · 값 불변)을 함께 확인한다.

## 골든 기대값 산정 절차

계산 인수 기준(AC-01~07 · AC-09~14)은 "얼마가 나와야 하는가"를 정하지 않으면 판정할 수 없다. **본 문서가 지금 금액을 적지 않는 이유는 설계가 덜 됐기 때문이 아니라 기준값이 미확인이기 때문**이다 — 확인되지 않은 요율·세액표로 만든 기대값은 그 자체가 오답이고, 오답을 기준으로 통과 판정을 내리면 결함이 인수 기준의 보증을 받고 배포된다. 기대값은 아래 5단계를 거쳐 확정한다.

| 단계 | 내용 | 완료 판정 |
|:-:|------|----------|
| ① | **미확인 기준값 전량 확인 완료가 선행 조건**이다 — **2026-08-03 전건 확인 완료로 충족됐다**(목록 정본 [../01_overview/05_priorities_roadmap.md](../01_overview/05_priorities_roadmap.md)). 남은 선행 작업은 확인값의 기준값 행 시드다 | 미확인 목록의 0단계 항목이 0건이고 각 기준값 행에 출처·확인자가 기록됨 |
| ② | 확정된 기준값으로 **대표 케이스별 수기 계산 대조표**를 만든다. 케이스마다 입력(근태 버킷 분·근로조건·부양가족 수·지급일) · 적용 기준값 행 식별자와 값 · **단계별 중간값** · 항목별 반올림 적용 지점 · 최종 금액을 한 줄씩 적어 손으로 검산한다. 노무·세무 검토자가 이 표를 읽고 산식을 따라갈 수 있어야 한다 | 대조표가 AC-01~07 · AC-09~14의 케이스를 모두 덮고 검토자 승인이 기록됨 |
| ③ | 대조표의 최종 금액을 **정수(원) 기대값으로 동결**해 형상관리에 넣는다. 기대값 파일에는 값과 함께 **산출 근거(기준값 행 식별자 · 규칙 버전 · 대조표 참조)**를 남긴다 | 기대값이 코드와 같은 저장소에 버전 관리되고 근거 없이 바뀐 값이 없음 |
| ④ | **구현 출력을 스냅샷해 기대값으로 삼는 것을 금지한다.** 구현이 틀렸을 때 그 틀린 값이 정답으로 굳어 회귀 시험이 결함을 영구 보존하기 때문이다. 기대값의 유일한 출처는 ②의 수기 대조표다 | 기대값 파일의 생성 경로에 구현 호출이 없음 |
| ⑤ | **기준값 또는 규칙 버전이 바뀌면 기대값을 재산정**한다. 새 값으로 ②를 다시 수행해 새 기대값을 추가하되 **과거 귀속분의 기존 기대값은 그대로 둔다** — 과거 확정은 동결된 값으로 재현되어야 하므로(REQ-GLB-10) 기대값도 귀속 기준일 축으로 누적한다 | 규칙 버전별 기대값이 공존하고 과거 케이스가 계속 통과함 |

**이 절차가 끝나기 전에는 AC-11(결정론)과 AC-12(기준값 정정 후 불변)를 판정할 수 없다.** 두 항목은 "같은 입력에 같은 값" · "기준값을 바꿔도 과거 값 불변"을 보는데, 비교 대상 기대값이 없으면 무엇에 대해 같음·불변인지 정의되지 않기 때문이다. 나머지 계산 항목도 ①~③ 완료 전에는 구조 검증(버킷 분해 합 · 라인 구성 · 차단 동작)까지만 수행하고 **금액 일치 판정을 보류**한다.

## 인수 기준 목록

| ID | 시나리오 | 수용 조건 |
|----|----------|-----------|
| AC-01 | 5인 이상 월급제 · 연장 + 야간 중복 | **Given** 상시근로자 스냅샷이 5인 이상이고 월급제 근로조건과 기준값 픽스처가 갖춰진 사업장에서 **When** 소정 시간대 야간 · 연장 · 연장야간이 함께 있는 한 달 근태를 마감하고 급여를 계산하면 **Then** 8버킷 분해 결과가 버킷 2·3·4로 나뉘고 지급배수가 각각 0.5 · 1.5 · 2.0(월급제 추가 지급 기준)으로 적용되며, 각 수당 라인에 기준시간 · 통상시급 · 가산율 · 적용 법칙이 동결 저장된다. **부정 확인** — 소정 버킷(버킷 1)에는 추가 지급이 발생하지 않고, 야간·연장이 겹친 시간대가 버킷 2와 3에 이중 계상되지 않으며 버킷 합계가 raw 실근로분과 정확히 일치한다. |
| AC-02 | 5인 이상 · 휴일 10시간(야간 2시간 포함) | **Given** 5인 이상 사업장에서 **When** 휴일에 10시간(그중 22시 이후 2시간)을 근무한 근태를 마감하고 계산하면 **Then** 버킷 5·6·7·8로 분해되고 8시간 초과분이 버킷 7·8로 배정되며 **휴일 8시간 초과분의 총 배수가 2.0**(야간 겹침 시 2.5)으로 산출된다. **부정 확인** — 휴일 8시간 초과분에 연장 가산 0.5가 추가되어 2.5(야간 겹침 시 3.0)가 되지 않는다. 휴일 근로시간이 주 40시간 산정에 포함되어 다른 날의 연장 판정을 바꾸지 않는다. |
| AC-03 | 5인 미만 · 동일 근태 | **Given** AC-01과 동일한 근태·근로조건이되 상시근로자 스냅샷이 5인 미만인 사업장에서 **When** 급여를 계산하면 **Then** 연장·휴일 버킷에 **실근로분 1.0배가 지급**되고 가산분만 0으로 동결되며, 결과와 명세서 계산방법에 5인 미만 사실과 가산 미적용 근거가 표기된다. **주휴수당 · 최저임금 검증 · 4대보험 · 소득세 · 명세서 · 임금대장은 그대로 적용**된다. **부정 확인** — 연장·휴일 버킷의 총 배수가 0이 되지 않는다(무급 처리는 임금체불이다). 연차는 leave.not_applicable/403으로 미적용이며 이는 오류가 아니다. |
| AC-04 | 주휴수당 발생·미발생 | **Given** 주 소정근로시간이 15시간 이상인 직원과 15시간 미만인 직원, 그리고 결근이 있는 직원이 같은 주에 있을 때 **When** 그 주를 포함한 급여를 계산하면 **Then** 15시간 이상 + 개근인 직원에게만 주휴수당 = (주 소정근로시간 ÷ 40) × 8 × 통상시급(40시간 이상은 8시간 상한)이 earning_item 올림 1원으로 발생하고, 미발생 직원의 결과에 **미발생 사유**가 명시된다. **규모와 무관하게 적용**된다. **부정 확인** — 지각·조퇴만 있고 결근이 없는 직원의 주휴가 사라지지 않는다. 월급제 직원에게 주휴가 이중 지급되지 않는다. |
| AC-05 | 4대보험 보험별 base 분리 | **Given** 건강보험 보수에는 다시 포함되지만 소득세법상 비과세인 항목이 1건 있는 급여에서 **When** 4대보험 공제를 산출하면 **Then** 국민연금·고용보험·산재보험의 base와 건강보험의 base가 **서로 다른 값**으로 산출되고 보험별 공제액이 각각 10원 미만 절사되며, **적용된 base와 기준값 행 ID가 보험별로 각각 결과 라인에 동결**된다. **부정 확인** — 하나의 과세표준 값을 4개 보험에 공용하지 않는다. 건강보험료와 국민연금 보험료의 base가 동일하게 나오지 않는다. |
| AC-06 | 보험별 가입 제외 판정 | **Given** 월 소정근로 60시간 미만이면서 계속근로 3개월 이상인 직원이 있을 때 **When** 보험별 가입 대상을 판정하면 **Then** 국민연금·건강보험은 제외, **고용보험은 적용**, **산재보험은 적용**으로 판정되고 각 판정의 **제외 근거가 결과에 남는다**. **부정 확인** — "초단시간이니 4대보험 전부 제외"로 처리되지 않는다. 산재보험료가 근로자 급여에서 공제되지 않는다. |
| AC-07 | 간이세액표 지급일 경계 | **Given** 간이세액표 개정 시행일 직전 버전과 직후 버전이 모두 기준값에 등록된 상태에서 **When** 귀속월은 같고 지급일만 시행일 전후로 다른 두 급여를 계산하면 **Then** 각각 **지급일 기준으로 다른 세액표 버전**이 선택되고, 결과에 과세표준 · 부양가족 수 · 8~20세 자녀 수 · 세액표 버전 · 원천징수 선택비율이 전부 동결된다. **부정 확인** — 귀속월 기준으로 버전이 선택되어 두 급여의 세액표 버전이 같아지지 않는다. 지급일이 비어 있으면 payroll.missing_payroll_terms/422로 계산이 차단되고 임의 기본값으로 진행되지 않는다. |
| AC-08 | 상시근로자 제2항 보정 | **Given** 일자별 근로자 수 시계열이 저장된 산정기간에서 **When** 평균이 5명 미만이지만 미달일수가 가동일수의 절반 미만인 경우와, 평균이 5명 이상이지만 미달일수가 절반 이상인 경우를 각각 산정하면 **Then** 전자는 **5인 이상으로**, 후자는 **5인 미만으로** 판정이 뒤집히고 스냅샷에 연인원 · 가동일수 · 평균값 · 시계열이 함께 저장된다. **부정 확인** — 판정이 반올림된 평균값 비교로 수행되지 않는다(연인원과 임계값 × 가동일수의 정수 비교여야 한다). 시계열 없이 평균값만으로 보정을 시도하지 않는다. |
| AC-09 | 단수 처리 — 항목별 1회 반올림 | **Given** 반올림 규칙 기준값이 등록된 상태에서 **When** 여러 수당·공제가 있는 급여를 계산하면 **Then** 각 항목의 **최종 금액에서만 1회** 반올림이 적용되고(지급 올림 1원 · 무급공제 절사 1원 · 법정공제 절사 10원) 항목 합계는 이미 반올림된 정수들의 합이 된다. **부정 확인** — 중간 몫을 반올림해 저장한 뒤 재사용하면 결과 금액이 달라진다는 사실을 **역으로 증명**한다(통상시급을 제외한 중간 반올림이 없어야 한다). 항목 합계를 다시 반올림하지 않는다. |
| AC-10 | 최저임금 경계 | **Given** 환산시급이 최저임금 경계에 근접한 급여에서 **When** 최저임금 검증을 수행하면 **Then** 환산시급 = 월 산입 임금 ÷ 월 환산 기준시간(= divisor와 같은 산식)이 **반올림 없이 NUMERIC 정밀도 그대로** 기준값과 비교되고, 미달이면 payroll.below_minimum_wage/422로 확정이 차단되거나 관리자 명시 확인이 요구된다. **부정 확인** — 절사·절상 어느 쪽으로도 판정이 뒤집히는 입력에서 판정이 바뀌지 않는다. **결근이 많은 달에 미달로 오판정되지 않는다** — 같은 근로조건에 결근일수만 다른 두 달의 환산시급이 동일해야 한다(분자·분모 모두 무급공제 반영 전 소정근로 축이므로). 미달 강행 확정 시 사유와 행위자가 감사 로그에 남고, **명세서에는 내부 경고가 노출되지 않는다**. |
| AC-11 | 계산 결정론 | **Given** 동일한 마감 근태 · 기준값 버전 · 귀속 기준일 · 지급일에서 **When** 같은 급여를 100회 재계산하면 **Then** 모든 회차의 결과가 항목 라인 순서까지 포함해 완전히 동일하다. 실행 시각 · 서버 로케일 · 타임존 환경변수를 바꿔도 결과가 변하지 않는다. **부정 확인** — 재계산이 부수효과를 남기지 않는다(확정 결과 · 감사 로그 외 행이 늘지 않는다). 난수 · 실행 시각 의존 · 부동소수점 누적이 결과에 개입하지 않는다. |
| AC-12 | 기준값 정정 후 과거 확정 불변 | **Given** 확정된 과거 급여와 그 계산에 쓰인 기준값이 있을 때 **When** 그 기준값 행을 정정하고 과거 명세서를 재출력하면 **Then** 확정 결과와 명세서 PDF의 금액·계산방법이 **한 자리도 변하지 않는다** — 결과에 동결된 기준값 행 ID와 실제 값이 쓰이기 때문이다. **부정 확인** — 기준값 이력 조회만으로 재현하려 하면 값이 달라진다는 사실을 함께 확인해 동결의 필요성을 증명한다. 기준값 변경이 과거 확정에 자동 소급되지 않는다. |
| AC-13 | 월 중 근로조건 변경 | **Given** 월 중 시급 또는 소정근로시간이 바뀌는 근로조건 이력이 있는 직원에서 **When** 그 달 급여를 계산하면 **Then** 유효기간별로 구간을 분할해 기본급·수당을 각각 산출한 뒤 합산하고, 반올림은 **분할 구간이 아니라 항목 단위 최종 금액에서 1회**만 적용된다. **부정 확인** — 근로조건 유효기간이 겹치면 hr.term_overlap/409로 저장 자체가 차단된다. 구간별로 반올림하면 합계가 달라진다는 사실을 역으로 확인한다. |
| AC-14 | 연차 비례 산정(단시간) | **Given** 5인 이상 사업장에 통상근로자 주 40시간과 단시간 주 20시간(주 5일 × 4시간) 직원이 있을 때 **When** 연차를 산정하면 **Then** 시간 = 통상 연차일수 × (20 ÷ 40) × 8로 환산한 뒤 1일 소정근로시간으로 나눠 **0.1일 올림**으로 일수가 확정되고 원장에 GRANT 행이 남는다. **부정 확인** — 주 15시간 미만 초단시간 근로자는 비례 산정 대상에서 제외된다. 중간 몫을 반올림하지 않는다. 스냅샷이 없으면 leave.employee_count_snapshot_required/422로 발생 자체가 차단된다. |
| AC-15 | 휴게 미달 마감 차단 | **Given** 실근로 8시간에 휴게 기록이 0분인 근태가 있을 때 **When** 그 달 근태 마감을 시도하면 **Then** attendance.closing_blocked/409로 차단되고 차단 사유 배열에 휴게시간 미달이 포함되며, 마감 기간이 LOCKED로 전이되지 않는다. **전 규모 적용**이므로 5인 미만에서도 동일하게 차단된다. **부정 확인** — 휴게를 보정해 기준을 충족시키면 같은 요청이 통과하고, 마감되지 않은 기간에 대한 급여 확정은 payroll.attendance_not_closed/409로 막힌다. |

검산: AC-01 ~ AC-15 = **15항목**. 원천 골든 케이스 G-01~G-15와 1대 1로 대응하며 누락·병합이 없다.

## 검증 순서

앞 항목의 산출물이 뒤 항목의 전제가 되므로 다음 순서로 수행한다.

```
[기반 · 규모 판정]   AC-08 → AC-15
[근태 → 수당]        AC-01 → AC-02 → AC-03 → AC-04 → AC-13
[공제 · 세금]        AC-05 → AC-06 → AC-07
[정밀도 · 재현성]    AC-09 → AC-10 → AC-11 → AC-12
[연차]               AC-14
```

- **AC-08(상시근로자 산정)이 가장 먼저다.** 스냅샷이 없으면 AC-01~AC-04·AC-14가 전부 차단되어 판정 자체가 불가능하다.
- **AC-15(휴게 미달 마감 차단)가 그다음이다.** 마감이 되지 않으면 급여 계산 입력이 만들어지지 않는다.
- AC-03은 AC-01과 **동일한 근태·근로조건**을 5인 미만 사업장에 재투입하는 항목이므로 AC-01 직후에 이어서 수행한다.
- AC-12는 AC-01~AC-07 중 최소 1건의 **확정된 급여**가 있어야 수행할 수 있다.
- 각 항목의 부정 확인은 정상 경로 확인 직후 같은 세션·같은 픽스처에서 이어서 수행한다.
